# Специальные синтаксические конструкции

Python 3.8 ввел новый синтаксис для определения **positional-only параметров** с использованием разделителя `/`, дополнив существовавший с Python 3 синтаксис для **keyword-only параметров** с использованием разделителя `*`. Эти конструкции позволяют точно контролировать, как аргументы могут передаваться в функцию
```python
# Полный синтаксис с обоими разделителями
def function(
    pos_only1, pos_only2, /,  # только позиционные
    pos_or_kwd1, pos_or_kwd2,  # можно и так, и так
    *,                         # разделитель: дальше только именованные
    kwd_only1, kwd_only2       # только именованные
):
    pass
```

## Positional-only аргументы (разделитель /)

### Что такое positional-only параметры?
Параметры, расположенные **до** разделителя `/`, могут быть переданы **только позиционно**. Их нельзя передать по имени
```python
def pow_function(x, y, /):
    """x и y могут быть только позиционными"""
    return x ** y

# Правильно:
print(pow_function(2, 3))     # 8

# Неправильно:
# print(pow_function(x=2, y=3))  # TypeError!
```

### История и мотивация
До Python 3.8 нельзя было создать функции с positional-only параметрами в чистом Python, хотя многие встроенные функции имели такое поведение
```python
# Встроенные функции с positional-only параметрами
help(len)      # len(obj, /)  — параметр только позиционный
help(abs)      # abs(x, /)    — только позиционный
help(divmod)   # divmod(x, y, /) — оба только позиционные
help(pow)      # pow(x, y, z, /) — все позиционные (кроме опционального mod)
```

Зачем это нужно?
1. **Совместимость с существующим C-кодом**
2. **Свобода переименования параметров** без опасности сломать код
3. **Чистота API** — некоторые параметры просто не должны иметь имени
4. **Производительность** — небольшое ускорение при вызове

### Синтаксис и правила
```python
# Базовая форма
def func(a, b, /):
    print(a, b)

func(1, 2)        # OK
# func(a=1, b=2)  # TypeError!

# Можно комбинировать с обычными параметрами
def func(a, b, /, c):
    print(a, b, c)

func(1, 2, 3)        # OK (c позиционно)
func(1, 2, c=3)      # OK (c по имени)
# func(a=1, b=2, c=3)  # TypeError: a,b только позиционные!

# Множественные positional-only параметры
def configure(host, port, /, timeout=30, retries=3):
    print(f"Connecting to {host}:{port} (timeout={timeout}, retries={retries})")

configure("localhost", 8080)                    # OK
configure("localhost", 8080, timeout=60)        # OK
# configure(host="localhost", port=8080)         # TypeError!
```

### Примеры из стандартной библиотеки
Многие функции в Python используют positional-only параметры:
```python
# Пример 1: Функции с семантикой, где имена не имеют значения
def distance(x1, y1, x2, y2, /):
    """Расстояние между двумя точками - имена координат не важны"""
    return ((x2 - x1) ** 2 + (y2 - y1) ** 2) ** 0.5

print(distance(0, 0, 3, 4))  # 5.0
# distance(x1=0, y1=0, x2=3, y2=4)  # TypeError - и так понятно!

# Пример 2: Функции, где порядок критичен
def divide(dividend, divisor, /):
    """dividend делимое, divisor делитель - порядок критичен!"""
    if divisor == 0:
        raise ValueError("Division by zero")
    return dividend / divisor

# Пример 3: Фабрики с обязательным порядком
def create_point(x, y, /, color="black", size=1):
    """x и y только позиционные, color и size можно по имени"""
    return {"x": x, "y": y, "color": color, "size": size}
```

### Когда использовать positional-only?
```python
# 1. Когда имена параметров не имеют значения
def add(*args):  # *args сам по себе positional-only
    return sum(args)

# 2. Когда хотите сохранить возможность переименования
def connect_to_db(host, port, /, user, password):
    """
    host и port можно переименовать в будущем без опасности сломать код.
    user и password — важные имена, их можно указывать явно.
    """
    pass

# 3. Для математических/научных функций
def quadratic_roots(a, b, c, /):
    """Коэффициенты уравнения a·x² + b·x + c = 0"""
    discriminant = b**2 - 4*a*c
    if discriminant < 0:
        return None
    sqrt_d = discriminant ** 0.5
    return ((-b - sqrt_d) / (2*a), (-b + sqrt_d) / (2*a))

# 4. Когда есть естественный порядок аргументов
def rgb_to_hex(r, g, b, /):
    """Конвертация RGB в HEX — порядок каналов фиксирован"""
    return f"#{r:02x}{g:02x}{b:02x}"
```

## Keyword-only аргументы (разделитель *)

### Что такое keyword-only параметры?
Параметры, расположенные **после** разделителя `*`, могут быть переданы **только по имени**
```python
def create_user(name, *, age, city):
    """name — позиционный, age и city — только именованные"""
    return {"name": name, "age": age, "city": city}

# Правильно:
print(create_user("Анна", age=25, city="Москва"))

# Неправильно:
# print(create_user("Анна", 25, "Москва"))  # TypeError!
```

### Мотивация для keyword-only
Keyword-only параметры появились в Python 3 и решают несколько проблем:
1. **Ясность кода** — обязательное именование делает код самодокументируемым
2. **Гибкость API** — можно добавлять новые параметры без изменения существующего кода
3. **Безопасность** — предотвращает ошибки с порядком аргументов

### Синтаксис и правила
```python
# Базовое использование
def func(*, a, b):
    print(a, b)

func(a=1, b=2)    # OK
# func(1, 2)       # TypeError!

# После * могут быть параметры с умолчаниями
def func(a, b, *, c=10, d=20):
    print(a, b, c, d)

func(1, 2, c=30)        # 1 2 30 20
func(1, 2, d=40)        # 1 2 10 40
func(1, 2)              # 1 2 10 20

# * сам по себе без имени — запрещает позиционные аргументы
def func(a, b, *, c):
    # * означает: после b не может быть позиционных аргументов
    pass

# *args работает иначе
def func(a, b, *args, c):
    # *args собирает лишние позиционные, c — keyword-only
    print(a, b, args, c)

func(1, 2, 3, 4, c=5)   # 1 2 (3,4) 5
```

## Комбинированное использование / и *

### Полный синтаксис
В одной функции можно использовать оба разделителя для точного контроля:
```python
def flexible_function(
    pos1, pos2,        # можно и так, и так
    /,                  # все до / только позиционные
    pos_or_kwd1,        # можно и так, и так
    pos_or_kwd2="def",  # с умолчанием
    *,                  # все после * только именованные
    kwd1,               # обязательный именованный
    kwd2="default"      # именованный с умолчанием
):
    print(f"pos_only: {pos1}, {pos2}")
    print(f"pos_or_kwd: {pos_or_kwd1}, {pos_or_kwd2}")
    print(f"kwd_only: {kwd1}, {kwd2}")

# Разрешенные вызовы:
flexible_function(1, 2, 3, 4, kwd1=5, kwd2=6)
flexible_function(1, 2, pos_or_kwd1=3, pos_or_kwd2=4, kwd1=5, kwd2=6)
flexible_function(1, 2, 3, pos_or_kwd2=4, kwd1=5, kwd2=6)
flexible_function(1, 2, 3, 4, kwd1=5)

# Запрещенные вызовы:
# flexible_function(pos1=1, pos2=2, ...)  # pos1,pos2 только позиционные
# flexible_function(1, 2, 3, 4, 5)        # kwd1 должен быть именованным
# flexible_function(1, 2, 3, kwd1=5)      # kwd2=6 не хватает? нет, есть умолчание
```

### Порядок параметров (важно!)
```python
# Правильный порядок (от менее к более специфичным):
def correct_order(
    # 1. Positional-only (до /)
    pos_only1, pos_only2,
    /,
    
    # 2. Обычные параметры (можно и так, и так)
    standard1, standard2="default",

# Неправильные порядки:
# def wrong1(a, /, b, *, c, d):  # OK, но b можно и так, и так
# def wrong2(*, a, /, b):        # SyntaxError: / must be before *
# def wrong3(a, *args, /, b):    # SyntaxError: / must be before *
# def wrong4(a, **kwargs, b):    # SyntaxError: **kwargs must be last
```

### Практический пример: HTTP клиент
```python
import requests
from typing import Optional, Dict, Any

class HTTPClient:
    def __init__(
        self,
        base_url: str,
        /,  # base_url только позиционный (имя не важно)
        *,
        timeout: float = 30.0,
        retries: int = 3,
        verify_ssl: bool = True,
        headers: Optional[Dict[str, str]] = None
    ):
        """
        HTTP клиент с гибкой конфигурацией.
        
        Args:
            base_url: Базовый URL (только позиционный)
            timeout: Таймаут запроса в секундах
            retries: Количество повторных попыток
            verify_ssl: Проверять SSL сертификаты
            headers: Заголовки по умолчанию
        """
        self.base_url = base_url.rstrip('/')
        self.timeout = timeout
        self.retries = retries
        self.verify_ssl = verify_ssl
        self.headers = headers or {}
    
    def request(
        self,
        method: str,
        endpoint: str,
        /,  # method и endpoint только позиционные
        *,
        params: Optional[Dict] = None,
        data: Optional[Dict] = None,
        json: Optional[Dict] = None,
        headers: Optional[Dict] = None,
        **kwargs: Any
    ) -> requests.Response:
        """
        Выполнить HTTP запрос.
        
        Args:
            method: HTTP метод (GET, POST и т.д.) - только позиционный
            endpoint: Путь к ресурсу - только позиционный
            params: Query параметры - только именованные
            data: Данные формы - только именованные
            json: JSON данные - только именованные
            headers: Дополнительные заголовки - только именованные
            **kwargs: Дополнительные параметры requests
        """
        url = f"{self.base_url}/{endpoint.lstrip('/')}"
        
        request_headers = {**self.headers, **(headers or {})}
        
        response = requests.request(
            method=method,
            url=url,
            params=params,
            data=data,
            json=json,
            headers=request_headers,
            timeout=self.timeout,
            verify=self.verify_ssl,
            **kwargs
        )
        
        return response

# Использование
client = HTTPClient("https://api.example.com", timeout=60, retries=5)

# Ясные вызовы
response = client.request("GET", "/users", params={"page": 1})
response = client.request("POST", "/users", json={"name": "Анна"})

# Нельзя перепутать порядок
# response = client.request(endpoint="/users", method="GET")  # TypeError!
# response = client.request("GET", "/users", {"page": 1})     # TypeError! params должен быть именованным
```

## Глубокие технические детали

### Как это работает внутри?
```python
import inspect

def analyze_func(func):
    sig = inspect.signature(func)
    print(f"Сигнатура: {sig}")
    
    for name, param in sig.parameters.items():
        kind = param.kind
        kind_name = {
            inspect.Parameter.POSITIONAL_ONLY: "POSITIONAL_ONLY",
            inspect.Parameter.POSITIONAL_OR_KEYWORD: "POSITIONAL_OR_KEYWORD",
            inspect.Parameter.VAR_POSITIONAL: "VAR_POSITIONAL (*args)",
            inspect.Parameter.KEYWORD_ONLY: "KEYWORD_ONLY",
            inspect.Parameter.VAR_KEYWORD: "VAR_KEYWORD (**kwargs)"
        }.get(kind, str(kind))
        
        print(f"  {name}: {kind_name}, default={param.default}")

def example(a, b, /, c, d=10, *args, e, f=20, **kwargs):
    pass

analyze_func(example)
# Сигнатура: (a, b, /, c, d=10, *args, e, f=20, **kwargs)
#   a: POSITIONAL_ONLY, default=<class 'inspect._empty'>
#   b: POSITIONAL_ONLY, default=<class 'inspect._empty'>
#   c: POSITIONAL_OR_KEYWORD, default=<class 'inspect._empty'>
#   d: POSITIONAL_OR_KEYWORD, default=10
#   args: VAR_POSITIONAL (*args), default=<class 'inspect._empty'>
#   e: KEYWORD_ONLY, default=<class 'inspect._empty'>
#   f: KEYWORD_ONLY, default=20
#   kwargs: VAR_KEYWORD (**kwargs), default=<class 'inspect._empty'>
```

## Частые ошибки и подводные камни

### 1. Неправильный порядок разделителей
```python
# ОШИБКА
def wrong(a, *, b, /, c):  # SyntaxError: / must be before *
    pass

# ПРАВИЛЬНО
def correct(a, /, b, *, c):
    pass
```

### 2. Забытый параметр после *
```python
def func(a, *, b):  # b обязательный keyword-only
    print(a, b)

func(1, b=2)  # OK
# func(1)     # TypeError: missing 1 required keyword-only argument: 'b'

# Если нужны опциональные keyword-only, дайте им умолчания
def func(a, *, b=None):
    print(a, b)
```

### 3. Путаница с *args и *
```python
# *args — собирает позиционные аргументы
def with_args(a, b, *args, c):
    print(a, b, args, c)

# * — разделитель, не собирает аргументы
def with_star(a, b, *, c):
    print(a, b, c)

with_args(1, 2, 3, 4, c=5)   # args = (3,4)
with_star(1, 2, c=3)          # нельзя передать 3,4 позиционно
```

### 4. Попытка передать positional-only по имени
```python
def func(a, /):
    pass

# func(a=1)  # TypeError!
```

### 5. Использование / в неправильном контексте
```python
# В lambda нельзя использовать /
# lambda a, /: a  # SyntaxError

# В методах классов работает
class MyClass:
    def method(self, a, /, b):
        print(a, b)
```

def validate_age(
    age: int,
    /,  # age только позиционный — имя не важно
    *,
    min_age: int = 0,
    max_age: int = 150,
    allow_none: bool = False
) -> bool:
    """
    Проверяет корректность возраста.
    
    Args:
        age: Проверяемый возраст (только позиционный)
        min_age: Минимально допустимый возраст
        max_age: Максимально допустимый возраст
        allow_none: Разрешать None

        return allow_none
    return min_age <= age <= max_age

**О:** Чтобы разрешить переименование параметров в будущем, для соответствия встроенным функциям, и когда имена параметров не имеют семантического значения.

**В: Зачем нужны keyword-only параметры?**
**О:** Чтобы сделать код самодокументируемым, предотвратить ошибки с порядком аргументов, и позволить добавлять новые параметры без изменения существующего кода.

**В: Можно ли использовать / и * в одной функции?**
**О:** Да, это часто полезно для точного контроля над API. Сначала /, потом обычные параметры, потом *.

**В: Влияют ли эти разделители на производительность?**
**О:** Незначительно. Positional-only могут быть немного быстрее, keyword-only — немного медленнее, но разница обычно несущественна.

**В: Работают ли эти разделители в lambda?**
**О:** Нет, lambda функции не поддерживают этот синтаксис.

**В: Как это влияет на наследование?**
**О:** Сигнатура метода должна быть совместима с родительским, включая разделители.

### Ключевые выводы
```python
"""
1. / — все параметры слева только позиционные
2. * — все параметры справа только именованные
3. Порядок: позиционные, /, обычные, *, именованные, **kwargs
4. Positional-only: имена можно менять без опасности
5. Keyword-only: код становится самодокументируемым
6. Оба разделителя можно использовать вместе
7. Встроенные функции часто используют positional-only
8. Для API с множеством опций используйте keyword-only
9. Для математических функций используйте positional-only
10. Документируйте намерения при использовании разделителей
"""
```

### Ментальная модель
```
Представьте функцию как здание с разными входами:

    /     обычные     *
[вход1][вход2][вход3][вход4][вход5]

/ — турникет: через этот вход можно пройти только 
    в порядке очереди (позиционно)

Обычные параметры — обычные двери: можно войти
    по порядку или назвать имя

* — охранник: дальше можно пройти только 
    назвав себя по имени (именованные)

Пример:
def func(a, /, b, *, c):
    pass

a — только по порядку (турникет)
b — можно по порядку или по имени (обычная дверь)
c — только по имени (охранник)
```

### Проверка знаний: что выведет код?
```python
# Тест 1: Positional-only
def test1(a, b, /, c):
    print(a, b, c)

# Какие вызовы правильные?
# test1(1, 2, 3)
# test1(1, 2, c=3)
# test1(a=1, b=2, c=3)

# Тест 2: Keyword-only
def test2(*, a, b=10):
    print(a, b)

# Какие вызовы правильные?
# test2(5)
# test2(a=5)
# test2(a=5, b=20)
# test2(5, 20)

# Тест 3: Комбинация
def test3(x, /, y=10, *, z):
    print(x, y, z)

# Какие вызовы правильные?
# test3(1, z=3)
# test3(1, 2, z=3)
# test3(1, y=2, z=3)
# test3(x=1, y=2, z=3)

# Тест 4: Сложная комбинация
def test4(a, /, b, c=30, *args, d, **kwargs):
    print(a, b, c, args, d, kwargs)

test4(1, 2, 3, 4, 5, d=6, e=7, f=8)
# Что выведет?

# Ответы:
# 1: Первые два правильные, третий - TypeError
# 2: test2(a=5) и test2(a=5, b=20) правильные
# 3: Первые три правильные, четвертый - TypeError
# 4: 1 2 3 (4,5) 6 {'e':7, 'f':8}
```
