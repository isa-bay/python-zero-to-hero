# Введение в Python

### Что такое Python?

**Python** — это высокоуровневый, интерпретируемый язык программирования общего назначения с динамической типизацией и автоматическим управлением памятью, делающий акцент на простоте и читаемости кода

1.  **Высокоуровневый язык:**
    - Python абстрагирует программиста от деталей работы аппаратного обеспечения и операционной системы (управление памятью, регистры процессора, системные вызовы)

2.  **Интерпретируемый, а не компилируемый (с нюансом):**
    - Код Python выполняется построчно специальной программой — интерпретатором, без предварительной компиляции в машинный код
    - Это дает преимущества:
        - **Кроссплатформенность:** Один и тот же код работает на Windows, macOS, Linux (если есть интерпретатор)
        - **Простота отладки:** Вы можете остановить программу, изменить код и продолжить выполнение (REPL)
    - *Нюанс:* Современный Python на самом деле **компилирует** код в промежуточный байт-код (в папке `__pycache__`), который затем выполняется виртуальной машиной. Это делает его "компилируемо-интерпретируемым" гибридом, как Java

3.  **Динамическая типизация:**
    - Тип переменной определяется автоматически во время выполнения программы, когда ей присваивается значение
    - Вам не нужно объявлять `int x = 5;`, достаточно написать `x = 5`
    - Переменная может менять свой тип: `x = 5; x = "hello"` (хотя это считается плохой практикой, тк приводит к нарушению эширования, оптимизации и может привести к ошибке внутри кода, которую сложно словить)

4.  **Автоматическое управление памятью (Garbage Collection / сборщик мусора):**
    - Python сам отслеживает, какие объекты больше не используются, и освобождает занимаемую ими память. Это избавляет от огромного класса ошибок (утечки памяти, висячие указатели), характерные для C/C++

5.  **Общее назначение:**
    - Python не заточен под одну узкую задачу (в отличие от R для статистики или PHP для веба). На нем можно писать всё: от скриптов для автоматизации до веб-серверов и нейросетей

### История создания
**Создатель:** Гвидо ван Россум (Guido van Rossum), голландский программист

**Хронология:**
- **1989:** Гвидо, работая в центре математики и информатики в Нидерландах (CWI), ищет себе "хобби-проект", чтобы скоротать рождественские каникулы. Он решает создать интерпретатор для нового языка, который будет потомком языка **ABC** (обучающий язык, созданный в CWI). Ему не нравился сложный синтаксис ABC и отсутствие возможностей для взаимодействия с ОС Amoeba, под которую он писал
- **Название:** Название взято не в честь змеи, а в честь британского комедийного сериала 1970-х "**Летающий цирк Монти Пайтона**" (Monty Python's Flying Circus). Гвидо хотел, чтобы название было коротким, уникальным и немного загадочным. Создатель языка подчеркивал, что "Python" звучит достаточно дерзко
- **феврал 1991:** Гвидо публикует исходный код версии 0.9.0 в группе новостей Usenet `alt.sources`. Это считается днем рождения Python как открытого проекта. Уже в этой версии были классы, функции, обработка исключений и основные типы данных
- **Ключевые вехи развития:**
    - **1994:** Создана первая группа пользователей Python (comp.lang.python)
    - **2000:** Выходит **Python 2.0**. Главное новшество — **списковые включения (list comprehensions)** и система сборки мусора для обнаружения циклов ссылок. Процесс разработки становится более открытым
    - **2008:** Выходит **Python 3.0 (Python 3000)**. Это была осознанная поломка обратной совместимости. Гвидо и команда решили, что накопившиеся за 10 лет шероховатости и устаревшие конструкции (вроде `print` без скобок) нужно исправить раз и навсегда, даже ценой перехода
    - **2018-2020:** Завершается эпоха Python 2. Выходят последние версии 2.7, и сообщество окончательно переходит на Python 3
    - **2018 - наст. время:** Гвидо уходит с поста "великодушного пожизненного диктатора" (BDFL) после разногласий по поводу PEP 572 (выражения присваивания `:=`). Управление переходит к Совету из пяти человек (Steering Council).

### Философия Python (Zen of Python)
Это сборник из 20 принципов, которые влияют на дизайн языка и написание идиоматического кода. Набрать в интерпретаторе `import this` — и они появятся на экране

**Ключевые принципы с пояснениями:**

1.  **Beautiful is better than ugly.** (Красивое лучше уродливого.)
    - Код должен быть эстетически приятным. Читать свой код через полгода должно быть приятно.
2.  **Explicit is better than implicit.** (Явное лучше неявного.)
    - Лучше написать код понятно, чем полагаться на магию, которую сложно отлаживать. Импорты должны быть явными, передача параметров — понятной.
3.  **Simple is better than complex.** (Простое лучше сложного.)
    - Если задачу можно решить простым способом — решайте её простым способом. Не создавайте избыточных абстракций.
4.  **Complex is better than complicated.** (Сложное лучше запутанного.)
    - Если задача сложна по своей сути (например, в физическом движке), код может быть сложным, но он должен быть логичным и структурированным (сложным), а не запутанным и хаотичным (complicate — "запутанный").
5.  **Flat is better than nested.** (Плоское лучше вложенного.)
    - Избегайте глубокой вложенности условий, циклов и структуры папок (если это разумно).
6.  **Sparse is better than dense.** (Разреженное лучше плотного.)
    - Используйте пробелы и отступы. Не пытайтесь уместить всю логику в одну строку, если от этого страдает читаемость.
7.  **Readability counts.** (Читаемость имеет значение.)
    - **Это, пожалуй, самый главный принцип.** Код пишут один раз, а читают сотни раз (другие разработчики и вы сами в будущем).
8.  **Special cases aren't special enough to break the rules.** (Особые случаи не настолько особенные, чтобы нарушать правила.)
    - Даже если вы уверены, что ваш случай уникален, скорее всего, лучше следовать общепринятым практикам.
9.  **Although practicality beats purity.** (Хотя практичность важнее безупречности.)
    - Но если правило мешает решить реальную практическую задачу, его можно нарушить (но очень осторожно!).
10. **Errors should never pass silently.** (Ошибки никогда не должны проходить незамеченными.)
    - Если что-то пошло не так, программа должна сообщить об этом. Не подавляйте исключения без веской причины.
11. **Unless explicitly silenced.** (Если только они не были явно скрыты.)
    - ...но если вы сознательно решили проигнорировать ошибку, сделайте это явно (например, через `except` с последующим логированием).
12. **In the face of ambiguity, refuse the temptation to guess.** (В случае неоднозначности откажитесь от искушения угадать.)
    - Если поведение может быть истолковано двояко, интерпретатор должен выдать ошибку, а не пытаться угадать, что имел в виду программист. Это делает язык более безопасным.
13. **There should be one-- and preferably only one --obvious way to do it.** (Должен быть один — и желательно только один — очевидный способ сделать это.)
    - В противовес языкам вроде Perl ("There's more than one way to do it"). Python стремится к единообразию решений.
14. **Although that way may not be obvious at first unless you're Dutch.** (Хотя этот способ может быть неочевиден с первого раза, если только вы не голландец (шутка про Гвидо).)
15. **Now is better than never.** (Сейчас лучше, чем никогда.)
    - Лучше написать рабочий прототип сегодня, чем идеальный, но никогда не дописанный код.
16. **Although never is often better than *right* now.** (Хотя никогда часто лучше, чем *прямо* сейчас.)
    - Но если вы торопитесь и пишете откровенно плохой, хрупкий код — лучше не писать его вообще.

### Области применения

1.  **Веб-разработка (Backend):**
    - **Фреймворки:** Django (мощный, "всё включено"), Flask (легкий, гибкий), FastAPI (современный, асинхронный, для API).
    - **Задачи:** создание серверной логики сайтов, REST API, обработка запросов.
    - *Кто использует:* Instagram (Django), Pinterest (Django/Flask), Uber (Pyramid/FastAPI).

2.  **Наука о данных (Data Science), Машинное обучение (ML) и Аналитика:**
    - Это доминирующая область для Python.
    - **Библиотеки:** NumPy, Pandas (анализ данных), Matplotlib, Seaborn (визуализация), Scikit-learn (классические ML-алгоритмы), TensorFlow, PyTorch (глубокое обучение).
    - *Кто использует:* Все исследовательские лаборатории, Netflix (для рекомендательных систем), Spotify (для анализа предпочтений).

3.  **Автоматизация и скриптинг (DevOps, SRE):**
    - Python идеален для написания скриптов, которые автоматизируют рутинные операции: работа с файлами, отправка писем, парсинг логов, взаимодействие с API, настройка серверов (Ansible написан на Python).

4.  **Тестирование (QA Automation):**
    - Огромное количество фреймворков для автоматизации тестирования написано на Python или для Python: Selenium, Pytest, Robot Framework.
    - *Кто использует:* Любая компания, которая пишет автотесты.

5.  **Встраиваемые системы и Интернет вещей (IoT):**
    - Микрокомпьютеры (Raspberry Pi) и микроконтроллеры (MicroPython, CircuitPython) активно используют Python. Он позволяет быстро прототипировать устройства "умного дома", роботов и т.д.

6.  **Десктопные приложения (GUI):**
    - Используется реже, но возможно. Библиотеки: Tkinter (встроенный), PyQt / PySide, Kivy (для мобильных тоже).
    - *Примеры:* Dropbox (клиент), BitTorrent (старые клиенты).

7.  **Образование:**
    - Из-за своей простоты Python стал языком №1 для обучения программированию в школах и университетах по всему миру.

### Версии Python (2 vs 3)
**Ключевое различие: Python 3 — это новый язык, который не обратно совместим с Python 2.**

**Почему это произошло?**
- Гвидо ван Россум и команда разработчиков решили, что в Python 2 накопилось много "исторического груза": устаревшие конструкции, нелогичности и дублирующиеся способы сделать одно и то же.
- Было принято волевое решение выпустить новую мажорную версию (Python 3000), в которой можно "сломать" старый код, чтобы сделать язык чище и подготовить его к будущему на 20 лет вперед.

**Ключевые отличия Python 3 от Python 2 (самые заметные):**

| Особенность | Python 2 | Python 3 | Почему это важно |
| :--- | :--- | :--- | :--- |
| **`print`** | Оператор: `print "hello"` | Функция: `print("hello")` | В Python 3 легче менять поведение печати (например, убрать перевод строки или перенаправить в файл). |
| **Деление `/`** | `3 / 2 = 1` (целочисленное) | `3 / 2 = 1.5` (вещественное) | В Python 3 поведение более ожидаемое для новичков и математиков. Для целочисленного деления нужно `//`. |
| **Тип `str` / `unicode`** | `str` (байты) и `unicode` (текст) | `str` (текст — Unicode) и `bytes` (байты) | В Python 3 четкое разделение текста и бинарных данных, что решает массу проблем с кодировками (например, кракозябры). |
| **Итераторы** | `range()` возвращает список, `xrange()` — итератор. | `range()` ведет себя как `xrange()` (итератор). | Экономия памяти в Python 3 по умолчанию. |
| **Ввод** | `input()` интерпретирует ввод как код; `raw_input()` как строку. | `input()` всегда возвращает строку (как `raw_input` в Py2). | Python 3 безопаснее и проще. |
| **Асинхронность** | Сложно, через сторонние библиотеки (Twisted, Gevent). | Встроенная поддержка `async`/`await` (начиная с 3.5). | Python 3 готов к современным высоконагруженным приложениям. |

**Итог:**
- **Разработка Python 2 остановлена навсегда** 1 января 2020 года. Для него больше не выходят патчи безопасности.
- **Использовать Python 2 сегодня — это угроза безопасности и невозможность использовать новые библиотеки.** Все новые проекты пишутся только на Python 3.
- **Актуальная версия:** На начало 2024 года — Python 3.12, 3.13.

### Плюсы и минусы Python

**Плюсы (Сильные стороны):**

1.  **Простота и легкость изучения:** Синтаксис Python близок к английскому языку и требует меньше "шума" (скобок, точек с запятой), чем другие языки. Это лучший язык для начала карьеры в IT.
2.  **Читаемость кода:** Благодаря принудительным отступам и философии Zen, код на Python легко читать и поддерживать, даже если его писал другой человек.
3.  **Огромное сообщество и экосистема (PyPi):** Есть библиотека для всего. Если вам нужно спарсить сайт, сделать HTTP-запрос, построить график или обучить нейросеть — скорее всего, есть готовая библиотека (PyPI — Python Package Index содержит сотни тысяч пакетов).
4.  **Кроссплатформенность:** "Написал однажды — запусти где угодно" (при наличии интерпретатора).
5.  **Продуктивность разработки:** На Python можно написать прототип или даже готовое решение в 2-3 раза быстрее, чем на Java или C++. Это "язык для мышления", а не для борьбы с компилятором.
6.  **Универсальность:** Можно использовать в вебе, аналитике, автоматизации — не нужно учить новый язык под каждую задачу.

**Минусы (Слабые стороны):**

1.  **Скорость выполнения (Performance):**
    - Python интерпретируемый и динамический, поэтому он работает **значительно медленнее** компилируемых языков (C++, Java, Go) или даже некоторых других интерпретируемых (JavaScript на V8).
    - *Решение:* "Горячие" участки кода можно писать на C++ (как это делается в NumPy) или использовать JIT-компиляторы (PyPy).
2.  **GIL (Global Interpreter Lock — Глобальная блокировка интерпретатора):**
    - Это механизм, который позволяет только одному потоку выполняться в один момент времени в рамках одного процесса Python.
    - Это сильно ограничивает использование многопоточности для задач, связанных с параллельными вычислениями на многоядерных процессорах (CPU-bound задачи). Для I/O-bound задач многопоточность работает нормально, так как потоки "ждут" ввода-вывода.
    - *Решение:* Использовать многопроцессорность (`multiprocessing`), asyncio или писать расширения на C, которые могут освобождать GIL.
3.  **Высокое потребление памяти:** Из-за того, что в Python "всё есть объект" (даже числа), накладные расходы на хранение данных выше, чем в языках с более "сырыми" типами данных.
4.  **Сложность мобильной разработки:** Python не является языком выбора для нативной разработки под iOS или Android (хотя есть инструменты вроде Kivy или BeeWare, они не мейнстримны).
5.  **Динамическая типизация (палка о двух концах):** С одной стороны, это плюс для скорости написания. С другой — это минус для надежности больших проектов. Ошибка типа (передали число вместо строки) может проявиться только во время выполнения, а не на этапе компиляции.
    - *Решение:* Современный Python активно использует **type hints** (подсказки типов, появились в Python 3.5) и статические анализаторы (mypy, Pyright), чтобы совместить гибкость динамики с надежностью статики.
