# 7. Стандартная библиотека и прикладные инструменты

Стандартная библиотека Python закрывает множество прикладных задач без сторонних зависимостей: очереди и подсчёт, приоритеты, числовые вычисления, случайные выборки, идентификаторы, хэширование, конфигурацию и представление данных. Умение выбирать подходящий модуль часто важнее написания собственной универсальной обёртки.

Глава сохраняет восемь тем и 28 пунктов README. Примеры ориентированы на Python 3.12–3.14; возможности, появившиеся в 3.13 и 3.14, отмечены отдельно. Подробная работа с файлами, процессами, датами, регулярными выражениями и логированием относится к следующим самостоятельным главам. Здесь они появляются только там, где нужны конкретному инструменту.

Короткие Python-блоки независимы: необходимые данные создаются внутри примера, ожидаемые ошибки перехватываются, файловые эксперименты используют временные каталоги. Исключение — явно помеченный пример gettext, для которого сначала создаётся и компилируется показанный каталог перевода. Код не требует доступа к сети. `assert` проверяет ожидаемый результат примера; проверки входных значений в прикладном коде выполняются явными исключениями.

В конце находится практический анализатор событий: TOML-конфигурация, Counter, deque, куча top-k, числовой массив, статистика, воспроизводимая выборка и подписанный отчёт. Файлы проекта отмечены путями и используются вместе. При этом проект не пытается искусственно применить каждую функцию главы.

## Специализированные контейнеры — collections

### deque: очередь, стек и ограниченное окно

`deque` — двусторонняя очередь. Она поддерживает добавление и удаление с обоих концов без перемещения всех остальных элементов. Для FIFO-очереди это обычно более подходящее представление, чем список с частым `pop(0)`.

```python
from collections import deque


queue = deque(["first", "second"])
queue.append("third")
assert queue.popleft() == "first"
assert list(queue) == ["second", "third"]

stack = deque([1, 2])
stack.append(3)
assert stack.pop() == 3
stack.appendleft(0)
assert list(stack) == [0, 1, 2]
```

| Операция | Смысл | Ожидаемая стоимость |
|---|---|---|
| `append`, `pop` | Правый конец | Примерно O(1) |
| `appendleft`, `popleft` | Левый конец | Примерно O(1) |
| `extend`, `extendleft` | Добавить несколько элементов | O(k) по числу добавлений |
| Доступ у конца | Например, `d[0]`, `d[-1]` | O(1) |
| Индекс в середине | Поиск по внутренним блокам | Может быть O(n) |
| Поиск значения, удаление по значению | Просмотр элементов | O(n) |

Срезы как у списка не поддерживаются. Если основная работа — произвольное индексирование и сортировка, список может быть лучше. Название «очередь» не означает, что контейнер запрещает операции стека: интерфейс предоставляет обе стороны.

**Ограниченное окно.** `maxlen` задаёт максимальное число сохраняемых элементов. При добавлении в заполненную очередь старый элемент с противоположной стороны удаляется автоматически.

```python
from collections import deque


recent = deque(maxlen=3)
for value in [10, 20, 30, 40]:
    recent.append(value)
assert list(recent) == [20, 30, 40]
recent.appendleft(5)
assert list(recent) == [5, 20, 30]
```

Это удобно для последних событий и скользящего окна. Но `maxlen` измеряет **число элементов**, а не байты: три объекта могут удерживать гигабайты. Также удаление из очереди не уничтожает объект, если на него ещё кто-то ссылается.

**Не все добавления одинаковы.** `extendleft` последовательно добавляет элементы слева и потому разворачивает порядок. `insert` в уже заполненный bounded deque не вытесняет элемент молча, а вызывает `IndexError`.

```python
from collections import deque


values = deque([3])
values.extendleft([1, 2])
assert list(values) == [2, 1, 3]
values.rotate(1)
assert list(values) == [3, 2, 1]
values.rotate(-1)
assert list(values) == [2, 1, 3]

bounded = deque([1, 2], maxlen=2)
try:
    bounded.insert(1, 9)
except IndexError:
    pass
else:
    raise AssertionError("Вставка в заполненный deque должна быть отклонена")
```

`rotate` полезен для циклического обхода, но не следует считать поворот на произвольное расстояние бесплатным. Для сложного планировщика заранее определите правила удаления, справедливости и изменения приоритета.

**Потоки.** Документация описывает потокобезопасные добавления и удаления с концов, но составная операция `if queue: queue.popleft()` не становится атомарной. Между проверкой и извлечением другой поток может опустошить очередь. Для блокирующего ожидания, `maxsize`, task tracking и координации используйте подходящий `queue.Queue`; для asyncio — `asyncio.Queue`. У deque нет автоматического backpressure: bounded-окно просто теряет вытеснённые элементы.

### Counter и defaultdict: подсчёт и группировка

`Counter` хранит соответствие «хэшируемый элемент → счётчик». Отсутствующий ключ при доступе через `[]` даёт ноль, а не `KeyError`. Это удобно для частот слов, статусов, категорий и результатов обработки.

```python
from collections import Counter


statuses = Counter([200, 200, 404, 500, 200])
assert statuses[200] == 3
assert statuses[403] == 0
assert 403 not in statuses
assert statuses.total() == 5
assert statuses.most_common(2) == [(200, 3), (404, 1)]
```

При равных частотах `most_common` сохраняет порядок первого появления. Это детерминированное правило относительно входа, но не алфавитный порядок. Если нужен независимый от порядка поступления результат, задайте вторичный ключ явно.

**Обновление суммирует, а не заменяет.**

```python
from collections import Counter


counts = Counter({"a": 2, "b": 1})
counts.update({"a": 3})
assert counts["a"] == 5
counts.subtract({"a": 5, "b": 2})
assert counts == Counter({"a": 0, "b": -1})
assert "a" in counts
assert +counts == Counter()
assert Counter(a=1) == Counter(a=1, b=0)
```

Нулевой счётчик сам по себе не удаляет ключ. `subtract` сохраняет отрицательные и нулевые значения, а операции мультимножеств возвращают только положительные результаты:

```python
from collections import Counter


left = Counter(a=3, b=1)
right = Counter(a=1, b=2)
assert left + right == Counter(a=4, b=3)
assert left - right == Counter(a=2)
assert left & right == Counter(a=1, b=1)
assert left | right == Counter(a=3, b=2)
assert list(Counter(a=2, b=-1).elements()) == ["a", "a"]
```

Не переносите семантику `dict | dict` на `Counter | Counter`: здесь берётся максимум счётчиков. `elements()` рассчитан на целые значения и игнорирует неположительные. `total()` включает отрицательные значения, если они есть; это может быть балансом изменений, а не числом реально наблюдавшихся событий.

Counter не решает проблему кардинальности. Если ключом сделать уникальный request ID, размер словаря будет расти вместе с числом запросов. Для метрик выбирайте ограниченные категории, а для больших потоков — соответствующий агрегатор или приближённую структуру.

`defaultdict` вызывает фабрику при чтении отсутствующего ключа через `[]`. Фабрика создаёт отдельное значение, сохраняет его в словаре и возвращает вызывающему коду.

```python
from collections import defaultdict


groups: defaultdict[str, list[int]] = defaultdict(list)
for category, value in [("a", 1), ("b", 2), ("a", 3)]:
    groups[category].append(value)
assert dict(groups) == {"a": [1, 3], "b": [2]}
assert groups["a"] is not groups["b"]
```

Передаётся **фабрика `list`**, а не результат `list()`. Фабрика без аргументов вызывается отдельно для каждого нового ключа. Если она возвращает один общий список из замыкания, независимость пропадёт.

```python
from collections import defaultdict


values: defaultdict[str, int] = defaultdict(int)
assert values.get("missing") is None
assert "missing" not in values
assert values["missing"] == 0
assert "missing" in values
```

`get`, проверка `in` и обычный обход не запускают `__missing__`. Это важный побочный эффект `[]`: даже «просто прочитать» может изменить состояние. Для read-only API можно вернуть обычный dict, копию или ограниченный интерфейс.

`setdefault(key, [])` тоже подходит для простой группировки, но выражение default вычисляется до вызова метода, даже если ключ уже существует. Для дорогого значения это может быть лишней работой. При конкурентном обновлении нескольких полей ни Counter, ни defaultdict не создают бизнес-транзакцию автоматически.

### ChainMap: слои конфигурации и поиск значений

`ChainMap` объединяет несколько отображений в **живое представление**. Поиск идёт слева направо: первый найденный ключ побеждает. Исходные словари не копируются.

```python
from collections import ChainMap


defaults = {"timeout": 30, "retries": 3}
file_config = {"timeout": 10}
overrides = {"retries": 1}
config = ChainMap(overrides, file_config, defaults)

assert config["timeout"] == 10
assert config["retries"] == 1
file_config["timeout"] = 15
assert config["timeout"] == 15
```

**Запись идёт только в первый слой.** Чтение из нижнего слоя не делает его целью последующего присваивания.

```python
from collections import ChainMap


defaults = {"limit": 100}
local: dict[str, int] = {}
config = ChainMap(local, defaults)
config["limit"] = 5
assert local == {"limit": 5}
assert defaults == {"limit": 100}
del config["limit"]
assert config["limit"] == 100

try:
    del config["limit"]
except KeyError:
    pass
else:
    raise AssertionError("Удаление не должно затронуть нижний слой")
```

`new_child()` добавляет новый первый слой, `parents` даёт цепочку без текущего первого слоя. Это удобно для вложенного контекста обработки.

```python
from collections import ChainMap


base = ChainMap({"region": "eu"}, {"retries": 3})
request = base.new_child({"request_id": "r-1", "retries": 1})
assert request["retries"] == 1
assert request.parents["retries"] == 3
assert "request_id" not in base
```

Порядок итерации ключей не равен порядку поиска значений: он определяется обходом отображений от последнего к первому с сохранением уже встреченных ключей. Если вывод должен быть отсортирован, сортируйте явно; не используйте случайный порядок конфигурационных слоёв как формат отчёта.

`dict(config)` создаёт **поверхностный снимок** текущих эффективных значений. Вложенные списки останутся общими. Для рабочего приложения полезно после объединения выполнить валидацию и создать неизменяемую конфигурацию: тогда последующее изменение исходного словаря не перепишет незаметно настройки уже запущенного задания.

Слои должны иметь согласованную схему. Значение из environment обычно строковое, а default может быть числом. ChainMap не преобразует `"10"` в `10`, не отбрасывает `None` и не различает «не передано» с «явно сбросить». Эти правила задаются до или после объединения.

### namedtuple vs typing.NamedTuple vs dataclass

Все три инструмента помогают заменить неясный набор позиционных значений именованными полями, но создают разные контракты.

```python
from collections import namedtuple


Point = namedtuple("Point", ["x", "y"], defaults=[0])
point = Point(1)
assert point.x == 1
assert point.y == 0
assert point[0] == 1
assert tuple(point) == (1, 0)
assert point._asdict() == {"x": 1, "y": 0}
assert point._replace(y=2) == Point(1, 2)
```

`namedtuple` создаёт подкласс tuple с именами полей. Он поддерживает распаковку, индексирование и tuple-сравнения. Методы `_fields`, `_asdict`, `_replace` являются публичными несмотря на начальное подчёркивание. Default-значения относятся к последним полям.

`typing.NamedTuple` добавляет удобное объявление аннотаций:

```python
from typing import NamedTuple


class Position(NamedTuple):
    x: int
    y: int = 0

    def squared_length(self) -> int:
        return self.x**2 + self.y**2


assert Position(3, 4).squared_length() == 25
assert Position(1, 2) == (1, 2)
```

Аннотации не валидируют реальные аргументы. `_replace` создаёт новую запись, но не превращает её в проверенную доменную модель. Неизменяемость tuple-оболочки также не замораживает вложенный список.

```python
from dataclasses import dataclass
from typing import NamedTuple


class UserKey(NamedTuple):
    value: int


class OrderKey(NamedTuple):
    value: int


@dataclass(frozen=True, slots=True)
class UserId:
    value: int


@dataclass(frozen=True, slots=True)
class OrderId:
    value: int


assert UserKey(1) == OrderKey(1) == (1,)
assert UserId(1) != OrderId(1)
```

Равенство NamedTuple по tuple-содержимому может быть неожиданным для разных предметных сущностей. Сгенерированное равенство dataclass требует одинакового фактического класса. Это важнее небольшой разницы в количестве строк объявления.

| Свойство | namedtuple | NamedTuple | dataclass |
|---|---|---|---|
| Runtime-основа | tuple | tuple | Обычный класс |
| Аннотации | Не основная форма фабрики | Есть | Есть |
| Позиционная распаковка | Да | Да | Не автоматически |
| Обычное изменение полей | Нет | Нет | Возможно; отключается frozen |
| Связь с tuple-равенством | Да | Да | Нет |
| Инварианты и жизненный цикл | Ограниченная удобная модель | Ограниченная удобная модель | Можно явно проектировать |

Для маленькой позиционной записи, совместимой с tuple-API, NamedTuple удобен. Для предметного объекта с независимой идентичностью, валидацией и будущим расширением полей dataclass часто яснее. Для ресурса или сложной машины состояний может быть лучше обычный класс. Подробные контракты dataclasses рассмотрены в главе об ООП.

### OrderedDict, UserDict, UserList и UserString

Обычный `dict` сохраняет порядок вставки; для самого этого свойства OrderedDict больше не требуется. OrderedDict остаётся полезен, когда порядок нужно **активно менять**.

```python
from collections import OrderedDict


recent = OrderedDict([("a", 1), ("b", 2), ("c", 3)])
recent.move_to_end("a")
assert list(recent) == ["b", "c", "a"]
recent.move_to_end("c", last=False)
assert list(recent) == ["c", "b", "a"]
assert recent.popitem(last=False) == ("c", 3)
```

Это основа для простого LRU-подобного порядка. Полноценный кэш дополнительно требует лимитов, политики ошибок, инвалидирования и конкурентного доступа; для кэширования чистого вызова часто достаточно `functools.lru_cache` с подходящим maxsize.

**Равенство зависит от второго операнда.** Два OrderedDict сравниваются с учётом порядка, а сравнение с обычным mapping использует обычную семантику отображения.

```python
from collections import OrderedDict


first = OrderedDict([("a", 1), ("b", 2)])
second = OrderedDict([("b", 2), ("a", 1)])
assert first != second
assert first == dict(second)
```

`UserDict`, `UserList`, `UserString` — обёртки с доступным внутренним `.data`. Они удобны для наследования и изменения поведения. У встроенного C-типа не все внутренние операции обязаны вызывать переопределённый Python-метод так, как ожидает автор подкласса.

```python
from collections import UserDict


class UpperKeys(UserDict[str, int]):
    def __setitem__(self, key: str, value: int) -> None:
        self.data[key.upper()] = value


values = UpperKeys()
values["a"] = 1
values.update({"b": 2})
assert dict(values) == {"A": 1, "B": 2}
```

Если правило должно выполняться для всех способов изменения, проверьте конструктор, `update`, `setdefault`, объединение, удаление и прямой доступ к `.data`. Само наследование от удобной обёртки не обеспечивает недоступность внутреннего хранилища.

UserList полезен для пользовательской последовательности с привычным поведением списка; UserString — для обёртки строковых операций. Если задача требует только двух методов с сильным инвариантом, композиция над list/dict/str может быть проще, чем открытие всего изменяемого API.

### collections.abc: Iterable, Sequence, Mapping и Set

ABC из `collections.abc` описывают контракты контейнеров и дают mixin-реализации части операций. Они помогают объявлять точный интерфейс вместо привязки к конкретному list или dict.

| ABC | Основной смысл | Важная оговорка |
|---|---|---|
| Iterable | Можно получить итератор | Не обещает повторный обход |
| Iterator | Итератор с `__next__` | Может быть одноразовым |
| Sequence | Индексируемая последовательность с длиной | Не обещает неизменяемость реализации |
| MutableSequence | Изменяемая последовательность | Дополнительные операции и инварианты |
| Mapping | Отображение ключей в значения | Обход выдаёт ключи |
| MutableMapping | Отображение с изменением | Нужна согласованность чтения/записи/удаления |
| Set | Интерфейс множества | Сравнения включения образуют частичный порядок |

```python
from collections.abc import Iterator, Mapping


class Headers(Mapping[str, str]):
    def __init__(self, values: dict[str, str]) -> None:
        self._values = dict(values)

    def __getitem__(self, key: str) -> str:
        return self._values[key]

    def __iter__(self) -> Iterator[str]:
        return iter(self._values)

    def __len__(self) -> int:
        return len(self._values)


headers = Headers({"Accept": "application/json"})
assert list(headers) == ["Accept"]
assert headers.get("missing", "default") == "default"
assert list(headers.items()) == [("Accept", "application/json")]
```

`get`, `items` и другие операции здесь предоставлены общим контрактом. Их стоимость зависит от базовых методов: если `__getitem__` выполняет сетевой запрос, «обычный» mixin может неожиданно сделать много запросов. Подстановка относится и к производительности, которую обещает API.

Runtime-проверка ABC и реальная возможность выполнить операцию не всегда совпадают. Например, старый протокол последовательности может поддерживать `iter()` через `__getitem__`, даже не имея `__iter__`:

```python
from collections.abc import Iterable


class LegacySequence:
    def __getitem__(self, index: int) -> int:
        if not 0 <= index < 3:
            raise IndexError(index)
        return index * 10


values = LegacySequence()
assert not isinstance(values, Iterable)
assert list(iter(values)) == [0, 10, 20]
```

Виртуальная регистрация через `register` также не внедряет методы и не доказывает полноценную реализацию контракта. Для статической структурной типизации собственных интерфейсов используйте Protocol из предыдущей главы; ABC и Protocol решают связанные, но разные задачи.

**Документация:** [collections](https://docs.python.org/3.14/library/collections.html), [collections.abc](https://docs.python.org/3.14/library/collections.abc.html).

## Упорядоченные структуры и числовые массивы

### heapq: куча, top-k, merge и очередь с приоритетом

`heapq` работает с обычным списком как с двоичной min-heap. Минимальный элемент расположен в `heap[0]`; каждый родитель не больше своих детей. При этом весь список **не отсортирован**.

```python
import heapq


heap = [7, 1, 5, 3]
heapq.heapify(heap)
assert heap[0] == 1
heapq.heappush(heap, 2)
assert [heapq.heappop(heap) for _ in range(len(heap))] == [1, 2, 3, 5, 7]
```

| Операция | Назначение | Типичная стоимость |
|---|---|---|
| `heapify` | Построить кучу из списка | O(n) |
| `heap[0]` | Прочитать минимум | O(1) |
| `heappush`, `heappop` | Добавить/извлечь | O(log n) |
| Произвольный поиск по значению | Не поддержан отдельным индексом | Обычно O(n) |
| Полное извлечение по порядку | Повторные pop | O(n log n) |

Если нужна только полная сортировка, `sorted` часто проще и эффективнее. Куча полезна, когда нужно многократно получать следующий минимум, поддерживать ограниченный top-k или объединять уже отсортированные потоки.

**Две похожие составные операции имеют разный смысл.** `heappushpop` добавляет элемент и возвращает минимум, сохраняя в куче более крупные значения. `heapreplace` безусловно извлекает текущий минимум и кладёт новый элемент.

```python
import heapq


first = [2, 5, 8]
heapq.heapify(first)
assert heapq.heappushpop(first, 1) == 1
assert sorted(first) == [2, 5, 8]

second = [2, 5, 8]
heapq.heapify(second)
assert heapq.heapreplace(second, 1) == 2
assert sorted(second) == [1, 5, 8]
```

Поэтому для сохранения крупнейших k значений удобен `heappushpop` над min-heap фиксированного размера: слишком маленький кандидат сразу уйдёт. При `heapreplace` сначала нужно отдельно решить, достоин ли кандидат замены. У пустой кучи `heapreplace` вызывает `IndexError`; `heappushpop([], x)` возвращает x и оставляет пустую кучу.

```python
import heapq


values = [5, 1, 9, 3, 7, 2]
assert heapq.nlargest(3, values) == [9, 7, 5]
assert heapq.nsmallest(2, values) == [1, 2]

top: list[int] = []
for value in values:
    if len(top) < 3:
        heapq.heappush(top, value)
    else:
        heapq.heappushpop(top, value)
assert sorted(top, reverse=True) == [9, 7, 5]
```

Ограниченная куча использует O(k) дополнительной памяти и обычно O(n log k) работы, когда k мало относительно n. Встроенные `nlargest`/`nsmallest` выбирают подходящие пути реализации; при больших k полная сортировка может оказаться лучше. Для одного минимума/максимума используйте `min`/`max`, если не нужна сама куча.

**`merge` — ленивое слияние, а не сортировка произвольного потока.**

```python
import heapq


first = iter([1, 4, 9])
second = iter([2, 4, 8])
merged = heapq.merge(first, second)
assert next(merged) == 1
assert list(merged) == [2, 4, 4, 8, 9]
```

Каждый вход обязан уже быть отсортирован в том же порядке и по согласованному ключу. Дубликаты сохраняются. При `reverse=True` входы тоже должны идти по убыванию. Слияние не загружает все данные сразу, но держит состояние нескольких источников; число одновременно открытых источников и их собственные буферы всё равно имеют значение.

**Max-heap в новых версиях.**

```python
# Python 3.14+: публичные операции max-heap.
import heapq


heap = [1, 5, 3]
heapq.heapify_max(heap)
assert heap[0] == 5
heapq.heappush_max(heap, 7)
assert heapq.heappop_max(heap) == 7
assert heapq.heappushpop_max(heap, 9) == 9
assert heapq.heapreplace_max(heap, 2) == 5
```

В старом коде числовые приоритеты часто инвертируют знаком. Это приём для подходящего числового домена, а не общий способ обратить порядок произвольных объектов. Не используйте частные функции `_heapify_max` как стабильный публичный API для поддерживаемой библиотеки.

### Равные приоритеты и несравнимые элементы

Кортежи сравниваются лексикографически. В записи `(priority, payload)` при равном priority Python попробует сравнить payload. Словари, произвольные объекты и смешанные типы могут оказаться несравнимыми.

```python
import heapq


heap = []
heapq.heappush(heap, (1, {"task": "a"}))
try:
    heapq.heappush(heap, (1, {"task": "b"}))
except TypeError:
    pass
else:
    raise AssertionError("Словари не имеют такого порядка")
```

После исключения сравнения не рассчитывайте на автоматический откат изменения контейнера. Операции с пользовательскими компараторами могут оставить частично изменённое состояние. Проектируйте сравнимый ключ **до** добавления.

Обычное решение — уникальный монотонный номер поступления:

```python
import heapq
from itertools import count


sequence = count()
heap: list[tuple[int, int, dict[str, str]]] = []
heapq.heappush(heap, (1, next(sequence), {"task": "first"}))
heapq.heappush(heap, (1, next(sequence), {"task": "second"}))
assert heapq.heappop(heap)[2] == {"task": "first"}
assert heapq.heappop(heap)[2] == {"task": "second"}
```

Номер одновременно обеспечивает сравнимость и определяет справедливость при равных приоритетах. В dataclass можно использовать `order=True`, а payload исключить через `field(compare=False)`. Уникальность номера должна охватывать все одновременно находящиеся в куче записи.

**Изменение приоритета.** Нельзя просто поменять поле priority у объекта внутри кучи: инвариант расположения не будет восстановлен. Для частых обновлений используют индекс и ленивое удаление старой записи.

```python
import heapq
from dataclasses import dataclass, field
from itertools import count


@dataclass(order=True)
class Entry:
    priority: int
    sequence: int
    task_id: str = field(compare=False)
    active: bool = field(default=True, compare=False)


class PriorityTasks:
    def __init__(self) -> None:
        self._heap: list[Entry] = []
        self._active: dict[str, Entry] = {}
        self._sequence = count()

    def put(self, task_id: str, priority: int) -> None:
        previous = self._active.get(task_id)
        if previous is not None:
            previous.active = False
        entry = Entry(priority, next(self._sequence), task_id)
        self._active[task_id] = entry
        heapq.heappush(self._heap, entry)

    def cancel(self, task_id: str) -> None:
        self._active.pop(task_id).active = False

    def pop(self) -> str:
        while self._heap:
            entry = heapq.heappop(self._heap)
            if entry.active:
                del self._active[entry.task_id]
                return entry.task_id
        raise KeyError("Нет активных задач")


tasks = PriorityTasks()
tasks.put("a", 10)
tasks.put("b", 5)
tasks.put("a", 1)
assert tasks.pop() == "a"
assert tasks.pop() == "b"
```

Устаревшие записи остаются в `_heap` до извлечения. При частых обновлениях и редком pop память может расти, хотя активных задач мало: нужна периодическая очистка/rebuild. Не сохраняйте в старой записи большой payload без причины. Пример также однопоточный; для блокирующего конкурентного API рассмотрите `queue.PriorityQueue` и отдельно задайте правила атомарного обновления.

Приоритеты должны иметь согласованный порядок. `NaN` и компаратор с меняющимся внешним состоянием способны сделать результат бессмысленным без явного исключения. Для числовых приоритетов проверяйте допустимость и конечность значений.

### bisect: поиск позиции и вставка в отсортированный список

`bisect_left` возвращает левую границу вставки: перед первым элементом, который не меньше искомого. `bisect_right` — правую: после всех равных. Функции предполагают, что диапазон уже отсортирован.

```python
from bisect import bisect_left, bisect_right


values = [10, 20, 20, 30]
assert bisect_left(values, 20) == 1
assert bisect_right(values, 20) == 3
assert bisect_left(values, 25) == 3
assert bisect_right(values, 5) == 0

left = bisect_left(values, 20)
right = bisect_right(values, 20)
assert values[left:right] == [20, 20]
```

Это границы разделения, а не автоматическая проверка существования. Для поиска точного совпадения после получения индекса нужно проверить диапазон и значение.

```python
from bisect import bisect_left
from collections.abc import Sequence


def find(values: Sequence[int], target: int) -> int | None:
    index = bisect_left(values, target)
    if index < len(values) and values[index] == target:
        return index
    return None


assert find([1, 3, 5], 3) == 1
assert find([1, 3, 5], 4) is None
```

`bisect` в основном использует отношение `<`, а не вызывает `==` как обязательную часть поиска. Для пользовательского типа порядок и равенство должны быть осмысленно согласованы, если поверх границы строится точный поиск.

**Поиск быстрый, вставка в список — нет.** `insort_left`/`insort_right` находят позицию и вставляют элемент. Сам поиск требует O(log n) сравнений, но перемещение хвоста списка — O(n). Для большого числа вставок итог может быть квадратичным.

```python
from bisect import insort


values = [1, 3, 5]
insort(values, 4)
assert values == [1, 3, 4, 5]
```

Для уже накопленного batch часто проще добавить элементы и один раз отсортировать. Для частых динамических обновлений рассмотрите другую структуру, но измеряйте реальную нагрузку: компактный список с редкими вставками может быть вполне эффективным.

**Параметр key применяется несимметрично.** В `bisect_left(records, x, key=...)` функция применяется к элементам records, а x уже должен быть значением ключа. В `insort(..., record, key=...)` ключ используется для поиска, но вставляется исходный record.

```python
from bisect import bisect_left, insort_right
from dataclasses import dataclass
from operator import attrgetter


@dataclass(frozen=True)
class Event:
    timestamp: int
    name: str


events = [Event(10, "a"), Event(20, "b")]
assert bisect_left(events, 15, key=attrgetter("timestamp")) == 1
insort_right(events, Event(15, "c"), key=attrgetter("timestamp"))
assert [event.name for event in events] == ["a", "c", "b"]
```

Вычисленный key не обязан кэшироваться между поисками. Для дорогого ключа можно держать параллельный массив ключей, но тогда появляется инвариант согласованности двух структур. Изменение поля, по которому уже отсортирован список, также ломает предположение поиска.

При concurrent-доступе «найти позицию → вставить» требует общей синхронизации. Два корректных бинарных поиска, выполненных относительно разных состояний, не дают корректную общую вставку. Границы `lo`/`hi` относятся к текущему диапазону, а не к снимку данных.

### array: типизированные массивы vs list и NumPy

`array.array` хранит значения одного машинного формата компактнее, чем список ссылок на отдельные Python-объекты. Это одномерный изменяемый контейнер стандартной библиотеки, а не маленькая замена всему NumPy.

```python
from array import array


values = array("d", [1.0, 2.5, 3.0])
values.append(4.0)
assert values.tolist() == [1.0, 2.5, 3.0, 4.0]
assert values.typecode == "d"
assert len(values.tobytes()) == len(values) * values.itemsize
```

| Typecode | Типичная категория | Что учитывать |
|---|---|---|
| `b`, `B` | Signed/unsigned char | Небольшой целочисленный диапазон |
| `h`, `H` | Short integer | Размер и диапазон зависят от формата платформы |
| `i`, `I` | C int / unsigned int | Не Python-int произвольной точности |
| `l`, `L` | C long / unsigned long | Особенно важно не предполагать одинаковый размер на разных ОС |
| `q`, `Q` | Long long / unsigned long long | Проверяйте доступность и itemsize |
| `f`, `d` | Машинные float / double | Ограниченная точность и округление |

У Python `int` нет фиксированного машинного верхнего предела, а у элемента целочисленного array он есть. Добавление слишком большого значения вызывает `OverflowError`. У float-массива значения также не становятся десятичными точными числами.

```python
from array import array


values = array("B", [0, 255])
try:
    values.append(256)
except OverflowError:
    pass
else:
    raise AssertionError("Unsigned byte не вмещает 256")
assert values.tolist() == [0, 255]
```

**Бинарное представление нативное.** `tobytes`/`frombytes` не создают самостоятельно переносимый сетевой формат: нужно знать typecode, itemsize и порядок байтов. Для протокола с фиксированным endian и шириной удобнее явно задать формат через `struct`.

```python
import struct
from array import array


values = array("I", [1, 2])
raw = values.tobytes()
restored = array("I")
restored.frombytes(raw)
assert restored == values
assert struct.pack(">I", 1) == b"\x00\x00\x00\x01"
```

`byteswap` меняет порядок байтов каждого элемента, а не записывает метаданные о требуемом формате. Дважды выполненный swap возвращает исходные байты. Для сохраняемого файла отдельно определите заголовок, версию, размеры и порядок байтов.

**Buffer protocol и memoryview.** Можно получить представление без копирования, но оно разделяет память и ограничивает изменение размера массива.

```python
from array import array


values = array("d", [1.0, 2.0])
with memoryview(values) as view:
    view[0] = 3.0
    assert values[0] == 3.0
    try:
        values.append(4.0)
    except BufferError:
        pass
    else:
        raise AssertionError("Нельзя менять размер при активном buffer export")

values.append(4.0)
assert values.tolist() == [3.0, 2.0, 4.0]
```

Zero-copy здесь означает отсутствие копии буфера для view, а не отсутствие всех аллокаций и не независимое владение. Представление нужно освободить, когда оно больше не требуется. Изменение элемента видно всем владельцам.

| Свойство | list | array | NumPy ndarray |
|---|---|---|---|
| Поставка | Встроенный тип | Стандартная библиотека | Сторонняя библиотека |
| Элементы | Ссылки на произвольные объекты | Один машинный формат | dtype и развитая модель массивов |
| Размерность | Вложенность организуется вручную | Основной контейнер одномерный | Многомерные shape/strides |
| Векторизованная арифметика | Нет | Нет общего ndarray-API | Основной сценарий |
| Умножение контейнера на целое | Повторение | Повторение | Обычно поэлементная операция |
| Передача буфера | Не сплошной числовой буфер | Поддерживается | Поддерживается с учётом layout |

```python
from array import array


values = array("i", [1, 2])
assert (values * 2).tolist() == [1, 2, 1, 2]
```

Для компактной последовательности чисел, бинарного обмена и небольшого алгоритма array может быть достаточно. Для broadcasting, многомерной линейной алгебры и табличных вычислений выбирают инструменты с соответствующей моделью. Сравнивайте не только память оболочки, но и стоимость преобразования на границе библиотек.

**Документация:** [heapq](https://docs.python.org/3.14/library/heapq.html), [bisect](https://docs.python.org/3.14/library/bisect.html), [array](https://docs.python.org/3.14/library/array.html), [NumPy arrays](https://numpy.org/doc/stable/user/absolute_beginners.html).

## Математика и статистика

### math и cmath: числовые функции и области определения

`math` предоставляет функции для вещественных вычислений и отдельные точные целочисленные операции. `cmath` работает с комплексными числами. Выбор модуля задаёт область определения и ожидаемый результат.

```python
import cmath
import math


assert math.sqrt(9) == 3.0
assert cmath.sqrt(-1) == 1j
try:
    math.sqrt(-1)
except ValueError:
    pass
else:
    raise AssertionError("Вещественный sqrt не должен принимать -1")
```

Не переводите вычисление в комплексную область автоматически, если отрицательное значение на самом деле является ошибкой данных. Исключение полезно: оно показывает, где нарушена модель. Для комплексных функций также существуют ветви и разрезы; обычные законы преобразования логарифмов и степеней нельзя применять без условий.

**Основные группы функций.**

| Группа | Примеры | Практический смысл |
|---|---|---|
| Точные целочисленные операции | `isqrt`, `factorial`, `comb`, `perm`, `gcd`, `lcm` | Не превращать большие int в неточный float |
| Округление | `floor`, `ceil`, `trunc` | Разные правила для отрицательных значений |
| Логарифмы и экспоненты | `log`, `log2`, `log10`, `exp`, `exp2` | Проверять область и переполнение |
| Малые приращения | `log1p`, `expm1` | Точнее вычислять около нуля |
| Геометрия | `hypot`, `dist`, `atan2` | Устойчивее ручных формул и правильные квадранты |
| Суммы и произведения | `fsum`, `prod`, `sumprod` | Явно выбирать точность и соответствие входов |
| Диагностика float | `isfinite`, `isnan`, `isinf`, `isclose`, `ulp`, `nextafter` | Проверять корректность и понимать границы представления |

```python
import math


assert math.isqrt(10**40) == 10**20
assert math.comb(5, 2) == 10
assert math.perm(5, 2) == 20
assert math.gcd(24, 36) == 12
assert math.lcm(4, 6) == 12
assert math.prod([2, 3, 4]) == 24
assert math.sumprod([1, 2], [10, 20]) == 50
```

`isqrt` возвращает целую часть точного корня. Он лучше `int(math.sqrt(big_int))` для очень больших целых. `sumprod` доступен с Python 3.12; несовпадающие длины входов являются ошибкой, а не поводом молча обрезать более длинный вход.

```python
import math


assert math.floor(-1.2) == -2
assert math.ceil(-1.2) == -1
assert math.trunc(-1.2) == -1
assert math.isclose(math.hypot(3, 4), 5.0)
assert math.isclose(math.dist((0, 0), (3, 4)), 5.0)
assert math.isclose(math.degrees(math.atan2(1, 0)), 90.0)
```

Тригонометрические функции используют радианы. Параметры `atan2(y, x)` идут в указанном порядке; это не просто `atan(y/x)` с теми же проблемами деления на ноль и потери квадранта.

**Точность суммирования.**

```python
import math


values = [1e16, 1.0, -1e16]
naive = 0.0
for value in values:
    naive += value
assert naive == 0.0
assert math.fsum(values) == 1.0
```

Обычное последовательное накопление потеряло небольшое слагаемое. `math.fsum` использует более аккуратный алгоритм. При этом не утверждайте, что встроенный `sum(values)` во всех версиях обязательно даст тот же плохой результат: алгоритм суммирования float был улучшен в Python 3.12. Требования к точности проверяют на целевой версии и конкретных данных.

```python
import math


small = 1e-16
assert math.log(1.0 + small) == 0.0
assert math.log1p(small) > 0.0
assert math.expm1(small) > 0.0
```

`log1p(x)` вычисляет логарифм `1+x`, а `expm1(x)` — `exp(x)-1` с лучшим поведением для малых x. Нельзя исправить уже потерянные биты, сначала вычислив `1+x`, а затем передав округлённый результат в другую функцию.

```python
# Python 3.13+: fused multiply-add с одним итоговым округлением.
import math


assert math.fma(2.0, 3.0, 4.0) == 10.0
```

FMA выполняет умножение и сложение с одним итоговым округлением в float. Это может повысить точность, но не делает весь алгоритм точным и не обещает универсальное ускорение.

**Сравнение приблизительных результатов.**

```python
import math


assert 0.1 + 0.2 != 0.3
assert math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-12)
assert not math.isclose(1e-12, 0.0)
assert math.isclose(1e-12, 0.0, abs_tol=1e-9)
assert math.nextafter(1.0, math.inf) > 1.0
assert math.ulp(1.0) > 0.0
```

У `isclose` есть относительный и абсолютный допуск. Около нуля особенно важен абсолютный. Выбирайте допуск в единицах задачи, а не добавляйте случайный epsilon ко всем сравнениям. Близость не обязана быть транзитивным отношением и не подходит как произвольная замена равенства ключей словаря.

`math.pow` работает в float-модели; встроенный `pow` и оператор `**` поддерживают дополнительные целочисленные сценарии, включая модульную степень. Для точных десятичных величин и рациональных вычислений есть `decimal` и `fractions`. Преобразование их в float ради удобного вызова math может потерять смысл выбранного представления.

Для complex используйте `cmath.isclose`, `phase`, `polar`, `rect` и соответствующие функции комплексной области. Обычное сравнение `<` для complex не определено; упорядочивание требует явно выбранной меры, например модуля.

### statistics: средние, квантили, дисперсия и выборка

`statistics` рассчитан на математическую статистику над обычными Python-данными. Он удобен для небольших и средних наборов, диагностических отчётов и алгоритмов без тяжёлого аналитического стека. Это не замена всей статистической методологии и не автоматический распределённый агрегатор.

```python
from statistics import fmean, mean, median, median_high, median_low


values = [1, 2, 3, 100]
assert mean(values) == 26.5
assert fmean(values) == 26.5
assert median(values) == 2.5
assert median_low(values) == 2
assert median_high(values) == 3
```

Среднее чувствительно к крупным значениям, медиана характеризует середину порядка. `median_low`/`median_high` выбирают реальное центральное наблюдение вместо усреднения пары. Ни одна мера не является «самой правильной» независимо от вопроса.

| Инструмент | Назначение | Условия и ограничения |
|---|---|---|
| `mean` | Арифметическое среднее | Зависит от поддерживаемых числовых типов |
| `fmean` | Среднее с float-результатом | Преобразует данные в float, поддерживает weights |
| `geometric_mean` | Мультипликативная центральная тенденция | Нужны положительные данные |
| `harmonic_mean` | Среднее для некоторых отношений/скоростей | Вес должен соответствовать смыслу задачи |
| `median` | Середина упорядоченного набора | Может потребоваться полная сортировка |
| `mode`, `multimode` | Наиболее частые значения | Несколько мод не всегда стоит сводить к одной |
| `variance`, `stdev` | Оценка по выборке | Как правило, минимум два наблюдения |
| `pvariance`, `pstdev` | Дисперсия/отклонение рассматриваемой совокупности | Другая нормировка |
| `quantiles` | Границы равновероятных долей по выбранному методу | Метод и размер выборки влияют на результат |

**Веса должны соответствовать вопросу.** Среднее двух средних без размеров групп обычно некорректно.

```python
from statistics import fmean


group_means = [10.0, 100.0]
group_sizes = [9, 1]
assert fmean(group_means) == 55.0
assert fmean(group_means, weights=group_sizes) == 19.0
```

Группа из девяти наблюдений должна иметь больший вклад, если требуется среднее по всем десяти наблюдениям. Однако усреднение квантилей таким способом не восстанавливает квантиль общего набора: у агрегатов разные правила объединения.

**Выборка и совокупность.**

```python
import math
from statistics import pstdev, pvariance, stdev, variance


values = [1.0, 2.0, 3.0]
assert variance(values) == 1.0
assert math.isclose(pvariance(values), 2 / 3)
assert stdev(values) == 1.0
assert math.isclose(pstdev(values), math.sqrt(2 / 3))
```

Для выборочной дисперсии используется нормировка n−1, для дисперсии указанной совокупности — n. Правильный выбор определяется тем, что означает набор, а не тем, какой результат хочется получить. Стандартное отклонение имеет исходные единицы, дисперсия — квадрат единиц.

**Квантили и интерполяция.**

```python
from statistics import quantiles


values = [10, 20, 30, 40]
assert quantiles(values, n=4, method="exclusive") == [12.5, 25.0, 37.5]
assert quantiles(values, n=4, method="inclusive") == [17.5, 25.0, 32.5]
```

`exclusive` и `inclusive` задают разные правила оценки положения крайних наблюдений. У `quantiles(..., n=100)` возвращается 99 границ; p95 находится по индексу 94. Это не гарантия совпадения с `percentile_approx` в Spark, настройкой базы данных или другой библиотекой: сравнивайте определения и метод интерполяции.

В Python 3.12 одному наблюдению для `quantiles` недостаточно. Начиная с 3.13 такой случай разрешён. Для переносимого прикладного API лучше явно выбрать поведение пустого и одноэлементного набора.

```python
# Python 3.13+: quantiles допускает одно наблюдение.
from statistics import quantiles


assert quantiles([10], n=4) == [10.0, 10.0, 10.0]
```

**Частоты и связи.** `mode` при нескольких модах возвращает первую встреченную, `multimode` — список всех наиболее частых вариантов. Для линейной связи есть `correlation`, для ранговой — `method="ranked"` с Python 3.12. `covariance` и `linear_regression` решают другие связанные задачи.

```python
import math
from statistics import correlation, linear_regression, mode, multimode


assert mode(["b", "a", "a", "b"]) == "b"
assert multimode(["b", "a", "a", "b"]) == ["b", "a"]
assert math.isclose(correlation([1, 2, 3], [2, 4, 6]), 1.0)
model = linear_regression([1, 2, 3], [3, 5, 7])
assert model.slope == 2.0
assert model.intercept == 1.0
```

Корреляция не доказывает причинную связь, а хорошая линейная аппроксимация на трёх точках не подтверждает качество прогноза на другом распределении. Проверяйте размер данных, выбросы, способ отбора и смысл переменных.

**Оценка плотности в новых версиях.**

```python
# Python 3.13+: kernel density estimation.
import math
from statistics import kde, kde_random


data = [0.0, 1.0, 2.0]
density = kde(data, h=0.5)
cumulative = kde(data, h=0.5, cumulative=True)
assert density(1.0) > 0.0
assert 0.0 < cumulative(1.0) < 1.0
draw = kde_random(data, h=0.5, seed=17)
assert all(math.isfinite(draw()) for _ in range(3))
```

Bandwidth `h` определяет сглаживание и сильно влияет на оценку. Возвращаемая функция — модель, построенная из данных, а не доказательство истинного распределения. Для `kde_random` документация отдельно допускает изменения конкретных значений между версиями при улучшении численных методов.

### Пустые данные, NaN, единицы измерения и корректность результата

Перед вычислением определите, какие значения допустимы и что означает отсутствие данных. Ноль и отсутствие среднего — разные состояния. Возврат `0.0` для пустого потока может скрыть отсутствие наблюдений.

```python
import math
from collections.abc import Iterable
from statistics import fmean


def mean_latency_ms(values: Iterable[float]) -> float | None:
    checked: list[float] = []
    for value in values:
        if not math.isfinite(value) or value < 0:
            raise ValueError("Задержка должна быть конечной и неотрицательной")
        checked.append(value)
    return fmean(checked) if checked else None


assert mean_latency_ms([]) is None
assert mean_latency_ms([10.0, 20.0]) == 15.0
```

Для произвольного внешнего ввода дополнительно проверяются реальные типы и исключается bool, если это нужно контракту. Здесь функция принимает уже числовые значения, а проверяет их допустимость для задержки.

`NaN` не равен самому себе и не задаёт привычный полный порядок. Он может неожиданно влиять на сортировку, медиану и квантили. Бесконечность может появиться из переполнения или внешнего формата. Не делайте политику «пропускать» неявно: решите, отклоняется ли набор, фильтруются ли значения и фиксируется ли число отброшенных наблюдений.

```python
import math
from statistics import StatisticsError, mean


nan = float("nan")
assert nan != nan
assert not math.isfinite(nan)
assert not math.isfinite(float("inf"))
try:
    mean([])
except StatisticsError:
    pass
else:
    raise AssertionError("Пустой набор не имеет такого среднего")
```

**Не смешивайте единицы.** Среднее из 100 миллисекунд и 1 секунды после потери единиц становится средним из чисел 100 и 1, а не корректной задержкой. Нормализуйте единицы на границе, называйте поле `latency_ms` и документируйте формат результата.

Проверяйте и семантику весов: средняя скорость при одинаковом времени и одинаковом расстоянии вычисляется по-разному. Если каждая часть пути имеет одинаковое расстояние, гармоническое среднее скоростей подходит; при одинаковом времени используется обычное среднее. Формула не заменяет модель измерения.

Для p99 на десятке наблюдений число с несколькими знаками после запятой не создаёт достоверность измерения хвоста. Для потока больших данных точный квантиль может потребовать хранения/сортировки; приближённый алгоритм имеет свои гарантии и погрешность. Не усредняйте p95 отдельных partitions как p95 общего набора.

Смешивание float, Decimal и Fraction поддерживается не одинаково во всех функциях. Выберите числовую модель явно, избегайте скрытого преобразования и проверьте допустимый диапазон промежуточных результатов. Правильный тип результата ещё не доказывает правильность статистического вывода.

**Документация:** [math](https://docs.python.org/3.14/library/math.html), [cmath](https://docs.python.org/3.14/library/cmath.html), [statistics](https://docs.python.org/3.14/library/statistics.html).

## Случайные числа — random

### Распределения, choice(), choices(), sample() и shuffle()

`random` предоставляет псевдослучайные числа для моделирования, тестовых данных, перемешивания и выборок. У генератора есть внутреннее состояние: результат следующего вызова определяется этим состоянием и алгоритмом. Равномерный выбор и нормальное распределение — разные модели; менять одну функцию на другую только ради «случайности» нельзя.

| Функция | Результат | Существенное условие |
|---|---|---|
| `random()` | Float из интервала `[0.0, 1.0)` | Правая граница исключена |
| `uniform(a, b)` | Float между границами | Из-за округления правая граница иногда достижима |
| `randrange(start, stop, step)` | Элемент соответствующего `range` | `stop` исключён; не создаёт весь список |
| `randint(a, b)` | Целое от `a` до `b` | Обе границы включены |
| `choice(sequence)` | Один элемент | Пустая последовательность вызывает `IndexError` |
| `choices(population, weights=..., k=n)` | Список из `n` выборов | С возвращением: повторные позиции допустимы |
| `sample(population, k=n)` | Список из `n` выбранных позиций | Без возвращения; `n` не больше размера популяции |
| `shuffle(list)` | Меняет список на месте | Возвращает `None` |
| `getrandbits(k)` | Неотрицательное целое с максимум `k` битами | Псевдослучайность, не секретный ключ |

```python
from random import Random


rng = Random(2026)
population = ["red", "green", "blue"]

assert rng.choice(population) in population
assert len(rng.choices(population, weights=[1, 2, 7], k=20)) == 20

selected = rng.sample(range(100), k=10)
assert len(selected) == len(set(selected)) == 10

cards = list(range(8))
result = rng.shuffle(cards)
assert result is None
assert sorted(cards) == list(range(8))

assert 3 <= rng.randint(3, 7) <= 7
assert rng.randrange(2, 20, 2) in range(2, 20, 2)
```

**Возвращение относится к позиции, а не к уникальному значению.** В `sample(["a", "a"], 2)` две разные позиции содержат одинаковые строки, поэтому результат имеет два `"a"`. Если нужны разные значения, сначала сформируйте уникальную популяцию по правилам предметной области.

```python
from random import Random


rng = Random(10)
assert rng.sample(["a", "a"], k=2) == ["a", "a"]
assert rng.sample(["a", "b"], k=0) == []

try:
    rng.sample(["a", "b"], k=3)
except ValueError:
    pass
else:
    raise AssertionError("Нельзя выбрать три позиции из двух без возвращения")

unique_names = sorted({"bob", "alice", "bob"})
assert set(rng.sample(unique_names, k=2)) == {"alice", "bob"}
```

В современных версиях `sample` ожидает последовательность: множество нужно преобразовать явно. Простое `list(a_set)` не обеспечивает одинаковый порядок между процессами. Сортировка подходит, если элементы сравнимы и именно такой порядок предусмотрен экспериментом.

**Веса.** Для `choices` укажите относительные `weights` или накопленные `cum_weights`, но не оба аргумента сразу. Длина весов должна совпадать с длиной популяции. Весам положено быть неотрицательными и конечными, сумме — положительной. Нулевой вес запрещает выбирать соответствующую позицию. Не полагайтесь на то, что каждая разновидность некорректных весов обязательно диагностируется одинаково: валидируйте свой вход.

```python
import math
from random import Random


def weighted_choice(population: list[str], weights: list[float], rng: Random) -> str:
    if not population or len(population) != len(weights):
        raise ValueError("Нужны элементы и по одному весу на элемент")
    if any(not math.isfinite(weight) or weight < 0 for weight in weights):
        raise ValueError("Вес должен быть конечным и неотрицательным")
    try:
        total = math.fsum(weights)
    except OverflowError as error:
        raise ValueError("Сумма весов слишком велика") from error
    if not math.isfinite(total) or total <= 0:
        raise ValueError("Сумма весов должна быть конечной и положительной")
    return rng.choices(population, weights=weights, k=1)[0]


assert weighted_choice(["never", "always"], [0.0, 1.0], Random(4)) == "always"

for bad_weights in [[0.0, 0.0], [-1.0, 2.0], [float("nan"), 1.0], [1e308, 1e308]]:
    try:
        weighted_choice(["a", "b"], bad_weights, Random(4))
    except ValueError:
        pass
    else:
        raise AssertionError("Некорректные веса должны быть отклонены")
```

`choices` с равными весами и серия вызовов `choice` могут дать разные последовательности при одинаковом seed: внутри используются разные способы выбора. Не превращайте случайный результат конкретного вспомогательного алгоритма в долговременный контракт.

**Распределение выбирается по смыслу данных.**

| Функция | Модель и параметры | Пример применения |
|---|---|---|
| `uniform(a, b)` | Равномерная величина на интервале | Смещение внутри временного окна |
| `triangular(low, high, mode)` | Треугольное распределение | Грубая модель с известными минимумом, максимумом и модой |
| `normalvariate(mu, sigma)`, `gauss(mu, sigma)` | Нормальное, среднее `mu` и стандартное отклонение `sigma` | Шум около среднего |
| `expovariate(lambd)` | Экспоненциальное; для ожидания берут положительную интенсивность | Интервал между независимыми событиями |
| `lognormvariate(mu, sigma)` | Логарифм величины распределён нормально | Положительные величины с правым хвостом |
| `betavariate(alpha, beta)` | Бета-распределение на `[0, 1]` | Моделирование долей |
| `gammavariate(alpha, beta)` | Гамма-распределение: форма и масштаб | Положительные длительности |
| `weibullvariate(alpha, beta)` | Масштаб и форма | Модель времени до отказа |
| `binomialvariate(n, p)` | Число успехов в `n` испытаниях; Python 3.12+ | Повторные независимые события |

Нормальное распределение допускает отрицательные значения. Если задержка по определению неотрицательна, отрицательные сэмплы — сигнал несоответствия модели. Замена каждого отрицательного числа нулём меняет распределение и создаёт дополнительную массу в нуле.

```python
import math
from random import Random
from statistics import fmean


rng = Random(15)
rate_per_second = 2.0
waits_seconds = [rng.expovariate(rate_per_second) for _ in range(1000)]
assert all(value >= 0 and math.isfinite(value) for value in waits_seconds)

# Теоретическое среднее равно 1 / rate_per_second.
# Маленькая выборка не обязана дать ровно это число.
observed_mean = fmean(waits_seconds)
assert observed_mean > 0

successes = rng.binomialvariate(n=20, p=0.3)
assert 0 <= successes <= 20
```

`lambd` измеряется в событиях на единицу времени: если задано два события в секунду, результат ожидания выражен в секундах. Параметр `beta` у разных библиотек бывает масштабом или обратной интенсивностью. Переносите формулу, проверив определения, а не совпадение названий.

### Независимые Random, seed, getstate()/setstate()

Функции уровня модуля используют общий скрытый экземпляр `Random`. Если тест или сторонняя библиотека вызывает `random.seed(...)`, это может изменить поведение другого кода в том же процессе.

Передавайте экземпляр генератора как зависимость. Тогда тест сам выбирает seed, а компонент не изменяет глобальный поток случайных чисел.

```python
from random import Random


def choose_workers(names: list[str], count: int, rng: Random) -> list[str]:
    return rng.sample(names, k=count)


first = Random(1234)
second = Random(1234)
population = ["anna", "boris", "vera", "gleb"]

assert choose_workers(population, 2, first) == choose_workers(population, 2, second)

# Продвижение first не меняет состояние second.
state = second.getstate()
first.random()
assert second.getstate() == state
```

Seed не обязательно число: поддерживаются и некоторые другие типы, включая строки и байты. Для конфигурации эксперимента целое обычно удобнее: его проще записать, проверить и передать между программами. `seed(None)` предназначен для автоматической инициализации и не даёт воспроизводимого опыта.

**Снимок состояния продолжает поток с конкретного места.** Это больше информации, чем исходный seed: не нужно заново выполнять все предыдущие вызовы.

```python
from random import Random


rng = Random(700)
rng.random()
rng.randrange(100)

checkpoint = rng.getstate()
expected_next = [rng.random() for _ in range(5)]

rng.setstate(checkpoint)
assert [rng.random() for _ in range(5)] == expected_next

resumed = Random()
resumed.setstate(checkpoint)
assert [resumed.random() for _ in range(5)] == expected_next
```

`getstate` возвращает внутреннее представление, которое следует передавать в `setstate` как единое значение. Не редактируйте его поля по догадкам. Долговременное хранение состояния требует зафиксированной среды и собственного формата контрольной точки. Загружать чужой pickle ради восстановления генератора опасно: pickle может выполнить код.

Независимые объекты отделяют состояния, но одинаковые seed создают одинаковые потоки. Для нескольких статистически независимых моделирований недостаточно скопировать один генератор во все процессы. Схема распределения потоков — часть эксперимента. `Random(master_seed + worker_id)` даёт детерминированные разные инициализации, но сама по себе не является доказательством статистической независимости.

### Воспроизводимость эксперимента и ограничения между версиями

«Одинаковый seed» — только одно из условий. Имеют значение алгоритм, версия интерпретатора, входные данные, их порядок, число вызовов и распределение вызовов между исполнителями.

```python
from random import Random


def experiment(seed: int, candidates: list[str]) -> list[str]:
    rng = Random(seed)
    ordered = sorted(candidates)
    return [rng.choice(ordered) for _ in range(6)]


assert experiment(42, ["b", "a", "c"]) == experiment(42, ["c", "b", "a"])

# Лишний вызов изменяет состояние даже тогда, когда его результат не нужен.
left = Random(42)
right = Random(42)
left.random()
assert left.getstate() != right.getstate()
```

Если сортировка меняет смысл исходных данных, сохраняйте исходный порядок вместе с набором, а не сортируйте его автоматически. Для строк порядок может зависеть от выбранного ключа нормализации; для пользовательских объектов нужен явный стабильный идентификатор.

**Границы обещаний Python.** Документация предусматривает совместимый способ инициализации и сохранение последовательности метода `random()` при одинаковом seed и совместимом seeder. Она не обещает неизменность всех деталей `sample`, `choices`, распределений и их потребления состояния между всеми версиями Python. Отдельно учитывайте исправления ошибок и замену используемой библиотеки.

Для повторения научного или производственного расчёта сохраняйте:

- версию алгоритма и исходного кода;
- версию Python, зависимости и важные параметры среды;
- seed или контрольную точку генератора;
- входные данные либо устойчивую ссылку на их версию и контрольную сумму;
- порядок обработки, число исполнителей и схему раздачи случайных потоков;
- настройки преобразований: фильтры, единицы, веса и правила округления.

В регрессионных тестах полезно проверять свойства: размер выборки, отсутствие повторных позиций, допустимый диапазон, воспроизводимость внутри выбранной среды. Если эталон требует точной последовательности, зафиксируйте реализацию и явно признайте эту зависимость.

**Параллельное выполнение.** Потокобезопасность генератора не закрепляет за конкретной задачей конкретный номер случайного значения. Планировщик может поменять порядок обращений. У общей генерации в free-threaded сборке также возможна конкуренция за синхронизацию; отдельные экземпляры на исполнителя уменьшают совместное состояние.

У `gauss` есть особая оговорка: одновременные обращения из разных потоков могут вернуть одинаковый результат из внутреннего кэша. Используйте отдельные генераторы, блокировку или `normalvariate` в зависимости от модели. Даже после устранения этой особенности распределение результатов по задачам не становится автоматически воспроизводимым.

### random для моделирования; secrets для защитных токенов

Генератор `random`, включая основной алгоритм Mersenne Twister, не предназначен для противодействия угадыванию. Непредсказуемость токена — отдельное требование. «Большое случайное число», «сложный seed» и «хэш текущего времени» не превращают его в безопасный секрет.

`secrets` использует источник случайности операционной системы и предоставляет функции для токенов и выбора секретных значений.

```python
import secrets


raw = secrets.token_bytes(32)
hex_token = secrets.token_hex(32)
url_token = secrets.token_urlsafe(32)

assert len(raw) == 32
assert len(hex_token) == 64
assert all(character in "0123456789abcdef" for character in hex_token)
assert set(url_token) <= set(
    "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_"
)

code = secrets.randbelow(1_000_000)
assert 0 <= code < 1_000_000
display_code = f"{code:06d}"
assert len(display_code) == 6
```

Аргумент `32` означает **32 случайных байта**, то есть 256 бит исходной случайности. Длина текстового представления зависит от кодировки. Передавайте размер явно, если формат токена — часть протокола: значение по умолчанию не стоит превращать в контракт.

Шестизначный код имеет всего миллион вариантов, даже когда источник случайности правильный. Ограничение числа попыток, срок действия, одноразовость и привязка к назначению остаются требованиями протокола. Не выводите реальные токены в логи и не используйте примеры с фиксированными секретами как рабочие ключи.

`random.SystemRandom` также обращается к системной случайности. Его `seed` не управляет потоком, а `getstate` и `setstate` не предоставляют воспроизводимую контрольную точку.

```python
from random import SystemRandom


rng = SystemRandom()
assert 0 <= rng.randrange(10) < 10

try:
    rng.getstate()
except NotImplementedError:
    pass
else:
    raise AssertionError("У системного источника нет состояния Random для экспорта")
```

**Критерий выбора:** эксперименту требуется управляемый и воспроизводимый поток, секрету — устойчивость к предсказанию. Проектируйте API так, чтобы эти задачи не разделяли один генератор по случайности.

**Документация:** [random](https://docs.python.org/3.14/library/random.html), [secrets](https://docs.python.org/3.14/library/secrets.html).

## Идентификаторы, хэши и бинарные кодировки

### uuid: виды идентификаторов и выбор под задачу

UUID — 128-битный идентификатор с определённой структурой. Его можно хранить как 16 байт, целое число или стандартную строку с дефисами. Версия определяет способ построения; одинаковая длина идентификаторов не делает их свойства одинаковыми.

| Версия | Источник идентификатора | Когда рассматривать | Ограничение |
|---|---|---|---|
| UUIDv1 | Время, последовательность и идентификатор узла | Совместимость с существующим протоколом | Может раскрывать время и сведения об узле |
| UUIDv3 | MD5 от namespace и имени | Совместимость с системой именованных UUIDv3 | Детерминированность; не средство защиты от подделки |
| UUIDv4 | Случайные биты с фиксированными полями формата | Независимое создание идентификаторов | Возможность коллизии мала, но не равна нулю |
| UUIDv5 | SHA-1 от namespace и имени | Один идентификатор для одного нормализованного имени | Известное имя позволяет воспроизвести идентификатор |
| UUIDv6 | Перестановка временных полей модели v1 | Временные UUID с лучшей локальностью порядка | Python 3.14+; учитывать раскрытие метаданных |
| UUIDv7 | Время в миллисекундах и дополнительные поля | Новые временно упорядочиваемые идентификаторы | Python 3.14+; не глобальная последовательность транзакций |
| UUIDv8 | Пользовательская структура в рамках формата | Согласованный специализированный протокол | Python 3.14+; семантику определяет приложение |

Версии v3 и v5 используют хэши как часть стандартизованной схемы идентификаторов. Это не рекомендация применять MD5 или SHA-1 для нового механизма проверки подлинности.

```python
from uuid import NAMESPACE_URL, UUID, uuid4, uuid5


identifier = uuid4()
assert identifier.version == 4
assert UUID(str(identifier)) == identifier
assert UUID(hex=identifier.hex) == identifier
assert UUID(bytes=identifier.bytes) == identifier
assert UUID(int=identifier.int) == identifier
assert len(identifier.bytes) == 16
assert len(identifier.hex) == 32

name = "https://example.test/customers/42"
stable = uuid5(NAMESPACE_URL, name)
assert stable == uuid5(NAMESPACE_URL, name)
assert stable != uuid5(NAMESPACE_URL, name + "/")
assert stable.version == 5
```

**Имена требуют правил.** `"Alice"` и `"alice"` — разные входы. URL с завершающим слешем и без него также различаются. Решите, нужно ли нормализовать регистр, Unicode, адреса и пробелы. Версионируйте эти правила: изменение нормализации может изменить все вычисляемые ID.

Namespace отделяет пространства имён. Один и тот же номер `42` в сущностях «заказ» и «клиент» не должен случайно означать одно и то же имя. Удобно один раз закрепить собственный namespace и внутри него явно кодировать тип сущности.

**Разбор и проверка — разные действия.** `UUID(text)` разбирает несколько допустимых текстовых представлений. Аргумент `version=4` при создании объекта не проверяет исходные биты, а устанавливает биты версии и варианта. Для валидации сначала разбирайте, затем проверяйте свойства.

```python
from uuid import NAMESPACE_DNS, RFC_4122, UUID, uuid5


def parse_v4(text: str) -> UUID:
    value = UUID(text)
    if value.variant != RFC_4122 or value.version != 4:
        raise ValueError("Требуется UUID версии 4")
    return value


original = uuid5(NAMESPACE_DNS, "example.test")
forced = UUID(str(original), version=4)
assert forced.version == 4
assert forced != original

try:
    parse_v4(str(original))
except ValueError:
    pass
else:
    raise AssertionError("UUIDv5 не должен проходить проверку UUIDv4")
```

Название константы `RFC_4122` сохранено для совместимости API, хотя современное описание UUID находится в RFC 9562. Если протокол требует только каноническую строку, дополнительно проверьте `str(value) == text`; парсер сам по себе допускает и другие формы.

`bytes` и `bytes_le` — разные представления порядка байтов некоторых полей. Не меняйте их при обмене с базой или другим языком без описания формата.

```python
# Python 3.14+: временные версии и специальные границы UUID.
from datetime import UTC, datetime
from uuid import MAX, NIL, UUID, uuid6, uuid7, uuid8


time_based = uuid6()
time_ordered = uuid7()
custom = uuid8(1, 2, 3)

assert time_based.version == 6
assert time_ordered.version == 7
assert custom.version == 8
assert NIL == UUID(int=0)
assert MAX == UUID(int=(1 << 128) - 1)

created_at = datetime.fromtimestamp(time_ordered.time / 1000, tz=UTC)
assert created_at.tzinfo is UTC
```

UUIDv7 удобен, когда временная близость ключей помогает индексу. Но сортировка ID не доказывает причинность событий и порядок фиксации транзакций. Между процессами и машинами действуют разные часы и состояния генераторов; изменение часов и выбранная реализация также имеют значение. Сохраняйте время события отдельным полем, если оно нужно предметной области.

У `uuid8()` значения по умолчанию не обязаны происходить из криптографически стойкого генератора. Не переносите ожидания от `uuid4()` на любую функцию с названием UUID.

**Уникальность и доступ.** В базе всё равно нужен `UNIQUE` или первичный ключ. При миллиардах случайных UUID вероятность коллизии остаётся очень небольшой, но корректность записи не должна опираться на слово «невозможно». Идентификатор не заменяет проверку прав доступа. Для bearer-токена лучше явный механизм секретов с требованиями к энтропии, сроку жизни и отзыву.

### hashlib: потоковое хэширование и проверка целостности

Криптографический хэш отображает байтовое сообщение в короткий отпечаток. Для целостности обычно нужен устойчивый современный алгоритм, например SHA-256. Хэшируется **последовательность байтов**, а не абстрактная строка, Python-объект или путь к файлу.

```python
import hashlib


payload = "Привет, Python".encode("utf-8")
whole = hashlib.sha256(payload)

streamed = hashlib.sha256()
streamed.update(payload[:5])
streamed.update(payload[5:])

assert streamed.digest() == whole.digest()
assert streamed.hexdigest() == whole.hexdigest()
assert len(whole.digest()) == 32
assert len(whole.hexdigest()) == 64

branch = streamed.copy()
branch.update(b"!")
assert branch.digest() != streamed.digest()
```

Границы вызовов `update` не входят в сообщение: два обновления `b"ab"` и `b"c"` эквивалентны одному `b"abc"`. Для структурированных данных это может стать неоднозначностью.

```python
from hashlib import sha256


def framed_hash(parts: list[bytes]) -> str:
    digest = sha256()
    for part in parts:
        digest.update(len(part).to_bytes(8, byteorder="big"))
        digest.update(part)
    return digest.hexdigest()


assert sha256(b"ab" + b"c").digest() == sha256(b"a" + b"bc").digest()
assert framed_hash([b"ab", b"c"]) != framed_hash([b"a", b"bc"])
```

Укажите кодировку текста, нормализацию Unicode, разделители и порядок полей. Отсортированные ключи JSON делают конкретную сериализацию предсказуемее, но не превращают её автоматически в универсальный канонический формат между языками и версиями числовых моделей.

**Большой файл не нужно читать целиком.** Достаточно последовательно подавать блоки в хэш. Память зависит от размера блока, а не от размера содержимого.

```python
import hashlib
from pathlib import Path
from tempfile import TemporaryDirectory


def file_sha256(path: Path, chunk_size: int = 128 * 1024) -> str:
    if chunk_size <= 0:
        raise ValueError("Размер блока должен быть положительным")
    digest = hashlib.sha256()
    with path.open("rb") as stream:
        while chunk := stream.read(chunk_size):
            digest.update(chunk)
    return digest.hexdigest()


with TemporaryDirectory() as directory:
    path = Path(directory) / "payload.bin"
    content = b"example\x00" * 1000
    path.write_bytes(content)
    expected = hashlib.sha256(content).hexdigest()
    assert file_sha256(path, chunk_size=17) == expected

    # file_digest появился в Python 3.11.
    with path.open("rb") as stream:
        assert hashlib.file_digest(stream, "sha256").hexdigest() == expected
```

`file_digest` работает с бинарным файловым объектом. После вызова не полагайтесь на его текущую позицию и внутренний буфер: закройте объект или явно организуйте дальнейшую работу по документированному контракту. В Python 3.14 неблокирующий файловый объект вызывает `BlockingIOError` вместо прежнего некорректного поведения; пример использует обычный блокирующий файл.

Если файл меняется во время чтения, результат не обязательно описывает какую-либо согласованную версию. Контрольная сумма не создаёт снимок файловой системы. Для воспроизводимого артефакта обеспечьте неизменность, версионирование или подходящую блокировку на уровне источника.

**Сравнивать нужно с доверенным ожиданием.** SHA-256 файла полезен, когда ожидаемая сумма получена из независимого доверенного источника. Если злоумышленник заменил и архив, и лежащий рядом текстовый checksum, совпадение ничего не говорит об авторе.

| Инструмент | Для чего подходит | Что не обеспечивает |
|---|---|---|
| `hash(obj)` | Внутренние хэш-таблицы Python | Стабильный checksum между запусками |
| CRC и другие некриптографические суммы | Обнаружение случайного повреждения | Устойчивость к намеренной подмене |
| SHA-256, SHA-3 | Криптографический отпечаток | Аутентификацию без доверенного ожидания |
| HMAC | Проверка сообщения обладателем общего ключа | Шифрование и публичное доказательство авторства |
| KDF для паролей | Замедленная проверка пароля с солью и параметрами | Превращение слабого пароля в сильный |

`algorithms_available` зависит от сборки и криптографического backend. Некоторые среды ограничивают MD5. Аргумент `usedforsecurity=False` описывает назначение вызова и не исправляет криптографические слабости алгоритма.

Для паролей не используйте `sha256(password)` и не придумывайте собственное «много раз захэшировать». Нужна предназначенная для паролей схема с уникальной солью, параметрами стоимости и форматом хранения. В stdlib есть `pbkdf2_hmac` и, при поддержке сборки, `scrypt`; выбор и актуальные параметры относятся к отдельной теме безопасности.

У семейства SHAKE длину выхода передают в `digest(length)` или `hexdigest(length)`; у обычного SHA-256 она фиксирована. Длина шестнадцатеричного текста в два раза больше длины байтового результата.

### hmac и compare_digest(); хэш vs аутентификация

HMAC связывает сообщение с секретным ключом. Проверяющая сторона заново вычисляет MAC и сравнивает его с переданным значением. Изменение сообщения, ключа или подписи должно приводить к отказу.

```python
import hmac
import secrets


key = secrets.token_bytes(32)
message = b"report:v1\nrequest=42\namount=100"
tag = hmac.digest(key, message, "sha256")

assert len(tag) == 32
assert hmac.compare_digest(tag, hmac.digest(key, message, "sha256"))
assert not hmac.compare_digest(tag, hmac.digest(key, message + b"0", "sha256"))

incremental = hmac.new(key, digestmod="sha256")
incremental.update(b"report:v1\n")
incremental.update(b"request=42\namount=100")
assert hmac.compare_digest(tag, incremental.digest())
```

При обычном `==` сравнение может завершаться после различающегося участка. `compare_digest` предназначен для сравнения аутентификационных значений без такой зависимости от содержимого. Это не обещание, что весь HTTP-обработчик, декодирование или проверка длины выполняются за постоянное время.

Оба аргумента должны иметь совместимые типы: байтовые значения либо ASCII-строки. Не сравнивайте сырые байты одного тега с шестнадцатеричной строкой другого. Перед сравнением проверьте формат и ожидаемую длину.

```python
import hmac


expected = b"\x01" * 32
same = bytes([1]) * 32
different = b"\x02" * 32
assert hmac.compare_digest(expected, same)
assert not hmac.compare_digest(expected, different)
assert hmac.compare_digest(expected.hex(), same.hex())

try:
    hmac.compare_digest(expected, expected.hex())
except TypeError:
    pass
else:
    raise AssertionError("Байты и hex-строка — разные представления")
```

**Что входит в подпись.** Все значимые поля должны входить в однозначно определённую последовательность байтов: версия протокола, назначение, идентификатор, тело, а при необходимости время и nonce. Если подписать только тело, неподписанный адрес назначения или тип операции может изменить смысл запроса.

Не собирайте MAC как `sha256(secret + message)`: у такого самодельного протокола другие свойства, включая риски, связанные со структурой хэш-функции. Используйте HMAC как готовую конструкцию.

HMAC подтверждает владение **общим** ключом. Любой проверяющий с этим ключом также может создать корректный тег. Для проверки многими сторонами без возможности подписывать нужен другой класс инструментов — цифровая подпись.

**Повторное воспроизведение.** Перехваченная пара «сообщение + корректный тег» остаётся корректной. HMAC сам не хранит использованные nonce, не проверяет срок действия и не отзывает ключи. Эти действия задаёт протокол. Шифрования также нет: сообщение доступно наблюдателю.

Ключ хранится вне исходного кода и репозитория, имеет отдельное назначение и план ротации. В примерах новый ключ создаётся на запуск; это демонстрация API, а не способ обеспечить проверяемость отчётов после перезапуска.

### base64: кодировка данных, а не шифрование

Base64 переносит произвольные байты через текстовые форматы. Для декодирования не нужен секрет. Любой получатель может восстановить содержимое, поэтому пароль в Base64 остаётся открытым паролем с другим представлением.

```python
import base64


payload = b"\xfb\xff\x00Python"
standard = base64.b64encode(payload)
url_safe = base64.urlsafe_b64encode(payload)

assert base64.b64decode(standard, validate=True) == payload
assert base64.urlsafe_b64decode(url_safe) == payload
assert b"+" in standard or b"/" in standard
assert b"+" not in url_safe and b"/" not in url_safe
assert isinstance(standard, bytes)

text = url_safe.decode("ascii")
assert text.encode("ascii") == url_safe
assert len(standard) == 4 * ((len(payload) + 2) // 3)
```

Алфавит URL-safe заменяет `+` и `/` на `-` и `_`. Символ `=` остаётся padding. Некоторые протоколы исключают padding, другие требуют его; это нужно задать явно. «URL-safe» не значит, что строку можно без правил встроить в любой фрагмент URL, HTML или команду оболочки.

По умолчанию `b64decode` может отбрасывать символы вне алфавита. Для строгой проверки обычного Base64 передавайте `validate=True` и ограничивайте размер входа.

```python
import base64
import binascii


assert base64.b64decode(b"Z!g==") == b"f"

try:
    base64.b64decode(b"Z!g==", validate=True)
except binascii.Error:
    pass
else:
    raise AssertionError("Посторонний символ должен быть отклонён")
```

**Строгий алфавит и каноническая строка — не одно и то же.** Проверка `validate=True` не является универсальной проверкой единственного канонического представления. Для протокола с одним допустимым написанием можно декодировать, повторно закодировать и сравнить с исходным текстом.

```python
import base64
import binascii


def decode_canonical_urlsafe(text: str, max_chars: int = 4096) -> bytes:
    if len(text) > max_chars:
        raise ValueError("Слишком длинная строка")
    try:
        encoded = text.encode("ascii")
        decoded = base64.b64decode(encoded, altchars=b"-_", validate=True)
    except (UnicodeEncodeError, binascii.Error) as error:
        raise ValueError("Некорректный Base64") from error
    canonical = base64.urlsafe_b64encode(decoded).decode("ascii")
    if canonical != text:
        raise ValueError("Требуется канонический URL-safe Base64 с padding")
    return decoded


assert decode_canonical_urlsafe("Zg==") == b"f"

for bad in ["Z!g==", "Zg", "Zh==", "+w==", "Привет"]:
    try:
        decode_canonical_urlsafe(bad)
    except ValueError:
        pass
    else:
        raise AssertionError(f"Недопустимое представление: {bad!r}")
```

Вызов `b64decode(..., altchars=b"-_", validate=True)` сам по себе не гарантирует использование исключительно URL-safe алфавита. Повторное кодирование в примере одновременно закрепляет алфавит, padding и представление неиспользуемых битов.

Если протокол требует вариант **без** padding, опишите его отдельно: проверьте разрешённые символы, восстановите только допустимое количество `=`, декодируйте и сравните с повторно закодированным результатом без padding. Не лечите любую ошибку добавлением случайного числа знаков `=`.

| Представление | Особенность | Типичный выбор |
|---|---|---|
| Hex | Два символа на байт | Короткие отпечатки, ручная диагностика |
| Base64 | Четыре символа на три байта до учёта padding | Бинарные данные в JSON и текстовых протоколах |
| Base32 | Более длинное, ограниченный алфавит | Протоколы, где важны правила ввода и регистра |
| Base85 | Плотнее Base64, сложнее алфавит | Только при поддержке форматом обмена |

Кодировка не обнаруживает намеренную подмену. Если передаётся HMAC, сначала декодируйте и проверьте формат, затем сравнивайте MAC. Не считайте успешное декодирование доказательством подлинности.

**Документация:** [uuid](https://docs.python.org/3.14/library/uuid.html), [hashlib](https://docs.python.org/3.14/library/hashlib.html), [hmac](https://docs.python.org/3.14/library/hmac.html), [base64](https://docs.python.org/3.14/library/base64.html).

## Конфигурационные форматы

### tomllib: чтение TOML и отсутствие встроенного writer

`tomllib` входит в стандартную библиотеку с Python 3.11 и читает TOML. Он превращает синтаксис конфигурации в обычные Python-значения, но не проверяет предметную модель приложения.

```toml
title = "Latency report"
enabled = true
workers = 4
slow_ms = 250.5
labels = ["api", "production"]

[storage]
directory = "./reports"
compressed = false

[[sources]]
name = "frontend"
weight = 0.7

[[sources]]
name = "backend"
weight = 0.3
```

Ключи внутри таблицы `[storage]` попадают во вложенный словарь. Конструкция `[[sources]]` создаёт массив таблиц, то есть список словарей. Значения имеют собственные типы: `false` превращается в `False`, а не в строку `"false"`.

```python
import tomllib
from datetime import date, datetime, time
from decimal import Decimal


source = """
enabled = false
workers = 4
ratio = 0.1
release_date = 2026-01-20
starts_at = 09:30:00
created_at = 2026-01-20T09:30:00Z

[service]
name = "example"
"""

data = tomllib.loads(source, parse_float=Decimal)
assert data["enabled"] is False
assert data["workers"] == 4
assert data["ratio"] == Decimal("0.1")
assert data["release_date"] == date(2026, 1, 20)
assert data["starts_at"] == time(9, 30)
assert isinstance(data["created_at"], datetime)
assert data["created_at"].tzinfo is not None
assert data["service"]["name"] == "example"
```

`parse_float=Decimal` позволяет сохранить десятичную модель для TOML-чисел с дробной частью. Он не превращает все числовые значения в Decimal: целые остаются целыми. Пользовательский callback не должен возвращать `dict` или `list`. Допустимость NaN, бесконечности, знака и диапазона для конкретного поля проверяет приложение.

**Два способа чтения.**

| Вызов | Вход | Особенность |
|---|---|---|
| `tomllib.loads(text)` | Строка `str` | Текст уже декодирован вызывающим кодом |
| `tomllib.load(file)` | Файловый объект в бинарном режиме | TOML читается как UTF-8 по правилам модуля |

```python
from pathlib import Path
from tempfile import TemporaryDirectory
import tomllib


with TemporaryDirectory() as directory:
    path = Path(directory) / "settings.toml"
    path.write_text("[report]\ntop_k = 5\n", encoding="utf-8")
    with path.open("rb") as stream:
        data = tomllib.load(stream)
    assert data == {"report": {"top_k": 5}}
```

Не открывайте файл для `tomllib.load` в текстовом режиме по аналогии с `json.load`. Различие контрактов API стоит проверять, а не угадывать по названию функции.

**После парсинга нужна модель.** Разделяйте синтаксическую ошибку TOML, отсутствие файла и недопустимые настройки. Строка `workers = "many"` синтаксически корректна, но для числа исполнителей непригодна.

```python
from dataclasses import dataclass
import tomllib


@dataclass(frozen=True, slots=True)
class Settings:
    workers: int
    enabled: bool


def parse_settings(text: str) -> Settings:
    raw = tomllib.loads(text)
    if set(raw) - {"workers", "enabled"}:
        raise ValueError("Неизвестные параметры")
    workers = raw.get("workers", 1)
    enabled = raw.get("enabled", True)
    if type(workers) is not int or not 1 <= workers <= 64:
        raise ValueError("workers должен быть целым от 1 до 64")
    if type(enabled) is not bool:
        raise ValueError("enabled должен быть логическим значением")
    return Settings(workers=workers, enabled=enabled)


assert parse_settings("workers = 4\nenabled = false") == Settings(4, False)

try:
    parse_settings("workers = true")
except ValueError:
    pass
else:
    raise AssertionError("bool не должен проходить как число исполнителей")
```

Здесь `type(value) is int` выбран намеренно: `bool` является подклассом `int`, но `workers = true` не имеет нужного смысла. Это проверка формата внешних данных, а не универсальный запрет наследования от числовых типов.

Для конфигурации из недоверенного источника задавайте ограничение размера до полного чтения и разбора. Проверка `len(path.read_bytes())` после загрузки не ограничивает уже выделенную память. В практическом проекте ниже файл читается с лимитом.

```python
# Python 3.14+: структурированные сведения об ошибке TOML.
import tomllib


try:
    tomllib.loads("workers = [1,\n")
except tomllib.TOMLDecodeError as error:
    assert isinstance(error.msg, str)
    assert isinstance(error.doc, str)
    assert error.pos >= 0
    assert error.lineno >= 1
    assert error.colno >= 1
else:
    raise AssertionError("Незавершённый массив должен вызвать ошибку")
```

До Python 3.14 не полагайтесь на эти публичные атрибуты ошибки. Во всех рассматриваемых версиях можно перехватывать `TOMLDecodeError` и выводить её текст. Не показывайте пользователю весь исходный документ, если в нём могут быть секреты.

**Записи в tomllib нет.** Функций `dump` и `dumps` модуль не предоставляет. Для генерации TOML документация указывает на сторонние инструменты: Tomli-W для записи и TOMLKit для редактирования с сохранением оформления. Обычный парсер не сохраняет комментарии, пустые строки и исходное представление значений.

Не создавайте writer конкатенацией строк для произвольных входов: экранирование, многострочные строки, даты и вложенные таблицы быстро превращают это в собственный неполный сериализатор.

### configparser: секции, интерполяция и преобразование типов

`configparser` работает с INI-подобной конфигурацией. Формат удобен для небольших настроек с секциями и строковыми значениями. В отличие от TOML, типы в основном задаются при чтении.

```ini
[DEFAULT]
timeout = 10

[server]
host = localhost
port = 8080
enabled = false
```

```python
from configparser import ConfigParser
from io import StringIO


parser = ConfigParser()
parser.read_file(
    StringIO(
        """
[DEFAULT]
timeout = 10
[server]
host = localhost
port = 8080
enabled = false
"""
    )
)

assert parser["server"]["port"] == "8080"
assert parser.getint("server", "port") == 8080
assert parser.getboolean("server", "enabled") is False
assert parser.getint("server", "timeout", fallback=99) == 10
assert parser.getint("server", "missing", fallback=99) == 99
assert bool(parser["server"]["enabled"]) is True
```

`bool("false")` возвращает `True`, потому что строка непустая. Для INI используйте `getboolean`: он понимает определённый набор написаний, включая `yes/no`, `on/off`, `true/false` и `1/0`. Произвольная строка не должна молча становиться «истиной».

**DEFAULT и fallback.** Значения из `DEFAULT` доступны через секции. Они имеют приоритет перед `fallback` метода: fallback используется, когда значение действительно не найдено. Если требуется проверить только явно записанные ключи секции, учитывайте, что section proxy показывает и унаследованные defaults.

**Регистр ключей.** По умолчанию имена опций нормализуются в нижний регистр. Имена секций регистрозависимы. Для сохранения регистра задайте `optionxform` до чтения.

```python
from configparser import ConfigParser


default = ConfigParser()
default.read_string("[Service]\nAPIKey = example\n")
assert default["Service"]["apikey"] == "example"
assert default["Service"]["APIKEY"] == "example"
assert "service" not in default

exact = ConfigParser()
exact.optionxform = str
exact.read_string("[Service]\nAPIKey = example\n")
assert "APIKey" in exact["Service"]
assert "apikey" not in exact["Service"]
```

**Интерполяция подставляет другие параметры.** Обычный `ConfigParser` использует `%(name)s`. Для буквального процента в интерполируемом значении нужен `%%`. Если значения сами содержат проценты — например, чужой шаблон или пароль, — может быть правильнее отключить интерполяцию.

```python
from configparser import ConfigParser, ExtendedInterpolation


basic = ConfigParser()
basic.read_string("[paths]\nroot = /srv/app\nlogs = %(root)s/logs\nprogress = 100%%\n")
assert basic["paths"]["logs"] == "/srv/app/logs"
assert basic["paths"]["progress"] == "100%"

extended = ConfigParser(interpolation=ExtendedInterpolation())
extended.read_string("[base]\nroot = /srv/app\n[paths]\nlogs = ${base:root}/logs\n")
assert extended["paths"]["logs"] == "/srv/app/logs"

raw = ConfigParser(interpolation=None)
raw.read_string("[credentials]\nvalue = contains%percent\n")
assert raw["credentials"]["value"] == "contains%percent"
```

`ExtendedInterpolation` поддерживает `${section:option}` и ссылки внутри секции; буквальный доллар записывается как `$$`. Эта возможность не означает автоматическое чтение переменных окружения. Подстановки окружения нужно спроектировать и подключить явно.

**Чтение нескольких файлов.** `read([...])` возвращает список успешно прочитанных файлов; отсутствующие файлы могут быть пропущены. Это удобно для необязательных пользовательских настроек. Если файл обязателен, откройте его сами и вызовите `read_file` — тогда отсутствие не потеряется.

```python
from configparser import ConfigParser, DuplicateOptionError
from pathlib import Path
from tempfile import TemporaryDirectory


with TemporaryDirectory() as directory:
    root = Path(directory)
    base = root / "base.ini"
    override = root / "override.ini"
    base.write_text("[service]\nport = 8000\n", encoding="utf-8")
    override.write_text("[service]\nport = 9000\n", encoding="utf-8")

    parser = ConfigParser()
    loaded = parser.read(
        [str(root / "absent.ini"), str(base), str(override)],
        encoding="utf-8",
    )
    assert loaded == [str(base), str(override)]
    assert parser.getint("service", "port") == 9000

    required = ConfigParser()
    with base.open(encoding="utf-8") as stream:
        required.read_file(stream, source=str(base))
    assert required.getint("service", "port") == 8000

try:
    ConfigParser().read_string("[x]\na = 1\na = 2\n")
except DuplicateOptionError:
    pass
else:
    raise AssertionError("Повтор опции внутри одного источника запрещён")
```

Поздний файл переопределяет совпадающий параметр раннего. Режим `strict=True`, включённый по умолчанию, запрещает дубликаты внутри одного источника, но не запрещает такую последовательность файлов. Порядок источников — часть контракта конфигурации.

Дополнительные риски: ошибки интерполяции могут проявляться при получении значения, числовой getter не проверяет предметный диапазон, `getfloat` не запрещает автоматически NaN и бесконечность. После чтения соберите проверенную модель настроек, как для TOML.

Не используйте `eval` для превращения строки INI в список или объект. Если нужна сложная типизированная структура, выберите соответствующий формат. Конфигурация также не является хранилищем секретов только потому, что файл называется `settings.ini`.

**Документация:** [tomllib](https://docs.python.org/3.14/library/tomllib.html), [configparser](https://docs.python.org/3.14/library/configparser.html).

## Локализация и представление данных

### gettext: переводы, каталоги и формы множественного числа

Интернационализация подготавливает программу к разным языкам, локализация добавляет конкретные переводы и правила представления. `gettext` решает задачу каталога сообщений. Он не переводит текст автоматически и не форматирует сам даты, валюты и все грамматические формы.

Обычно исходные сообщения становятся ключами поиска. Программа передаёт ключ в каталог и получает перевод. Если сообщение не найдено, fallback может вернуть исходный текст.

```python
from gettext import NullTranslations


catalog = NullTranslations()
translate = catalog.gettext

template = translate("Hello, {name}!")
assert template.format(name="Иса") == "Hello, Иса!"


def format_file_count(catalog: NullTranslations, count: int) -> str:
    if count < 0:
        raise ValueError("Число файлов не может быть отрицательным")
    template = catalog.ngettext("{count} file", "{count} files", count)
    return template.format(count=count)


assert format_file_count(catalog, 1) == "1 file"
assert format_file_count(catalog, 5) == "5 files"
assert catalog.pgettext("menu", "Open") == "Open"
```

**Сначала перевод, затем подстановка.** Выражение `translate(f"Hello, {name}!")` создаёт множество разных ключей с пользовательскими данными. Инструмент извлечения сообщений не может получить из него один устойчивый шаблон. Используйте литерал `"Hello, {name}!"`, а переменные подставляйте после поиска перевода.

Именованные поля позволяют переводчику поменять порядок слов. Проверяйте наличие и совместимость полей в переводах: ошибка `{cout}` вместо `{count}` проявится при форматировании.

**Формы числа выбираются правилами языка.** Проверка `count == 1` недостаточна для русского: 1 файл, 2 файла, 5 файлов, 11 файлов, 21 файл. Метод `ngettext` получает исходные singular/plural и число, а нужную форму перевода выбирает каталог.

Типичный путь каталога:

| Файл | Назначение |
|---|---|
| `locale/report.pot` | Шаблон извлечённых сообщений |
| `locale/ru/LC_MESSAGES/report.po` | Редактируемый русский перевод |
| `locale/ru/LC_MESSAGES/report.mo` | Скомпилированный каталог для выполнения |

`report` — domain, то есть имя набора сообщений. `ru` — выбранный язык. Каталог `.po` хранится в репозитории как исходник; `.mo` должен попасть в поставку приложения как ресурс.

**Пример файла перевода** `locale/ru/LC_MESSAGES/report.po`:

```po
msgid ""
msgstr ""
"Project-Id-Version: report 1.0\n"
"Language: ru\n"
"Content-Type: text/plain; charset=UTF-8\n"
"Content-Transfer-Encoding: 8bit\n"
"Plural-Forms: nplurals=3; plural=(n%10==1 && n%100!=11 ? 0 : n%10>=2 && n%10<=4 && (n%100<10 || n%100>=20) ? 1 : 2);\n"

#, python-brace-format
msgid "Hello, {name}!"
msgstr "Привет, {name}!"

#, python-brace-format
msgid "{count} file"
msgid_plural "{count} files"
msgstr[0] "{count} файл"
msgstr[1] "{count} файла"
msgstr[2] "{count} файлов"

msgctxt "menu"
msgid "Open"
msgstr "Открыть"

msgctxt "state"
msgid "Open"
msgstr "Открыт"
```

Здесь три формы. Условие учитывает не только последнюю цифру, но и 11–14. Формула относится к целочисленному количеству в данном сообщении; форматирование дробных количеств и всех падежей требует более широкой языковой модели.

Для компиляции можно использовать GNU gettext. `msgfmt` и `xgettext` — отдельные утилиты, их установка не является частью установки Python.

```bash
# Выполняется после создания указанного PO-файла и установки GNU gettext.
msgfmt --check --check-format \
  -o locale/ru/LC_MESSAGES/report.mo \
  locale/ru/LC_MESSAGES/report.po
```

Следующий блок относится к тому же примеру каталога и запускается из каталога, содержащего папку `locale`.

```python
# example-group: gettext
from gettext import translation
from pathlib import Path


catalog = translation(
    "report",
    localedir=Path("locale"),
    languages=["ru"],
    fallback=False,
)

assert catalog.gettext("Hello, {name}!").format(name="Иса") == "Привет, Иса!"
for count, expected in [
    (1, "1 файл"),
    (2, "2 файла"),
    (5, "5 файлов"),
    (11, "11 файлов"),
    (21, "21 файл"),
    (22, "22 файла"),
    (25, "25 файлов"),
    (111, "111 файлов"),
]:
    template = catalog.ngettext("{count} file", "{count} files", count)
    assert template.format(count=count) == expected

assert catalog.pgettext("menu", "Open") == "Открыть"
assert catalog.pgettext("state", "Open") == "Открыт"
```

**Контекст.** `pgettext(context, message)` различает одинаковое слово в разных местах: действие «Открыть» и состояние «Открыт». Для сочетания контекста и числа существует `npgettext`. Не разбивайте предложение на кусочки только ради повторного использования: порядок и согласование слов различаются по языкам.

**Объект перевода лучше глобальной установки.** `catalog.install()` помещает `_` в пространство встроенных имён. Это удобно в небольшой самостоятельной программе, но библиотека не должна менять глобальный язык вызывающего приложения. В веб-сервисе выбирайте объект перевода для запроса и передавайте его явно.

`languages=None` позволяет искать язык через окружение. Для воспроизводимого сервиса указывайте выбранный язык сами, сопоставив предпочтения пользователя с поддерживаемым набором. Не создавайте путь к файлу простым добавлением непроверенной строки языка.

**Fallback должен быть осознанным.** `fallback=True` помогает приложению продолжить работу без перевода. Но он также скрывает ошибку сборки, когда все `.mo` забыли включить в пакет. Тест поставки должен загрузить обязательные каталоги с `fallback=False` и проверить несколько характерных сообщений.

Не загружайте произвольные чужие каталоги как доверенную часть приложения. Перевод может менять смысл интерфейса, содержать нежелательный текст и некорректные поля. Проверяйте каталоги в сборке так же, как другие ресурсы.

### locale: форматирование и глобальное состояние процесса

`locale` обращается к локальным соглашениям ОС: десятичному разделителю, группировке цифр, денежному формату, сравнению строк. Локаль состоит из категорий: числовая, денежная, временная и другие.

| Категория/функция | Для чего нужна |
|---|---|
| `LC_NUMERIC` | Десятичный разделитель и группировка |
| `LC_MONETARY` | Валютное представление |
| `LC_TIME` | Локализованные названия и временные форматы |
| `LC_COLLATE` | Правила сравнения строк |
| `LC_CTYPE` | Классификация символов и связанные настройки среды |
| `localeconv()` | Словарь текущих соглашений |
| `format_string`, `atof`, `atoi` | Представление и чтение чисел по текущей локали |
| `strxfrm` | Ключ сортировки с учётом текущей локали |

**Главное ограничение — состояние процесса.** `setlocale` меняет не настройку одного объекта и не context variable текущей coroutine. На большинстве систем изменение не является потокобезопасным. Нельзя менять `ru_RU` и `en_US` перед форматированием каждого запроса в многопоточном сервере.

Следующий пример предназначен для отдельной однопоточной программы. Он использует стандартную локаль `C`, чтобы не зависеть от наличия конкретных языковых пакетов в ОС.

```python
import locale


previous = locale.setlocale(locale.LC_NUMERIC)
try:
    locale.setlocale(locale.LC_NUMERIC, "C")
    assert locale.format_string("%.2f", 1234.5, grouping=False) == "1234.50"
    assert locale.atof("1234.50") == 1234.5
    assert locale.localeconv()["decimal_point"] == "."
finally:
    locale.setlocale(locale.LC_NUMERIC, previous)
```

Восстановление в `finally` полезно в изолированном коде, но не делает переключение безопасным для потоков: между установкой и восстановлением другие исполнители уже могли увидеть чужую локаль. Собственная блокировка помогает только тогда, когда **все** обращения в процессе соблюдают тот же протокол, включая сторонний код.

**Наличие и имена локалей зависят от платформы.** `ru_RU.UTF-8` может отсутствовать в контейнере. На другой ОС имя может отличаться. Перехватывайте `locale.Error` и решайте, требуется ли локаль обязательно или можно использовать явный fallback.

`setlocale(category, "")` запрашивает предпочтения окружения; это не выбор языка конкретного пользователя сервиса. Инициализировать локаль один раз на старте CLI-приложения иногда уместно. Вызывать такое изменение внутри универсальной библиотеки обычно нельзя.

**Хранение и отображение имеют разные требования.** JSON-число использует точку по своему формату, даже когда человеку показывают запятую. Не сохраняйте сумму в БД строкой `"1 234,50"`, если системе нужно выполнять арифметику. Сохраняйте число и валюту отдельно, форматируйте на границе интерфейса.

Локализованные числа также неоднозначны: `"1,234"` в одной среде означает 1234, в другой — 1.234. Пользовательский ввод требует известной локали и явных правил, а не удаления всех запятых и пробелов.

Перевод через отдельный объект `gettext` не изолирует `locale` автоматически. Если приложению нужны разные числовые и временные форматы одновременно, нужен инструмент с явной локалью на вызов или собственное строго ограниченное форматирование. Глобальное переключение не решает эту задачу.

При работе с файлами указывайте кодировку формата явно, например `encoding="utf-8"`. Не путайте язык интерфейса, кодировку текста, часовой пояс и локаль: это независимые настройки. Для определения кодировки существуют отдельные API; старый `getdefaultlocale` в рассматриваемых версиях уже устарел.

### pprint, reprlib и textwrap для диагностического вывода

Диагностический вывод должен помогать исследовать данные, не раскрывая секреты и не создавая неограниченный объём. Стандартная библиотека предоставляет разные инструменты для структуры, сокращения представления и оформления текста.

**pprint показывает вложенную структуру.** `pprint` и `pp` печатают, `pformat` возвращает строку. Параметры управляют глубиной, шириной, компактностью и порядком ключей.

```python
from io import StringIO
from pprint import pformat, pp


data = {"z": [1, 2, 3], "a": {"inner": [4, 5]}}
text = pformat(data, width=30, sort_dicts=False)
assert text.index("'z'") < text.index("'a'")
assert "\n" in text

limited = pformat(data, depth=1)
assert "..." in limited

stream = StringIO()
pp(data, stream=stream, sort_dicts=False)
assert stream.getvalue().endswith("\n")
```

У `pp` по умолчанию `sort_dicts=False`, у `pprint` и `pformat` — `True`. Если порядок несёт смысл, указывайте параметр явно. Ширина — пожелание для размещения, а не жёсткая гарантия: длинная неделимая строка может оказаться шире.

Рекурсивные встроенные структуры отображаются со специальной пометкой. Но произвольный `__repr__` пользовательского объекта может бросить исключение или выполнить дорогое действие. `pprint` не является песочницей.

**reprlib сокращает большие представления.** Это полезно для коллекции из тысяч объектов, когда нужны первые элементы и признаки структуры.

```python
from reprlib import Repr, recursive_repr


limited = Repr(maxlist=3, maxstring=18, maxlevel=3)
assert "..." in limited.repr(list(range(100)))
assert len(limited.repr("x" * 1000)) < 1000


class Node:
    def __init__(self, name: str) -> None:
        self.name = name
        self.children: list[Node] = []

    @recursive_repr(fillvalue="<cycle>")
    def __repr__(self) -> str:
        return f"Node({self.name!r}, {self.children!r})"


node = Node("root")
node.children.append(node)
assert "<cycle>" in repr(node)
```

Параметры конструктора `Repr` в таком виде доступны с Python 3.12. Декоратор `recursive_repr` обнаруживает повторный вход для объекта в том же потоке; он не предназначен для поиска всех циклов предметного графа.

**Сокращение не равно очистке секретов.** Токен может целиком поместиться в первые символы. Маскируйте чувствительные поля до передачи форматтеру и лучше формируйте диагностическое представление из разрешённых полей.

```python
from pprint import pformat


raw = {
    "request_id": "req-42",
    "status": 200,
    "authorization": "Bearer confidential-example",
    "body": {"password": "another-confidential-example"},
}
safe = {key: raw[key] for key in ("request_id", "status")}
text = pformat(safe, sort_dicts=True)
assert "confidential" not in text
assert "request_id" in text
```

Список разрешённых полей в примере намеренно небольшой. Универсальная функция «удалить ключ password» не заметит секрет в другом поле, списке, пользовательском объекте или URL.

**textwrap оформляет текст.**

| Функция | Действие | Оговорка |
|---|---|---|
| `dedent` | Удаляет общий отступ | Табуляции и пробелы не считаются одинаковыми |
| `indent` | Добавляет префикс строкам | По умолчанию пропускает пустые строки |
| `fill` | Переносит текст в одну строку с переводами | Правила пробелов и длинных слов настраиваются |
| `wrap` | То же, результат списком строк | Удобно для дальнейшей обработки |
| `shorten` | Схлопывает пробелы и сокращает по словам | Не подходит для точного сохранения исходного текста |

```python
import textwrap


source = """
    first line
    second line
"""
clean = textwrap.dedent(source).strip()
assert clean == "first line\nsecond line"
assert textwrap.indent(clean, "> ") == "> first line\n> second line"

paragraph = "alpha beta gamma delta"
assert textwrap.fill(paragraph, width=10) == "alpha beta\ngamma\ndelta"
assert textwrap.shorten(paragraph, width=16, placeholder="...") == "alpha beta..."
assert textwrap.shorten("  alpha \n beta  ", width=20) == "alpha beta"

preserved = textwrap.indent("a\n\nb", "| ", predicate=lambda line: True)
assert preserved == "| a\n| \n| b"
```

Ширина Python-строки не равна числу занимаемых колонок терминала. Комбинируемые знаки, emoji, широкие символы и управляющие последовательности требуют отдельного учёта. `textwrap` подходит для обычного текста, но не является полноценным движком терминальной вёрстки.

Диагностический `repr` — не формат обмена. Не восстанавливайте неизвестные данные через `eval(pformat(...))`. Для обмена используйте формат с описанной схемой, ограничениями и безопасным парсером.

**Документация:** [gettext](https://docs.python.org/3.14/library/gettext.html), [формы множественного числа GNU gettext](https://www.gnu.org/software/gettext/manual/html_node/Plural-forms.html), [locale](https://docs.python.org/3.14/library/locale.html), [pprint](https://docs.python.org/3.14/library/pprint.html), [reprlib](https://docs.python.org/3.14/library/reprlib.html), [textwrap](https://docs.python.org/3.14/library/textwrap.html).

## Служебные типы и операторы

### types.SimpleNamespace и MappingProxyType

`SimpleNamespace` — изменяемый объект с атрибутами без заранее описанной схемы. Он удобен для небольшого адаптера или временного набора параметров, когда полноценная предметная модель ещё не нужна.

```python
from types import SimpleNamespace


settings = SimpleNamespace(host="localhost", port=8080)
assert settings.host == "localhost"

settings.debug = True
del settings.port
assert vars(settings) == {"host": "localhost", "debug": True}
assert settings == SimpleNamespace(debug=True, host="localhost")

# vars возвращает живой словарь атрибутов.
attributes = vars(settings)
attributes["host"] = "example.test"
assert settings.host == "example.test"
```

Это не mapping: у объекта нет интерфейса `settings["host"]` или `settings.get(...)`. Равенство namespace сравнивает содержимое атрибутов, но не создаёт доменный тип «настройки сервера». Объект не проверяет диапазоны, обязательные поля и неизвестные имена.

```python
# Python 3.13+: позиционный источник и copy.replace.
from copy import replace
from types import SimpleNamespace


original = SimpleNamespace({"host": "localhost", "port": 8000}, debug=False)
changed = replace(original, port=9000)
assert original.port == 8000
assert changed.port == 9000
assert changed.host == original.host
```

Для устойчивой схемы API предпочтительнее dataclass, NamedTuple или обычный класс. Случайная опечатка `settings.timout = 10` в namespace просто создаст ещё один атрибут.

**MappingProxyType предоставляет доступ без операций записи.** Он показывает исходный mapping и отражает его дальнейшие изменения. Это представление, а не копия.

```python
from types import MappingProxyType


source = {"mode": "safe", "limits": [10, 20]}
view = MappingProxyType(source)

assert view["mode"] == "safe"
source["mode"] = "fast"
assert view["mode"] == "fast"

try:
    view["mode"] = "other"
except TypeError:
    pass
else:
    raise AssertionError("Через обычный интерфейс proxy записывать нельзя")

# Вложенный список остаётся изменяемым.
view["limits"].append(30)
assert source["limits"] == [10, 20, 30]
```

Слова «только чтение» относятся к операциям самого представления. Вложенные объекты могут меняться, а другой владелец исходного словаря может записывать в него напрямую. Такой объект не является глубоко неизменяемой структурой или границей безопасности для выполнения враждебного кода.

**Снимок верхнего уровня создаётся отдельно.**

```python
from types import MappingProxyType


source = {"a": 1}
snapshot = MappingProxyType(dict(source))
source["a"] = 2
source["b"] = 3
assert dict(snapshot) == {"a": 1}

try:
    hash(snapshot)
except TypeError:
    pass
else:
    raise AssertionError("Readonly-обёртка не делает dict хэшируемым")
```

Начиная с Python 3.12 у proxy существует операция хэширования, которая опирается на лежащий под ним mapping. Обычный `dict` остаётся нехэшируемым. Наличие read-only интерфейса и возможность использовать значение ключом словаря — разные свойства.

Если значения снимка — неизменяемые числа или строки, неглубокой копии часто достаточно. Для вложенного графа решите, нужны ли копии, преобразование списков в tuple или отдельная неизменяемая модель. `deepcopy` не является универсальной заменой этому решению.

Proxy не обеспечивает согласованный снимок при конкурентных записях. Сначала организуйте владение и синхронизацию исходных данных, затем создавайте нужное представление.

### operator: функциональный доступ к операциям и атрибутам

`operator` предоставляет функции, соответствующие операциям языка, и фабрики небольших вызываемых объектов. Они удобны там, где API принимает `key`, предикат или бинарную функцию.

| Инструмент | Пример | Эквивалент по смыслу |
|---|---|---|
| `itemgetter("age")` | Получить поле mapping | `lambda item: item["age"]` |
| `itemgetter(0, 2)` | Получить несколько элементов | Возвращает tuple выбранных значений |
| `attrgetter("address.city")` | Получить вложенный атрибут | `lambda item: item.address.city` |
| `methodcaller("strip")` | Вызвать метод без аргументов | `lambda item: item.strip()` |
| `add`, `mul` | Передать операцию как функцию | `a + b`, `a * b` |
| `contains(container, value)` | Проверить вхождение | `value in container` |
| `index` | Получить точное целочисленное представление | Протокол `__index__` |
| `length_hint` | Оценить число элементов | Подсказка, а не точная длина |

```python
from dataclasses import dataclass
from operator import attrgetter, itemgetter, methodcaller


rows = [
    {"name": "b", "score": 10},
    {"name": "a", "score": 10},
    {"name": "c", "score": 5},
]
ordered = sorted(rows, key=itemgetter("score", "name"))
assert [row["name"] for row in ordered] == ["c", "a", "b"]
assert itemgetter(0, 2)(["x", "y", "z"]) == ("x", "z")
assert methodcaller("replace", "-", "_")("python-zero-to-hero") == (
    "python_zero_to_hero"
)


@dataclass
class Address:
    city: str


@dataclass
class User:
    address: Address


assert attrgetter("address.city")(User(Address("Казань"))) == "Казань"
```

Несколько полей в `itemgetter` или `attrgetter` возвращаются tuple. В сортировке такой ключ сравнивается лексикографически. Это позволяет явно задать дополнительный критерий при равенстве основного.

**Получение атрибута может выполнять код.** Property, дескриптор или `__getattr__` могут читать файл, обращаться к сети или менять состояние. `attrgetter` не делает доступ пассивным. Аналогично `methodcaller` действительно вызывает метод, поэтому результат зависит от его побочных эффектов.

Не принимайте произвольный путь атрибута или название метода из пользовательского запроса без предметного списка допустимых операций. Для HTTP-поля `sort=name` обычно нужен mapping «публичное имя → разрешённая функция ключа».

**Логические и побитовые операции различаются.** `operator.and_` соответствует `&`, а `or_` — `|`. Это не короткозамкнутые `and` и `or`. Аргументы обычной функции вычисляются до входа в неё, поэтому им нельзя напрямую заменить условие, которое должно лениво избежать второго вычисления.

```python
import operator


assert operator.contains(["a", "b"], "b")
assert operator.eq([1], [1])
assert operator.is_(None, None)
assert operator.truth([]) is False
assert operator.and_(0b1100, 0b1010) == 0b1000

original = [1]
alias = original
extended = operator.iadd(original, [2])
assert extended is original is alias
assert alias == [1, 2]

number = 10
changed = operator.iadd(number, 5)
assert number == 10
assert changed == 15
```

`iadd` выполняет операцию `__iadd__` с предусмотренными языком fallback, но не присваивает результат переменной вызывающего кода. Для списка операция изменила объект; для int вернула новое значение. Эквивалент присваивания требует `value = operator.iadd(value, other)`.

**index не равен int.** `int(3.9)` усекает дробную часть, `int("12")` разбирает строку. `operator.index` запрашивает точное целое для индекса, размера или среза. Он не должен молча округлять.

```python
import operator


class BatchSize:
    def __index__(self) -> int:
        return 4


assert operator.index(BatchSize()) == 4
assert int(3.9) == 3

try:
    operator.index(3.9)
except TypeError:
    pass
else:
    raise AssertionError("Дробный float не имеет протокола точного индекса")


class UncertainIterator:
    def __iter__(self):
        return self

    def __next__(self):
        raise StopIteration

    def __length_hint__(self) -> int:
        return 100


iterator = UncertainIterator()
assert operator.length_hint(iterator) == 100
assert list(iterator) == []
```

Оценка `length_hint` помогает предварительному выделению памяти, но не должна определять корректность алгоритма, лимит загрузки или число фактически прочитанных элементов. Если вход недоверенный, считайте реальные элементы и ограничивайте ресурсы отдельно.

```python
# Python 3.14+: готовые предикаты проверки None.
from operator import is_none, is_not_none


assert list(filter(is_not_none, [0, None, "", False, 3])) == [0, "", False, 3]
assert is_none(None)
assert not is_none(0)
```

`filter(None, values)` удалил бы все falsy-значения, включая `0`, `""` и `False`. Предикат `is_not_none` удаляет только `None`. Для Python 3.12–3.13 используйте явное условие `value is not None`.

**Документация:** [types](https://docs.python.org/3.14/library/types.html), [operator](https://docs.python.org/3.14/library/operator.html).


**Практика: анализатор задержек со средствами стандартной библиотеки**

Соберём небольшую программу, которая читает JSONL: одна строка — одно событие. У события есть путь, задержка в миллисекундах и HTTP-подобный статус. Программа строит статистический отчёт, сохраняет top-k медленных событий, последние значения и небольшую случайную выборку.

Это конечный пакетный анализ с ограничениями, а не бесконечный потоковый движок. Точные квантили потребуют хранения чисел. Проект показывает, как небольшие модули работают вместе и где заканчиваются их гарантии.

| Инструмент | Роль в программе |
|---|---|
| `tomllib`, `ChainMap` | Файл настроек, переопределения и defaults |
| `Counter` | Число событий по пути и статусу |
| `deque(maxlen=...)` | Последнее окно наблюдений |
| `array("d")` | Компактное хранение задержек |
| `heapq` | Top-k без сортировки всех объектов событий |
| `statistics`, `bisect` | Среднее, медиана, p95 и число значений выше порога |
| `Random` | Воспроизводимая резервуарная выборка |
| `hashlib`, `uuid` | Отпечаток нормализованного входа и ID отчёта |
| `MappingProxyType` | Снимки счётчиков без операций записи |
| `hmac`, `base64` | Аутентификация точных байтов отчёта отдельным ключом |

**Контракт входа и результата.**

- Вход кодируется UTF-8, каждая строка содержит ровно один JSON-объект.
- Разрешены только поля `path`, `latency_ms`, `status`; повторные ключи запрещены.
- Путь начинается с `/`, имеет не более 128 символов, не содержит управляющих символов C0 и кодируется в UTF-8. Это метка для группировки, а не полноценный валидатор URL.
- Задержка конечна, находится между 0 и 1 000 000 мс; bool и строка не считаются числом.
- Статус — целое от 100 до 599; bool не считается статусом.
- Пустой файл допустим, пустая строка внутри файла считается ошибкой.
- Для пустого набора среднее, медиана, p95 и среднее окна равны `null`. Для одного наблюдения p95 равен этому наблюдению.
- Порог медленного события включён: `latency_ms >= slow_ms`.
- При одинаковой задержке top-k предпочитает более раннюю строку.
- Ошибка любой строки отменяет весь результат; частичный отчёт не выводится.

Ограничения числа строк, категорий, окна и выборки не дают случайной настройке создать структуру без верхней границы. CLI читает строку с ограничением длины **до** JSON-парсинга. Лимит строки измеряется в символах Python, лимит конфигурации — в байтах.

Все файлы ниже положите в один каталог. Во время выполнения сторонние пакеты не нужны; pytest, mypy и Ruff используются только при разработке.

# project: stdlib_report.py
from __future__ import annotations

import argparse
import base64
import binascii
import hashlib
import heapq
import hmac
import json
import math
import platform
import sys
import tomllib
from array import array
from bisect import bisect_left
from collections import ChainMap, Counter, deque
from collections.abc import Iterable, Iterator, Mapping, Sequence
from dataclasses import dataclass
from pathlib import Path
from random import Random
from statistics import fmean, median, quantiles
from types import MappingProxyType
from typing import TextIO
from uuid import UUID, uuid5

MAX_CONFIG_BYTES = 65_536
MAX_LINE_CHARS = 65_536
MAX_LATENCY_MS = 1_000_000.0
REPORT_NAMESPACE = UUID("b0e85c0c-48ca-4623-b7dc-b06b88cd9136")


class InputError(ValueError):
    """Нарушение формата или ограничений входа."""


def require_int(value: object, name: str, lower: int, upper: int) -> int:
    if type(value) is not int or not lower <= value <= upper:
        raise InputError(f"{name}: требуется целое от {lower} до {upper}")
    return value


def require_number(value: object, name: str) -> float:
    if isinstance(value, bool) or not isinstance(value, (int, float)):
        raise InputError(f"{name}: требуется число")
    try:
        result = float(value)
    except OverflowError as error:
        raise InputError(f"{name}: слишком большое число") from error
    if not math.isfinite(result) or not 0 <= result <= MAX_LATENCY_MS:
        raise InputError(f"{name}: требуется конечное число от 0 до 1000000")
    return 0.0 if result == 0 else result


def string_mapping(value: object, name: str) -> dict[str, object]:
    if not isinstance(value, dict):
        raise InputError(f"{name}: требуется объект с полями")
    result: dict[str, object] = {}
    for key, item in value.items():
        if not isinstance(key, str):
            raise InputError(f"{name}: ключи должны быть строками")
        result[key] = item
    return result


@dataclass(frozen=True, slots=True)
class Settings:
    window_size: int = 3
    top_k: int = 2
    sample_size: int = 2
    seed: int = 7
    slow_ms: float = 100.0
    max_rows: int = 10_000
    max_categories: int = 1000

    def __post_init__(self) -> None:
        require_int(self.window_size, "window_size", 1, 100_000)
        require_int(self.top_k, "top_k", 0, 10_000)
        require_int(self.sample_size, "sample_size", 0, 10_000)
        require_int(self.seed, "seed", 0, (1 << 64) - 1)
        require_int(self.max_rows, "max_rows", 1, 1_000_000)
        require_int(self.max_categories, "max_categories", 1, 100_000)
        object.__setattr__(self, "slow_ms", require_number(self.slow_ms, "slow_ms"))

    def as_dict(self) -> dict[str, object]:
        return {
            "window_size": self.window_size,
            "top_k": self.top_k,
            "sample_size": self.sample_size,
            "seed": self.seed,
            "slow_ms": self.slow_ms,
            "max_rows": self.max_rows,
            "max_categories": self.max_categories,
        }


def load_settings(
    path: Path | None = None,
    overrides: Mapping[str, object] | None = None,
) -> Settings:
    document: dict[str, object] = {}
    if path is not None:
        with path.open("rb") as stream:
            content = stream.read(MAX_CONFIG_BYTES + 1)
        if len(content) > MAX_CONFIG_BYTES:
            raise InputError("Конфигурация превышает лимит размера")
        try:
            document = string_mapping(
                tomllib.loads(content.decode("utf-8")), "Конфигурация"
            )
        except (UnicodeError, tomllib.TOMLDecodeError) as error:
            raise InputError("Некорректная конфигурация TOML/UTF-8") from error
    if set(document) - {"report"}:
        raise InputError("Неизвестная секция конфигурации")
    section = string_mapping(document.get("report", {}), "report")
    defaults = Settings().as_dict()
    values: ChainMap[str, object] = ChainMap(
        dict(overrides) if overrides is not None else {}, section, defaults
    )
    if set(values) - set(defaults):
        raise InputError("Неизвестный параметр конфигурации")
    return Settings(
        window_size=require_int(values["window_size"], "window_size", 1, 100_000),
        top_k=require_int(values["top_k"], "top_k", 0, 10_000),
        sample_size=require_int(values["sample_size"], "sample_size", 0, 10_000),
        seed=require_int(values["seed"], "seed", 0, (1 << 64) - 1),
        slow_ms=require_number(values["slow_ms"], "slow_ms"),
        max_rows=require_int(values["max_rows"], "max_rows", 1, 1_000_000),
        max_categories=require_int(
            values["max_categories"], "max_categories", 1, 100_000
        ),
    )


@dataclass(frozen=True, slots=True)
class Observation:
    ordinal: int
    path: str
    latency_ms: float
    status: int

    def as_dict(self) -> dict[str, object]:
        return {
            "ordinal": self.ordinal,
            "path": self.path,
            "latency_ms": self.latency_ms,
            "status": self.status,
        }


def unique_object(pairs: list[tuple[str, object]]) -> dict[str, object]:
    result: dict[str, object] = {}
    for key, value in pairs:
        if key in result:
            raise InputError("Повтор ключа JSON")
        result[key] = value
    return result


def parse_observation(line: str, ordinal: int) -> Observation:
    if len(line) > MAX_LINE_CHARS:
        raise InputError(f"Строка {ordinal}: превышен лимит длины")
    try:
        raw: object = json.loads(line, object_pairs_hook=unique_object)
    except (ValueError, RecursionError) as error:
        raise InputError(f"Строка {ordinal}: некорректный JSON") from error
    data = string_mapping(raw, f"Строка {ordinal}")
    if set(data) != {"path", "latency_ms", "status"}:
        raise InputError(f"Строка {ordinal}: неверный набор полей")
    path = data["path"]
    if (
        not isinstance(path, str)
        or not path.startswith("/")
        or len(path) > 128
        or any(ord(character) < 32 for character in path)
    ):
        raise InputError(f"Строка {ordinal}: некорректный path")
    try:
        path.encode("utf-8")
    except UnicodeError as error:
        raise InputError(f"Строка {ordinal}: path не кодируется в UTF-8") from error
    latency_ms = require_number(data["latency_ms"], "latency_ms")
    status = require_int(data["status"], "status", 100, 599)
    return Observation(ordinal, path, latency_ms, status)


def bounded_lines(stream: TextIO, max_chars: int = MAX_LINE_CHARS) -> Iterator[str]:
    if max_chars <= 0:
        raise InputError("Лимит строки должен быть положительным")
    while line := stream.readline(max_chars + 1):
        if len(line) > max_chars:
            raise InputError("Строка превышает лимит длины")
        yield line


def canonical_json(value: object) -> bytes:
    return json.dumps(
        value,
        ensure_ascii=False,
        sort_keys=True,
        separators=(",", ":"),
        allow_nan=False,
    ).encode("utf-8")


@dataclass(frozen=True, slots=True)
class Report:
    settings: Settings
    count: int
    mean_ms: float | None
    median_ms: float | None
    p95_ms: float | None
    recent_mean_ms: float | None
    slow_count: int
    by_path: Mapping[str, int]
    by_status: Mapping[int, int]
    top: tuple[Observation, ...]
    sample: tuple[Observation, ...]
    input_sha256: str

    def as_dict(self) -> dict[str, object]:
        payload: dict[str, object] = {
            "algorithm": "stdlib-report/v1",
            "python": platform.python_version(),
            "settings": self.settings.as_dict(),
            "count": self.count,
            "mean_ms": self.mean_ms,
            "median_ms": self.median_ms,
            "p95_ms": self.p95_ms,
            "recent_mean_ms": self.recent_mean_ms,
            "slow_count": self.slow_count,
            "by_path": dict(self.by_path),
            "by_status": {
                str(status): count for status, count in self.by_status.items()
            },
            "top": [event.as_dict() for event in self.top],
            "sample": [event.as_dict() for event in self.sample],
            "input_sha256": self.input_sha256,
        }
        identifier = uuid5(REPORT_NAMESPACE, canonical_json(payload).decode("utf-8"))
        return {"report_id": str(identifier), **payload}


def analyze(lines: Iterable[str], settings: Settings) -> Report:
    by_path: Counter[str] = Counter()
    by_status: Counter[int] = Counter()
    recent: deque[float] = deque(maxlen=settings.window_size)
    latencies = array("d")
    top: list[tuple[float, int, Observation]] = []
    sample: list[Observation] = []
    rng = Random(settings.seed)
    digest = hashlib.sha256()
    count = 0

    for ordinal, line in enumerate(lines, 1):
        if ordinal > settings.max_rows:
            raise InputError("Превышен лимит строк")
        event = parse_observation(line, ordinal)
        if event.path not in by_path and len(by_path) >= settings.max_categories:
            raise InputError("Превышен лимит разных path")
        by_path[event.path] += 1
        by_status[event.status] += 1
        recent.append(event.latency_ms)
        latencies.append(event.latency_ms)
        digest.update(canonical_json(event.as_dict()) + b"\n")
        count = ordinal

        if settings.top_k:
            entry = (event.latency_ms, -ordinal, event)
            if len(top) < settings.top_k:
                heapq.heappush(top, entry)
            else:
                heapq.heappushpop(top, entry)

        if settings.sample_size:
            if len(sample) < settings.sample_size:
                sample.append(event)
            else:
                slot = rng.randrange(ordinal)
                if slot < settings.sample_size:
                    sample[slot] = event

    ordered = sorted(latencies)
    if not ordered:
        mean_ms = median_ms = p95_ms = None
    else:
        mean_ms = fmean(latencies)
        median_ms = float(median(ordered))
        p95_ms = (
            ordered[0]
            if count == 1
            else quantiles(ordered, n=100, method="inclusive")[94]
        )
    return Report(
        settings=settings,
        count=count,
        mean_ms=mean_ms,
        median_ms=median_ms,
        p95_ms=p95_ms,
        recent_mean_ms=fmean(recent) if recent else None,
        slow_count=count - bisect_left(ordered, settings.slow_ms),
        by_path=MappingProxyType(dict(by_path)),
        by_status=MappingProxyType(dict(by_status)),
        top=tuple(entry[2] for entry in sorted(top, reverse=True)),
        sample=tuple(sorted(sample, key=lambda event: event.ordinal)),
        input_sha256=digest.hexdigest(),
    )


def check_key(key: bytes) -> None:
    if len(key) < 32:
        raise InputError("Нужен отдельный случайный ключ длиной не меньше 32 байт")


def sign_bytes(payload: bytes, key: bytes) -> str:
    check_key(key)
    tag = hmac.digest(key, b"stdlib-report/v1\x00" + payload, "sha256")
    return base64.urlsafe_b64encode(tag).decode("ascii")


def verify_bytes(payload: bytes, signature: str, key: bytes) -> bool:
    check_key(key)
    if len(signature) != 44:
        return False
    try:
        supplied = base64.b64decode(
            signature.encode("ascii"), altchars=b"-_", validate=True
        )
    except (UnicodeError, binascii.Error):
        return False
    if len(supplied) != 32:
        return False
    if base64.urlsafe_b64encode(supplied).decode("ascii") != signature:
        return False
    expected = hmac.digest(key, b"stdlib-report/v1\x00" + payload, "sha256")
    return hmac.compare_digest(supplied, expected)

**Почему структуры выбраны именно так.**

`Settings` проверяется и при чтении файла, и при непосредственном создании. Это не позволяет обойти ограничения обычным вызовом конструктора. Значение `slow_ms` нормализуется в float; отрицательный ноль превращается в обычный ноль. Слои ChainMap существуют только во время чтения, после чего создаётся самостоятельная проверенная модель.

`Observation` и `Report` в этом проекте — внутренние модели после проверки входа. Они не являются универсальными валидирующими контейнерами для произвольного прямого конструирования. Замороженность dataclass запрещает присваивание её полей, но сама по себе не проверяет их содержимое.

В куче хранится `(latency_ms, -ordinal, event)`. Корень — худший из оставленных кандидатов: меньшая задержка, а при равенстве более поздняя строка. Уникальный ordinal не позволяет сравнению дойти до несравнимых Observation. В конце сортируются только k сохранённых событий.

Резервуарная выборка хранит не более `sample_size` событий. Для очередного события с номером n выбирается слот от 0 до n−1; если слот меньше k, он заменяется. После n наблюдений каждое имеет вероятность k/n находиться в резервуаре при n >= k. Для старого элемента это произведение вероятности попасть раньше, k/(n−1), и вероятности пережить текущий шаг, (n−1)/n.

Порядок хранения резервуара служебный; в отчёте выборка сортируется по ordinal. Независимый Random не зависит от глобального `random.seed`, но перенос точного результата между версиями всё ещё требует фиксации среды.

Счётчики копируются перед обёрткой MappingProxyType. Значения в них — неизменяемые int, поэтому в этом случае неглубокого снимка достаточно. `as_dict` также создаёт новые словари и списки: получатель JSON-представления не меняет отчёт.

**Что означает отпечаток.** `input_sha256` вычисляется от нормализованных событий, включая их порядковые номера, с разделителем новой строки. Перестановка ключей JSON, внешние пробелы и запись 10 вместо 10.0 отпечаток не меняют. Изменение порядка разных событий — меняет.

Это не контрольная сумма исходного файла. Если нужно подтвердить побайтовую идентичность файла, хэшируйте его байты отдельно. Также сериализация здесь определена для собственной модели Python, а не объявлена общим стандартом канонизации JSON.

ID UUIDv5 зависит от всего содержимого отчёта до добавления самого ID: настроек, результата, реальной выборки, версии Python и версии алгоритма. Поэтому отчёты по одному входу с разными настройками не получают ID только на основании одинакового входного checksum. UUID здесь — удобный идентификатор, не доказательство подлинности.

**Стоимость.** Пусть n — число строк, c — число разных путей, w — окно, k — размер top-k, s — резервуар. Память растёт как O(n + c + w + k + s), поскольку все задержки сохраняются для точных квантилей. Сортировка чисел требует O(n log n), обработка top-k — до O(n log(k + 1)), финальная сортировка top-k — O(k log k).

`sorted(array)` создаёт список Python-чисел; статистические функции также могут создавать внутренние копии. Компактный исходный array не означает, что весь пик памяти равен `n * itemsize`. Для значительно больших данных пересмотрите требование точного квантиля или используйте внешнюю обработку.

**Аутентификация отчёта.** CLI печатает JSON без подписи. Функции `sign_bytes` и `verify_bytes` предназначены для вызывающего кода, который уже управляет ключами. Они подписывают точные байты с префиксом назначения протокола. Произвольное переформатирование JSON после подписи меняет байты и делает проверку неуспешной.

`check_key` проверяет только длину. Он не способен доказать, что ключ действительно создан безопасным генератором, не был опубликован или не применяется в другом протоколе. В рабочем приложении получите отдельный случайный ключ из подходящего хранилища и обеспечьте его сохранение и ротацию.

**Файл `demo_signature.py`.**

<!-- project: demo_signature.py -->
```python
# project: demo_signature.py
import secrets

from stdlib_report import Settings, analyze, canonical_json, sign_bytes, verify_bytes

report = analyze(['{"path":"/api","latency_ms":15,"status":200}'], Settings())
payload = canonical_json(report.as_dict())

# Ключ только для этой демонстрации; для следующего процесса его здесь нет.
key = secrets.token_bytes(32)
signature = sign_bytes(payload, key)

assert verify_bytes(payload, signature, key)
assert not verify_bytes(payload + b" ", signature, key)
print("Исходные байты подтверждены; изменение обнаружено.")
```


Здесь ключ существует только внутри запуска, поэтому следующий запуск не сможет проверить предыдущую подпись. Это демонстрация владения ключом, а не схема его хранения. Подпись также не обеспечивает конфиденциальность и защиту от повторной передачи старого отчёта.
