# 3. Функции

Функция превращает последовательность действий в именованный контракт: какие значения она принимает, что возвращает, какие изменения делает и как сообщает об ошибках. Владение функциями означает не только знание `def` и `return`, но и понимание времени вычисления аргументов, областей видимости, ленивого выполнения, обёрток и состояния.

Эта глава продолжает [«Синтаксис и базовые конструкции»](02.%20syntax_and_basic_constructs.md). Все 16 тем и 120 пунктов сохранены в порядке README. Основные примеры рассчитаны на Python 3.12–3.14; отдельные возможности 3.13 и 3.14 помечены. Базовая версия проверки — CPython 3.14.8. Вызовы, замыкания и протоколы описываются через гарантии языка; детали CPython названы отдельно.

Короткие Python-блоки независимы и содержат проверки ожидаемого поведения. Намеренные ошибки перехватываются; невалидный синтаксис проверяется через `compile()` над заранее заданной строкой. В практической части расположен сквозной проект с функциями валидации, ленивым конвейером, внедряемыми зависимостями, декоратором и тестами.

## Основы функций

### Что такое функция? Зачем нужны

Функция — вызываемый объект, связывающий входные аргументы с выполнением тела и результатом. При этом не всякий вызываемый объект является обычной Python-функцией: классы, связанные методы, `partial` и экземпляры с `__call__` тоже могут вызываться через круглые скобки.

Функции помогают выделить правило, которое можно назвать, проверить и использовать независимо от места вызова. Полезная граница часто совпадает с одним смысловым преобразованием: разобрать дату, проверить запись, вычислить итог. Извлечение случайных пяти строк в функцию само по себе такой границы не создаёт.

```python
def net_amount(gross_minor: int, discount_minor: int) -> int:
    if gross_minor < 0 or not 0 <= discount_minor <= gross_minor:
        raise ValueError("Некорректная сумма или скидка")
    return gross_minor - discount_minor


assert net_amount(1_000, 150) == 850
```

Здесь смысл выражен в имени и единицах: сумма в минимальных денежных единицах. Контракт включает ошибку, а не только тип результата. В рабочем API дополнительно решается, допустимы ли подклассы `int`, `bool`, смешение валют и переполнение внешнего хранилища. Аннотации сами это не проверяют.

### Определение и вызов функции

Инструкция `def` создаёт объект функции и связывает его с именем, когда выполнение доходит до этой инструкции. Тело обычной функции исполняется при вызове, а не при определении. Значения по умолчанию и выражения декораторов относятся к этапу определения; аннотации имеют отдельную, зависящую от версии модель.

```python
events = []


def make_default():
    events.append("default")
    return 10


def calculate(value=make_default()):
    events.append("body")
    return value * 2


assert events == ["default"]
assert calculate() == 20
assert calculate(3) == 6
assert events == ["default", "body", "body"]
```

Каждое повторное исполнение `def`, например внутри фабрики, создаёт новую функцию. Имя функции можно перепривязать, как любое другое имя; это не изменяет ранее созданный объект, если на него остались ссылки. Функцию достаточно определить до момента фактического вызова, а не обязательно до определения всех других функций, которые на неё ссылаются.

```python
def outer():
    return helper()


def helper():
    return 42


assert outer() == 42
```

### Анатомия функции

Определение включает `def`, имя, список параметров, необязательную аннотацию результата, двоеточие и тело. Первая строка-литерал тела может быть docstring. Аннотации и defaults принадлежат объекту функции; локальные значения конкретного вызова принадлежат его выполнению.

```python
def format_user(name: str, *, active: bool = True) -> str:
    """Сформировать короткую строку статуса пользователя."""
    status = "active" if active else "inactive"
    return f"{name}: {status}"


assert format_user("Alice") == "Alice: active"
assert format_user("Alice", active=False) == "Alice: inactive"
assert format_user.__name__ == "format_user"
assert format_user.__kwdefaults__ == {"active": True}
```

У Python-функции есть код, пространство глобальных имён, значения по умолчанию, метаданные и, при необходимости, замыкание. Код функции не является всем её состоянием: две функции с одним и тем же кодом могут иметь разные захваченные значения. Функция с `yield` и `async def` меняет модель выполнения; это разобрано в соответствующих темах.

### return и возвращаемые значения

`return expression` вычисляет выражение и завершает текущий вызов. `return` без выражения и достижение конца обычной функции возвращают `None`. Можно вернуть объект любого типа, включая другую функцию, итератор и корутину.

```python
def bounds(values):
    if not values:
        return None
    return min(values), max(values)


assert bounds([]) is None
assert bounds([3, 1, 5]) == (1, 5)
minimum, maximum = bounds([3, 1, 5])
assert minimum == 1 and maximum == 5
```

«Несколько возвращаемых значений» здесь означают один кортеж. Возврат объекта не создаёт глубокую копию: возвращённый список может быть тем же объектом, который хранится внутри другого состояния.

```python
def identity(value):
    return value


items = [1]
assert identity(items) is items


def return_with_cleanup():
    value = [1]
    try:
        return value
    finally:
        value.append(2)


assert return_with_cleanup() == [1, 2]
```

Возвращаемое выражение вычисляется до `finally`, но фактический выход происходит после него. Мутация возвращаемого объекта в очистке видна снаружи; перепривязка локального имени к другому объекту уже не заменит вычисленный результат. `return` из самого `finally` способен заменить результат или скрыть исключение, поэтому не используй его для обычной очистки.

### Параметры и аргументы (базовые понятия)

Параметр объявлен в определении функции; аргумент — конкретное значение или выражение при вызове. Сначала вычисляются выражения аргументов, затем они связываются с параметрами по правилам сигнатуры. Только после успешного связывания начинается тело обычной функции.

```python
def add(left, right):
    return left + right


assert add(2, 3) == 5
assert add(left=2, right=3) == 5

try:
    add(2, left=3)
except TypeError:
    pass  # Один параметр получил значение дважды.
else:
    raise AssertionError("Некорректный вызов принят")
```

В определении `left` и `right` — параметры, `2` и `3` — аргументы вызова. «Необязательный» параметр имеет default; «допускающий `None`» параметр разрешает специальное значение. Это разные свойства: `def f(value: int | None)` всё ещё требует аргумент, а `def f(value: int = 0)` можно вызвать без него.

### Документирование функций (docstrings)

Docstring описывает публичный контракт: смысл параметров, единицы, возвращаемый результат, ограничения, побочные эффекты и ожидаемые исключения. Он хранится в `__doc__`, доступен через `help()` и извлекается инструментами документации.

```python
def average(values: list[float]) -> float:
    """Вычислить среднее непустого списка конечных измерений.

    Не изменяет входной список.
    Raises:
        ValueError: Если список пуст.
    """
    if not values:
        raise ValueError("Нельзя усреднить пустой список")
    return sum(values) / len(values)


assert average([1.0, 3.0]) == 2.0
assert "Не изменяет" in average.__doc__
```

В примере конечность чисел является предпосылкой вызывающего кода, а не выполненной внутри проверкой. Документируй это различие честно. Для финансовых и измерительных алгоритмов также указывай правила точности и округления. Аннотация `float` не сообщает о допустимости `NaN`, `inf`, единицах и масштабе.

Google-, NumPy- и reStructuredText-стили допустимы; важнее единообразие проекта и работоспособность примеров. Docstring не должен повторять каждую строку реализации. Для большого API добавь исполняемые примеры через doctest или отдельные тесты. Не храни обязательные данные только в docstring: запуск с `-OO` может его удалить.

### Типы функций: встроенные, из модулей, пользовательские

Встроенные функции доступны через `builtins`, например `len()` и `sum()`. Функции модулей получаются после импорта, например `math.isfinite()`. Пользовательские определяются через `def` или `lambda`. «Из модуля» — место получения, а не отдельный внутренний тип: модуль может экспортировать Python-функцию, встроенную функцию или вызываемый объект.

```python
import inspect
import math


def double(value):
    return value * 2


assert inspect.isfunction(double)
assert inspect.isbuiltin(len)
assert math.isfinite(3.0)
assert callable(double) and callable(len)
```

Не все вызываемые объекты поддерживают одинаковую интроспекцию. У встроенной функции может не быть `__code__`, исходного Python-текста или извлекаемой сигнатуры. При проектировании обработчика обычно нужен контракт вызываемого объекта, а не требование, чтобы он был создан именно через `def`.

### Функция vs процедура

В Python нет отдельного синтаксического вида «процедура». Так обычно называют функцию, основная цель которой — побочный эффект и которая возвращает `None`: записать файл, добавить элемент, отправить событие.

```python
def append_event(events: list[str], event: str) -> None:
    events.append(event)


events = []
result = append_event(events, "started")
assert result is None
assert events == ["started"]
```

Разделение команд и запросов помогает сделать API предсказуемым: функция `get_user()` обычно возвращает данные, а `delete_user()` выполняет изменение и сообщает о результате по документированному правилу. Не запрещено совмещать изменение и результат, но такой контракт должен быть явным. Возврат `None` сам по себе не означает неудачу.

### Функции как объекты первого класса

Функцию можно сохранить в переменной, поместить в коллекцию, передать аргументом и вернуть из другой функции. Имя функции без скобок обозначает объект; со скобками выполняется вызов и передаётся уже его результат.

```python
def double(value):
    return value * 2


operation = double
assert operation is double
assert operation(3) == 6

operations = {"double": double, "absolute": abs}
assert operations["absolute"](-5) == 5


def apply(operation, value):
    return operation(value)


assert apply(double, 4) == 8
```

Таблица обработчиков полезна для диспетчеризации, но требует политики неизвестного ключа. Передавай в неё только разрешённые вызываемые объекты: выбор функции по произвольному пользовательскому имени через `eval()` не нужен. Состояние и ошибки callback тоже являются частью контракта принимающей функции.

**Документация:** [определение функций](https://docs.python.org/3.14/reference/compound_stmts.html#function-definitions), [tutorial: функции](https://docs.python.org/3.14/tutorial/controlflow.html#defining-functions), [модель пользовательских функций](https://docs.python.org/3.14/reference/datamodel.html#user-defined-functions).

## Аргументы функций

### Позиционные аргументы

Позиционный аргумент сопоставляется параметру по порядку. Такая форма коротка и удобна для естественных операндов, но несколько однотипных значений подряд повышают риск перепутать смысл.

```python
def rectangle_area(width, height):
    return width * height


assert rectangle_area(3, 4) == 12
try:
    rectangle_area(3, 4, 5)
except TypeError:
    pass
```

Параметр `self` у связанного метода получает объект автоматически, но у обычной функции никакого особого «нулевого» аргумента нет. При ревью вызова `connect(host, port, timeout, retries)` спроси, какие настройки лучше сделать именованными, чтобы перестановка не давала правдоподобный ошибочный результат.

### Именованные (ключевые) аргументы

Ключевой аргумент связывается с параметром по имени. Порядок ключевых аргументов обычно не меняет соответствие, хотя порядок их вычисления и порядок попадания в `**kwargs` наблюдаемы.

```python
def format_range(start, stop, step=1):
    return start, stop, step


assert format_range(stop=10, start=0) == (0, 10, 1)
assert format_range(0, step=2, stop=10) == (0, 10, 2)

try:
    format_range(start=0, stop=10, unknown=True)
except TypeError:
    pass
```

Для параметров positional-or-keyword имя становится частью совместимости публичного API: переименование `timeout` в `deadline` сломает вызовы по ключу. Именованные аргументы полезны для флагов, единиц и необязательных настроек. В обычной записи вызова позиционные выражения идут до ключевых; распаковки имеют дополнительные разрешённые комбинации, разобранные ниже.

### Аргументы по умолчанию

Default вычисляется при исполнении `def` и сохраняется в объекте функции. Он не вычисляется заново при каждом вызове. Это относится к спискам, словарям, текущему времени, случайным числам и результатам загрузки конфигурации.

```python
def bad_append(value, items=[]):
    items.append(value)
    return items


first = bad_append(1)
second = bad_append(2)
assert first is second
assert second == [1, 2]
```

Обычное исправление — маркер отсутствия и создание объекта внутри вызова:

```python
def append_value(value, items=None):
    if items is None:
        items = []
    items.append(value)
    return items


assert append_value(1) == [1]
assert append_value(2) == [2]
existing = []
assert append_value(3, existing) is existing
assert existing == [3]
```

Этот вариант всё ещё меняет переданный список: default исправлен, но мутация остаётся контрактом функции. Если `None` является допустимым входом, используй отдельный `MISSING = object()` и проверку идентичности. Для времени создания записи обычно нужен `timestamp=None` с вычислением внутри, а не `timestamp=datetime.now()`.

Параметры с default должны следовать после обязательных в общей позиционной части, включая разделение через `/`. У keyword-only параметров обязательные и имеющие defaults могут стоять в другом порядке, например `def f(*, optional=1, required): ...` допустимо.

### Механизм передачи аргументов

Python передаёт объекты через связывание локальных имён с теми же объектами, которые получились при вычислении аргументов. Это называют call by sharing или передачей объектных ссылок. Обычное присваивание параметру не меняет привязку имени у вызывающего кода, а мутация общего объекта может быть видна снаружи.

```python
def rebind(items):
    items = [99]
    return items


def mutate(items):
    items.append(99)


original = [1]
assert rebind(original) == [99]
assert original == [1]
mutate(original)
assert original == [1, 99]
```

Не описывай это как «списки передаются по ссылке, числа по значению»: механизм один, различаются изменяемость и выполняемая операция. Передача большого списка не копирует автоматически все элементы. Если нужна независимость, выбери копирование нужной глубины или неизменяемый интерфейс.

```python
def independent_update(rows):
    copied = rows.copy()
    copied[0].append(2)
    return copied


original = [[1]]
result = independent_update(original)
assert result is not original
assert original == [[1, 2]]  # Вложенный объект остался общим.
```

Исключение не откатывает уже совершённую мутацию. Для атомарного изменения сначала подготовь новое состояние и проверь его, затем замени состояние в подходящей границе; внешние ресурсы требуют своей транзакционной модели.

### Произвольное число позиционных аргументов (*args)

Параметр со звёздочкой собирает оставшиеся позиционные аргументы в кортеж. Имя `args` — соглашение, смысл задаёт `*`.

```python
def sum_scaled(scale, *values):
    assert isinstance(values, tuple)
    return scale * sum(values)


assert sum_scaled(2, 1, 2, 3) == 12
assert sum_scaled(2) == 0
assert sum_scaled(2, *[1, 2]) == 6
```

`f([1, 2])` передаёт один список, а `f(*[1, 2])` — два отдельных аргумента. Упаковка в `args` не делает вложенные элементы неизменяемыми и не копирует их глубоко. После `*args` обычные параметры становятся keyword-only.

Слишком универсальная сигнатура `def process(*args): ...` скрывает контракт и ошибки вызова. Используй её для действительно переменного числа однотипных значений или обёртки, а не вместо проектирования API.

### Произвольное число именованных аргументов (**kwargs)

`**kwargs` собирает не связанные с другими параметрами ключевые аргументы в новый словарь. Ключи вызова должны быть строками. Порядок ключевых аргументов сохраняется.

```python
def collect(name, **metadata):
    return name, metadata


name, metadata = collect("load", source="api", batch=3)
assert name == "load"
assert metadata == {"source": "api", "batch": 3}
assert list(metadata) == ["source", "batch"]

source = {"batch": [1]}
_, copied = collect("load", **source)
assert copied is not source
assert copied["batch"] is source["batch"]
```

Новый словарь не означает независимых значений. Если функция принимает произвольные настройки, определись, как она обрабатывает неизвестные ключи: опечатка `timeuot` не должна молча превращаться в неиспользуемую настройку. Для публичного набора опций чаще лучше явные keyword-only параметры или типизированная структура.

### Комбинация разных типов аргументов

Полная схема сигнатуры выглядит так: positional-only, `/`, positional-or-keyword, `*args` или голая `*`, keyword-only, `**kwargs`. Каждый раздел имеет свою роль; `args` и `kwargs` не являются специальными словами.

```python
def inspect_call(source, /, mode="read", *paths, strict=False, **options):
    return source, mode, paths, strict, options


assert inspect_call("local", "write", "a", "b", strict=True, retries=2) == (
    "local",
    "write",
    ("a", "b"),
    True,
    {"retries": 2},
)
assert inspect_call("local", mode="read") == ("local", "read", (), False, {})
```

| Вид параметра | Передача | Пример роли |
| --- | --- | --- |
| До `/` | Только по позиции | Основной объект операции |
| Между `/` и `*` | По позиции или имени | Небольшое число естественных аргументов |
| `*args` | Остальные позиционные | Произвольное число элементов |
| После `*` | Только по имени | Настройки и флаги |
| `**kwargs` | Остальные ключевые | Расширения или прозрачная переадресация |

Чем универсальнее сигнатура, тем больше работы по валидации и документации. Не используй все формы в каждой функции только потому, что они доступны. Для обычного прикладного API часто достаточно нескольких явных параметров и keyword-only настроек.

### Распаковка аргументов при вызове (* и **)

В вызове `*iterable` разворачивает позиционные аргументы, `**mapping` — именованные. Допустимы несколько распаковок. Позиционный источник потребляется до входа в тело, поэтому бесконечный iterable нельзя так передать в обычный вызов.

```python
def collect(*args, **kwargs):
    return args, kwargs


assert collect(*[1, 2], *range(3, 5), **{"a": 1}, **{"b": 2}) == (
    (1, 2, 3, 4),
    {"a": 1, "b": 2},
)

try:
    collect(**{"a": 1}, **{"a": 2})
except TypeError:
    pass
else:
    raise AssertionError("Дубли ключей вызова не отклонены")

assert {**{"a": 1}, **{"a": 2}} == {"a": 2}
```

В вызове дубли ключей являются ошибкой, а в литерале словаря позднее значение заменяет раннее. При предварительном объединении `options = defaults | overrides` ты сам задаёшь политику замены, а затем передаёшь уже один mapping.

Есть тонкость порядка: звёздная распаковка может синтаксически идти после явно записанного ключевого аргумента, но её значения всё равно связываются как позиционные.

```python
def pair(left, right):
    return left, right


assert pair(right=2, *[1]) == (1, 2)
try:
    pair(left=1, *[2])
except TypeError:
    pass  # left получил и позиционный, и ключевой аргумент.
```

Это разрешённая, но не самая читаемая форма. Для вызовов с побочными эффектами в выражениях не полагайся на интуитивное «как записано»: сначала упрости вызов и сохрани промежуточные значения. Успешное связывание аргументов не гарантирует их смысловую корректность.

**Документация:** [вызовы](https://docs.python.org/3.14/reference/expressions.html#calls), [дополнительные возможности параметров](https://docs.python.org/3.14/tutorial/controlflow.html#more-on-defining-functions), [PEP 448](https://peps.python.org/pep-0448/).

<a id="special-parameters"></a>

## Специальные синтаксические конструкции

### Positional-only аргументы (разделитель /)

Параметры слева от `/` можно передать только по позиции. Синтаксис пользовательских функций доступен с Python 3.8. Он полезен, когда имя параметра — деталь реализации и не должно становиться частью публичного API.

```python
def normalize(value, /):
    return value.strip()


assert normalize(" a ") == "a"
try:
    normalize(value=" a ")
except TypeError:
    pass
```

Positional-only имя может одновременно встретиться как ключ в `**kwargs`, потому что этот ключ не связывается с позиционным параметром:

```python
def attach(name, /, **metadata):
    return name, metadata


assert attach("event", name="display") == ("event", {"name": "display"})
```

Это помогает избежать конфликтов между внутренним именем основного аргумента и внешним набором полей. Не вводи `/` только ради микроскопической экономии вызова; решение влияет прежде всего на удобство и совместимость интерфейса.

### Keyword-only аргументы (разделитель *)

Параметры после голой `*` или после `*args` принимаются только по имени. Keyword-only параметр может быть обязательным, если у него нет default.

```python
def connect(host: str, *, timeout_seconds: float, retries: int = 3):
    return host, timeout_seconds, retries


assert connect("example.test", timeout_seconds=1.5) == ("example.test", 1.5, 3)
try:
    connect("example.test", 1.5)
except TypeError:
    pass
```

Это особенно полезно для булевых флагов и однотипных настроек: `load(path, strict=True, overwrite=False)` понятнее `load(path, True, False)`. Добавление нового необязательного keyword-only параметра обычно меньше рискует нарушить позиционные вызовы, но всё равно требует проверки обёрток и наследников.

### Комбинированное использование / и *

```python
def clamp(value: float, /, lower: float, upper: float, *, inclusive: bool = True):
    if lower > upper:
        raise ValueError("Нижняя граница больше верхней")
    if not inclusive and not lower < value < upper:
        raise ValueError("Значение не внутри открытого интервала")
    return max(lower, min(value, upper))


assert clamp(20.0, lower=0.0, upper=10.0) == 10.0
assert clamp(5.0, 0.0, 10.0, inclusive=False) == 5.0
```

Основное значение здесь передаётся по позиции, границы можно назвать, настройка только именованная. Проверка `NaN` в демонстрации не входит в контракт; для внешних измерений её нужно добавить. Разделители не делают API корректным автоматически: они лишь задают допустимые формы вызова.

**Самопроверка:** для `def f(a, /, b=2, *, c, d=4): ...` объясни, какие вызовы допустимы: `f(1, c=3)`, `f(a=1, c=3)`, `f(1, 5, 3)`, `f(1, b=5, c=3)`. Затем реши, какие имена можно менять без нарушения разрешённых вызовов.

**Документация:** [специальные параметры](https://docs.python.org/3.14/tutorial/controlflow.html#special-parameters), [PEP 570](https://peps.python.org/pep-0570/), [PEP 3102](https://peps.python.org/pep-3102/).

<a id="scope"></a>

## Области видимости (Scope)

### Локальные переменные

При каждом вызове функции создаётся собственное локальное состояние. Присваивание имени внутри тела обычно делает его локальным во всей функции, если не используется `global` или `nonlocal`. Это определяется при компиляции блока, а не после фактического прохождения строки присваивания.

```python
value = 10


def broken():
    print(value)
    value = 20


try:
    broken()
except UnboundLocalError:
    pass
assert value == 10
```

Даже недостижимое присваивание может изменить классификацию имени. Параметры, цели циклов, `with ... as`, импорта и захваты pattern matching тоже связывают имена. Если локальное имя не получило значения на выбранном пути, его чтение завершится ошибкой.

`locals()` пригоден для диагностики, но не для надёжного изменения локальных переменных. С Python 3.13 его семантика в оптимизированных областях формализована как независимые снимки; в более старых версиях есть отличия поведения словаря. Присваивание `locals()['x'] = 10` не является переносимым способом задать `x`.

### Глобальные переменные

Глобальная область функции — пространство имён модуля, где функция определена. Она не становится пространством вызывающего модуля. Глобальное имя обычно ищется при вызове, поэтому поздняя перепривязка видна функции.

```python
RATE = 2


def scaled(value):
    return value * RATE


assert scaled(3) == 6
RATE = 5
assert scaled(3) == 15
assert scaled.__globals__["RATE"] == 5
```

Если модуль выполняется под именем `__main__`, его глобальные значения принадлежат этому экземпляру модуля. Изменение словаря `__globals__` способно изменить поведение функции, но для обычного API такие скрытые изменения нежелательны. Стабильную настройку лучше передать аргументом, объектом конфигурации или замыканием.

### Правило LEGB (Local, Enclosing, Global, Built-in)

Для обычного поиска имён в функциях используется порядок: локальная область, охватывающие функции, глобальная область модуля, встроенные имена. Область вызывающей функции в этот поиск не входит: Python использует лексическую, а не динамическую область видимости.

```python
label = "global"


def make_reader():
    label = "enclosing"

    def read():
        return label

    return read


reader = make_reader()


def caller():
    label = "caller"
    return reader()


assert caller() == "enclosing"
```

LEGB — полезная схема, но у классов, включений и областей аннотаций есть дополнительные правила. Например, метод не видит атрибут класса как обычное охватывающее имя: обычно нужны `self.attr`, `cls.attr` или явное имя класса. Новые generic-параметры и ленивые аннотации не стоит объяснять только четырьмя буквами LEGB.

### Ключевое слово global

`global name` указывает, что связывание и удаление данного имени в текущем блоке относится к модулю. Объявление не делает данные общими между процессами и не обеспечивает синхронизацию потоков.

```python
count = 0
events = []


def increment():
    global count
    count += 1
    events.append("incremented")  # Для мутации списка global не нужен.


increment()
assert count == 1
assert events == ["incremented"]
```

Имя объявляется `global` до его использования в соответствующем блоке. Если функции нужно вернуть новый счётчик, часто проще `return count + 1`, оставив управление состоянием вызывающему коду. Составное изменение глобального значения не становится безопасным конкурентным счётчиком из-за одной инструкции `global` или наличия GIL.

### Ключевое слово nonlocal

`nonlocal` обращается к существующей привязке в ближайшей подходящей охватывающей функции. Он не создаёт отсутствующую переменную и не выбирает глобальную область модуля.

```python
def make_counter(start=0):
    count = start

    def increment():
        nonlocal count
        count += 1
        return count

    return increment


first = make_counter(10)
second = make_counter(100)
assert first() == 11
assert first() == 12
assert second() == 101
```

Для изменения элемента захваченного списка `nonlocal` не нужен; для перепривязки самого списка нужен. Наличие `nonlocal` — хороший сигнал, что функция хранит состояние между вызовами. Такому состоянию нужны правила сброса, конкурентного доступа и срока жизни, если замыкание используется в долгоживущем сервисе.

### Глобальное состояние: зависимости, тестируемость и допустимые применения

Глобальная константа таблицы кодов, stateless logger и явно управляемый реестр могут быть уместны. Проблемы возникают, когда результат функции скрыто зависит от изменяемой конфигурации, текущей сессии, времени или соединения, которое создаётся при импорте.

```python
from collections.abc import Callable


def is_expired(deadline: float, *, now: Callable[[], float]) -> bool:
    return now() >= deadline


assert is_expired(10.0, now=lambda: 11.0)
assert not is_expired(10.0, now=lambda: 9.0)
```

Зависимость от времени стала явной и легко подменяется в тесте. Для сроков внутри процесса обычно нужна монотонная шкала, для сохранённой календарной даты — согласованный timezone-aware timestamp; взаимозаменять их нельзя.

Не передавай механически десятки зависимостей каждой функции. Выдели небольшой объект контекста или сервис, если зависимости имеют единый жизненный цикл. Важно, чтобы было понятно, откуда они приходят и кто освобождает ресурсы. Импорт модуля не должен без причины открывать сеть и запускать бесконечную работу.

### Вложенные функции

Вложенный `def` создаётся при выполнении внешней функции. Он подходит для локального помощника, callback и фабрики поведения. Это также означает, что вложенный объект создаётся заново при каждом соответствующем вызове внешней функции.

```python
def make_formatter(prefix):
    def format_value(value):
        return f"{prefix}:{value}"

    return format_value


first = make_formatter("A")
second = make_formatter("A")
assert first("x") == "A:x"
assert first is not second
assert "make_formatter.<locals>.format_value" in first.__qualname__
```

Если помощнику не нужны локальные данные и его полезно тестировать независимо, функция уровня модуля может быть проще. Вложенные функции и лямбды часто неудобны для стандартной сериализации `pickle` и запуска через multiprocessing со `spawn`: экспортируемая функция уровня модуля обычно переносимее. Захват соединений или больших таблиц тоже меняет срок жизни ресурсов.

### Замыкания (Closures)

Замыкание сохраняет доступ к свободным переменным охватывающей функции после её завершения. Python-функция хранит соответствующие ячейки в `__closure__`; сами имена перечислены в `__code__.co_freevars`.

```python
def make_multiplier(factor):
    def multiply(value):
        return value * factor

    return multiply


triple = make_multiplier(3)
assert triple(4) == 12
assert triple.__code__.co_freevars == ("factor",)
assert triple.__closure__[0].cell_contents == 3
```

Захвачена привязка к объекту, а не автоматически глубокая копия значения. Если это список, его изменения могут быть видны всем функциям, читающим ту же ячейку. Две функции, созданные одним вызовом фабрики, могут разделять состояние; функции из разных вызовов обычно получают разные ячейки.

Замыкание удерживает необходимые объекты, пока само достижимо. Если захваченный объект велик, не удивляйся его долгому времени жизни. Для небольшого скрытого состояния замыкание удобно; если нужны сложная диагностика, несколько методов, явное закрытие или сериализация, класс часто делает контракт яснее.

### Замыкания и связывание переменных

Свободная переменная читается во время вызова вложенной функции. Поэтому функции, созданные в одном цикле, могут видеть одно последнее значение переменной, а не отдельные снимки каждой итерации.

```python
bad = [lambda: index for index in range(3)]
assert [function() for function in bad] == [2, 2, 2]

fixed_defaults = [lambda index=index: index for index in range(3)]
assert [function() for function in fixed_defaults] == [0, 1, 2]


def bind(value):
    def read():
        return value

    return read


fixed_factory = [bind(index) for index in range(3)]
assert [function() for function in fixed_factory] == [0, 1, 2]
```

Default фиксирует ссылку при создании конкретной функции, но делает соответствующий параметр доступным для передачи вызывающим кодом. Фабрика создаёт отдельную область и может дать более точный интерфейс. Ещё один вариант — `functools.partial`, если нужно связать аргументы готовой функции.

Фиксация изменяемого объекта тоже не делает снимок его содержимого. Для независимого состояния копирование должно быть явным. Позднее связывание не всегда ошибка: иногда замыкание как раз должно видеть актуальную конфигурацию; зафиксируй требуемую семантику в контракте.

**Документация:** [модель выполнения и связывание имён](https://docs.python.org/3.14/reference/executionmodel.html), [global и nonlocal](https://docs.python.org/3.14/reference/simple_stmts.html), [locals](https://docs.python.org/3.14/library/functions.html#locals).

<a id="type-hints"></a>

## Аннотации типов (Type Hints)

### Что такое аннотации типов

Аннотация описывает ожидаемый тип для человека и инструмента. Она не проверяет аргумент при вызове и не преобразует его. Python допускает аннотации, не являющиеся типами; интерпретацию задаёт используемый инструмент.

```python
def identity(value: int) -> int:
    return value


assert identity(3) == 3
assert identity("text") == "text"  # Во время выполнения запрета нет.
```

Современный Python меняет время вычисления аннотаций. В версиях до 3.14 обычные аннотации функций по умолчанию вычислялись при определении; `from __future__ import annotations` включал строковое представление. В Python 3.14 стандартная модель использует отложенное вычисление. Поэтому не основывай библиотеку на предположении «любая аннотация уже готовый класс».

```python
# Python 3.14+: отложенное вычисление аннотаций.
import annotationlib

events = []


def annotation_value():
    events.append("evaluated")
    return int


def identity(value: annotation_value()) -> int:
    return value


assert events == []
annotations = annotationlib.get_annotations(identity)
assert annotations["value"] is int
assert events == ["evaluated"]
```

Разрешение аннотаций способно выполнить код. Работай с доверенными объектами, выбирай API и формат получения по задаче. `typing.get_type_hints()` полезен для разрешения типов и forward references, `inspect` — для сигнатуры, `annotationlib` в 3.14 — для управления представлением. Детальный обзор системы типизации находится в отдельном разделе справочника.

### Аннотация возвращаемого значения

`-> T` описывает результат обычного вызова функции. `-> None` означает отсутствие содержательного результата, а `Never`/`NoReturn` — что функция нормально не возвращается, например всегда возбуждает исключение.

```python
from typing import Never


def parse_count(text: str) -> int:
    return int(text)


def fail(message: str) -> Never:
    raise ValueError(message)


assert parse_count("12") == 12
try:
    fail("invalid")
except ValueError:
    pass
```

Аннотация `int | None` требует от вызывающего кода обработать отсутствие. Не используй `None` для нескольких несвязанных исходов, если потребителю нужно их различать: отсутствующая запись, неверный запрос и недоступность сети часто требуют разных вариантов результата или исключений.

Для генераторной функции аннотация обычно описывает возвращаемый итератор, а для `async def` после `->` указывается результат после `await`, не весь coroutine object. Эти две особенности разобраны далее с примерами.

### Аннотация параметров

Описывай необходимый интерфейс, а не случайный текущий тип. Если функция только перебирает элементы один раз, `Iterable[T]` часто точнее `list[T]`. Если нужны длина и индексирование — `Sequence[T]`; для чтения ключей — `Mapping[K, V]`.

```python
from collections.abc import Iterable, Mapping


def sum_positive(values: Iterable[int]) -> int:
    return sum(value for value in values if value > 0)


def get_timeout(settings: Mapping[str, int]) -> int:
    return settings.get("timeout", 30)


assert sum_positive(iter([-1, 2, 3])) == 5
assert get_timeout({"timeout": 0}) == 0
```

Тип `Iterable` не обещает повторный проход, `Sequence` не обещает неизменность самого объекта, а аннотация `Mapping` не запрещает другому владельцу менять исходный словарь. Если нужен стабильный снимок, создай его явно.

Для callback используй `Callable[[A, B], R]`, а для именованных и keyword-only параметров сложного протокола — `Protocol` с `__call__`. Простая форма `Callable` не выражает все детали сигнатуры, включая имена keyword-only параметров.

### Современный синтаксис: list[T], tuple[T, ...], dict[K, V], T | None и Any

```python
from typing import Any

names: list[str] = ["Alice", "Bob"]
point: tuple[int, int] = (10, 20)
many_numbers: tuple[int, ...] = (1, 2, 3)
scores: dict[str, int] = {"Alice": 10}
optional_score: int | None = None
unknown: object = "text"
unchecked: Any = "text"

assert len(names) == 2
assert point[0] == many_numbers[0] * 10
assert scores["Alice"] == 10
assert optional_score is None
assert isinstance(unknown, str)
assert unchecked.upper() == "TEXT"
```

`tuple[int, int]` — ровно два целых; `tuple[int, ...]` — произвольная длина. `Any` разрешает операции почти без статических ограничений, а `object` требует обоснования через сужение типа. Поэтому `object` подходит для неизвестного внешнего значения, которое нужно валидировать, а `Any` — осознанный выход из проверки.

Python 3.12 позволяет задавать generic-параметры непосредственно в определении:

```python
def first[T](values: list[T]) -> T:
    if not values:
        raise ValueError("Пустой список")
    return values[0]


assert first([1, 2]) == 1
assert first(["a", "b"]) == "a"
```

Типовая переменная связывает вход и выход, а `Any` такой связи не обеспечивает. Для поддержки старых версий и большого количества существующего кода встречается форма `TypeVar`; обе записи остаются полезными для чтения библиотек. Не смешивай произвольно правила двух стилей в одном generic-определении.

### Аннотации для *args и **kwargs

В `*args: int` аннотируется каждый отдельный позиционный элемент, поэтому локальное `args` имеет кортеж целых. В `**kwargs: str` аннотируется каждое значение словаря, а не весь mapping одним типом.

```python
def total(*values: int) -> int:
    return sum(values)


def describe(**labels: str) -> str:
    return ",".join(f"{key}={value}" for key, value in sorted(labels.items()))


assert total(1, 2, 3) == 6
assert describe(team="data", env="test") == "env=test,team=data"
```

Если ключи и типы значений известны, используй явные параметры либо `TypedDict` с `Unpack`:

```python
from typing import NotRequired, TypedDict, Unpack


class RequestOptions(TypedDict):
    timeout: float
    retries: NotRequired[int]


def request_options(**options: Unpack[RequestOptions]) -> tuple[float, int]:
    return options["timeout"], options.get("retries", 3)


assert request_options(timeout=1.5) == (1.5, 3)
```

Это статическое описание, не автоматическая валидация словаря при выполнении. Для прозрачной передачи сигнатуры обёрткой нужны `ParamSpec` и `P.args`/`P.kwargs`, а не `*args: Any, **kwargs: Any` с потерей связи между входом и исходной функцией. Полный пример находится в теме о декораторах.

### Проверка типов с mypy

Mypy анализирует код без обычного исполнения функции. Он проверяет совместимость объявленных типов и выводит часть типов сам, но не доказывает произвольные бизнес-инварианты и не заменяет runtime-проверки внешних данных.

Сохрани небольшой файл `type_example.py`:

```python
def repeat_text(text: str, count: int) -> str:
    return text * count


result: str = repeat_text("a", 3)
assert result == "aaa"
```

Запуск после установки инструмента в окружение проекта:

```bash
python -m pip install mypy
python -m mypy --strict type_example.py
```

Вызов `repeat_text(3, 'a')` может работать для этой конкретной реализации умножения, но нарушает заявленный контракт и должен быть отклонён статическим анализом. Именно контракт, а не случайный успешный пример исполнения, определяет допустимое использование API.

`--strict` включает набор усиленных проверок, состав которого зависит от версии Mypy. Зафиксируй версию инструмента в проекте и начни с проверки публичных границ и критичных модулей. `# type: ignore` должен быть узким и обоснованным; массовый `Any` способен скрыть ошибки, создав видимость полностью типизированного проекта.

### Когда использовать аннотации

В первую очередь аннотируй публичные функции, границы модулей, сложные callback, структуры данных и участки с несколькими вариантами результата. Это помогает ревью, навигации IDE и безопасному рефакторингу. Короткой локальной переменной с очевидным значением часто хватает вывода типа.

Аннотации особенно полезны, когда необходимо отличить `str` от `bytes`, `Iterable` от многократно читаемой коллекции и `None` от допустимого нуля. Однако `int` не различает миллисекунды и секунды, `str` — логин и SQL-запрос, а `float` — метры и доллары. Для смысловых различий используй имена, отдельные модели, `NewType` или собственные типы по сложности задачи.

**Самопроверка:** спроектируй сигнатуру функции, которая один раз читает измерения, применяет callback и возвращает ленивые результаты. Затем измени требование: нужен повторный обход и индексирование. Объясни, какие типы и гарантии пришлось изменить.

**Документация:** [typing](https://docs.python.org/3.14/library/typing.html), [annotationlib](https://docs.python.org/3.14/library/annotationlib.html), [Mypy](https://mypy.readthedocs.io/en/stable/), [PEP 695](https://peps.python.org/pep-0695/), [PEP 692](https://peps.python.org/pep-0692/).

## Рекурсия

### Что такое рекурсия

Рекурсия — решение задачи через вызов той же функции или группы взаимно вызывающих функций для меньшей или более простой задачи. Каждый обычный вызов имеет собственное локальное состояние. Правильная рекурсия требует не только конечного случая, но и гарантированного продвижения к нему.

```python
def count_down(value: int) -> list[int]:
    if value < 0:
        raise ValueError("Нужно неотрицательное число")
    if value == 0:
        return [0]
    return [value, *count_down(value - 1)]


assert count_down(3) == [3, 2, 1, 0]
```

Этот пример иллюстрирует управление, но многократно копирует растущий список. Для создания такой последовательности `list(range(...))` проще и эффективнее. Рекурсивная форма особенно естественна для деревьев, вложенных выражений и разбиения задачи; она не является самостоятельной оптимизацией.

### Базовый случай и рекурсивный случай

Базовый случай возвращает результат без нового рекурсивного вызова. Рекурсивный случай должен уменьшать меру сложности: оставшуюся глубину, длину участка или число необработанных узлов. Для произвольного графа одной глубины недостаточно — могут потребоваться обнаружение циклов и множество посещённых вершин.

```python
def sum_nested(value: int | list) -> int:
    if type(value) is int:
        return value
    if isinstance(value, list):
        return sum(sum_nested(item) for item in value)
    raise TypeError("Разрешены целые числа и вложенные списки")


assert sum_nested([1, [2, 3], [], [4, [5]]]) == 15
```

Контракт этого примера — конечное дерево без циклических ссылок. `data=[]; data.append(data)` нарушит его и приведёт к неограниченной рекурсии до защитного отказа. Наличие проверки пустого списка не спасает от цикла в графе. Если вход внешний, предел глубины и политика циклов должны быть заданы явно.

### Примеры: факториал, числа Фибоначчи

```python
def factorial(number: int) -> int:
    if type(number) is not int:
        raise TypeError("Ожидается int без bool")
    if number < 0:
        raise ValueError("Факториал определён для неотрицательных целых")
    if number < 2:
        return 1
    return number * factorial(number - 1)


assert factorial(0) == 1
assert factorial(5) == 120
```

Для рабочего кода обычно подходит `math.factorial()`. Умножение больших целых не имеет константной стоимости, поэтому оценка «n вызовов» не описывает всю цену вычисления больших факториалов.

Наивный Фибоначчи повторно вычисляет одни и те же подзадачи и имеет экспоненциальный рост числа вызовов:

```python
from functools import cache


@cache
def fibonacci(number: int) -> int:
    if type(number) is not int or number < 0:
        raise ValueError("Нужен неотрицательный int")
    if number < 2:
        return number
    return fibonacci(number - 1) + fibonacci(number - 2)


assert fibonacci(10) == 55
assert fibonacci(20) == 6765
assert fibonacci.cache_info().hits > 0
fibonacci.cache_clear()
```

Мемоизация устраняет повторные подзадачи, но сохраняет результаты в памяти и не отменяет глубину стека. Итеративная версия хранит только два последних числа и не расходует стек пропорционально номеру:

```python
def fibonacci_iterative(number: int) -> int:
    if type(number) is not int or number < 0:
        raise ValueError("Нужен неотрицательный int")
    previous, current = 0, 1
    for _ in range(number):
        previous, current = current, previous + current
    return previous


assert fibonacci_iterative(20) == 6765
```

### Глубина рекурсии и ограничения

CPython ограничивает глубину рекурсии, чтобы обнаружить опасное разрастание вложенных вызовов. Текущее значение доступно через `sys.getrecursionlimit()`. Фактическое число допустимых дополнительных вызовов зависит от уже занятого стека, обёрток и реализации, поэтому оно не обязано совпадать с этим числом.

```python
import sys


def never_finishes():
    return never_finishes()


assert sys.getrecursionlimit() > 0
try:
    never_finishes()
except RecursionError:
    pass
else:
    raise AssertionError("Ожидалось ограничение рекурсии")
```

Простое увеличение `sys.setrecursionlimit()` не исправляет ошибочный алгоритм и может быть опасным для ресурсов. Внутреннее устройство кадров и взаимодействие с C-стеком менялось между версиями CPython; переносимого обещания «каждая рекурсия занимает столько-то байтов C-стека» нет. Для глубоко вложенных внешних данных чаще нужен явный стек и ограничение глубины.

### Хвостовая рекурсия и отсутствие гарантированной tail-call оптимизации

Хвостовой вызов — последний результативный шаг функции, после которого не требуется продолжать её вычисления. В CPython такая форма не превращается автоматически в цикл и всё равно накапливает рекурсивные вызовы.

```python
def factorial_tail(number: int, accumulator: int = 1) -> int:
    if number < 0:
        raise ValueError("Нужно неотрицательное число")
    if number == 0:
        return accumulator
    return factorial_tail(number - 1, accumulator * number)


assert factorial_tail(5) == 120
```

Не рассчитывай на tail-call optimization как гарантию Python. Если глубина зависит от размера входа, перепиши на цикл или используй явный стек. Декоратор-мемоизация уменьшает повторение вычислений, но не делает хвостовую рекурсию безопасной для любого размера.

### Рекурсия vs циклы

| Критерий | Рекурсия | Цикл с явным состоянием |
| --- | --- | --- |
| Деревья и вложенные выражения | Часто близка к форме данных | Нужен собственный стек |
| Линейная последовательность | Может создавать лишние вызовы | Обычно проще и экономнее |
| Контроль очень большой глубины | Ограничен стеком исполнения | Можно явно ограничивать буфер |
| Отладка | Видна цепочка вызовов | Видны состояние и очередь работы |
| Циклы в графе | Нужно обнаруживать отдельно | Тоже нужно обнаруживать отдельно |

```python
def flatten_integers(tree):
    missing = object()
    stack = [iter([tree])]
    result = []
    while stack:
        item = next(stack[-1], missing)
        if item is missing:
            stack.pop()
        elif type(item) is int:
            result.append(item)
        elif isinstance(item, list):
            stack.append(iter(item))
        else:
            raise TypeError("Разрешены целые числа и списки")
    return result


assert flatten_integers([1, [2, [3]], 4]) == [1, 2, 3, 4]
```

Отдельный объект-маркер отличает исчерпание от любого входного значения. Если вместо него использовать `None`, неверный элемент `None` можно случайно принять за конец вложенного списка и потерять оставшиеся значения. Явный стек тоже занимает память и сам по себе не защищает от бесконечного графа.

**Документация:** [ограничение рекурсии](https://docs.python.org/3.14/library/sys.html#sys.getrecursionlimit), [math.factorial](https://docs.python.org/3.14/library/math.html#math.factorial), [functools.cache](https://docs.python.org/3.14/library/functools.html#functools.cache).

## Лямбда-функции

### Синтаксис лямбда-функций

`lambda parameters: expression` создаёт функцию, возвращающую значение одного выражения. Отдельного `return` нет. Лямбда поддерживает правила аргументов, defaults, `*args` и keyword-only параметры, но не отдельный синтаксис аннотаций параметров и результата.

```python
double = lambda value: value * 2
assert double(3) == 6
assert double.__name__ == "<lambda>"

formatter = lambda value, *, prefix="item": f"{prefix}:{value}"
assert formatter(3, prefix="row") == "row:3"
```

Присваивание лямбды имени здесь показывает семантику. Для постоянной именованной операции обычно понятнее `def`: появятся осмысленное имя в traceback, docstring и удобные аннотации. Лямбда не имеет специальной ускоренной модели вызова.

### Ограничения лямбд

Тело содержит одно выражение, поэтому в нём нельзя написать обычные `return`, `try`, `for`-инструкцию или блок присваиваний. При этом одно выражение может выполнять сколько угодно побочных эффектов через вызовы: синтаксическая краткость не гарантирует простоту или чистоту.

```python
try:
    compile("lambda x: return x", "<lambda>", "eval")
except SyntaxError:
    pass

events = []
callback = lambda value: events.append(value)
assert callback("called") is None
assert events == ["called"]
```

Не обходи ограничение списком вызовов, вложенными условными выражениями и генератором, используемым ради исключения. Если нужны несколько действий, обработка ошибок или важная документация, используй `def`.

### Когда использовать лямбды

Лямбда подходит для короткого локального callback, смысл которого понятен рядом с местом использования: ключ сортировки, простой предикат, преобразование поля. Для повторяемого бизнес-правила дай функции имя.

```python
rows = [{"age": 30}, {"age": 20}]
assert sorted(rows, key=lambda row: row["age"])[0]["age"] == 20
assert list(filter(lambda value: value > 0, [-1, 2, 3])) == [2, 3]
```

Если существует готовая функция, передай её напрямую: `key=len`, `map(str, values)`. Не создавай `lambda x: len(x)` без дополнительного смысла. При захвате переменных помни о позднем связывании, особенно при регистрации callback в цикле.

### Лямбды с условиями

```python
category = lambda value: "positive" if value > 0 else "non-positive"
assert category(2) == "positive"
assert category(0) == "non-positive"
```

Внутри находится условное выражение, которое вычисляет только выбранную ветвь. Для трёх и более сложных вариантов обычная функция с `if/elif` обычно яснее. Лямбда не является подходящим местом, чтобы спрятать полноценную валидацию диапазонов, преобразование типов и сообщения об ошибках.

### Лямбды в сортировке

```python
users = [
    {"name": "Bob", "score": 10},
    {"name": "Alice", "score": 20},
    {"name": "Ann", "score": 10},
]
ordered = sorted(users, key=lambda user: (-user["score"], user["name"].casefold()))
assert [user["name"] for user in ordered] == ["Alice", "Ann", "Bob"]
```

Ключ вычисляется для каждого элемента и затем участвует в сравнении. Он должен возвращать согласованно сравнимые значения. Для простого извлечения поля подходят `operator.itemgetter` и `attrgetter`; для `None`, `NaN` и нескольких направлений сравнения полезнее именованная функция с явным контрактом, как в предыдущей главе.

### Лямбда vs обычная функция

| Свойство | `lambda` | `def` |
| --- | --- | --- |
| Тело | Одно выражение | Несколько инструкций |
| Имя в метаданных | Обычно `<lambda>` | Имя определения |
| Docstring | Не объявляется обычным способом | Поддерживается |
| Аннотации в определении | Нет | Да |
| Замыкание и defaults | Да | Да |
| Типичная роль | Короткий callback рядом с вызовом | Именованный контракт |

Обе формы создают обычные Python-функции и подчиняются одной модели областей видимости. Замена `def` на `lambda` обычно не является оптимизацией. Выбирай так, чтобы вызывающий код и traceback объясняли действие без расшифровки длинного выражения.

**Документация:** [lambda expressions](https://docs.python.org/3.14/reference/expressions.html#lambdas), [tutorial: lambda](https://docs.python.org/3.14/tutorial/controlflow.html#lambda-expressions).

## Функции высшего порядка

### Что такое функция высшего порядка

Функция высшего порядка принимает функцию как аргумент или возвращает функцию. Это основа callback, стратегий, фабрик поведения, декораторов и функциональных конвейеров. Передаваемая операция должна иметь понятный контракт входа, выхода и ошибок.

```python
from collections.abc import Callable, Iterable


def transform[T, R](values: Iterable[T], operation: Callable[[T], R]) -> list[R]:
    return [operation(value) for value in values]


assert transform([1, 2, 3], str) == ["1", "2", "3"]
assert transform([1, 2], lambda value: value * 10) == [10, 20]
```

Передача функции делает зависимость явной и позволяет менять алгоритм без условной цепочки по строковому режиму. Но произвольный callback может изменить данные, возбудить исключение или обратиться к сети; принимающий API не должен предполагать чистоту, если она не указана в договорённости.

### map(): применение функции к последовательности

`map(function, iterable, ...)` возвращает ленивый итератор результатов. Функция получает по одному элементу каждого входа. По умолчанию несколько источников заканчиваются на самом коротком.

```python
calls = []


def double(value):
    calls.append(value)
    return value * 2


mapped = map(double, [1, 2, 3])
assert calls == []
assert next(mapped) == 2
assert calls == [1]
assert list(mapped) == [4, 6]
assert list(mapped) == []
assert list(map(pow, [2, 3], [3, 2])) == [8, 9]
```

Ошибка callback произойдёт при чтении соответствующего результата, а не обязательно при создании `map`. Итератор расходуется; повторный обход не повторяет преобразование с начала. При работе с бесконечным входом потребитель обязан иметь условие остановки.

```python
# Python 3.14+: контроль длины входов map.
mapped = map(lambda left, right: left + right, [1, 2], [10], strict=True)
assert next(mapped) == 11
try:
    next(mapped)
except ValueError:
    pass
else:
    raise AssertionError("Различие длины не обнаружено")
```

Как и у `zip(strict=True)`, проверка происходит постепенно и не откатывает уже выполненные callback. Если нельзя иметь частично совершённые побочные эффекты, нужен другой уровень организации обработки.

### filter(): фильтрация последовательности

`filter(predicate, iterable)` лениво возвращает исходные элементы, для которых предикат истинен. Он не возвращает результаты предиката. При `predicate=None` сохраняются все истинные элементы.

```python
values = [-1, 0, 2, 3]
assert list(filter(lambda value: value > 0, values)) == [2, 3]
assert list(filter(None, [None, 0, False, "", 2, "a"])) == [2, "a"]
assert list(filter(lambda value: value is not None, [None, 0, False])) == [0, False]
```

Последние две формы различаются. Если ноль и пустая строка — корректные данные, `filter(None, ...)` их потеряет. Предикат, возбудивший исключение, прерывает текущее чтение; `filter` не превращает его автоматически в «элемент не подходит».

### sorted() и параметр key

`sorted()` — функция высшего порядка, потому что принимает функцию ключа. Ключ описывает критерий сравнения, а не попарный компаратор. Для нескольких полей можно вернуть кортеж; для дорогого критерия важно, что ключ вычисляется один раз на элемент при успешной сортировке.

```python
words = ["bbb", "a", "cc"]
assert sorted(words, key=len) == ["a", "cc", "bbb"]


def descending_score(row):
    return -row["score"], row["id"]


rows = [{"id": 2, "score": 10}, {"id": 1, "score": 10}]
assert sorted(rows, key=descending_score)[0]["id"] == 1
```

Сортировка материализует весь конечный вход и не является потоковой только потому, что получила генератор. Для top-k большого потока смотри `heapq.nsmallest`/`nlargest`, если такой алгоритм соответствует задаче. Стабильность и пропущенные значения подробно разобраны в предыдущей главе.

### reduce() из functools

`reduce()` последовательно объединяет элементы с накопителем. Функция принимает два аргумента: текущий накопитель и очередной элемент. Это левая свёртка, порядок которой важен для неассоциативных операций и округления.

```python
from functools import reduce
from operator import mul, sub

assert reduce(mul, [2, 3, 4], 1) == 24
assert reduce(sub, [10, 3, 1]) == 6  # (10 - 3) - 1
assert reduce(mul, [], 1) == 1
```

Без начального значения первый элемент становится накопителем, а пустой источник вызывает `TypeError`. Для сложения, проверки условий и минимума предпочитай `sum`, `any`, `all`, `min`: они понятнее и могут иметь специализированное поведение. Для всех промежуточных накопленных результатов есть `itertools.accumulate()`.

### zip() и map вместе

Несколько потоков можно объединить по позиции и затем преобразовать пары. Важны длины, момент потребления и форма аргументов callback.

```python
from itertools import starmap

quantities = [2, 3]
prices_minor = [100, 250]

totals = (
    quantity * price for quantity, price in zip(quantities, prices_minor, strict=True)
)
assert list(totals) == [200, 750]

assert list(starmap(pow, [(2, 3), (3, 2)])) == [8, 9]
assert list(
    map(lambda pair: pair[0] + pair[1], zip([1, 2], [10, 20], strict=True))
) == [11, 22]
```

`map(f, zip(...))` передаёт функции один кортеж, `map(f, source_a, source_b)` — два отдельных аргумента. `starmap()` распаковывает каждый элемент-кортеж в вызов функции. Не выбирай более сложную комбинацию, если простое генераторное выражение прямо описывает формулу.

### map/filter vs list comprehensions

| Запись | Результат | Когда удобна |
| --- | --- | --- |
| `map(f, values)` | Ленивый итератор | Уже есть подходящая функция |
| `filter(p, values)` | Ленивый итератор исходных элементов | Уже есть предикат |
| `[f(x) for x in values if p(x)]` | Готовый список | Простой локальный фильтр и преобразование |
| `(f(x) for x in values if p(x))` | Генератор | Однократная ленивая обработка |
| Обычный `for` | Определяется телом | Несколько действий, обработка ошибок и учёт состояния |

`map` не гарантированно быстрее включения, а включение не гарантированно быстрее подходящей встроенной операции. Зависит от callback, версии, данных и потребителя. Сначала обеспечь корректность и понятную модель памяти, потом измеряй.

**Самопроверка:** построй конвейер «удалить внешние пробелы → исключить пустые значения → нормализовать регистр». Объясни, в какой момент выполняется каждая операция, что произойдёт при втором обходе и где хранится результат.

**Документация:** [встроенные map/filter/zip/sorted](https://docs.python.org/3.14/library/functions.html), [functools.reduce](https://docs.python.org/3.14/library/functools.html#functools.reduce), [itertools.starmap](https://docs.python.org/3.14/library/itertools.html#itertools.starmap).

## Модуль functools

### functools.partial — частичное применение функций

`partial()` связывает часть аргументов готовой функции и возвращает вызываемый объект. Новые позиционные аргументы добавляются после сохранённых, новые ключевые могут заменить сохранённые ключевые значения. Исходная функция не выполняется до вызова полученного объекта.

```python
from functools import partial


def format_number(value: int, *, prefix: str, width: int = 3) -> str:
    return f"{prefix}{value:0{width}d}"


format_user_id = partial(format_number, prefix="U-")
assert format_user_id(7) == "U-007"
assert format_user_id(7, width=5) == "U-00007"
assert format_user_id(7, prefix="X-") == "X-007"
assert format_user_id.func is format_number
assert format_user_id.keywords == {"prefix": "U-"}
```

Следовательно, `partial` не запрещает вызывающему коду менять заранее указанный keyword. Если значение должно быть обязательной политикой, создай обёртку с нужной сигнатурой и валидацией. Сохранённые аргументы удерживаются по ссылке: изменяемая конфигурация может изменить поведение будущих вызовов.

В Python 3.14 появился `Placeholder`, позволяющий оставить незаполненной позицию внутри набора аргументов, а не только дописывать аргументы справа.

```python
# Python 3.14+: Placeholder в partial.
from functools import Placeholder, partial

replace_dashes = partial(str.replace, Placeholder, "-", "_")
assert replace_dashes("a-b-c") == "a_b_c"

surround = partial(
    lambda left, value, right: f"{left}{value}{right}", "[", Placeholder, "]"
)
assert surround("x") == "[x]"
```

Все оставленные позиции нужно заполнить при вызове; `Placeholder` нельзя передавать как keyword в `partial`. Частичное применение отличается от каррирования: `partial` просто фиксирует часть одного вызова, а каррирование обычно превращает многоместную функцию в цепочку одноаргументных.

### functools.partialmethod — частичное применение методов

`partialmethod` предназначен для определения метода класса и корректного связывания экземпляра. Обычный `partial` в теле класса не является полной заменой этому descriptor-поведению.

```python
from functools import partialmethod


class Worker:
    def __init__(self):
        self.enabled = False

    def set_enabled(self, value: bool):
        self.enabled = value

    enable = partialmethod(set_enabled, True)
    disable = partialmethod(set_enabled, False)


worker = Worker()
worker.enable()
assert worker.enabled is True
worker.disable()
assert worker.enabled is False
```

`worker.enable()` по смыслу вызывает `worker.set_enabled(True)`. Для уже связанного метода экземпляра обычный `partial(worker.method, ...)` может быть вполне подходящим callback. Выбирай `partialmethod`, когда создаёшь именно атрибут-метод на уровне класса; глубокий механизм дескрипторов разбирается в главе об объектной модели и ООП.

### functools.lru_cache — кэширование результатов

`lru_cache(maxsize=N)` хранит результаты по ключам вызова и вытесняет наименее недавно использованные записи при переполнении. Аргументы должны подходить для хеширования. `cache_info()` показывает попадания, промахи и размер, `cache_clear()` очищает состояние.

```python
from functools import lru_cache

calls = []


@lru_cache(maxsize=2)
def square(value: int) -> int:
    calls.append(value)
    return value**2


assert square(2) == 4
assert square(2) == 4
assert calls == [2]
assert square.cache_info().hits == 1
square(3)
square(4)
assert square.cache_info().currsize == 2
square(2)  # Запись 2 была вытеснена.
assert calls == [2, 3, 4, 2]
square.cache_clear()
assert square.cache_info().currsize == 0
```

Кэш подходит для детерминированного вычисления с относительно дорогим повторным результатом. Если функция зависит от времени, пользователя, внешнего файла или скрытой глобальной настройки, это должно отражаться в ключе либо в политике инвалидирования. Не добавляй кэш просто потому, что функция вызывается часто.

`maxsize=None` и `functools.cache` дают неограниченный кэш; `maxsize=0` фактически отключает хранение. Значение N ограничивает число записей, а не число байтов. Один результат может удерживать очень большой граф объектов.

### Продвинутое кэширование функций и методов

**Эквивалентность вызовов.** Разные формы одного смыслового вызова могут создавать разные ключи. `f(1)`, `f(1, 2)` и `f(a=1, b=2)` не обязаны делить запись, даже если default `b=2` делает результат одинаковым.

```python
from functools import lru_cache


@lru_cache(maxsize=16)
def add(a, b=2):
    return a + b


assert add(1) == add(1, 2) == add(a=1, b=2) == 3
assert add.cache_info().misses == 3


@lru_cache(maxsize=16, typed=True)
def type_name(value):
    return type(value).__name__


assert type_name(1) == "int"
assert type_name(1.0) == "float"
assert type_name(True) == "bool"
```

`typed=True` различает непосредственные типы аргументов, но не является рекурсивной типизацией всего содержимого контейнера. При `typed=False` не строй универсального предположения, какие равные значения обязательно разделят запись: существуют детали построения ключа и оптимизации отдельных типов.

Для канонизации сложного вызова можно сначала связать его с сигнатурой через `inspect.signature(...).bind()`, применить defaults и сформировать собственный ключ. Однако это не универсальная формула: важны хешируемость, порядок keyword-данных, стоимость ключа и смысл эквивалентности. Превращение произвольного `dict` в строку не даёт автоматически корректный канонический ключ.

**Владение результатом.** Кэш возвращает сохранённый объект, а не новую копию.

```python
from functools import lru_cache


@lru_cache(maxsize=4)
def bad_default_roles(user_id):
    return ["reader"]


first = bad_default_roles(1)
first.append("admin")
assert bad_default_roles(1) == ["reader", "admin"]
```

Для переиспользуемых результатов обычно лучше неизменяемая форма, например кортеж. Если нужен изменяемый результат, возвращай копию на границе и документируй её глубину.

**Конкурентный доступ.** Внутренняя структура стандартного кэша защищена от повреждения при многопоточном доступе, но два параллельных промаха могут вычислить один ключ несколько раз. Это не single-flight и не гарантия «функция выполнится ровно один раз». Если результатом является внешняя запись, одной мемоизации недостаточно.

**Методы.** У кэшированного метода `self` участвует в ключе. Кэш, находящийся на функции класса, может удерживать экземпляры и делить общий лимит между ними. Если поля экземпляра, влияющие на результат, меняются, ключ `self` может остаться тем же и результат устареет. Варианты: неизменяемое состояние, версия в ключе, явный сброс, per-instance кэш с понятным сроком жизни.

**Свойства.** `cached_property` вычисляет значение при доступе и обычно сохраняет его в `__dict__` экземпляра. Это не кэш с лимитом или TTL. Удаление атрибута позволяет пересчитать его. Он требует подходящего хранилища атрибутов и не подходит автоматически каждому `__slots__`-классу. Начиная с 3.12 встроенная прежняя блокировка удалена; для однократного вычисления при конкурентном доступе нужна собственная синхронизация.

**Ошибки и жизненный цикл.** Обычное возбуждённое исключение не сохраняется как успешный результат `lru_cache`. Генератор и coroutine object обычно нельзя безопасно кэшировать как готовый результат: это одноразовые состояния. Для async нужен кэш результатов с отдельной моделью task, отмены и конкурентных запросов, а не просто `@lru_cache` над `async def`.

TTL, отрицательное кэширование, массовые одновременные промахи, инвалидирование при обновлении данных и наблюдаемость требуют отдельного проектирования. Контролируй hit rate, размер и стоимость удерживаемых значений. Кэш повышает скорость ценой памяти и потенциальной устарелости, а не бесплатно.

### functools.wraps для декораторов

`wraps(original)` переносит основные метаданные на функцию-обёртку и устанавливает `__wrapped__`. Это помогает документации, introspection и инструментам следовать к исходной функции.

```python
import inspect
from functools import wraps


def passthrough(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        return function(*args, **kwargs)

    return wrapper


@passthrough
def add(left: int, right: int = 1) -> int:
    """Сложить два числа."""
    return left + right


assert add(2, 3) == 5
assert add.__name__ == "add"
assert add.__doc__ == "Сложить два числа."
assert inspect.unwrap(add) is add.__wrapped__
assert list(inspect.signature(add).parameters) == ["left", "right"]
```

`wraps` не меняет реальное тело wrapper и не делает его физическую сигнатуру идентичной исходной. `inspect.signature` обычно следует по `__wrapped__`; с `follow_wrapped=False` можно увидеть параметры обёртки. Он также не гарантирует правильный тип, await-поведение, закрытие генератора и сохранение дополнительных API вроде `cache_info` у любого стека обёрток.

### functools.reduce — свертка последовательности

Начальное значение определяет поведение пустого входа и тип первого накопителя. Оно не обязано совпадать с типом элементов, если функция свёртки поддерживает такой контракт.

```python
from functools import reduce

rows = [("A", 10), ("B", 20), ("A", 5)]


def add_to_totals(totals, row):
    key, amount = row
    totals[key] = totals.get(key, 0) + amount
    return totals


assert reduce(add_to_totals, rows, {}) == {"A": 15, "B": 20}
```

В этой форме свёртка мутирует накопитель; это не делает алгоритм чистым. Обычный цикл с теми же действиями может быть проще. Не используй `reduce` с многократным копированием растущего списка или словаря, если можно накапливать данные линейно.

```python
# Python 3.14+: initial как именованный аргумент reduce.
from functools import reduce
from operator import add

assert reduce(add, [1, 2, 3], initial=10) == 16
```

На Python 3.12–3.13 начальное значение передавай третьим позиционным аргументом. Для промежуточных сумм подходит `accumulate`, для итоговой суммы — `sum`; не скрывай простую задачу универсальной свёрткой.

### functools.singledispatch — обобщенные функции

`singledispatch` выбирает реализацию по runtime-типу первого аргумента с учётом правил наследования и зарегистрированных абстракций. Это одиночная диспетчеризация, не выбор по всем аргументам и не статическая перегрузка.

```python
from functools import singledispatch


@singledispatch
def render(value):
    raise TypeError(f"Нет обработчика для {type(value).__name__}")


@render.register(int)
def render_int(value):
    return f"integer:{value}"


@render.register(str)
def render_str(value):
    return f"text:{value}"


assert render(3) == "integer:3"
assert render("a") == "text:a"
assert render(True) == "integer:True"
assert render.dispatch(int) is render_int
```

`bool` попал в обработчик `int`, потому что является его подклассом; при необходимости зарегистрируй `bool` отдельно. Параметр диспетчеризации передаётся позиционно. Дополнительные параметры не участвуют в выборе реализации.

Регистрация по `list` различает тип контейнера, но не `list[int]` и `list[str]`: параметризация не является отдельным runtime-классом. Аннотации могут помочь регистрации поддерживаемого типа, однако они не превращают диспетчер в валидатор содержимого. Выбор между несколькими виртуальными ABC может оказаться неоднозначным; не создавай пересекающиеся регистрации без понятной политики.

### functools.singledispatchmethod — обобщённые методы

`singledispatchmethod` переносит одиночную диспетчеризацию на методы: выбирается тип первого аргумента после `self` или `cls`.

```python
from functools import singledispatchmethod


class Renderer:
    @singledispatchmethod
    def render(self, value):
        raise TypeError("Неподдерживаемый тип")

    @render.register
    def render_integer(self, value: int):
        return f"int:{value}"

    @render.register
    def render_text(self, value: str):
        return f"str:{value}"


renderer = Renderer()
assert renderer.render(7) == "int:7"
assert renderer.render("a") == "str:a"
```

При сочетании с `classmethod` и другими декораторами учитывай их порядок; для доступности `.register` `singledispatchmethod` должен быть внешним в поддерживаемой комбинации. Это инструмент расширяемого поведения по типу входа, а не обязательная замена обычному методу, `match` или полиморфизму самих объектов.

**Самопроверка:** выбери, где нужен `partial`, где `partialmethod`, где `lru_cache`, а где явный объект состояния. Объясни, кто удерживает `self` у кэшированного метода и как изменится результат после изменения поля экземпляра.

**Документация:** [functools](https://docs.python.org/3.14/library/functools.html), [PEP 443: single dispatch](https://peps.python.org/pep-0443/), [cached_property](https://docs.python.org/3.14/library/functools.html#functools.cached_property).

## Декораторы

### Что такое декоратор

Декоратор получает определяемый объект и возвращает объект, который будет связан с его именем. Часто результатом является функция-обёртка, однако декоратор может зарегистрировать исходную функцию и вернуть её без изменения или заменить её другим вызываемым объектом.

```python
registry = {}


def register(function):
    registry[function.__name__] = function
    return function


@register
def handle_event(value):
    return value * 2


assert registry["handle_event"] is handle_event
assert handle_event(3) == 6
```

Декорирование происходит при исполнении определения, часто во время импорта модуля. Поэтому создание соединения, чтение файлов и изменение общего реестра внутри декоратора являются побочными эффектами импорта. Отделяй регистрацию статического API от запуска внешней работы.

### Простые декораторы (без аргументов)

Простой декоратор принимает функцию непосредственно. Обёртка должна передать аргументы, вернуть результат и сохранить нужную модель ошибок.

```python
from functools import wraps

events = []


def observed(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        events.append("before")
        try:
            return function(*args, **kwargs)
        finally:
            events.append("after")

    return wrapper


@observed
def divide(left, right):
    return left / right


assert divide(6, 2) == 3
try:
    divide(1, 0)
except ZeroDivisionError:
    pass
assert events == ["before", "after", "before", "after"]
```

`finally` обеспечивает наблюдение обоих исходов, но его собственная ошибка может заменить исходную. Если телеметрия обязана быть best effort, задай узкую политику её отказа отдельно. Нельзя автоматически считать произвольный callback логирования безошибочным.

### Синтаксический сахар @

Форма `@decorate` над определением примерно соответствует `function = decorate(function)` после создания функции. Для нескольких декораторов выражения вычисляются сверху вниз, а полученные декораторы применяются снизу вверх.

```python
events = []


def decorate(label):
    events.append(f"evaluate:{label}")

    def apply(function):
        events.append(f"apply:{label}")
        return function

    return apply


@decorate("outer")
@decorate("inner")
def operation():
    return 42


assert events == ["evaluate:outer", "evaluate:inner", "apply:inner", "apply:outer"]
assert operation() == 42
```

Это объясняет, почему действия при создании декоратора и при выполнении обёртки происходят в разные моменты. Если декоратор возвращает невызываемый объект, имя всё равно получит этот объект; синтаксис сам не гарантирует дальнейшую вызываемость.

### Декораторы с аргументами

Фабрика декораторов принимает настройки и возвращает сам декоратор. Получаются три уровня: конфигурация, применение к функции, выполнение вызова.

```python
from functools import wraps


def require_positive(*, parameter):
    if not isinstance(parameter, str) or not parameter:
        raise ValueError("Нужно имя параметра")

    def decorate(function):
        import inspect

        signature = inspect.signature(function)
        if parameter not in signature.parameters:
            raise ValueError("В сигнатуре нет указанного параметра")

        @wraps(function)
        def wrapper(*args, **kwargs):
            bound = signature.bind(*args, **kwargs)
            bound.apply_defaults()
            value = bound.arguments[parameter]
            if type(value) is not int or value <= 0:
                raise ValueError(f"{parameter} должен быть положительным int")
            return function(*args, **kwargs)

        return wrapper

    return decorate


@require_positive(parameter="count")
def repeat(text, count=1):
    return text * count


assert repeat("a", 3) == "aaa"
assert repeat("a") == "a"
try:
    repeat("a", count=0)
except ValueError:
    pass
```

Это учебная проверка простого явного параметра. Для `*args`, `**kwargs` и сложных типов нужна другая политика. `signature.bind()` проверяет форму вызова, а не тип и диапазон. Получение сигнатуры один раз при декорировании уменьшает повторную работу, но фиксирует предположение, что интерфейс исходной функции потом не изменяется.

### Несколько декораторов (стек декораторов)

`@outer` над `@inner` означает `outer(inner(function))`. Вызов входит во внешнюю обёртку, затем во внутреннюю; выход обычно идёт в обратном порядке.

```python
from functools import lru_cache, wraps

events = []


def log_calls(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        events.append("called")
        return function(*args, **kwargs)

    return wrapper


@log_calls
@lru_cache(maxsize=8)
def square(value):
    events.append("computed")
    return value**2


assert square(2) == square(2) == 4
assert events == ["called", "computed", "called"]
assert square.__wrapped__.cache_info().hits == 1
```

Если поменять порядок, внешний кэш не вызовет внутреннее логирование при попадании. Аналогично различается смысл «измерить весь запрос» и «измерить только вычисление после промаха», «повторять уже ограниченный запрос» и «ограничивать каждую повторную попытку». Порядок декораторов — часть поведения, которую нужно тестировать.

### functools.wraps для сохранения метаданных

Без `wraps` имя, docstring и аннотации обёртки обычно описывают `wrapper`, а не исходную функцию. С `wraps` сохраняется связь через `__wrapped__`, а инструменты могут восстановить пользовательскую сигнатуру.

```python
import inspect
from functools import wraps


def decorate(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        return function(*args, **kwargs)

    return wrapper


@decorate
def add(left: int, /, right: int = 1, *, scale: int = 1) -> int:
    """Сложить и масштабировать."""
    return (left + right) * scale


assert add.__name__ == "add"
assert add.__doc__ == "Сложить и масштабировать."
assert "left" in inspect.signature(add).parameters
assert list(inspect.signature(add, follow_wrapped=False).parameters) == [
    "args",
    "kwargs",
]
assert add(2, right=3, scale=2) == 10
```

`wraps` помогает runtime-интроспекции, но не выражает статическую связь между сигнатурами. Для этого нужен `ParamSpec`. Перенос метаданных не является доказательством прозрачности и может затронуть аннотации; учитывай особенности их вычисления в поддерживаемых версиях.

### Прозрачные обёртки и сохранение поведения функции

Обёртка, которая заявляет сохранение API, должна сохранять результат, ожидаемые исключения, допустимые формы вызова, синхронную/асинхронную модель и жизненный цикл ресурсов. Метаданные и типы — отдельные стороны этой задачи.

Типизированная обёртка обычной синхронной функции:

```python
from collections.abc import Callable
from functools import wraps
from typing import ParamSpec, TypeVar

P = ParamSpec("P")
R = TypeVar("R")


def passthrough(function: Callable[P, R]) -> Callable[P, R]:
    @wraps(function)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        return function(*args, **kwargs)

    return wrapper


@passthrough
def greet(name: str, *, prefix: str = "Hello") -> str:
    return f"{prefix}, {name}"


assert greet("Alice", prefix="Hi") == "Hi, Alice"
```

`ParamSpec` сохраняет связь полного набора аргументов с исходной функцией, а `TypeVar` — её результат. Это точнее, чем `Callable[..., Any]`. Для декоратора, который добавляет или убирает параметр, могут потребоваться `Concatenate` и явное документирование новой сигнатуры.

**Асинхронная обёртка** должна дождаться результата, если её дополнительные действия должны охватывать фактическое выполнение:

```python
import asyncio
import inspect
from collections.abc import Awaitable, Callable
from functools import wraps
from typing import ParamSpec, TypeVar

P = ParamSpec("P")
R = TypeVar("R")
events = []


def observe_async(function: Callable[P, Awaitable[R]]) -> Callable[P, Awaitable[R]]:
    @wraps(function)
    async def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        events.append("start")
        try:
            return await function(*args, **kwargs)
        finally:
            events.append("finish")

    return wrapper


@observe_async
async def compute(value: int) -> int:
    await asyncio.sleep(0)
    return value * 2


assert inspect.iscoroutinefunction(compute)
assert asyncio.run(compute(3)) == 6
assert events == ["start", "finish"]
```

Обычная `def`-обёртка вокруг `async def`, которая просто возвращает coroutine object, измерит создание этого объекта, а не его выполнение. Она также может изменить распознавание функции фреймворком. Функция, возвращающая awaitable, и coroutine function — разные категории, даже если результат обеих можно ожидать.

**Генераторная обёртка** должна учитывать потребление, `send`, `throw` и закрытие. `yield from` делегирует стандартный генераторный протокол и может сохранить значение завершения:

```python
from functools import wraps


def delegate(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        return (yield from function(*args, **kwargs))

    return wrapper


@delegate
def values():
    yield 1
    return "done"


iterator = values()
assert next(iterator) == 1
try:
    next(iterator)
except StopIteration as error:
    assert error.value == "done"
```

Простая обёртка, возвращающая генератор, может быть корректна как адаптер результата, но её таймер и `try` не охватывают последующее чтение. У асинхронного генератора нет `yield from`; одного `async for` тоже недостаточно для заявления о полной прозрачности `asend`/`athrow`. Поддерживаемый протокол нужно выбрать явно.

Функции-обёртки, помещённые в класс, обычно сохраняют обычное связывание метода. Экземпляр класса-декоратора с `__call__` не получает descriptor-поведение автоматически; для метода может понадобиться `__get__`. Не обещай универсальную прозрачность одной обёрткой для всех видов callable.

### Декораторы классов

Декоратор класса получает созданный объект класса и возвращает объект, который свяжется с его именем. Он может зарегистрировать класс, изменить атрибуты или создать новый объект. Это не то же самое, что декоратор отдельного метода.

```python
registered_types = {}


def register_type(name):
    def decorate(cls):
        if name in registered_types:
            raise ValueError("Тип уже зарегистрирован")
        registered_types[name] = cls
        return cls

    return decorate


@register_type("event")
class Event:
    pass


assert registered_types["event"] is Event
```

`dataclass` — известный пример декоратора класса, добавляющего методы по объявленным полям. Если декоратор заменяет класс другим, могут измениться идентичность, сериализация, наследование и introspection. Для простой регистрации предпочтительнее вернуть тот же объект, если замена не требуется контрактом.

### Встроенные декораторы: @staticmethod, @classmethod, @property

| Декоратор | Что получает вызов/доступ | Типичная задача |
| --- | --- | --- |
| `staticmethod` | Не добавляет `self` или `cls` | Вспомогательная операция в пространстве класса |
| `classmethod` | Класс как первый аргумент | Альтернативный конструктор с учётом подкласса |
| `property` | Управляемый доступ как к атрибуту | Вычисляемое или проверяемое свойство |

```python
class Temperature:
    def __init__(self, celsius: float):
        self._celsius = celsius

    @staticmethod
    def kelvin_offset() -> float:
        return 273.15

    @classmethod
    def from_kelvin(cls, value: float):
        return cls(value - cls.kelvin_offset())

    @property
    def celsius(self) -> float:
        return self._celsius


temperature = Temperature.from_kelvin(273.15)
assert temperature.celsius == 0.0
assert Temperature.kelvin_offset() == 273.15
```

`property` вызывается через `obj.attr`, а не `obj.attr()`. Дорогой или выполняющий сетевой запрос property может неожиданно нарушить ожидания пользователя API. Валидация абсолютного нуля и конечности здесь опущена ради механизма; полноценная температурная валидация появится в проекте главы.

Эти декораторы связаны с дескрипторами. Порядок их сочетания с пользовательскими декораторами важен; поддержка необычных комбинаций менялась по версиям. Не рассчитывай, что любой callable можно обернуть в любой порядок и получить тот же метод.

### Примеры полезных декораторов (таймер, логирование)

Для длительности используй монотонный высокоточный счётчик `time.perf_counter()`, а не календарные часы. Возвращай исходный результат, измеряй и ошибочный выход, не записывай автоматически все аргументы с секретами и большими данными.

```python
from functools import wraps
from time import perf_counter


def timed(*, emit):
    def decorate(function):
        @wraps(function)
        def wrapper(*args, **kwargs):
            started = perf_counter()
            try:
                return function(*args, **kwargs)
            finally:
                emit(function.__qualname__, perf_counter() - started)

        return wrapper

    return decorate


measurements = []


@timed(emit=lambda name, seconds: measurements.append((name, seconds)))
def total(values):
    return sum(values)


assert total([1, 2, 3]) == 6
assert len(measurements) == 1
assert measurements[0][1] >= 0
```

Измерение включает накладные расходы обёртки и не заменяет профилирование приложения. Если `emit` возбудит исключение, оно повлияет на результат: пример предполагает надёжный sink. Для обычного логирования можно передать заранее настроенный logger, а для теста — функцию, собирающую события.

Декораторы повторных попыток требуют ещё более явного контракта: какие ошибки временные, сколько попыток, общий deadline, задержка, отмена и безопасность повторения действия. Не добавляй универсальный `except Exception: retry` к произвольной операции записи.

### Декораторы vs наследование

Декоратор удобен для добавления ортогонального поведения вокруг операции: метрик, регистрации, проверки или адаптации. Наследование моделирует отношение типов и переопределение поведения объекта. Для зависимости с собственным состоянием и жизненным циклом композиция через явный объект часто лучше обоих.

Не используй наследование только ради таймера одной функции; не прячь через стек декораторов сложный бизнес-процесс с десятком скрытых переходов. Чем больше обёрток, тем важнее возможность посмотреть исходную функцию, понять порядок и проверить каждый вид выхода.

**Самопроверка:** поменяй местами кэш и таймер. Что именно теперь измеряется? Затем оберни `async def` обычным синхронным таймером и объясни, почему даже корректное число секунд может измерять другое действие. Для генератора отдельно проверь раннее закрытие.

**Документация:** [декораторы в определениях](https://docs.python.org/3.14/reference/compound_stmts.html#function-definitions), [functools.wraps](https://docs.python.org/3.14/library/functools.html#functools.wraps), [ParamSpec](https://docs.python.org/3.14/library/typing.html#typing.ParamSpec), [staticmethod/classmethod/property](https://docs.python.org/3.14/library/functions.html).

## Функции-генераторы

### Что такое генератор

Функция, содержащая `yield` в своём теле, является генераторной. Её вызов создаёт generator object, но не начинает обычное исполнение тела. Этот объект является одноразовым итератором: выполнение продолжается при `next()` или другом запросе протокола.

```python
import inspect

events = []


def numbers():
    events.append("started")
    yield 1
    yield 2


generator = numbers()
assert inspect.isgeneratorfunction(numbers)
assert inspect.isgenerator(generator)
assert iter(generator) is generator
assert events == []
assert next(generator) == 1
assert events == ["started"]
assert list(generator) == [2]
assert list(generator) == []
```

Даже `yield` в недостижимой ветке меняет вид функции. Генераторная функция и возвращённый генератор — разные объекты. Аннотация `Iterator[T]` описывает интерфейс выдаваемых значений; `Generator[YieldType, SendType, ReturnType]` — более полный синхронный протокол.

### yield vs return

`yield expression` выдаёт значение и приостанавливает выполнение, сохраняя возможность продолжения. `return value` завершает синхронный генератор; значение доступно как `StopIteration.value` и результат `yield from`, но не как очередной элемент `for`.

```python
def sequence():
    yield 1
    yield 2
    return "complete"


assert list(sequence()) == [1, 2]
generator = sequence()
assert next(generator) == 1
assert next(generator) == 2
try:
    next(generator)
except StopIteration as error:
    assert error.value == "complete"
```

Не возбуждай `StopIteration` вручную внутри генераторного тела для обычного завершения. Если такое исключение выходит из тела, оно преобразуется в `RuntimeError` по PEP 479, чтобы случайное исчерпание вложенного итератора не выглядело успешным концом внешнего генератора.

```python
def broken():
    yield 1
    raise StopIteration("unexpected")


generator = broken()
assert next(generator) == 1
try:
    next(generator)
except RuntimeError as error:
    assert isinstance(error.__cause__, StopIteration)
```

В ручном методе `__next__` `StopIteration` остаётся правильным сигналом протокола. Разница относится к тому, кто управляет генераторным выполнением.

### Состояние между вызовами

Генератор сохраняет локальные переменные, текущую точку выполнения и ссылки на необходимые объекты. Поэтому можно поэлементно поддерживать накопитель без хранения всех результатов.

```python
from collections.abc import Iterable, Iterator


def running_total(values: Iterable[int]) -> Iterator[int]:
    total = 0
    for value in values:
        total += value
        yield total


generator = running_total([1, 2, 3])
assert next(generator) == 1
assert next(generator) == 3
assert next(generator) == 6
assert next(generator, None) is None
```

Вызовы `running_total()` создают независимое состояние, но один generator object нельзя многократно «начать сначала». Генератор не даёт автоматической потокобезопасности; повторный вход в уже выполняющийся генератор отклоняется. Если нужно несколько независимых потребителей, создавай независимые источники или явно проектируй буферизацию.

Ленивость не гарантирует малое удержание памяти. Локальная переменная, исходный список, замыкание и исключение могут продолжать удерживать большие объекты между `yield`. Профилируй живой граф ссылок, а не только размер самого generator object.

### yield from — делегирование в другой подгенератор

`yield from iterable` выдаёт значения вложенного источника, а для подходящего генератора также делегирует `send`, `throw` и закрытие. Значение завершения подгенератора становится значением выражения `yield from`.

```python
def child():
    received = yield "ready"
    return received * 2


def parent():
    result = yield from child()
    yield ("result", result)


generator = parent()
assert next(generator) == "ready"
assert generator.send(7) == ("result", 14)
assert next(generator, None) is None
```

Для простого списка `yield from [1, 2]` похож на цикл с `yield`, но замена полного делегирования обычным `for` теряет часть двустороннего протокола и return value. Если внутренний iterable не поддерживает расширенные методы, действуют соответствующие ограничения делегирования.

```python
def flatten(chunks):
    for chunk in chunks:
        yield from chunk


assert list(flatten([[1, 2], [], [3]])) == [1, 2, 3]
```

`yield from` относится к синхронным генераторам. Он недопустим внутри `async def` с `yield`; для асинхронного источника используется отдельный протокол, обычно `async for` с явной политикой закрытия.

### Генераторные выражения

Генераторное выражение — компактный способ задать одно преобразование с обходом и фильтрами. Круглые скобки можно опустить, если это единственный аргумент вызова, например `sum(x*x for x in values)`.

```python
values = [1, 2, 3, 4]
generator = (value**2 for value in values if value % 2 == 0)
assert list(generator) == [4, 16]
assert sum(value**2 for value in values) == 30
```

Внешний iterable и его итератор получаются при создании выражения; вычисление результата и дальнейшие части откладываются. Переменная цикла не выходит в охватывающую область, но другие свободные имена читаются позже, как в обычном замыкании.

```python
factor = 2
generator = (value * factor for value in [1, 2])
factor = 10
assert list(generator) == [10, 20]
```

Для нескольких шагов, `try/finally`, управления ресурсом и сложных проверок лучше генераторная функция с именем. Подробный синтаксис включений разобран в предыдущей главе; здесь важно время выполнения и одноразовость.

### Генераторы как корутины (.send(), .throw(), .close())

Синхронный генератор может не только выдавать значения, но и принимать их в точке `yield`. `send(value)` возобновляет его и делает `value` результатом выражения `yield`; `next(generator)` эквивалентен отправке `None`. В ещё не запущенный генератор сначала можно отправить только `None`.

```python
events = []


def accumulator():
    total = 0
    try:
        while True:
            try:
                value = yield total
            except ValueError:
                total = 0
            else:
                total += value
    finally:
        events.append("closed")


generator = accumulator()
assert next(generator) == 0
assert generator.send(5) == 5
assert generator.send(3) == 8
assert generator.throw(ValueError("reset")) == 0
assert generator.send(2) == 2
generator.close()
assert events == ["closed"]
```

`throw(exception_instance)` вводит исключение в приостановленную точку; генератор может его обработать, завершиться или выдать новое значение. Старая многопараметрическая форма `throw(type, value, traceback)` устаревает с Python 3.12; для нового кода передавай объект исключения.

`close()` инициирует завершение через `GeneratorExit` в приостановленном генераторе. Очистка в `finally` выполняется; попытка выдать новое значение вместо закрытия приводит к `RuntimeError`. Не перехватывай `GeneratorExit` ради продолжения обычного потока данных.

```python
# Python 3.13+: значение return при close.
def closable():
    try:
        yield 1
    except GeneratorExit:
        return "closed"


generator = closable()
assert next(generator) == 1
assert generator.close() == "closed"
```

На Python 3.12 `close()` не возвращает это значение вызывающему коду. Синхронные generator-based coroutines исторически важны, но не являются полной заменой современным `async def` и `await`: планирование и асинхронные протоколы у них разные.

### Жизненный цикл генератора

`inspect.getgeneratorstate()` различает созданное, выполняющееся, приостановленное и закрытое состояние. Обычное завершение, необработанное исключение и успешное `close()` завершают генератор; после этого он не может начать тело заново.

```python
import inspect


def one_value():
    yield 1


generator = one_value()
assert inspect.getgeneratorstate(generator) == inspect.GEN_CREATED
assert next(generator) == 1
assert inspect.getgeneratorstate(generator) == inspect.GEN_SUSPENDED
generator.close()
assert inspect.getgeneratorstate(generator) == inspect.GEN_CLOSED
assert next(generator, "end") == "end"
```

`break` у потребителя не является универсальной командой закрыть произвольный генератор. Если ранний выход должен немедленно освободить ресурс, используй явное закрытие или `contextlib.closing()` для подходящего объекта.

```python
from contextlib import closing

events = []


def managed_values():
    events.append("opened")
    try:
        yield 1
        yield 2
    finally:
        events.append("released")


with closing(managed_values()) as source:
    for item in source:
        assert item == 1
        break
assert events == ["opened", "released"]
```

Тело ещё не начатого генератора не выполняется при его простом создании; закрытие такого объекта не обязано заходить в неисполненный `try/finally`. Поэтому ресурс, открытый снаружи до создания генератора, должен иметь отдельного владельца. Не полагайся на момент сборки мусора как на переносимую гарантию своевременного закрытия.

На основе генераторов `contextlib.contextmanager` строит контекстный менеджер с ровно одной точкой `yield`: код до неё обслуживает вход, код после — выход. Исключение из `with` приходит в точку `yield`; случайно поймав и не повторно возбудив его, можно подавить ошибку. Это отдельный полезный протокол, который подробно продолжается в теме управления ресурсами.

### Примеры использования

Потоковая обработка строк позволяет откладывать чтение и преобразование, но жизненный цикл файла должен охватывать всё потребление.

```python
from collections.abc import Iterator
from pathlib import Path
from tempfile import TemporaryDirectory


def meaningful_lines(path: Path) -> Iterator[tuple[int, str]]:
    with path.open(encoding="utf-8") as source:
        for line_number, line in enumerate(source, start=1):
            text = line.strip()
            if text and not text.startswith("#"):
                yield line_number, text


with TemporaryDirectory() as directory:
    path = Path(directory) / "config.txt"
    path.write_text("# comment\n\nalpha\n beta \n", encoding="utf-8")
    assert list(meaningful_lines(path)) == [(3, "alpha"), (4, "beta")]
```

Если потребитель берёт только первый элемент, оборачивай источник в `closing` или предоставляй API контекстного менеджера, чтобы закрытие было детерминированным. Такой генератор не читает весь файл заранее, но память всё ещё зависит от длины строки и действий потребителя.

Другие применения: выдача страниц API по требованию, обход дерева, генерация ограниченных комбинаций, накопительные метрики. Для каждого укажи, допустим ли повторный обход, в какой момент проявляется ошибка и что происходит при раннем прекращении потребления.

**Документация:** [генераторы и yield](https://docs.python.org/3.14/reference/expressions.html#yield-expressions), [генераторные методы](https://docs.python.org/3.14/reference/expressions.html#generator-iterator-methods), [contextlib](https://docs.python.org/3.14/library/contextlib.html), [PEP 380](https://peps.python.org/pep-0380/), [PEP 479](https://peps.python.org/pep-0479/).

## Интроспекция функций

### Атрибуты функций: `__name__`, `__doc__`, `__annotations__`

Метаданные помогают документации, диагностике и инструментам. `__name__` — короткое имя, `__qualname__` — квалифицированное имя с лексической вложенностью, `__module__` — модуль определения, `__doc__` — docstring. Сами эти атрибуты не доказывают, что объект ведёт себя соответственно им: часть метаданных изменяема.

```python
def calculate(value: int, scale: int = 2, *, offset: int = 0) -> int:
    """Масштабировать значение и добавить смещение."""
    return value * scale + offset


assert calculate.__name__ == "calculate"
assert "Масштабировать" in calculate.__doc__
assert calculate.__defaults__ == (2,)
assert calculate.__kwdefaults__ == {"offset": 0}
assert calculate.__annotations__["return"] is int
assert calculate.__code__.co_name == "calculate"
```

`__defaults__` хранит позиционные defaults, `__kwdefaults__` — keyword-only defaults; это реальные используемые объекты. Изменение изменяемого default через доступ к нему меняет будущие вызовы. `__globals__` ссылается на глобальный словарь определения, а `__closure__` — на захваченные ячейки либо `None`.

С 3.12 generic-функции имеют `__type_params__`; в 3.14 модель отложенных аннотаций добавляет связанные механизмы вычисления. `__annotations__` может содержать объекты или строки, а доступ к аннотациям — инициировать вычисление. Для библиотечного анализа предпочитай документированные API вместо ручных предположений о всех возможных формах.

### Модуль inspect для анализа функций

`inspect` различает функции, методы, генераторные и корутинные функции и соответствующие объекты выполнения. Суффикс `function` обычно относится к определению, а проверка без него — к созданному объекту.

```python
import inspect


def regular():
    return 1


def generator_function():
    yield 1


async def coroutine_function():
    return 1


assert inspect.isfunction(regular)
assert inspect.isgeneratorfunction(generator_function)
assert inspect.iscoroutinefunction(coroutine_function)

generator = generator_function()
coroutine = coroutine_function()
assert inspect.isgenerator(generator)
assert inspect.iscoroutine(coroutine)
assert inspect.isawaitable(coroutine)
generator.close()
coroutine.close()  # Созданный объект не оставлен без завершения.
```

Для обычного callable, возвращающего awaitable, `iscoroutinefunction()` может быть ложным, хотя его результат поддерживает `await`. Для обёрток и `partial` детали распознавания развивались между версиями. Если проект выбирает механизм вызова по introspection, явно поддержи нужные категории и проверь декорированные функции.

Исследование объекта не всегда без побочных эффектов: получение атрибутов и разрешение аннотаций может выполнять код. Для инструментов статического доступа есть, например, `inspect.getattr_static`, но это тоже специальный интерфейс с ограничениями.

### Получение исходного кода функции

`inspect.getsource()` пытается найти исходный текст по доступным данным о модуле и файле. Он не восстанавливает произвольный Python-код из байт-кода. Функции из REPL, `exec`, недоступного файла или нативного расширения могут не иметь извлекаемого исходника.

```python
import importlib.util
import inspect
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as directory:
    path = Path(directory) / "source_example.py"
    path.write_text("def triple(value):\n    return value * 3\n", encoding="utf-8")
    spec = importlib.util.spec_from_file_location("source_example", path)
    assert spec is not None and spec.loader is not None
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    source = inspect.getsource(module.triple)
    assert "return value * 3" in source
    assert module.triple(4) == 12
```

В этом примере файл создаётся специально, поэтому блок воспроизводим даже при запуске из строки. В библиотечном инструменте обрабатывай `OSError` и `TypeError` как нормальную невозможность получить текст. Для обёрток может понадобиться `inspect.unwrap()`; исходный текст декорированной функции может включать строки декораторов.

Полученный код — диагностический материал, а не автоматически доверенный код для повторного исполнения. AST и байт-код полезны для анализа, но не дают универсальной безопасной сериализации функции со всем её окружением.

### Проверка сигнатуры функции

`inspect.signature()` возвращает объект `Signature` с параметрами, их видами, defaults и аннотацией результата. Это удобнее ручного чтения `co_argcount`, которое не описывает все особенности вызова и может относиться к обёртке.

```python
from inspect import Parameter, signature


def operation(source, /, mode="read", *, strict=False):
    return source, mode, strict


sig = signature(operation)
assert sig.parameters["source"].kind is Parameter.POSITIONAL_ONLY
assert sig.parameters["mode"].kind is Parameter.POSITIONAL_OR_KEYWORD
assert sig.parameters["strict"].kind is Parameter.KEYWORD_ONLY
assert sig.parameters["mode"].default == "read"
assert sig.return_annotation is sig.empty
```

Для некоторых встроенных callable сигнатура недоступна; обработай `ValueError` и `TypeError`. По умолчанию `signature()` обычно следует через `__wrapped__`. Нестандартный `__signature__` способен влиять на результат в CPython, но сам по себе не меняет связывание аргументов при реальном вызове.

```python
# Python 3.14+: выбор строкового формата аннотаций сигнатуры.
import annotationlib
import inspect


def combine(value: int, suffix: str) -> str:
    return str(value) + suffix


sig = inspect.signature(combine, annotation_format=annotationlib.Format.STRING)
assert sig.parameters["value"].annotation == "int"
assert sig.return_annotation == "str"
```

Строковое представление полезно для документации, но управление форматом аннотаций не является общим sandbox для анализа недоверенных объектов. Выбирай формат и разрешение имён осознанно.

### Работа с объектами сигнатур

`Signature.bind()` проверяет, соответствуют ли переданные аргументы сигнатуре, и возвращает `BoundArguments`. `bind_partial()` допускает отсутствие части обязательных аргументов, что полезно для частичной подготовки вызова. Ни один метод не проверяет тип и бизнес-смысл значений.

```python
from inspect import signature


def operation(value, /, scale=2, *extra, offset=0, **metadata):
    return value * scale + offset, extra, metadata


sig = signature(operation)
bound = sig.bind(3, offset=1, tag="test")
bound.apply_defaults()
assert bound.arguments["value"] == 3
assert bound.arguments["scale"] == 2
assert bound.arguments["extra"] == ()
assert bound.arguments["metadata"] == {"tag": "test"}
assert operation(*bound.args, **bound.kwargs) == (7, (), {"tag": "test"})

bound.arguments["scale"] = 10
assert operation(*bound.args, **bound.kwargs)[0] == 31

partial_bound = sig.bind_partial(offset=1)
assert "value" not in partial_bound.arguments
try:
    sig.bind(offset=1)
except TypeError:
    pass
```

До `apply_defaults()` в `arguments` могут отсутствовать не переданные необязательные параметры. После него добавляются defaults, пустой `args` и пустой `kwargs` для соответствующих видов. Свойства `bound.args` и `bound.kwargs` вычисляются из текущего отображения аргументов.

`Signature` и `Parameter` неизменяемы; для новой версии используются `.replace()`. Изменение объекта сигнатуры не переписывает тело функции и не создаёт реальный новый интерфейс вызова. Если адаптер рекламирует новую сигнатуру, он должен действительно выполнить нужное связывание и преобразование.

### Функции, методы и вызываемые объекты

Функция в атрибуте класса участвует в descriptor-протоколе: доступ через экземпляр обычно создаёт связанный метод. Он хранит объект в `__self__` и исходную функцию в `__func__`. Экземпляр с `__call__` вызываем, но не является обычной функцией.

```python
import inspect
from functools import partial


class Multiplier:
    def __init__(self, factor):
        self.factor = factor

    def apply(self, value):
        return value * self.factor

    def __call__(self, value):
        return self.apply(value)


multiplier = Multiplier(3)
method = multiplier.apply
assert inspect.ismethod(method)
assert method.__self__ is multiplier
assert method.__func__ is Multiplier.apply
assert method(4) == multiplier(4) == 12
assert callable(multiplier)
assert not inspect.isfunction(multiplier)
assert callable(partial(pow, 2))
assert callable(Multiplier)
```

`callable(obj)` говорит о наличии механизма вызова, а не о допустимости любых аргументов, успешном завершении и типе результата. Для plugin API лучше задать протокол вызова и проверить нужный контракт, чем требовать только `inspect.isfunction()` и тем самым исключить полезные методы и объекты.

**Документация:** [inspect](https://docs.python.org/3.14/library/inspect.html), [атрибуты функций](https://docs.python.org/3.14/reference/datamodel.html#user-defined-functions), [PEP 362: signatures](https://peps.python.org/pep-0362/).

## Асинхронные функции (async/await)

### Что такое асинхронность

Асинхронность позволяет одной задаче уступить выполнение, пока она ожидает операцию, и дать циклу событий обслуживать другие задачи. Это кооперативная конкурентность. Она сама по себе не создаёт несколько CPU-ядер для Python-вычислений и не превращает блокирующий вызов в неблокирующий.

`async def` определяет coroutine function. Вызов обычно создаёт coroutine object; `await` ожидает awaitable в асинхронном контексте. Task оборачивает корутину для планирования её выполнения циклом событий.

| Объект | Смысл |
| --- | --- |
| Coroutine function | Определение через `async def` без `yield` |
| Coroutine object | Конкретное отложенное выполнение |
| Awaitable | Объект, результат которого можно ожидать |
| `asyncio.Task` | Запланированное выполнение корутины |
| Async generator | Асинхронный источник элементов, получаемых через `async for` |

`time.sleep()`, синхронный HTTP-клиент и тяжёлый CPU-цикл внутри `async def` блокируют поток event loop. Для допустимой блокирующей I/O-работы можно рассмотреть `asyncio.to_thread()`, а для CPU-задачи — отдельный процесс или другую подходящую модель. Выбор зависит от нагрузки, сериализации и среды исполнения.

### Определение async функции

```python
import asyncio


async def double(value: int) -> int:
    await asyncio.sleep(0)
    return value * 2


assert asyncio.run(double(3)) == 6
```

Аннотация `-> int` описывает результат после ожидания, а сам вызов `double(3)` возвращает coroutine object. `await` допустим внутри `async def` и некоторых специально поддерживаемых интерактивных сред; в обычном модуле top-level `await` не является стандартным способом запуска.

Асинхронная функция с `yield` становится async generator function. Её результат читается через `async for`, а не одним `await`; непустой `return value` в таком генераторе запрещён.

```python
import asyncio
from collections.abc import AsyncIterator
from contextlib import aclosing


async def ticks(limit: int) -> AsyncIterator[int]:
    for value in range(limit):
        await asyncio.sleep(0)
        yield value


async def collect() -> list[int]:
    result = []
    async with aclosing(ticks(3)) as source:
        async for value in source:
            result.append(value)
    return result


assert asyncio.run(collect()) == [0, 1, 2]
```

Async generator поддерживает `anext`, `asend`, `athrow`, `aclose`, но его протокол отличается от синхронного генератора. Для детерминированного освобождения ресурсов при раннем выходе подходит `contextlib.aclosing()` в соответствующем контексте. Полный разбор async I/O, отмены и потоков находится в разделе конкурентности справочника.

### Вызов асинхронных функций

Прямое создание корутины не равно её исполнению. Для последовательного выполнения используй `await`; для конкурентных дочерних задач — структурированную группу, например `asyncio.TaskGroup`, доступную с 3.11.

```python
import asyncio

events = []


async def compute(value: int) -> int:
    events.append(value)
    await asyncio.sleep(0)
    return value * 2


async def main() -> list[int]:
    coroutine = compute(1)
    assert events == []
    first = await coroutine
    assert first == 2

    async with asyncio.TaskGroup() as group:
        second_task = group.create_task(compute(2))
        third_task = group.create_task(compute(3))
    return [first, second_task.result(), third_task.result()]


assert asyncio.run(main()) == [2, 4, 6]
assert sorted(events) == [1, 2, 3]
```

Порядок внешних эффектов конкурентных задач обычно нельзя выводить из порядка создания без дополнительных гарантий. TaskGroup ожидает завершения дочерних задач и при обычной ошибке ребёнка отменяет остальных, затем сообщает ошибки по своей модели, часто через `ExceptionGroup`.

`asyncio.run()` предназначен для входа в асинхронное приложение и не вызывается внутри уже работающего event loop в том же потоке. В notebook или async-сервисе обычно нужно `await main()`. Coroutine object нельзя повторно ожидать после завершения; завершённый Task может многократно предоставлять свой результат.

Отмена требует очистки через `try/finally` или async context manager. `asyncio.CancelledError` наследуется от `BaseException`; если его поймали ради очистки, обычно нужно передать дальше. Тайм-аут — часть управления отменой, а не доказательство отсутствия внешнего эффекта.

```python
import asyncio

events = []


async def pending() -> None:
    try:
        await asyncio.Event().wait()
    finally:
        events.append("cleaned")


async def main() -> None:
    task = asyncio.create_task(pending())
    await asyncio.sleep(0)  # Дать задаче войти в тело.
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        pass


asyncio.run(main())
assert events == ["cleaned"]
```

Не создавай неограниченное число tasks для огромного входа. Для реальной загрузки нужны предел конкурентности, очереди/буферы, deadlines и освобождение ресурсов. Здесь разобрана модель вызова; полноценный сетевой конвейер требует следующих глав.

**Документация:** [async function definitions](https://docs.python.org/3.14/reference/compound_stmts.html#coroutine-function-definition), [корутины и tasks](https://docs.python.org/3.14/library/asyncio-task.html), [async generators](https://docs.python.org/3.14/reference/expressions.html#asynchronous-generator-functions).

<a id="best-practices"></a>

## Частые ошибки и Лучшие практики

### Изменяемые объекты как аргументы по умолчанию

Список, словарь или пользовательский объект в default разделяется всеми вызовами, где аргумент пропущен. Неизменяемый внешний контейнер тоже может содержать изменяемые элементы. Используй маркер отсутствия и создавай новое состояние внутри вызова, если оно должно быть независимым.

```python
def create_config(options=None):
    if options is None:
        return {"retries": 3}
    return dict(options)


first = create_config()
second = create_config()
first["retries"] = 10
assert second["retries"] == 3
```

Состояние в default может быть намеренным, но оно скрыто от пользователя сигнатуры и трудно сбрасывается. Для кэша и счётчика обычно яснее `lru_cache`, замыкание или объект с явным API. Не заменяй `None` на `[]` через `options or {}` без проверки контракта: допустимая пустота не обязана означать отсутствие.

### Забытый return (функция возвращает None)

Наличие вычисления в конце тела не возвращает его автоматически. `print(result)` тоже не заменяет `return result`. Все пути, для которых обещан результат, должны его возвращать либо завершаться исключением.

```python
def broken_double(value):
    value * 2


def correct_double(value):
    return value * 2


assert broken_double(3) is None
assert correct_double(3) == 6
```

Тип результата помогает анализатору заметить пропущенную ветвь. Ошибка особенно распространена в wrapper, где забыли `return function(...)`. Для генератора возвращённое значение не становится элементом потока, а для `async def` нужно отличать `return result` от `return coroutine` без ожидаемого `await`.

### Позднее связывание в замыканиях и лямбдах

Замыкание читает захваченную привязку при вызове. Функции, созданные одним циклом, не получают автоматически отдельное значение переменной на каждой итерации. Исправления — отдельная фабрика, `partial` или фиксация через default с пониманием изменяемости объекта.

```python
from functools import partial


def multiply(left, right):
    return left * right


operations = [partial(multiply, factor) for factor in [1, 2, 3]]
assert [operation(10) for operation in operations] == [10, 20, 30]
```

В обработчиках GUI, отложенных заданиях и async-задачах эта ошибка проявляется позже места создания. Проверяй callback после завершения цикла, а не только внутри той же итерации: немедленный вызов может скрыть проблему.

### Путаница между positional и keyword аргументами

Числа одного типа легко переставить без `TypeError`. Делай настройки keyword-only, особенно если они управляют длительностью, лимитом, перезаписью и обработкой ошибок. Основной объект операции можно оставить позиционным или positional-only.

```python
def retry_policy(*, attempts: int, timeout_seconds: float):
    if type(attempts) is not int or attempts < 1:
        raise ValueError("Некорректное число попыток")
    if timeout_seconds <= 0:
        raise ValueError("Некорректный тайм-аут")
    return attempts, timeout_seconds


assert retry_policy(timeout_seconds=1.5, attempts=3) == (3, 1.5)
```

Имена помогают только при правильных единицах и проверках. `timeout_seconds=1500` синтаксически допустим, но может быть ошибочно передан в миллисекундах. Разделяй относительный timeout, абсолютный deadline и ограничение на все повторные попытки.

### Слишком много аргументов

Длинный список часто означает несколько независимых обязанностей или скрытую модель данных. Не прячь его механически в неструктурированный `dict`: так исчезнут имена параметров и часть проверок. Выдели связанный набор настроек в модель, оставив зависимости и входные данные отдельными.

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class ExportOptions:
    delimiter: str = ","
    include_header: bool = True
    encoding: str = "utf-8"


def describe_export(path: str, *, options: ExportOptions) -> tuple[str, str]:
    return path, options.encoding


assert describe_export("report.csv", options=ExportOptions()) == ("report.csv", "utf-8")
```

Dataclass не валидирует поля автоматически. Если нужны ограничения, добавь их на границе. Не передавай через конфигурацию весь контейнер приложения, когда функция использует только две настройки: скрытая зависимость от большого context мешает изоляции не меньше глобальной переменной.

### Рекурсия без базового случая

Базовый случай должен быть достижим. `if n == 0` не завершит функцию для отрицательного `n`, если каждый шаг делает `n - 1`. Для обхода графа конечность списка соседей тоже не означает отсутствие циклов.

Проверяй пустой вход, ноль, отрицательные значения и глубоко вложенные структуры. Не исправляй `RecursionError` автоматическим увеличением лимита. Для размера, зависящего от внешнего ввода, выбери явный стек, предел глубины и политику циклических ссылок.

### Изменение глобальных переменных без global

`count += 1` перепривязывает имя и потому делает его локальным без `global`/`nonlocal`. `events.append(...)` меняет объект и не является перепривязкой `events`. Разница объясняет многие `UnboundLocalError`.

```python
count = 0


def next_count(current: int) -> int:
    return current + 1


count = next_count(count)
assert count == 1
```

В этом дизайне владелец состояния виден в вызывающем коде. Если действительно нужен общий счётчик, отдельный объект с синхронизацией и сбросом обычно даёт более ясный контракт, чем изменение модуля из многих функций.

### Функции должны делать одну вещь

«Одна вещь» означает один уровень ответственности, а не фиксированное число строк. Функция оркестрации может последовательно вызвать чтение, валидацию и запись, если её контракт — выполнить сценарий и согласовать ошибки. Внутри неё не обязательно должны жить все детали каждого шага.

Полезное разделение для конвейера: parser переводит внешнюю форму, validator проверяет контракт, чистое преобразование вычисляет значение, orchestration управляет источником и ошибками. Не дроби элементарную формулу на множество бессодержательных helpers. Название функции должно описывать действие без длинного списка несвязанных глаголов.

### Чистые функции (без побочных эффектов)

Чистая функция зависит только от явных входных значений и не меняет наблюдаемое внешнее состояние. Её проще тестировать, кэшировать и переиспользовать, но чистота не является требованием ко всем частям программы: кто-то должен читать файлы и отправлять данные.

```python
def discounted(amount_minor: int, *, discount_minor: int) -> int:
    if not 0 <= discount_minor <= amount_minor:
        raise ValueError("Некорректная скидка")
    return amount_minor - discount_minor


assert discounted(1_000, discount_minor=100) == 900
assert discounted(1_000, discount_minor=100) == 900
```

Чтение текущего времени, генератора случайных чисел и глобального кэша является зависимостью от состояния, даже без явной записи. Практичный дизайн — чистое ядро вычислений и явная внешняя оболочка. При этом мемоизация результата допустима только при правильной эквивалентности входов и политике владения сохранёнными объектами.

### Документирование функций

Документируй смысл и ограничения: единицы измерения, кодировку, нормализацию, допустимость пустого входа, порядок результата, повторный проход, мутацию и ожидаемые исключения. Для генератора укажи, что ошибка может возникнуть во время чтения, а для async — как работают отмена и ресурсы.

Не обещай «возвращает отсортированные данные», если порядок не задан для равных ключей, пропусков и `NaN`. Не обещай «не меняет вход», если возвращаемый объект содержит общие вложенные списки. Пример должен проверять хотя бы одну границу, а не только удачный центральный случай.

### Использование аннотаций типов

Используй аннотации вместе с проверкой типов в CI и runtime-валидацией там, где данные входят извне. Сам факт наличия `-> int` не защищает от фактического `None`, а `dict[str, object]` не является проверенной схемой JSON.

Для callbacks сохраняй отношения аргументов и результата через generic-параметры, `ParamSpec` или `Protocol`. При последовательной миграции сначала типизируй публичные границы и структуры, затем внутренние функции. Не добавляй `cast()` только чтобы скрыть непонятую ошибку: он ничего не проверяет во время выполнения.

### Ограничение количества параметров

Жёсткого универсального стилевого числа нет. Практический критерий — можно ли понять вызов, не открывая документацию и не запоминая порядок нескольких однотипных значений. Два параметра с неясными именами могут быть хуже шести хорошо сгруппированных keyword-only настроек.

Если набор параметров растёт, проверь: не смешаны ли разные операции, нет ли противоречивых флагов, являются ли части одной моделью и не требуется ли builder или отдельный объект. Не заменяй понятную сигнатуру универсальным `**kwargs` ради сокращения числа формальных параметров.

### Понятные имена функций и параметров

`parse_*` обычно переводит внешнюю запись, `validate_*` проверяет или возвращает нормализованную модель, `is_*` ожидаемо возвращает признак, `iter_*` — итерируемый поток, `load_*` может выполнять I/O. Выбери соглашение и соблюдай его.

Добавляй единицы там, где их легко спутать: `timeout_seconds`, `size_bytes`, `amount_minor`. Для флагов избегай двойного отрицания вроде `disable_no_cache`. Если функция возвращает `None` и делает изменение, имя должно отражать действие. Не используй `get_*` для неожиданной долгой операции без ясной документации.

### Избегание мутации входных данных

Если мутация не нужна контракту, создавай новый результат. Для неглубоких неизменяемых элементов поверхностной копии достаточно; для вложенного графа нужно определить требуемую независимость отдельно.

```python
def with_tag(tags: list[str], new_tag: str) -> list[str]:
    return [*tags, new_tag]


original = ["python"]
updated = with_tag(original, "data")
assert original == ["python"]
assert updated == ["python", "data"]
assert updated is not original
```

Не копируй всё через `deepcopy` по умолчанию: это может быть дорого и неверно для внешних ресурсов. Если операция меняет вход, назови и документируй это явно, выбери понятный результат и проверь поведение при ошибке в середине изменения.

## Практические примеры

### Функции для работы со строками

Нормализация должна иметь конкретный контракт. Здесь из последовательности фрагментов удаляются внешние пробелы, канонически эквивалентные формы сводятся в NFC, пустые результаты пропускаются. Регистр сохраняется, чтобы не менять смысл произвольного текста.

```python
import unicodedata
from collections.abc import Iterable


def clean_fragments(values: Iterable[str]) -> list[str]:
    if isinstance(values, str):
        raise TypeError("Нужен источник строк, а не одна строка")
    result = []
    for value in values:
        if not isinstance(value, str):
            raise TypeError("Каждый фрагмент должен быть строкой")
        normalized = unicodedata.normalize("NFC", value).strip()
        if normalized:
            result.append(normalized)
    return result


assert clean_fragments(iter([" a ", " ", "e\u0301"])) == ["a", "é"]
```

Если это логины, доменные имена или пароли, понадобятся другие правила. Смена регистра и NFKC не должны появляться в общем helper случайно. Функция потребляет одноразовый источник; результат можно обходить повторно, поскольку это готовый список.

### Функции для работы с числами

Явно отделяй корректный ноль от отсутствующего знаменателя. Уточняй, должны ли отклоняться `bool`, отрицательные значения и превышение общего количества.

```python
def percentage(part: int, total: int) -> float:
    """Доля от 0 до 100 для точных целых счётчиков."""
    if type(part) is not int or type(total) is not int:
        raise TypeError("Нужны int без bool")
    if total <= 0 or not 0 <= part <= total:
        raise ValueError("Нужно 0 <= part <= total и total > 0")
    return part / total * 100


assert percentage(0, 10) == 0.0
assert percentage(1, 4) == 25.0
try:
    percentage(0, 0)
except ValueError:
    pass
```

Результат `float` подходит для отображения или измерения доли с оговорённой точностью. Если нужен точный рациональный результат, верни `Fraction`; для фиксированных десятичных правил выбери `Decimal` и правило округления. Форматирование `f'{value:.2f}'` относится к представлению, а не к внутреннему контракту.

### Функции для обработки списков

Уникальность часто определяется ключом записи, а не всем объектом. Следующая функция сохраняет первое вхождение и порядок входа, не меняет исходные элементы и требует хешируемый устойчивый ключ.

```python
from collections.abc import Callable, Hashable, Iterable


def unique_by[T, K: Hashable](values: Iterable[T], key: Callable[[T], K]) -> list[T]:
    seen: set[K] = set()
    result: list[T] = []
    for value in values:
        marker = key(value)
        if marker not in seen:
            seen.add(marker)
            result.append(value)
    return result


rows = [{"id": 1, "v": "first"}, {"id": 2, "v": "b"}, {"id": 1, "v": "last"}]
result = unique_by(rows, key=lambda row: row["id"])
assert [row["v"] for row in result] == ["first", "b"]
assert result[0] is rows[0]
```

Результат содержит исходные объекты: это не глубокая копия. Число уникальных ключей определяет память `seen`; для бесконечного потока без ограниченной области дедупликации такой набор может расти бесконечно. Если важно последнее вхождение, правило и порядок результата будут другими.

### Функции валидации данных

Валидатор получает неизвестный объект и возвращает значение с более узким проверенным контрактом. Не смешивай «значение невозможно разобрать» с «значение отсутствует» без явного правила.

```python
def parse_port(value: object) -> int:
    if type(value) is int:
        port = value
    elif isinstance(value, str):
        text = value.strip()
        if not text or len(text) > 5 or not text.isascii() or not text.isdecimal():
            raise ValueError("Нужна ASCII-запись порта")
        port = int(text)
    else:
        raise TypeError("Нужны целое число или строка")

    if not 1 <= port <= 65_535:
        raise ValueError("Порт вне диапазона 1..65535")
    return port


assert parse_port(" 8080 ") == 8080
assert parse_port(443) == 443
for invalid in [True, "１２", "1.5", "0", 70_000]:
    try:
        parse_port(invalid)
    except (TypeError, ValueError):
        pass
    else:
        raise AssertionError("Неверный порт принят")
```

Проверка ASCII — сознательная политика формата, а не универсальное требование для всех чисел Python. Ограничение длины относится к строковой форме; `"000080"` будет отвергнута, хотя её числовое значение могло бы быть допустимым. Такие решения нужно документировать и проверять отдельными тестами.

### Декоратор для логирования

Библиотечный декоратор принимает logger как зависимость и не настраивает глобальное логирование. По умолчанию лучше писать имя операции и исход без автоматического дампа всех аргументов, где могут находиться токены и большие данные.

```python
import logging
from functools import wraps


def log_calls(logger):
    def decorate(function):
        @wraps(function)
        def wrapper(*args, **kwargs):
            logger.info("Started %s", function.__qualname__)
            try:
                result = function(*args, **kwargs)
            except Exception:
                logger.exception("Failed %s", function.__qualname__)
                raise
            logger.info("Finished %s", function.__qualname__)
            return result

        return wrapper

    return decorate


logger = logging.getLogger("functions.example")
logger.addHandler(logging.NullHandler())
logger.propagate = False


@log_calls(logger)
def add(left, right):
    return left + right


assert add(2, 3) == 5
```

Обёртка рассчитана на синхронную функцию. `except Exception` сохраняет обычный отказ через голый `raise` и не перехватывает все виды завершения. Логирование выполняется на выбранной границе: если каждый слой пишет traceback и затем повторно возбуждает ошибку, один инцидент создаст много дубликатов. Поведение при отказе самого logger зависит от его обработчиков и политики приложения.

### Декоратор для кэширования

Для чистой функции с неизменяемым результатом часто достаточно стандартного `lru_cache`. Нормализацию ключа удобно выполнить перед входом во внутренний кэш, чтобы лишние пробелы не занимали отдельные записи.

```python
from datetime import date
from functools import lru_cache


@lru_cache(maxsize=128)
def _parse_day_canonical(text: str) -> date:
    return date.fromisoformat(text)


def parse_day(text: str) -> date:
    return _parse_day_canonical(text.strip())


assert parse_day("2026-10-17") == date(2026, 10, 17)
assert parse_day(" 2026-10-17 ") == date(2026, 10, 17)
assert _parse_day_canonical.cache_info().hits == 1
```

Контракт здесь допускает формы, которые понимает `date.fromisoformat()` в выбранной версии; это не проверка строго десятисимвольной записи `YYYY-MM-DD`. Если внешний формат требует именно её, сначала проверь форму отдельно. Кэш ограничен числом записей, хранит ключи и объекты `date`; ошибки разбора не превращаются в успешные кэшированные результаты.

Не используй собственный неограниченный словарь в default как «простой кэш» для пользовательских данных. Если нужен TTL, инвалидирование или async, выбери отдельный явно описанный механизм вместо добавления скрытых исключений в этот пример.

**Сквозной проект: функциональный конвейер измерений**

Создадим небольшую библиотеку, которая переводит температуры из C/F/K в градусы Цельсия, нормализует идентификатор датчика, лениво обрабатывает записи и строит итог. Невалидные записи либо останавливают обработку, либо передаются callback. Сбор ошибок — независимое замыкание с ограниченным списком сообщений; измерение длительности — отдельный типизированный декоратор.

В проекте намеренно разделены три роли: чистый parser одной записи, управление потоком с политикой отказа и агрегация проверенных измерений. Источник может быть списком, генератором или адаптером чтения файла. Функции не открывают сеть и не управляют внешним файлом за спиной вызывающего кода.

Контракт:

- Входная запись — отображение с полями `sensor`, `value`, `unit`; дополнительные поля допускаются.
- Идентификатор — строка до 256 кодовых точек до нормализации и от 1 до 64 после NFC и удаления внешних пробелов. Регистр сохраняется.
- Значение — `int`, `float` либо ASCII-строка числа длиной до 64 после удаления пробелов; `bool`, бесконечности и `NaN` отвергаются. Исходный модуль не больше миллиона.
- Единицы C/F/K регистронезависимы. Числовая модель — `float`, подходящая для этого учебного измерительного контракта.
- Температура не может быть ниже абсолютного нуля; отклонение от него до `1e-9` градуса после преобразования считается округлением и прижимается к границе.
- Невалидное содержимое записи вызывает `ValueError`. Ошибка источника и отказ callback распространяются наружу; они не считаются автоматически ошибкой данных.
- Сохраняется не больше заданного числа примеров ошибок, но общий счётчик не обрезается. Снимок диагностики содержит неизменяемые объекты.
- Конвейер выдаёт элементы один раз. Частичное чтение означает частично выполненную обработку; полные счётчики появляются только после полного потребления.

Сохрани в `function_pipeline.py`:

```python
# function_pipeline.py
from __future__ import annotations

import json
import math
import unicodedata
from collections.abc import Callable, Iterable, Iterator, Mapping
from dataclasses import asdict, dataclass
from functools import lru_cache, partial, wraps
from time import perf_counter
from typing import ParamSpec, TypeVar

P = ParamSpec("P")
R = TypeVar("R")


@dataclass(frozen=True)
class Reading:
    sensor: str
    celsius: float


@dataclass(frozen=True)
class Issue:
    row_number: int
    message: str


@dataclass(frozen=True)
class IssueSnapshot:
    rejected: int
    samples: tuple[Issue, ...]


@dataclass(frozen=True)
class Summary:
    count: int
    minimum_c: float | None
    maximum_c: float | None
    mean_c: float | None


@dataclass(frozen=True)
class PipelineResult:
    summary: Summary
    issues: IssueSnapshot


def affine(value: float, /, *, scale: float, offset: float) -> float:
    return value * scale + offset


CONVERTERS: Mapping[str, Callable[[float], float]] = {
    "C": partial(affine, scale=1.0, offset=0.0),
    "F": partial(affine, scale=5 / 9, offset=-32 * 5 / 9),
    "K": partial(affine, scale=1.0, offset=-273.15),
}


@lru_cache(maxsize=128)
def _normalize_sensor_cached(raw: str) -> str:
    normalized = unicodedata.normalize("NFC", raw).strip()
    if not 1 <= len(normalized) <= 64:
        raise ValueError("некорректная длина идентификатора датчика")
    return normalized


def normalize_sensor(value: object) -> str:
    if not isinstance(value, str) or len(value) > 256:
        raise ValueError("некорректный идентификатор датчика")
    return _normalize_sensor_cached(value)


def parse_number(value: object) -> float:
    if isinstance(value, bool):
        raise ValueError("измерение должно быть числом")
    if isinstance(value, str):
        value = value.strip()
        if not value or len(value) > 64 or not value.isascii():
            raise ValueError("некорректная запись измерения")
    elif not isinstance(value, (int, float)):
        raise ValueError("измерение должно быть числом")

    try:
        result = float(value)
    except (ValueError, OverflowError) as error:
        raise ValueError("некорректная запись измерения") from error
    if not math.isfinite(result) or abs(result) > 1_000_000:
        raise ValueError("измерение вне допустимого диапазона")
    return result


def parse_reading(row: Mapping[str, object]) -> Reading:
    sensor = normalize_sensor(row.get("sensor"))
    raw_unit = row.get("unit")
    if not isinstance(raw_unit, str):
        raise ValueError("неизвестная единица измерения")
    converter = CONVERTERS.get(raw_unit.strip().upper())
    if converter is None:
        raise ValueError("неизвестная единица измерения")

    celsius = converter(parse_number(row.get("value")))
    if celsius < -273.15:
        if math.isclose(celsius, -273.15, rel_tol=0.0, abs_tol=1e-9):
            celsius = -273.15
        else:
            raise ValueError("температура ниже абсолютного нуля")
    return Reading(sensor, celsius)


def make_issue_collector(
    *,
    limit: int = 20,
) -> tuple[Callable[[int, str], None], Callable[[], IssueSnapshot]]:
    if type(limit) is not int:
        raise TypeError("limit должен быть int без bool")
    if limit < 0:
        raise ValueError("limit не может быть отрицательным")
    rejected = 0
    samples: list[Issue] = []

    def record(row_number: int, message: str) -> None:
        nonlocal rejected
        rejected += 1
        if len(samples) < limit:
            samples.append(Issue(row_number, message))

    def snapshot() -> IssueSnapshot:
        return IssueSnapshot(rejected, tuple(samples))

    return record, snapshot


def iter_readings(
    rows: Iterable[Mapping[str, object]],
    *,
    parser: Callable[[Mapping[str, object]], Reading] = parse_reading,
    reject: Callable[[int, str], None] | None = None,
) -> Iterator[Reading]:
    for row_number, row in enumerate(rows, start=1):
        try:
            reading = parser(row)
        except ValueError as error:
            if reject is None:
                raise
            reject(row_number, str(error))
            continue
        yield reading


def summarize(readings: Iterable[Reading]) -> Summary:
    count = 0
    minimum = maximum = None
    mean = 0.0
    for reading in readings:
        value = reading.celsius
        count += 1
        minimum = value if minimum is None else min(minimum, value)
        maximum = value if maximum is None else max(maximum, value)
        mean += (value - mean) / count
    return Summary(count, minimum, maximum, mean if count else None)


def build_report(
    rows: Iterable[Mapping[str, object]], *, max_errors: int = 20
) -> PipelineResult:
    reject, snapshot = make_issue_collector(limit=max_errors)
    summary = summarize(iter_readings(rows, reject=reject))
    return PipelineResult(summary, snapshot())


def timed(
    *,
    emit: Callable[[str, float, bool], None],
    clock: Callable[[], float] = perf_counter,
) -> Callable[[Callable[P, R]], Callable[P, R]]:
    def decorate(function: Callable[P, R]) -> Callable[P, R]:
        @wraps(function)
        def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
            started = clock()
            succeeded = False
            try:
                result = function(*args, **kwargs)
                succeeded = True
                return result
            finally:
                emit(function.__qualname__, clock() - started, succeeded)

        return wrapper

    return decorate


def demo() -> PipelineResult:
    rows: list[Mapping[str, object]] = [
        {"sensor": " room ", "value": "32", "unit": "F"},
        {"sensor": "cafe\u0301", "value": 273.15, "unit": "K"},
        {"sensor": "outdoor", "value": 25, "unit": "C"},
        {"sensor": "x", "value": True, "unit": "C"},
        {"sensor": "x", "value": 0, "unit": "R"},
    ]
    return build_report(iter(rows))


if __name__ == "__main__":
    print(json.dumps(asdict(demo()), ensure_ascii=False, indent=2, allow_nan=False))
```

`Mapping` описывает интерфейс таблицы преобразований, но не делает фактический словарь `CONVERTERS` неизменяемым во время выполнения. Это модульная таблица с политикой «не изменять после загрузки»; если сторонний код должен получать защищённое представление, можно использовать `MappingProxyType` и не публиковать исходный словарь. Сами `partial` тоже не превращаются в глубоко неизменяемые объекты.

Кэш нормализации ограничен и возвращает неизменяемые строки. Для конкретной нагрузки польза такого кэша должна измеряться: нормализация короткого уникального идентификатора может быть дешевле хранения и поиска. Он включён в проект, чтобы показать место чистой функции и ограниченное время жизни её сохранённых результатов.

`timed` рассчитан на обычную синхронную функцию. Он измеряет весь `build_report()`, потому что эта функция потребляет поток до конца. Если применить его к `iter_readings`, измеряться будет создание генератора. Зависимости `clock` и `emit` должны соответствовать своему контракту и не возбуждать исключений; иначе их ошибка может заменить исходный исход. Это сознательно fail-fast контракт телеметрии примера, не универсальная политика логирования.

`summarize()` рассчитывает на уже проверенные `Reading`, как и обещает разбиение слоёв. Конструктор dataclass сам не проверяет конечность: произвольный пользовательский parser обязан соблюдать контракт. Для измерений усреднение является приближённым и не гарантирует побитовую независимость от порядка входа.

## Частые вопросы и выводы

### Что вернет функция без return?

Обычная функция, дошедшая до конца, возвращает `None`; то же делает `return` без выражения. Если функция возбудила исключение, нормального результата нет. Для `async def` нормальное завершение без значения даёт `None` после `await`, а генераторная функция при вызове сначала возвращает generator object.

```python
def ordinary():
    pass


def generator_function():
    if False:
        yield 1


assert ordinary() is None
generator = generator_function()
assert generator is not None
assert list(generator) == []
```

Наличие `yield` определяет вид функции даже при недостижимой ветви. Поэтому вопрос о возвращаемом значении сначала требует уточнения: результат вызова, элемент потока или результат завершения генератора.

### Можно ли перегружать функции в Python?

Повторный `def` с тем же именем в одной области перепривязывает имя; автоматического набора реализаций по сигнатурам не создаётся. Вызов не выбирает между всеми прежними определениями, как в некоторых статически типизированных языках.

```python
def parse(value):
    return "first"


first = parse


def parse(value, *, strict=False):
    return "second", strict


assert first(1) == "first"
assert parse(1) == ("second", False)
```

Варианты проектирования: одна функция с defaults, явная проверка формы, `singledispatch` по первому типу или отдельные именованные функции. `typing.overload` описывает несколько статических вариантов одного API, после которых идёт одна runtime-реализация; сам декоратор не выполняет диспетчеризацию.

```python
from typing import overload


@overload
def first(value: str) -> str: ...


@overload
def first(value: list[int]) -> int: ...


def first(value: str | list[int]) -> str | int:
    if not value:
        raise ValueError("Пустой вход")
    return value[0]


assert first("abc") == "a"
assert first([1, 2]) == 1
```

Перегрузка операторов через специальные методы — ещё один отдельный механизм, описанный в модели данных. Не смешивай его со статическим `overload` и реестром `singledispatch`.

### В чем разница между параметром и аргументом?

Параметр существует в определении, аргумент — в конкретном вызове. В `def scale(value, factor=2)` есть параметры `value`, `factor`, а в `scale(10, factor=3)` переданы аргументы `10` и `3`. Default — значение на случай отсутствующего аргумента, а не третий аргумент каждого вызова.

Формальные виды параметров определяют, как связываются позиционные и именованные аргументы. Отдельно аннотации описывают допустимые значения, а runtime-проверки обеспечивают требуемые инварианты внешних данных.

### Как передать функцию как аргумент?

Передай вызываемый объект без выполнения: `apply(transform, value)`. Запись `apply(transform(value), ...)` сначала выполнит преобразование и передаст его результат. Если нужно заранее связать часть аргументов, используй `partial` или фабрику замыкания.

```python
from collections.abc import Callable


def apply[T, R](function: Callable[[T], R], value: T) -> R:
    return function(value)


assert apply(abs, -5) == 5
assert apply(str.upper, "python") == "PYTHON"
```

Получатель callback должен документировать число вызовов, допустимые ошибки, синхронность и возможность мутации. Это особенно важно, когда callback будет выполнен позже или в другом потоке: успешная регистрация ещё не означает успешное выполнение.

### Как узнать, является ли объект функцией?

Для обычной Python-функции используй `inspect.isfunction()`, для связанного Python-метода — `inspect.ismethod()`, для встроенной функции — `inspect.isbuiltin()`. `isgeneratorfunction()` и `iscoroutinefunction()` отвечают на более узкие вопросы о модели выполнения.

Если требуется просто вызвать объект по протоколу, проверка именно на функцию может быть лишней: метод, `partial` и экземпляр с `__call__` подходят по смыслу не хуже. Для доверенного внутреннего кода достаточно типового контракта, для внешнего plugin API нужны дополнительные проверки и понятная обработка отказов.

### Что такое callable объект?

Это объект, для которого определён механизм вызова. Функции, классы и некоторые экземпляры являются callable. Проверка `callable()` не подтверждает нужную сигнатуру и не гарантирует, что вызов не возбудит исключение.

```python
class BrokenOperation:
    def __call__(self, value):
        raise RuntimeError("Operation unavailable")


operation = BrokenOperation()
assert callable(operation)
try:
    operation(1)
except RuntimeError:
    pass
```

Соответствие интерфейсу проверяется сигнатурой, типами, документацией и поведением по мере необходимости. Нельзя вызвать произвольный объект «для проверки», если его действие может иметь нежелательный побочный эффект.

### Сколько параметров может быть у функции?

Ориентироваться на старое универсальное ограничение «не больше 255» нельзя: технические ограничения менялись и зависят от версии и реализации. Для прикладного API практический предел достигается намного раньше — когда интерфейс трудно понять и невозможно безопасно вызвать без постоянного сверения.

`*args` и `**kwargs` не снимают ограничения памяти и сложности. Огромная распаковка сначала создаёт аргументы вызова; для потока лучше передать один `Iterable` и обрабатывать его постепенно. Для связанных настроек используй отдельную модель, для независимых режимов — отдельные функции, если они упрощают контракт.

### Резюме по разделу функций

Функция — объект с кодом, окружением, метаданными и контрактом. Вызов связывает аргументы с параметрами; присваивание параметру и мутация объекта имеют разное влияние на вызывающий код. Defaults относятся к определению функции, свободные переменные обычно читаются при выполнении, а аннотации имеют зависящую от версии модель вычисления.

Высшие функции и декораторы позволяют собирать поведение из небольших операций. Для прозрачной обёртки недостаточно `*args`, `**kwargs` и `wraps`: нужно сохранить результат, ошибки, типовую связь, модель ожидания и ресурсный протокол. Кэш требует осмысленного ключа, ограничения памяти и политики устаревания.

Генератор откладывает вычисление и сохраняет состояние; корутина откладывает асинхронное выполнение, а Task делает его планируемым. Ни ленивость, ни асинхронность сами по себе не гарантируют ограниченную память, параллельное CPU-ускорение или автоматическое закрытие всех ресурсов.

**Критерий понимания:** ты можешь объяснить не только результат успешного вызова, но и момент вычисления, владельца состояния, возможные частичные эффекты, ошибочный выход и поведение при повторном использовании объекта выполнения.
