# 2. Синтаксис и базовые конструкции

Эта глава объясняет, как читать и писать Python-код: от токенов и присваивания до структурного сопоставления, исключений и ленивой обработки данных. Цель — понимать результат программы и уметь обосновать выбор конструкции, типа данных и способа обработки ошибки.

Материал рассчитан на Python 3.12–3.14. Основная версия для проверки — CPython 3.14.8; возможности, появившиеся после 3.12, отмечены отдельно. Здесь не используются экспериментальные особенности реализации. Операции с объектами опираются на [главу «Фундамент»](01.%20fundamental.md); устройство функций, замыканий и генераторов подробно продолжается в [главе «Функции»](03.%20functions.md).

Каждый короткий Python-пример можно запускать отдельно. Намеренные ошибки перехвачены; некорректный синтаксис исследуется через `compile()` над заранее заданной строкой. Таблицы сложности описывают обычные операции встроенных коллекций CPython; они не превращают стоимость произвольного пользовательского `__eq__` или `__hash__` в константу.

## Лексическая структура и грамматика Python

### Ключевые слова и мягкие ключевые слова — soft keywords

Интерпретатор сначала выделяет токены: имена, числа, строки, операторы, разделители и элементы структуры блоков. Грамматика определяет, какие последовательности токенов образуют программу. Поэтому сообщение `SyntaxError` относится к форме кода, а `NameError` обычно возникает уже при исполнении корректно разобранного кода.

Ключевое слово зарезервировано во всех синтаксических контекстах: нельзя назвать переменную `class`, `return`, `for` или `None`. Регистр значим: `True` — встроенная константа, а `true` — обычное имя, которое само по себе не определено.

Мягкое ключевое слово имеет специальное значение только внутри определённой конструкции. В рассматриваемых версиях это `match`, `case`, `_` и `type`: `type` участвует в инструкции создания псевдонима типа начиная с 3.12. В другом месте `match = 10` допустимо.

```python
import keyword

assert keyword.iskeyword("for")
assert not keyword.iskeyword("match")
assert keyword.issoftkeyword("match")
assert keyword.issoftkeyword("type")

match = "обычное имя"
print(match)  # обычное имя

try:
    compile("class = 10", "<example>", "exec")
except SyntaxError:
    print("Ключевое слово нельзя использовать как имя")
```

`list`, `str`, `sum`, `id` и `type` как имя встроенной функции не защищены от переопределения. Присваивание `list = []` синтаксически корректно, но последующий вызов `list(...)` обратится к этому списку. Актуальные наборы слов доступны как `keyword.kwlist` и `keyword.softkwlist`; не проверяй их вручную скопированным списком из старого учебника.

### Идентификаторы, Unicode и соглашения об именах

Идентификатор связывает имя с объектом. Он не может начинаться с цифры, содержать пробел или дефис. Допустимость Unicode-идентификаторов определяется специальными категориями символов, а не правилом «любой символ, который выглядит как буква». `str.isidentifier()` проверяет форму, но отдельно нужно исключить ключевые слова.

```python
import keyword

for candidate in ["user_id", "сумма", "2users", "user-name", "class"]:
    valid = candidate.isidentifier() and not keyword.iskeyword(candidate)
    print(candidate, valid)

# При разборе исходного кода имена нормализуются в NFKC.
K = 10  # U+212A KELVIN SIGN
assert K == 10
```

Нормализация идентификаторов не означает, что Python автоматически нормализует все строки или имена, переданные в `getattr()`. Латинская `a` и кириллическая `а` визуально похожи, но обычно остаются разными символами. Для общего кода команды выбирай предсказуемые ASCII-имена и проверяй подозрительные символы при ревью.

| Форма | Обычный смысл |
| --- | --- |
| `user_name`, `read_config` | Переменная или функция |
| `UserProfile` | Класс |
| `MAX_RETRIES` | Константа по соглашению |
| `_cache` | Непубличная часть API по соглашению |
| `class_` | Имя, избегающее конфликта с ключевым словом |
| `__name` внутри класса | Преобразование имени для уменьшения конфликтов наследования |
| `__iter__`, `__len__` | Документированные специальные имена |

Не придумывай собственные dunder-имена без необходимости: этот набор предназначен для протоколов языка. `_` часто обозначает неиспользуемое значение, но вне pattern matching остаётся обычным именем. В приложениях с переводами `_` может быть функцией `gettext`.

### Логические строки, отступы, явное и неявное продолжение строки

Физическая строка заканчивается переводом строки в файле. Логическая строка содержит синтаксически законченную инструкцию и может занимать несколько физических строк. Внутри `()`, `[]` и `{}` переносы разрешены без обратной косой черты.

```python
subtotal = 1_000
delivery = 200
discount = 150

total = (
    subtotal
    + delivery  # Комментарий внутри продолженного выражения допустим.
    - discount
)
assert total == 1_050

permissions = [
    "read",
    "write",
]
```

Последняя запятая облегчает изменение многострочных коллекций и уменьшает diff. В круглых скобках она может менять тип: `(10)` — число, `(10,)` — кортеж.

Обратная косая черта в конце строки тоже продолжает инструкцию, но после неё нельзя поставить комментарий или пробел. Обычно скобки удобнее. Не путай продолжение исходного кода с `\n` внутри строки: первое меняет размещение кода, второе создаёт символ в данных.

Отступ определяет вложенность. Язык не требует именно четырёх пробелов, однако это стандартное соглашение. Смешение табуляции и пробелов может вызвать `TabError`; изменение отступа способно изменить поведение корректной программы. Настрой редактор на четыре пробела и автоматическое форматирование.

```python
ready = True
if ready:
    print("Внутри условия")
print("После условия")
```

Точка с запятой позволяет разместить несколько простых инструкций в одной строке, но затрудняет чтение. После двоеточия одно строковое тело тоже допустимо; для ветвлений и проверок используй обычные многострочные блоки.

### Комментарии, docstrings и кодировка исходного файла

Комментарий начинается с `#` вне строкового литерала и заканчивается на физическом конце строки. Он должен объяснять причину, ограничение или договорённость, которую нельзя быстро вывести из самого кода.

Docstring — строковый литерал в начале модуля, класса или функции. Он доступен через `__doc__` и используется `help()` и инструментами документации. Любая другая строка в тройных кавычках не становится docstring автоматически и не является особым видом комментария.

```python
def normalize_login(value: str) -> str:
    """Вернуть логин без внешних пробелов в регистронезависимой форме."""
    # Casefold нужен для Unicode-сравнения без учёта регистра.
    return value.strip().casefold()


assert normalize_login("  ALICE ") == "alice"
assert "логин" in normalize_login.__doc__
```

Исходные `.py`-файлы по умолчанию читаются как UTF-8. Объявление `# -*- coding: utf-8 -*-` обычно избыточно; при другой кодировке специальный комментарий размещается в первой или второй строке по правилам объявления кодировки. Shebang вроде `#!/usr/bin/env python3` относится к запуску файла операционной системой.

Кодировка исходника не устанавливает кодировку всех файлов приложения. Для текстовых данных задавай её явно: `open(path, encoding="utf-8")`. `python -OO` может удалить docstrings: не помещай в них данные, необходимые для корректности приложения.

### Литералы, префиксы строк, escape-последовательности и сырые строки

Литерал — запись значения непосредственно в коде. Для целых доступны десятичная, двоичная `0b`, восьмеричная `0o` и шестнадцатеричная `0x` формы; подчёркивания разделяют разряды. Запись `-10` грамматически содержит унарный минус и положительный числовой литерал. `{}` создаёт словарь, а пустое множество создаётся как `set()`.

```python
assert 1_000 == 0b1111101000 == 0o1750 == 0x3E8
assert 1.5e2 == 150.0
assert (2 + 3j).imag == 3.0

text = "first\nsecond"
raw = r"first\nsecond"
assert len(text) == 12
assert len(raw) == 13
assert raw == "first\\nsecond"
assert "\N{SNOWMAN}" == "\u2603" == "☃"
```

| Префикс | Результат и назначение |
| --- | --- |
| Без префикса | `str`, текст Unicode |
| `r` | Правила raw-строки: обратная косая черта обычно сохраняется |
| `b` | `bytes`, последовательность байтов |
| `f` | `str` с вычислением выражений и форматированием |
| `u` | Тот же `str`; историческая совместимость |
| `t`, Python 3.14+ | Объект `Template`, сохраняющий структуру интерполяции |

Допустимы комбинации `rf`, `fr`, `rb`, `br`, а в 3.14 также `rt` и `tr`; `bf` не существует. Префикс нечувствителен к регистру. Bytes-литерал содержит непосредственно только ASCII-символы; произвольные байты записываются escape-последовательностями или получаются кодированием текста.

Raw-строка не может оканчиваться нечётным количеством обратных косых черт: последняя повлияла бы на закрывающую кавычку. `r"C:\temp"` допустима; для пути с завершающим разделителем используй, например, `"C:\\temp\\"` или `pathlib`. В `rf`-строке raw-правило относится к текстовым частям, а не отключает разбор выражений в `{...}`. Неизвестные escape-последовательности не используй: в современных версиях они диагностируются и могут стать ошибкой синтаксиса.

Соседние строковые литералы объединяются: `("hello " "world")`. Это удобно в длинных сообщениях, но пропущенная запятая в списке `['a' 'b']` незаметно создаст один элемент `'ab'`.

### Выражения vs инструкции; присваивание, del и оператор :=

Выражение вычисляется в значение: `2 + 3`, вызов функции, индексирование, условное выражение. Инструкция управляет исполнением и связыванием имён: присваивание, `if`, `for`, `del`, `return`. Вызов `print()` является выражением с результатом `None`, даже если обычно используется как самостоятельная инструкция.

Обычное `=` не возвращает присвоенное значение. Сначала вычисляется правая часть, затем выполняются присваивания целям. Целью могут быть имя, атрибут или элемент коллекции; последние два случая способны вызвать пользовательский код.

```python
values = [10, 20]
alias = values
del values
assert alias == [10, 20]

del alias[0]
assert alias == [20]

text = "hello"
if (length := len(text)) >= 5:
    print(length)  # 5
```

`del name` удаляет привязку имени, а `del container[index]` просит контейнер удалить элемент. Ни одна форма не обещает немедленного освобождения памяти объекта. Имя может исчезнуть, пока другие ссылки продолжают удерживать объект.

Оператор `:=`, доступный с 3.8, связывает простое имя и возвращает значение. Он не присваивает атрибуту, индексу или распаковке. В некоторых контекстах нужны скобки. Используй его, если он устраняет повторное вычисление и не делает условие трудно читаемым.

```python
for source in ["if x = 1:\n    pass", "(data[0] := 1)"]:
    try:
        compile(source, "<invalid>", "exec")
    except SyntaxError:
        print("Ожидаемая ошибка синтаксиса")
```

## Переменные

### Основы переменных

Переменная в Python — имя, связанное с объектом. Объект имеет тип, значение и идентичность. Имя не является заранее выделенной ячейкой с неизменным типом: после `x = 10` можно выполнить `x = "text"`, создав другую привязку.

```python
count = 10
assert type(count) is int

count = "ten"
assert type(count) is str

try:
    print(undefined_name)
except NameError:
    print("Имя ещё не определено")
```

Объявление без значения не создаёт объект автоматически. Даже `count: int` само по себе не связывает имя со значением. Выбирай имена по смыслу: `retry_count`, `elapsed_seconds`, `price_minor`. Указание единицы измерения предотвращает более серьёзные ошибки, чем косметическое сокращение имени.

### Правила именования

Имя должно быть допустимым идентификатором и не совпадать с ключевым словом. Помимо синтаксиса важен контракт: `users` ожидаемо содержит несколько пользователей, `is_active` — признак, `parse_config` — действие с результатом. Не используй `l`, `O` и `I` там, где их можно спутать с цифрами.

Не называй переменную встроенным типом или функцией, если это скрывает нужный API:

```python
import builtins

list = [1, 2]  # Технически допустимо, для рабочего кода имя неудачно.
try:
    list("abc")
except TypeError:
    print("Встроенное имя скрыто списком")

assert builtins.list("abc") == ["a", "b", "c"]
del list
assert list("ab") == ["a", "b"]
```

`builtins` полезен для диагностики, но обычное исправление — переименовать переменную. Не кодируй тип механически в каждом имени (`str_user_name`): он может поменяться, а лишний префикс останется. Смысл, единицы и роль обычно полезнее.

### Динамическая типизация

Тип принадлежит объекту; проверка допустимости операции часто происходит во время выполнения. Динамическая типизация не означает автоматическое согласование любых значений: Python не складывает строку и число по догадке.

```python
value = 10
value = "10"

try:
    result = value + 5
except TypeError:
    print("Для сложения нужны совместимые операнды")

assert int(value) + 5 == 15
assert value + str(5) == "105"
```

Duck typing позволяет работать с поведением объекта: функции, которой нужна итерация, не обязательно нужен именно `list`. Это не снимает требования к данным. «Объект можно итерировать» и «каждый его элемент является положительной целой суммой» — разные контракты. Внешние данные нужно валидировать независимо от аннотаций.

### Множественное присвоение

Цепочка `a = b = value` привязывает несколько имён к одному результату. Распаковка `a, b = iterable` извлекает отдельные элементы. При обычной распаковке число элементов должно совпасть; звёздная цель собирает остаток в новый список.

```python
left = right = []
left.append(1)
assert right == [1]
assert left is right

a, b = 1, 2
a, b = b, a
assert (a, b) == (2, 1)

first, *middle, last = range(5)
assert (first, middle, last) == (0, [1, 2, 3], 4)

point = (10, (20, 30))
x, (y, z) = point
assert (x, y, z) == (10, 20, 30)
```

Правая часть вычисляется до изменения целей, поэтому обмен корректен. Но множественное присваивание не является транзакцией: присваивание сложным целям идёт по порядку, и ошибка на поздней цели не откатывает предыдущие изменения.

```python
values = [0]
first = "old"
try:
    first, values[10] = "new", 99
except IndexError:
    pass
assert first == "new"
assert values == [0]
```

Одна распаковка может содержать не более одной звёздной цели на данном уровне. Не распаковывай в `head, *rest` очень большой или бесконечный источник: остаток материализуется целиком.

### Константы

Имена в верхнем регистре — соглашение, а не запрет изменения. `typing.Final` сообщает статическому анализатору намерение не перепривязывать имя; интерпретатор не превращает его в защищённую ячейку.

```python
from typing import Final

MAX_RETRIES: Final[int] = 3
DEFAULT_ROLES: Final[tuple[str, ...]] = ("reader",)
assert MAX_RETRIES == 3
```

`Final[list[str]]` не делает список неизменяемым. Константная привязка и неизменяемый объект — разные свойства. Для фиксированного набора используй `tuple`, `frozenset`, а для именованных вариантов состояния — `Enum`. Неизменяемый контейнер тоже может ссылаться на изменяемые объекты, поэтому глубокую неизменяемость нужно проектировать отдельно.

### Понимание ссылок

Присваивание передаёт ссылку на объект. Копирование контейнера нужно запрашивать отдельно, и обычная копия поверхностна: внешний контейнер новый, вложенные элементы прежние.

```python
original = [[1], [2]]
alias = original
shallow = original.copy()

assert alias is original
assert shallow is not original
assert shallow[0] is original[0]

shallow[0].append(99)
assert original == [[1, 99], [2]]

shallow.append([3])
assert len(original) == 2
```

```python
from copy import deepcopy

original = [[1], [2]]
independent = deepcopy(original)
independent[0].append(99)
assert original == [[1], [2]]
```

`deepcopy()` не является универсальным клонированием ресурсов: сокеты, файлы, соединения и внешнее состояние требуют своего жизненного цикла. Он также сохраняет отношения совместного использования внутри копируемого графа там, где это возможно. Выбирай копию по требуемой независимости, а не по принципу «глубже значит лучше».

Перепривязка и мутация различаются: `items = items + [x]` создаёт новый список, а `items.append(x)` меняет существующий. Именно поэтому изменения могут быть видны вызывающему коду через другие ссылки.

### Аннотации типов (type hints)

Аннотация описывает ожидаемый контракт для человека и анализатора. Она не преобразует значение и не проверяет вход автоматически. Начиная с 3.9 встроенные коллекции можно параметризовать как `list[int]`; с 3.10 объединение типов записывается `int | None`.

```python
def total(values: list[int]) -> int:
    return sum(values)


assert total([1, 2, 3]) == 6

age: int = "unknown"  # Статический анализатор сообщит ошибку.
assert isinstance(age, str)  # Во время выполнения присваивание состоялось.
```

Для читающей функции часто подходит `Iterable[int]`, для многократного обхода и индексирования — `Sequence[int]`, для словаря, который не нужно менять, — `Mapping[str, int]`. Эти формы точнее описывают потребности, чем безусловный `list` или `dict`.

`Any` выключает значительную часть статических проверок для соответствующего значения; `object` означает неизвестный объект, операции с которым нужно предварительно обосновать. `list[int]` нельзя использовать как обычный второй аргумент `isinstance()` для проверки всех элементов. Проверка контейнера и проверка содержимого — отдельные действия.

В 3.14 изменена стандартная модель вычисления аннотаций: нельзя переносить предположения о времени их вычисления и содержимом `__annotations__` из старого кода. Для их программной обработки применяй документированные средства `annotationlib` и `typing.get_type_hints()` с пониманием того, что разрешение аннотаций может выполнять код. Подробности относятся к главам о функциях и типизации.

### Область видимости

Для обычного кода функций полезна схема LEGB: локальная область, охватывающие функции, глобальная область модуля, встроенные имена. Это ориентир для поиска имён, а не универсальная модель всех специальных областей классов, включений и аннотаций.

Присваивание имени внутри функции обычно делает его локальным во всей функции. Поэтому чтение до присваивания вызывает `UnboundLocalError`, даже если снаружи есть одноимённое значение.

```python
count = 10


def broken():
    print(count)
    count = 20


try:
    broken()
except UnboundLocalError:
    print("Локальное имя прочитано до присваивания")

assert count == 10
```

`global` меняет место перепривязки на область модуля; `nonlocal` обращается к существующей привязке в охватывающей функции. Чтобы изменить элемент уже найденного списка, `global` обычно не нужен: имя не перепривязывается.

```python
def make_counter():
    count = 0

    def increment():
        nonlocal count
        count += 1
        return count

    return increment


counter = make_counter()
assert counter() == 1
assert counter() == 2

for last in range(3):
    pass
assert last == 2  # for не создаёт отдельную область.
```

Блоки `if`, `for`, `while`, `try` и `with` отдельной области имён не создают. Имя из `except ... as error` после обработчика очищается. Переменные итерации включений в Python 3 наружу не выходят; `:=` внутри включения имеет отдельное правило, разобранное далее.

### Производительность

Присваивание имени обычно не копирует объект, поэтому передача большого списка не означает копирования всех элементов. Но `data[:]`, `list(data)` или `deepcopy(data)` уже выполняют работу другого масштаба. Цена операции определяется тем, что реально происходит с данными.

В CPython доступ к локальным именам может отличаться от поиска глобального или атрибута, однако конкретные оптимизации зависят от версии и прогрева. Не превращай функции в набор псевдонимов встроенных операций без измерения. Существеннее часто оказываются повторное чтение файла, квадратичная обработка списка и ненужная материализация.

```python
from timeit import repeat

values = list(range(10_000))
durations = repeat(lambda: sum(values), number=100, repeat=3)
assert all(duration >= 0 for duration in durations)
print(f"Лучшее время: {min(durations):.6f} с")
```

Измеряй реальную нагрузку на нужной версии Python, отделяй подготовку данных от измеряемой части и сравнивай несколько повторов. `sys.getsizeof()` показывает размер непосредственно данного объекта, а не всего графа ссылок. Отдельная короткая операция не обязана ускорить приложение в целом.

### Частые вопросы и ключевые выводы

**Меняет ли `x = other` прежний объект `x`?** Нет, имя получает другую привязку. Для изменения объекта нужна операция мутации.

**Нужно ли объявлять переменные?** Обычно достаточно присваивания. Аннотация полезна для контракта, но не заменяет инициализацию.

**Почему меняется исходный список через другое имя?** Оба имени могут ссылаться на один объект или на общий вложенный объект после поверхностной копии.

**Когда нужен `global`?** Для перепривязки имени модуля из функции. Если состояние можно передать аргументом и вернуть явно, такой интерфейс обычно легче проверять.

**Самопроверка:** объясни результат без запуска, затем проверь:

```python
a = [1]
b = a
a = a + [2]
assert a == [1, 2]
assert b == [1]

c = [1]
d = c
c += [2]
assert c is d
assert d == [1, 2]
```

У этих двух фрагментов одинаковое новое содержимое первого имени, но разное влияние на другие ссылки. Это базовое различие нужно понимать до использования изменяемых параметров, кэшей и общих структур данных.

**Документация:** [модель выполнения](https://docs.python.org/3.14/reference/executionmodel.html), [копирование](https://docs.python.org/3.14/library/copy.html), [typing](https://docs.python.org/3.14/library/typing.html), [annotationlib](https://docs.python.org/3.14/library/annotationlib.html).

## Типы данных

### Основы типов данных

Тип определяет допустимые операции, представление значения и участие в протоколах. Практически важны четыре независимых вопроса: изменяем ли объект, хешируем ли он, поддерживает ли порядок и можно ли его многократно обходить. Ответ на один вопрос не определяет остальные.

Например, `tuple` неизменяем, но кортеж со списком внутри нехешируем; `set` изменяем и итерируем, однако не является последовательностью; генератор итерируем, но одноразовый. Не выбирай структуру только по сходству записи литерала.

```python
assert type(10) is int
assert isinstance(True, int)
assert isinstance("text", str)

try:
    hash(([1],))
except TypeError:
    print("Не каждый кортеж хешируем")
```

Хешируемый объект должен иметь хеш, не меняющийся за время его использования как ключа, и согласованные операции равенства и хеширования: равные объекты обязаны иметь одинаковый хеш. Пользовательский изменяемый объект иногда формально хешируем по идентичности; это не делает его состояние неизменяемым.

### Числовые типы (Numeric Types)

`int` хранит целые с произвольной точностью в пределах доступных ресурсов. Переполнение фиксированного 32- или 64-битного регистра для обычного сложения не происходит, но размер и стоимость вычислений растут с длиной числа. Ограничение преобразования очень длинных десятичных строк — отдельная защитная мера CPython, а не предел значения `int`.

```python
large = 2**200
assert large.bit_length() == 201
assert int("ff", 16) == 255
assert int("0b101", 0) == 5
assert divmod(-7, 3) == (-3, 2)
assert -7 == (-7 // 3) * 3 + (-7 % 3)
```

`float` в обычных сборках CPython — двоичная плавающая точка двойной точности. Он представляет конечный набор значений, а также бесконечности и `NaN`. Это не точная запись любого десятичного числа. `complex` состоит из действительной и мнимой частей; литерал мнимой части использует `j`, а не `i`.

```python
import math
import sys

assert sys.float_info.radix == 2
assert math.isinf(float("inf"))
assert math.isnan(float("nan"))

z = 3 + 4j
assert abs(z) == 5.0
assert z.conjugate() == 3 - 4j

try:
    print(z < 10)
except TypeError:
    print("Для complex не определён обычный порядок")
```

Для десятичной арифметики есть `decimal.Decimal`, для точных рациональных чисел — `fractions.Fraction`. Это разные модели, не просто «более точный float». Числовые типы не обязаны произвольно смешиваться: например, сложение `Decimal` и `float` отвергается, чтобы не скрыть неоднозначность преобразования.

### Численная корректность вычислений

Сначала выбери модель величины: счётчик, целое количество минимальных денежных единиц, десятичную величину с правилами округления, измерение с погрешностью или точную дробь. После этого выбирай тип и критерий сравнения.

```python
import math
from decimal import Decimal, ROUND_HALF_UP
from fractions import Fraction

assert 0.1 + 0.2 != 0.3
assert math.isclose(0.1 + 0.2, 0.3, rel_tol=1e-12)
assert math.isclose(1e-12, 0.0, abs_tol=1e-9)

assert Decimal("0.1") + Decimal("0.2") == Decimal("0.3")
assert Decimal(0.1) != Decimal("0.1")
assert Fraction(1, 3) * 3 == 1
assert Fraction("0.1") == Fraction(1, 10)

rounded = Decimal("2.345").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
assert rounded == Decimal("2.35")
```

`Decimal(0.1)` точно переносит уже приближённое двоичное значение. Если исходный контракт десятичный, создавай `Decimal` из строки или целого. Арифметика `Decimal` зависит от контекста точности и округления; конструктор строки сам по себе не гарантирует, что любая последующая операция останется точной.

```python
import math
from decimal import Decimal, localcontext

with localcontext() as context:
    context.prec = 6
    assert Decimal(1) / Decimal(7) == Decimal("0.142857")

values = [1e16, 1.0, -1e16]
naive_total = 0.0
for value in values:
    naive_total += value
assert naive_total == 0.0
assert math.fsum(values) == 1.0
assert round(2.5) == 2
assert round(3.5) == 4
assert round(2.675, 2) == 2.67
```

`round()` для встроенных чисел использует округление ближайшего значения с выбором чётного на точной середине. Число `2.675` в `float` уже не равно точной десятичной дроби `2.675`. Форматирование до двух знаков меняет представление, но не исходное значение.

Современный `sum()` для `float` использует улучшенный алгоритм суммирования, поэтому он не обязан совпадать с показанным наивным циклом. Ни улучшенный алгоритм, ни `fsum()` не делают все последующие вычисления точной вещественной арифметикой.

Условия `isclose()` должны соответствовать масштабу задачи. При сравнении с нулём часто нужна абсолютная погрешность: одна относительная не помогает для ненулевого малого числа и нуля. Не объявляй два числа «равными с эпсилон» без определения единиц, масштаба и допустимой ошибки.

```python
import math

nan = float("nan")
assert nan != nan
assert not (nan < 1 or nan >= 1)
assert 0.0 == -0.0
assert math.copysign(1.0, -0.0) == -1.0
```

Перед сортировкой, агрегацией или сериализацией внешних чисел реши, допустимы ли `NaN` и бесконечности. В некоторых форматах они недопустимы, а при сравнениях нарушают привычные ожидания. Для денежных расчётов учитывай также валюту и место округления: округлить каждую строку и округлить общий итог — разные правила.

### Логический тип (bool)

`bool` имеет два значения: `True` и `False`. Он является подклассом `int`, поэтому `True + True == 2` и `isinstance(True, int)` истинно. Это удобно для подсчёта условий, но опасно при проверке внешнего поля «целое количество».

```python
assert sum(value > 0 for value in [-2, 0, 3, 4]) == 2
assert int(True) == 1
assert bool("False") is True
assert bool("0") is True
assert bool("") is False


def is_quantity(value: object) -> bool:
    return type(value) is int and value > 0


assert is_quantity(3)
assert not is_quantity(True)
```

Непустая строка истинна независимо от написанного в ней слова. Для конфигурации определи разрешённые формы явно, например `{"true", "false"}`, и отвергай неизвестные. Не используй битовые операции как замену логическим без понимания типов и отсутствия короткого замыкания.

### Текстовый тип (str)

`str` — неизменяемая последовательность кодовых точек Unicode. Это не массив байтов и не последовательность визуальных символов пользователя. Индекс возвращает строку длины один, отдельного встроенного типа `char` нет.

```python
text = "Python"
assert text[0] == "P"
assert text[-1] == "n"
assert text[1:4] == "yth"
assert text[::-1] == "nohtyP"

try:
    text[0] = "J"
except TypeError:
    print("Строку нельзя изменить по индексу")

assert "é" != "e\u0301"
assert len("é") == 1
assert len("e\u0301") == 2
```

Индексирование неверного индекса вызывает `IndexError`, а обычный срез за пределы строки безопасно обрезается. Для работы с внешним текстом отдельно учитывай нормализацию, регистр, кодировку и правила разбиения на видимые символы. Подробный разбор ниже в теме «Работа со строками».

### NoneType (None)

`None` — единственный экземпляр `NoneType`, стандартный маркер отсутствия значения. Проверяй его через `is None` и `is not None`. Значения `0`, `False`, `""` и `[]` могут быть корректными данными и не равнозначны отсутствию.

```python
timeout = 0
effective_timeout = 30 if timeout is None else timeout
assert effective_timeout == 0
assert (timeout or 30) == 30  # Здесь потерялось допустимое значение 0.

settings = {"token": None}
assert settings.get("token") is None
assert settings.get("missing") is None
assert "token" in settings
assert "missing" not in settings
```

Если `None` сам является допустимым значением, введи отдельный объект-маркер:

```python
MISSING = object()
settings = {"token": None}

token = settings.get("token", MISSING)
missing = settings.get("other", MISSING)
assert token is None
assert missing is MISSING
```

Не пытайся отличать маркеры равенством, которое пользовательский тип может переопределить. `None` не поддерживает арифметику и обычное упорядочивание с числами; его присутствие в данных требует явного правила обработки.

### Коллекции

Коллекция хранит несколько объектов или задаёт способ доступа к ним. «Итерируемый» означает возможность получить итератор, «контейнер» — поддержку проверки принадлежности, «последовательность» — упорядоченный доступ по позиции. Одно и то же значение может поддерживать несколько протоколов.

```python
from collections.abc import Iterable, Mapping, Sequence, Set

assert isinstance([1, 2], Sequence)
assert isinstance({"a": 1}, Mapping)
assert isinstance({1, 2}, Set)
assert isinstance(range(3), Iterable)
assert not isinstance({1, 2}, Sequence)
```

ABC полезны для интерфейсов, однако не заменяют содержательную проверку данных. Строка тоже `Sequence`, но функция, ожидающая список имён, часто не должна принимать одиночное имя как последовательность букв. Валидация должна учитывать смысл входа.

### Последовательности (Sequence Types)

У последовательности есть порядок, длина и доступ к элементам по целому индексу. Базовые встроенные примеры: `list`, `tuple`, `range`, `str`, `bytes`, `bytearray`. Поддержка конкретных дополнительных операций различается: например, `range` не поддерживает конкатенацию.

Срез `sequence[start:stop:step]` исключает `stop`. Пропущенные границы зависят от знака шага. Нулевой шаг запрещён. Отрицательный индекс отсчитывается от конца.

```python
values = [0, 1, 2, 3, 4, 5]
assert values[1:5:2] == [1, 3]
assert values[-2:] == [4, 5]
assert values[100:200] == []
assert values[::-1] == [5, 4, 3, 2, 1, 0]
assert values[4:1:-1] == [4, 3, 2]

try:
    values[::0]
except ValueError:
    print("Шаг среза не может быть нулём")
```

Срез списка создаёт новый внешний список. Срез `range` создаёт другой компактный `range`; срезы некоторых внешних библиотек могут быть представлениями. Не переноси правила одного типа на все последовательности.

### Списки (list)

Список — изменяемая последовательность ссылок. Он подходит для упорядоченной группы элементов, добавления в конец, индексирования и сортировки на месте. Это не связный список; вставки и удаления в начале требуют сдвига элементов.

```python
values = [10, 20]
values.append(30)
values.extend([40, 50])
assert values == [10, 20, 30, 40, 50]

values.insert(1, 15)
assert values.pop() == 50
values.remove(20)  # Удаляет первое равное значение.
assert values == [10, 15, 30, 40]

result = values.append(99)
assert result is None
```

`append(iterable)` добавляет один объект; `extend(iterable)` добавляет элементы источника. Методы изменения на месте, такие как `append`, `extend`, `reverse`, `sort`, обычно возвращают `None`: это помогает заметить случайное `values = values.sort()`.

```python
values = [0, 1, 2, 3]
values[1:3] = [10, 20, 30]
assert values == [0, 10, 20, 30, 3]

values[::2] = [7, 8, 9]  # Для расширенного среза длины должны совпасть.
assert values == [7, 10, 8, 30, 9]
```

Для очереди с удалением из начала обычно подходит `collections.deque`. Для однородного числового массива с компактным представлением смотри `array` или специализированные библиотеки. Не рассчитывай, что список из миллиона чисел занимает ровно миллион машинных чисел: он хранит ссылки на объекты.

### Кортежи (tuple)

Кортеж — неизменяемая последовательность. Его создаёт запятая, а не просто круглые скобки. Он полезен для фиксированной группы значений, составного ключа и возврата нескольких результатов.

```python
single = (10,)
assert type(single) is tuple
assert type((10)) is int
assert tuple("ab") == ("a", "b")

record = ("Alice", ["reader"])
record[1].append("writer")
assert record == ("Alice", ["reader", "writer"])

locations = {(55.75, 37.62): "Москва"}
assert locations[(55.75, 37.62)] == "Москва"
```

Нельзя заменить `record[0]`, но можно изменить список, на который ссылается `record[1]`. Кортеж хешируем только при хешируемости всех элементов. Для записи с множеством смысловых полей лучше именованные структуры: `NamedTuple` или `dataclass`, а не обращения `record[7]` по памяти.

### Диапазоны (range)

`range(start, stop, step)` описывает арифметическую последовательность целых, не создавая список всех элементов. `stop` не включается; знак шага определяет направление. Если направление не позволяет достичь границы, диапазон пуст.

```python
assert list(range(5)) == [0, 1, 2, 3, 4]
assert list(range(5, 0, -2)) == [5, 3, 1]
assert list(range(5, 0)) == []

huge = range(0, 10**20, 3)
assert huge[2] == 6
assert 12 in huge
assert 13 not in huge
assert range(0, 3, 2) == range(0, 4, 2)
```

Равенство диапазонов определяется последовательностями значений, а не буквальным совпадением аргументов. Проверка принадлежности обычного целого использует арифметику; время не растёт линейно с числом элементов. При этом операции с очень большими целыми зависят от их размера. Диапазон может содержать больше элементов, чем допускает `len()` в CPython: тогда `len()` вызовет `OverflowError`, хотя индексирование некоторых позиций работает.

`range` — многократно итерируемый объект, не генератор и не итератор. `next(range(3))` не работает; нужен `next(iter(range(3)))`.

### Отображения (Mapping Types)

Отображение связывает ключ с одним значением. В отличие от последовательности, индекс здесь не обязательно позиция: `mapping[100]` ищет ключ `100`. Базовый изменяемый тип — `dict`; абстрактные интерфейсы — `Mapping` и `MutableMapping`.

```python
from collections import defaultdict
from types import MappingProxyType

groups = defaultdict(list)
groups["python"].append("Alice")
assert groups["python"] == ["Alice"]
assert groups.get("missing") is None  # get не вызывает фабрику.
assert "missing" not in groups

source = {"retries": 3}
view = MappingProxyType(source)
source["retries"] = 5
assert view["retries"] == 5
```

`MappingProxyType` запрещает запись через представление, но отражает изменения исходного словаря и не замораживает вложенные значения. Для настоящего снимка сначала создаётся копия, причём вопрос глубины копирования остаётся отдельным.

### Словари (dict)

Ключи словаря должны быть хешируемыми. Словарь сохраняет порядок вставки как гарантию языка начиная с Python 3.7. Обновление существующего ключа не переносит его в конец; удаление с повторной вставкой переносит. Равенство обычных словарей от порядка не зависит.

```python
settings = {"host": "localhost", "port": 8000}
settings["port"] = 9000
assert list(settings) == ["host", "port"]

defaults = {"timeout": 30, "retries": 3}
overrides = {"timeout": 0}
merged = defaults | overrides
assert merged == {"timeout": 0, "retries": 3}
assert defaults["timeout"] == 30

merged |= {"debug": True}
assert merged["debug"] is True
```

`mapping[key]` сообщает об отсутствии через `KeyError`. `get()` возвращает значение по умолчанию. `setdefault()` добавляет значение только при отсутствии ключа, однако выражение аргумента вычисляется перед вызовом даже при существующем ключе.

```python
calls = []


def make_default():
    calls.append("called")
    return []


data = {"a": [1]}
data.setdefault("a", make_default())
assert calls == ["called"]
assert data["a"] == [1]

keys = data.keys()
data["b"] = [2]
assert "b" in keys  # Динамическое представление, не снимок.
```

`keys()`, `values()` и `items()` возвращают представления. Для независимого перечня используй `list(data.items())`, понимая, что вложенные значения всё ещё общие. Не добавляй и не удаляй ключи в процессе непосредственного обхода словаря. Перезапись значения допустима, но изменение данных во время обхода всё равно должно быть осмысленным.

### Множества (Set Types)

Множество представляет уникальные хешируемые элементы. Оно удобно для проверки принадлежности, удаления дублей и операций над группами. У множества нет позиционного индекса и гарантированного порядка обхода.

```python
left = {1, 2, 3}
right = {3, 4}
assert left | right == {1, 2, 3, 4}
assert left & right == {3}
assert left - right == {1, 2}
assert left ^ right == {1, 2, 4}
assert {1, 2} <= left
assert {1, 2} < left
assert left.isdisjoint({9})
```

`<` и `<=` означают строгое и нестрогое включение, а не лексикографическое сравнение. Два множества могут быть несравнимы: ни одно не является подмножеством другого. Это частичный порядок, поэтому `sorted(list_of_sets)` не даёт естественной сортировки «по содержимому».

### Множества (set)

`set` изменяем: можно добавлять и удалять элементы. `add(x)` добавляет один элемент, `update(iterable)` — элементы источника. `remove(x)` вызывает `KeyError` при отсутствии, `discard(x)` молча оставляет множество без изменения.

```python
tags = set()
tags.add("python")
tags.update(["backend", "python"])
assert tags == {"python", "backend"}

tags.discard("missing")
try:
    tags.remove("missing")
except KeyError:
    print("Элемента нет")

assert type({}) is dict
assert type(set()) is set
```

`pop()` извлекает произвольный элемент, а не «первый» или случайный по заданному распределению. Для воспроизводимого вывода сортируй подходящие значения по явному ключу. Для сохранения порядка первых вхождений хешируемых элементов удобно `list(dict.fromkeys(values))`.

### Неизменяемые множества (frozenset)

`frozenset` представляет неизменяемое множество и сам хешируем. Его можно использовать как элемент другого множества или как ключ словаря, когда порядок частей ключа не важен.

```python
permissions = frozenset({"read", "write"})
policies = {permissions: "editor"}
assert policies[frozenset({"write", "read"})] == "editor"
assert permissions & {"read"} == frozenset({"read"})
assert permissions == {"read", "write"}
```

Все элементы всё равно должны быть хешируемыми. `frozenset` не сохраняет порядок и не заменяет кортеж, если значимо различие `(a, b)` и `(b, a)`. При бинарных операциях `set` и `frozenset` тип результата обычно определяется левым операндом; не полагайся только на равенство содержимого, если интерфейс требует конкретный тип.

### Тонкости встроенных коллекций

**Повторение ссылок.** Умножение списка повторяет ссылки, а не создаёт независимые вложенные объекты.

```python
bad = [[0] * 3] * 2
bad[0][0] = 1
assert bad == [[1, 0, 0], [1, 0, 0]]

good = [[0] * 3 for _ in range(2)]
good[0][0] = 1
assert good == [[1, 0, 0], [0, 0, 0]]
```

**Равные ключи.** Числовые значения, равные по `==` и имеющие одинаковый хеш, обозначают одну запись. `True`, `1` и `1.0` не образуют три независимых ключа.

```python
data = {True: "bool", 1: "int", 1.0: "float"}
assert len(data) == 1
assert data[True] == "float"
assert len({True, 1, 1.0}) == 1

shared = dict.fromkeys(["a", "b"], [])
shared["a"].append(1)
assert shared["b"] == [1]
```

**Счётчик.** `Counter` возвращает ноль для отсутствующего ключа при индексировании, но этот ключ не обязательно хранится. В арифметических операциях счётчиков и сравнении есть собственные правила.

```python
from collections import Counter

counts = Counter("aab")
assert counts["missing"] == 0
assert "missing" not in counts
assert Counter(a=1) == Counter(a=1, b=0)
assert +Counter(a=2, b=0, c=-1) == Counter(a=2)
```

**Мутация при обходе.** При удалении из списка соседний элемент может быть пропущен; для фильтрации обычно создай новую коллекцию. Изменение размера словаря или множества при обходе часто вызывает `RuntimeError`. Ни одна из этих конструкций не предоставляет автоматически изолированный снимок.

### Бинарные типы

`bytes` — неизменяемая последовательность байтов, `bytearray` — изменяемая, `memoryview` — доступ к буферу без обязательного копирования. Байт — целое от 0 до 255. Индексирование `bytes` возвращает `int`, срез — `bytes`.

```python
text = "Привет"
encoded = text.encode("utf-8")
assert type(encoded) is bytes
assert encoded.decode("utf-8") == text
assert len(encoded) == 12
assert b"ABC"[0] == 65
assert b"ABC"[:1] == b"A"

buffer = bytearray(b"abc")
view = memoryview(buffer)
view[0] = ord("A")
assert buffer == bytearray(b"Abc")
view.release()
```

Кодирование преобразует текст в байты, декодирование — байты в текст. `str(b"abc")` создаёт строковое представление `"b'abc'"`, а не декодирует содержимое. `errors="ignore"` может необратимо скрыть повреждение данных; выбирай обработку ошибок по контракту.

Экспортированный `memoryview` может удерживать исходный буфер и мешать изменению его размера. После `release()` представлением пользоваться нельзя. Конкретные форматы и размер элемента зависят от буфера: не всякий `memoryview` представляет просто последовательность однобайтных элементов.

### Преобразование типов

Конструкторы `int()`, `float()`, `str()`, `list()` и другие выполняют определённые преобразования, иногда с потерей информации. Явная запись делает намерение видимым, но не гарантирует правильность контракта.

```python
assert int(3.9) == 3
assert int(-3.9) == -3  # Усечение к нулю, не floor.
assert float("1.25") == 1.25
assert list("abc") == ["a", "b", "c"]
assert dict([("a", 1), ("b", 2)]) == {"a": 1, "b": 2}

for value in ["", "12.5", "twelve"]:
    try:
        int(value)
    except ValueError:
        print("Некорректная целочисленная запись")
```

`int("12.5")` не поддерживается: это не запись целого. Не заменяй её автоматически на `int(float(value))`, если дробная часть должна считаться ошибкой. `bool("false")` не разбирает логический текст. `list(iterator)` исчерпывает источник и требует память под все элементы. У каждого преобразования должны быть понятны допустимый вход, ошибки и возможные потери.

### Проверка типов

`isinstance(value, T)` учитывает подклассы и поддерживаемые механизмом ABC регистрации; `type(value) is T` требует точный тип. Обычно предпочитай интерфейс и `isinstance`, а точную проверку применяй там, где подкласс меняет смысл, например при запрете `bool` в количестве.

```python
assert isinstance(True, int)
assert type(True) is not int
assert isinstance(1, int | float)

values = [1, 2, 3]
assert isinstance(values, list)
assert all(type(item) is int for item in values)

try:
    isinstance(values, list[int])
except TypeError:
    print("Параметризованный list не проверяет содержимое в isinstance")
```

Проверка `hasattr()` тоже может выполнить пользовательский код поиска атрибута. Проверка перед действием не защищает от изменения внешнего состояния между двумя операциями. Для ожидаемого отказа самой операции часто удобнее выполнить её и обработать конкретное исключение, удерживая `try` узким.

### Сравнение типов

Равенство значений, идентичность объектов и равенство типов — три разных вопроса. `1 == 1.0` истинно, хотя типы различаются. `[1] == (1,)` ложно, несмотря на равные элементы. Для несвязанных встроенных типов обычный порядок чаще не определён.

```python
assert 1 == 1.0
assert type(1) is not type(1.0)
assert [1] != (1,)
assert {1, 2} == frozenset({2, 1})

for value in ["1", None, 1 + 0j]:
    try:
        1 < value
    except TypeError:
        print("Нужно определить общий ключ сравнения")
```

Не сортируй разнородные данные через `str()` без определения смысла: числа `2` и `10` станут строками с лексикографическим порядком `'10' < '2'`. Сначала нормализуй данные в общий домен или задавай ключ с категорией и сравнимым значением внутри категории.

### Производительность типов

| Операция | Обычная оценка для встроенных коллекций CPython | Что может изменить картину |
| --- | --- | --- |
| Индекс списка/кортежа | `O(1)` | Цена дальнейшей обработки элемента |
| `list.append()` | Амортизированно `O(1)` | Иногда требуется увеличение буфера |
| Вставка/удаление в начале списка | `O(n)` | Нужно сдвигать ссылки |
| Поиск `x in list` | `O(n)` | Стоимость сравнения элементов |
| Поиск ключа в `dict`, элемента в `set` | В среднем `O(1)`, худший случай `O(n)` | Хеширование, коллизии, пользовательское равенство |
| Срез списка длины `k` | `O(k)` и память под `k` ссылок | Ссылки на вложенные объекты остаются общими |
| Сортировка `n` значений | Худший случай `O(n log n)` сравнений | Ключи, распределение данных, уже упорядоченные участки |
| Объединение строк через `join` | Пропорционально общему размеру результата | Кодировка внутреннего представления и входной источник |

Операции над большими `int`, хеширование длинной новой строки и сравнение вложенных объектов не бесплатны. Нельзя переносить «словарь в среднем `O(1)`» на произвольную функцию, которая каждый раз строит ключ размером в мегабайт.

Создание множества имеет свою цену. Если проверка принадлежности одна, преобразование списка в `set` может не окупиться. Если проверок тысячи, предварительное построение часто меняет общую сложность с `O(mn)` на ожидаемую `O(n + m)`.

### Сравнение коллекций

| Потребность | Обычно подходит | Причина |
| --- | --- | --- |
| Упорядоченные изменяемые элементы | `list` | Индексирование, добавление, сортировка |
| Фиксированная позиционная группа | `tuple` | Структура не меняется |
| Поиск записи по ключу | `dict` | Явное отображение ключ → значение |
| Уникальность и операции над группами | `set` | Проверка принадлежности и алгебра множеств |
| Неизменяемая группа без порядка | `frozenset` | Можно использовать в хешируемом ключе |
| Арифметическая последовательность целых | `range` | Компактное описание |
| Очередь с обоих концов | `collections.deque` | Эффективные операции на концах |
| Группировка с автоматическим начальным значением | `defaultdict` | Фабрика вызывается при нужном доступе |
| Подсчёт вхождений | `Counter` | Семантика частот и готовые операции |

Порядок вставки словаря полезен, но не заменяет сортировку по бизнес-правилу. Множество удаляет дубли по равенству и хешу, а не по выбранному полю записи. Если уникальность определяется `user_id`, нужен ключ `user_id`, а не надежда на внешний вид объектов.

### Таблица типов данных

| Тип | Изменяемость | Хешируемость | Пример |
| --- | --- | --- | --- |
| `int`, `float`, `complex`, `bool` | Нет | Да | `42`, `1.5`, `2j`, `True` |
| `str` | Нет | Да | `"python"` |
| `NoneType` | Нет | Да | `None` |
| `list` | Да | Нет | `[1, 2]` |
| `tuple` | Нет | Если все элементы хешируемы | `(1, 2)` |
| `range` | Нет | Да | `range(10)` |
| `dict` | Да | Нет | `{"a": 1}` |
| `set` | Да | Нет | `{1, 2}` |
| `frozenset` | Нет | Да | `frozenset({1, 2})` |
| `bytes` | Нет | Да | `b"abc"` |
| `bytearray` | Да | Нет | `bytearray(b"abc")` |
| `memoryview` | Зависит от буфера и вида | Только при определённых условиях | `memoryview(b"abc")` |

Не используй значение `hash()` как устойчивый идентификатор между процессами или запусками: для ряда типов применяется рандомизация, а сам хеш допускает коллизии. Для воспроизводимого отпечатка данных выбирай каноническую сериализацию и подходящую криптографическую хеш-функцию.

### Частые ошибки

| Ошибка | Последствие | Исправление |
| --- | --- | --- |
| `[[0] * width] * height` | Все строки ссылаются на один список | Включение с созданием каждой строки |
| `values = values.append(x)` | Имя получает `None` | Вызвать метод отдельно |
| `if value:` для необязательного числа | Пропускается допустимый ноль | `if value is not None:` |
| `int(float(text))` для количества | Теряется дробная часть и возможна точность | Разбирать по контракту целого |
| `str(binary)` вместо декодирования | Получается представление байтов | `binary.decode(encoding)` |
| Ключ на основе меняющегося состояния | Нарушается поиск в хеш-таблице | Стабильный неизменяемый ключ |
| `set(values)` при значимом порядке | Порядок не сохраняется как контракт | `dict.fromkeys()` или явная дедупликация |
| `dict.fromkeys(keys, [])` | Значение-список общее | `{key: [] for key in keys}` |

Ошибки особенно опасны там, где программа выдаёт правдоподобный результат: округлённое количество, перепутанные единицы, слитые ключи `True` и `1`. Проверяй такие границы отдельными примерами, а не только обычным входом.

### Частые вопросы и ключевые выводы

**Почему `tuple` со списком можно изменить «внутри»?** Кортеж сохраняет свои ссылки; состояние объекта по одной из ссылок живёт по правилам этого объекта.

**Почему `{True, 1}` содержит один элемент?** Значения равны и имеют одинаковый хеш. Тип не является отдельной частью ключа автоматически.

**Подходит ли `float` для денег?** Для некоторых оценочных задач допустим, но точные денежные правила обычно требуют минимальных целых единиц или `Decimal` с заданным округлением и валютой.

**Всегда ли `set` быстрее списка?** Нет. Важны размер, число поисков, цена построения, хеширования и равенства.

**Самопроверка:** выбери типы для следующих задач и объясни ограничения: очередь заданий; множество ролей как ключ кэша; точная цена с двумя десятичными знаками; прочитанный сетевой пакет; результаты запроса, которые нужно пройти дважды. Для каждого решения назови, где возможна мутация и кто удерживает память.

**Документация:** [встроенные типы](https://docs.python.org/3.14/library/stdtypes.html), [collections](https://docs.python.org/3.14/library/collections.html), [числа с плавающей точкой](https://docs.python.org/3.14/tutorial/floatingpoint.html), [Decimal](https://docs.python.org/3.14/library/decimal.html), [Fraction](https://docs.python.org/3.14/library/fractions.html).

## Сортировка

### sorted() vs list.sort()

`sorted(iterable)` читает итерируемый источник и возвращает новый список. `list.sort()` меняет существующий список и возвращает `None`. Обе операции стабильны и принимают параметры `key` и `reverse`.

```python
original = [3, 1, 2]
ordered = sorted(original)
assert ordered == [1, 2, 3]
assert original == [3, 1, 2]

result = original.sort()
assert result is None
assert original == [1, 2, 3]

assert sorted({3, 1, 2}) == [1, 2, 3]
assert sorted({"b": 2, "a": 1}) == ["a", "b"]  # Ключи словаря.
```

Для уже имеющегося изменяемого списка `sort()` избегает создания второго списка ссылок, но алгоритм всё равно может требовать дополнительную память. «На месте» не означает `O(1)` дополнительной памяти. Для генератора `sorted()` полностью материализует данные; для бесконечного источника он не завершится.

Если сравнение или вычисление ключа вызывает исключение, исходный список при `sort()` может оказаться частично переставленным. Не считай сортировку транзакцией. Не изменяй сортируемый список из функции ключа или методов сравнения.

### Параметры key и reverse

`key` получает каждый элемент и возвращает значение, по которому его сравнивают. При успешной сортировке ключ вычисляется один раз для каждого входного элемента. Это обычно удобнее и дешевле, чем многократно извлекать нужное поле внутри попарного сравнения.

```python
names = ["Bob", "alice", "CAROL"]
assert sorted(names, key=str.casefold) == ["alice", "Bob", "CAROL"]
assert sorted([-10, 2, -3], key=abs) == [2, -3, -10]
assert sorted([1, 3, 2], reverse=True) == [3, 2, 1]

calls = []


def measured_key(value):
    calls.append(value)
    return len(value)


assert sorted(["aaa", "b", "cc"], key=measured_key) == ["b", "cc", "aaa"]
assert len(calls) == 3
```

`reverse=True` меняет направление сравнения ключей; ключу не нужно возвращать отрицательное значение. Не путай `key=str.casefold` с `key=str.casefold()`: передаётся вызываемый объект, а не результат его вызова. Ключ должен быть предсказуемым и не менять смысл данных в ходе сортировки.

### Стабильность сортировки

Стабильность означает сохранение исходного взаимного порядка элементов с равными ключами. Это свойство действует и при `reverse=True`.

```python
rows = [("A", 2), ("B", 1), ("C", 2), ("D", 1)]
ascending = sorted(rows, key=lambda row: row[1])
descending = sorted(rows, key=lambda row: row[1], reverse=True)
assert ascending == [("B", 1), ("D", 1), ("A", 2), ("C", 2)]
assert descending == [("A", 2), ("C", 2), ("B", 1), ("D", 1)]
```

Стабильность не создаёт воспроизводимый порядок из неопределённого входного порядка. Если данные пришли из множества или внешнего источника без установленного порядка, при равных ключах он останется таким, каким пришёл. Для воспроизводимого отчёта добавь явный последний критерий, например уникальный идентификатор.

`list(reversed(sorted(rows, key=...)))` перевернёт также порядок внутри групп равных ключей. Поэтому эта запись не эквивалентна стабильной сортировке с `reverse=True`.

### Составные ключи сортировки

Кортежи сравниваются лексикографически: сначала первый компонент, затем второй при равенстве первого и так далее. Это удобно для нескольких критериев с одинаковым направлением.

```python
users = [
    {"name": "Bob", "age": 30},
    {"name": "Alice", "age": 30},
    {"name": "Carol", "age": 20},
]
ordered = sorted(users, key=lambda user: (user["age"], user["name"]))
assert [user["name"] for user in ordered] == ["Carol", "Alice", "Bob"]

# Возраст по убыванию, имя по возрастанию.
mixed = sorted(users, key=lambda user: (-user["age"], user["name"]))
assert [user["name"] for user in mixed] == ["Alice", "Bob", "Carol"]
```

Отрицание подходит для обычных числовых критериев, но не для строк, `None` и произвольных объектов. `reverse=True` у составного ключа разворачивает весь порядок, а не только первый компонент. Для смешанных направлений часто понятнее многоэтапная сортировка.

### Многоэтапная сортировка

Благодаря стабильности можно сначала отсортировать по менее значимому критерию, затем по более значимому. Последний проход задаёт главный порядок.

```python
rows = [
    {"team": "B", "score": 10, "name": "Zoe"},
    {"team": "A", "score": 10, "name": "Bob"},
    {"team": "A", "score": 20, "name": "Alice"},
    {"team": "A", "score": 10, "name": "Ann"},
]
rows.sort(key=lambda row: row["name"])
rows.sort(key=lambda row: row["score"], reverse=True)
rows.sort(key=lambda row: row["team"])
assert [row["name"] for row in rows] == ["Alice", "Ann", "Bob", "Zoe"]
```

Здесь главный критерий — команда по возрастанию, затем балл по убыванию, затем имя. Цена — несколько проходов сортировки и вычислений ключей. Для дорогих ключей можно заранее подготовить значения, но сначала выбери простую проверяемую запись и измерь её на реальных данных.

### operator.itemgetter, attrgetter и methodcaller

Эти функции создают вызываемые объекты для извлечения элемента, атрибута или вызова метода. Они делают типовые ключи короче и часто хорошо выражают намерение.

```python
from dataclasses import dataclass
from operator import attrgetter, itemgetter, methodcaller

rows = [("Bob", 30), ("Alice", 20)]
assert sorted(rows, key=itemgetter(1, 0)) == [("Alice", 20), ("Bob", 30)]


@dataclass
class User:
    name: str
    age: int


users = [User("Bob", 30), User("Alice", 20)]
assert [user.name for user in sorted(users, key=attrgetter("age", "name"))] == [
    "Alice",
    "Bob",
]
assert sorted(["b", "A"], key=methodcaller("casefold")) == ["A", "b"]
```

`attrgetter("address.city")` проходит цепочку атрибутов. Отсутствие поля не превращается автоматически в `None`: возникнет исключение. Если нужна проверка, нормализация или обработка отсутствующих значений, именованная функция ключа обычно яснее сложной комбинации адаптеров.

### functools.cmp_to_key

Современный API сортировки принимает ключ, но некоторые внешние интерфейсы предоставляют функцию сравнения двух значений: отрицательный результат, ноль или положительный результат. `cmp_to_key()` адаптирует её к `key`.

```python
from functools import cmp_to_key


def compare_by_length(left: str, right: str) -> int:
    return (len(left) > len(right)) - (len(left) < len(right))


assert sorted(["bbb", "a", "cc"], key=cmp_to_key(compare_by_length)) == [
    "a",
    "cc",
    "bbb",
]
```

Для этого примера проще `key=len`; адаптер полезен при действительно готовом comparator API, например правилах внешнего сравнения текста. Компаратор вызывается многократно. Он должен задавать согласованный порядок: непоследовательные результаты и нарушение транзитивности делают итог ненадёжным. Не возвращай просто `left > right`: такого булева результата недостаточно для трёх вариантов сравнения.

### Сортировка значений с отсутствующими данными

Сначала задай правило: отсутствующие значения идут первыми или последними, пропускаются либо являются ошибкой. Затем построй ключ, внутри которого сравниваются совместимые значения.

```python
values = [3, None, 1, None, 2]
ascending = sorted(values, key=lambda value: (value is None, value or 0))
assert ascending == [1, 2, 3, None, None]

# По убыванию, но None всё ещё в конце.
descending = sorted(
    values,
    key=lambda value: (value is None, -value if value is not None else 0),
)
assert descending == [3, 2, 1, None, None]
```

В первом примере `value or 0` допустимо только благодаря узкому контракту `int | None`: ноль остаётся корректным ключом. Более общая и явная форма — `value if value is not None else 0`. Не переносись автоматически на пустые строки, объекты с особой истинностью и несколько разных маркеров.

При `reverse=True` группа `None` тоже поменяет сторону. Для записей отличай отсутствующий ключ от присутствующего значения `None`, если это имеет значение для отчёта.

### Частичный порядок и несравнимые значения

Сортировка требует согласованного отношения порядка для используемых ключей. Многие данные такого порядка не имеют: множества упорядочиваются включением, комплексные числа не поддерживают `<`, а смесь строки и числа обычно вызывает `TypeError`.

```python
values = [10, "2", 3, "11"]


def category_key(value):
    if type(value) is int:
        return 0, value
    if isinstance(value, str):
        return 1, value
    raise TypeError("Поддерживаются только целые числа и строки")


assert sorted(values, key=category_key) == [3, 10, "11", "2"]
```

Категория создаёт общий порядок между типами; внутри каждой категории действует своё правило. В примере строки сознательно сортируются как строки. Это технический порядок представления, а не утверждение, что число «меньше» текста по смыслу.

Сортировка множества множеств по `(len(value), sorted(value))` имеет смысл только при сравнимых элементах и если именно такое правило требуется. Предварительно определить смысл порядка важнее, чем заставить вызов `sorted()` завершиться.

### Особенности сортировки данных с NaN

Для `float('nan')` сравнения `<`, `>` и `==` с обычными числами и с самим собой не дают привычного полного порядка. Поэтому нельзя ожидать, что обычная числовая сортировка автоматически вынесет `NaN` в начало или конец.

```python
import math

values = [3.0, float("nan"), -1.0, float("nan"), 2.0]


def nan_last_key(value: float) -> tuple[bool, float]:
    return math.isnan(value), 0.0 if math.isnan(value) else value


ordered = sorted(values, key=nan_last_key)
assert ordered[:3] == [-1.0, 2.0, 3.0]
assert all(math.isnan(value) for value in ordered[3:])
```

Подстановка `0.0` для категории `NaN` важна: в сравнении ключей больше не участвует сам `NaN`. Для убывания с `NaN` в конце используй второй компонент `-value` только для обычных чисел. При наличии `None`, `NaN` и других маркеров задай несколько категорий явно. У `Decimal('NaN')` собственная модель исключительных состояний; не предполагается, что ключ для `float` автоматически подходит всем числовым типам.

**Самопроверка:** отсортируй пользователей по активным сначала, затем по убыванию рейтинга, затем по нормализованному имени; отсутствующий рейтинг всегда должен идти после присутствующего. Добавь уникальный идентификатор, чтобы результат не зависел от порядка входа.

**Документация:** [Sorting HOWTO](https://docs.python.org/3.14/howto/sorting.html), [operator](https://docs.python.org/3.14/library/operator.html), [cmp_to_key](https://docs.python.org/3.14/library/functools.html#functools.cmp_to_key).

## Работа со строками

### Основы строк

Строка содержит текст Unicode, не байты конкретной кодировки. Один пользовательский символ может включать несколько кодовых точек: букву с комбинируемым знаком, emoji с модификатором или последовательность с zero-width joiner. `len()` считает кодовые точки, а не экранную ширину.

```python
text = "Python"
assert isinstance(text[0], str)
assert len(text[0]) == 1
assert text[:100] == text

emoji = "👩\u200d💻"
assert len(emoji) == 3
assert len(emoji.encode("utf-8")) > len(emoji)

assert "кот" in "рыжий кот"
assert "" in "anything"
```

Выбор одинарных или двойных кавычек не меняет тип и семантику строки. Тройные кавычки позволяют записывать переводы строк, но отступы внутри литерала тоже становятся данными. Для многострочных шаблонов пригодится `textwrap.dedent()`.

```python
from textwrap import dedent

message = dedent("""\
    first
    second
""")
assert message == "first\nsecond\n"
```

### Основные операции со строками

Конкатенация `+` соединяет строки, `*` повторяет строку, срез извлекает часть. Все эти операции создают или возвращают неизменяемые строковые значения. Для сборки большого числа фрагментов обычно используй `str.join()`.

```python
parts = ["python", "zero", "hero"]
assert "-".join(parts) == "python-zero-hero"
assert "ha" * 3 == "hahaha"
assert "  a b  ".split() == ["a", "b"]
assert "a,,b,".split(",") == ["a", "", "b", ""]
assert "a=b=c".split("=", 1) == ["a", "b=c"]
assert "a=b=c".partition("=") == ("a", "=", "b=c")
assert "abc".partition("=") == ("abc", "", "")
```

`split()` без аргумента объединяет серии пробельных символов и убирает пустые элементы на краях. `split(" ")` разделяет по конкретному пробелу и сохраняет пустые части. `partition()` всегда возвращает тройку, что удобно для формата «ключ=значение».

Повторное `result += fragment` в большом цикле не является универсально линейным способом сборки: некоторые пути оптимизируются в CPython, но зависеть от них в алгоритме не следует. Для потокового вывода пиши части в файл, для буфера текста используй `io.StringIO`. `join()` требует строковых элементов и может материализовать вход ради создания результата; ленивый источник не отменяет память под конечную строку.

### Форматирование строк

F-строки удобны, когда шаблон задан в исходном коде. Выражения в фигурных скобках вычисляются при создании строки. `str.format()` полезен для отдельно переданного шаблона; `%` встречается в старом коде и в ленивом форматировании стандартного `logging`.

```python
name = "Alice"
score = 12.3456
assert f"{name}: {score:.2f}" == "Alice: 12.35"
assert "{name}: {score:.2f}".format(name=name, score=score) == "Alice: 12.35"
assert "%s: %.2f" % (name, score) == "Alice: 12.35"
assert f"{{name}} = {name}" == "{name} = Alice"
assert f"{score=}" == "score=12.3456"
```

Форматирование не является экранированием для SQL, HTML, shell или URL. Для SQL используй параметры драйвера, для HTML — соответствующий renderer или `html.escape()` по контексту, для запуска процессов — список аргументов без сборки shell-команды. Не передавай пользовательскую строку в `eval()` ради «подстановок».

При логировании `logger.debug("User %s", user_id)` позволяет отложить форматирование до фактической записи. `logger.debug(f"User {expensive()}")` вычислит `expensive()` ещё до решения логгера, нужен ли этот уровень.

### Продвинутое форматирование строк

Мини-язык форматирования описывает заполнение, выравнивание, знак, ширину, группировку, точность и способ представления. Ширина — минимальная, а не максимальная: длинное значение не обрезается автоматически.

```python
assert f"{'x':*>5}" == "****x"
assert f"{'x':^5}" == "  x  "
assert f"{42:06d}" == "000042"
assert f"{42:+d}" == "+42"
assert f"{255:#x}" == "0xff"
assert f"{12_345.678:,.2f}" == "12,345.68"
assert f"{0.125:.1%}" == "12.5%"
assert f"{'abcdef':.3s}" == "abc"

width, precision = 8, 2
assert f"{3.14159:{width}.{precision}f}" == "    3.14"

value = "a\nb"
assert f"{value!r}" == repr(value)
assert f"{value!s}" == str(value)
assert f"{'é'!a}" == "'\\xe9'"
```

`!s`, `!r` и `!a` сначала применяют `str`, `repr` и ASCII-представление. Без такой конверсии форматирование обращается к протоколу `__format__`. Спецификатор `n` учитывает локаль; десятичный разделитель и группировка могут зависеть от окружения. Для машинного формата выбери фиксированное правило, не локализованное отображение.

Начиная с 3.12 грамматика выражений f-строк расширена: поддерживаются случаи с повторным использованием кавычек, комментариями и обратной косой чертой внутри выражения, которые ранее ограничивались. Сложный расчёт всё равно лучше вынести в отдельную переменную.

**T-строки — Python 3.14+.** Они создают `string.templatelib.Template`, сохраняя постоянные части и объекты интерполяции. Это позволяет renderer самостоятельно применять контекстные преобразования.

```python
# Python 3.14+: t-строки и string.templatelib.
from string.templatelib import Template

name = "<Alice>"
template = t"<p>{name}</p>"
name = "Bob"

assert isinstance(template, Template)
assert not isinstance(template, str)
assert template.strings == ("<p>", "</p>")
assert template.interpolations[0].value == "<Alice>"
assert template.interpolations[0].expression == "name"
```

Выражение вычисляется при создании t-строки: последующая перепривязка `name` его не пересчитает. При этом сохранённое значение может быть ссылкой на изменяемый объект, а не глубоким снимком. T-строка сама не выполняет HTML-экранирование, SQL-параметризацию и не превращает небезопасный renderer в безопасный. Простое `str(template)` не означает «отрендерить как f-строку»; нужен обработчик с определённым контрактом.

### Методы строк

| Задача | Методы | Существенная деталь |
| --- | --- | --- |
| Удалить внешние пробелы | `strip`, `lstrip`, `rstrip` | Аргумент задаёт набор символов, а не подстроку |
| Удалить точный префикс/суффикс | `removeprefix`, `removesuffix` | Подходят для точных текстовых частей |
| Проверить начало/конец | `startswith`, `endswith` | Можно передать кортеж вариантов |
| Найти подстроку | `find`, `index`, `rfind`, `rindex` | `find` возвращает `-1`, `index` вызывает `ValueError` |
| Заменить | `replace`, `translate` | Исходная строка не меняется |
| Сравнивать без регистра | `casefold` | Более полное Unicode-преобразование, чем `lower` |
| Разбить на строки | `splitlines` | Учитывает несколько видов границ строк |
| Проверить числовые символы | `isdecimal`, `isdigit`, `isnumeric` | Разные множества Unicode-символов |

```python
assert "abbaXba".strip("ab") == "X"
assert "data.csv".removesuffix(".csv") == "data"
assert "straße".casefold() == "strasse"
assert "abc".find("z") == -1
assert "a\nb\r\nc".splitlines() == ["a", "b", "c"]

assert "²".isdigit()
assert not "²".isdecimal()
try:
    int("²")
except ValueError:
    print("isdigit не гарантирует совместимость с int")
```

Для ASCII-поля количества может потребоваться одновременно `isascii()` и `isdecimal()`. Для строки с разрешённым знаком эти методы сами по себе уже недостаточны. Разбор значения через соответствующий parser с обработкой исключения часто проще, но ограничения формата всё равно нужно определить.

```python
translation = str.maketrans({"-": "_", " ": None})
assert "a-b c".translate(translation) == "a_bc"

position = "abc".find("a")
assert position == 0
assert not bool(position)  # Поэтому if text.find(...) — неправильная проверка.
assert "a" in "abc"
```

### Юникод в Python

Unicode задаёт кодовые точки; UTF-8, UTF-16 и другие кодировки задают их байтовое представление. Нормализация решает отдельную задачу: сопоставление эквивалентных последовательностей кодовых точек.

```python
import unicodedata

composed = "é"
decomposed = "e\u0301"
assert composed != decomposed
assert unicodedata.normalize("NFC", decomposed) == composed
assert unicodedata.normalize("NFD", composed) == decomposed
assert unicodedata.normalize("NFKC", "①") == "1"

text = "Привет"
assert text.encode("utf-8").decode("utf-8") == text
```

NFC/NFD опираются на каноническую эквивалентность, NFKC/NFKD дополнительно выполняют совместимые преобразования, которые могут стереть значимые для задачи различия. Нормализацию выбирают для конкретного поля, а не применяют без разбора ко всему документу.

Регистронезависимое сравнение тоже требует политики. Для некоторых идентификаторов подходит нормализация и `casefold()`, но имена людей, пароли, пути и внешние идентификаторы могут иметь другие правила. Python не учитывает автоматически локальные правила сортировки естественного языка: сравнение строк обычно следует кодовым точкам. Для пользовательской локализованной сортировки нужен соответствующий инструмент и фиксированная локаль.

Срезы по кодовым точкам могут разорвать графемный кластер. `text[:20]` не гарантирует 20 видимых символов, а `.ljust()` не гарантирует ширину в 20 колонок терминала. Для интерфейсов с такими требованиями используй средства сегментации графем и измерения отображаемой ширины. Отдельно учитывай невидимые управляющие символы и похожие знаки в идентификаторах.

**Самопроверка:** объясни, почему `len(text)`, `len(text.encode('utf-8'))` и визуальная длина могут различаться. Напиши обработку поля логина с явно указанными правилами пробелов, Unicode-нормализации и регистра; перечисли данные, которые такой обработкой менять нельзя.

**Документация:** [методы строк](https://docs.python.org/3.14/library/stdtypes.html#string-methods), [мини-язык форматирования](https://docs.python.org/3.14/library/string.html#formatspec), [Unicode HOWTO](https://docs.python.org/3.14/howto/unicode.html), [unicodedata](https://docs.python.org/3.14/library/unicodedata.html), [string.templatelib](https://docs.python.org/3.14/library/string.templatelib.html).

## Операции и выражения

### Что такое выражение?

Выражение вычисляется в значение, но во время вычисления может изменить состояние, выполнить ввод-вывод или возбудить исключение. Вызов `save(data)` является выражением даже тогда, когда возвращает `None`. Следовательно, «это выражение» не означает «это чистое вычисление без побочных эффектов».

```python
events = []


def record(value):
    events.append(value)
    return value * 2


result = record(3) + record(4)
assert result == 14
assert events == [3, 4]
```

В обычных выражениях Python вычисляет составляющие слева направо. Приоритет определяет группировку, а специальные конструкции — какие части вообще будут вычислены: короткое замыкание, условное выражение и сравнение цепочкой могут пропустить часть выражений. Не выводи порядок исполнения только из визуальной близости операторов.

### Что такое оператор?

Оператор языка задаёт операцию над операндами: `+`, `*`, `==`, `in`, `is`, `and`. Слово «оператор» в русскоязычных материалах также используют для инструкции (`if`, `for`), поэтому полезно уточнять, идёт ли речь об операции внутри выражения или об инструкции управления.

Часть операций соответствует специальным методам объектов: `a + b`, `a[b]`, `a in b`. Другие, например `is`, имеют фиксированную семантику идентичности и не перегружаются. `and` и `or` управляют вычислением и не равнозначны обычному вызову метода над двумя заранее вычисленными аргументами.

### Операнды

Операнды — значения, участвующие в операции. Операция может быть унарной (`-x`), бинарной (`a + b`); условное выражение `x if condition else y` выбирает одну из двух ветвей по третьему компоненту.

```python
assert -5 == -(5)
assert [1] + [2] == [1, 2]
assert "ha" * 2 == "haha"
assert 2 * "ha" == "haha"
```

Один символ может задавать разные операции для разных типов: `+` складывает числа или соединяет списки. Возможность выполнения зависит от обоих операндов и их протоколов. Проверяй семантику, а не только наличие знакомого символа.

### Арифметические операции

| Операция | Смысл | Пример |
| --- | --- | --- |
| `+`, `-`, `*` | Сложение, вычитание, умножение | `3 * 4 == 12` |
| `/` | Деление | `5 / 2 == 2.5` |
| `//` | Деление с округлением вниз | `-5 // 2 == -3` |
| `%` | Остаток, согласованный с `//` | `-5 % 2 == 1` |
| `**` | Возведение в степень | `2 ** 10 == 1024` |
| `@` | Матричное умножение по протоколу типа | Встроенные списки его не реализуют |

```python
assert 7 / 2 == 3.5
assert 7 // 2 == 3
assert -7 // 2 == -4
assert -7 % 2 == 1
assert divmod(7, 2) == (3, 1)
assert pow(2, 10, 1000) == 24

try:
    1 / 0
except ZeroDivisionError:
    print("Деление на ноль")
```

Для целых `a == (a // b) * b + a % b` при ненулевом `b`; остаток ненулевого результата имеет знак делителя. Для `float` дополнительно действуют ограничения округления. Трёхаргументный `pow(a, b, modulus)` позволяет считать модульную степень без создания огромного промежуточного результата `a**b`.

### Операции сравнения

`==` и `!=` проверяют равенство по правилам типов; `<`, `<=`, `>`, `>=` — порядок. Python поддерживает цепочки: `low <= value < high` вычисляет средний операнд один раз и пропускает оставшиеся сравнения после ложного результата.

```python
calls = []


def middle():
    calls.append("middle")
    return 5


assert 0 < middle() < 10
assert calls == ["middle"]
assert (1, 9) < (2, 0)
assert "10" < "2"
```

Не заменяй цепочку механически на повторные вызовы `middle()`. Запись `a == b == c` означает два связанных сравнения, а не сравнение булева результата с `c`. Пользовательские и библиотечные типы могут возвращать из сравнения объект, отличный от `bool`, например массив; тогда обычный `if` потребует отдельной политики сведения результата.

### Логические операции

`and` возвращает первый ложный операнд или последний, если все истинны. `or` возвращает первый истинный или последний, если все ложны. `not` всегда возвращает `bool`. Это операции выбора по истинности, а не обязательного преобразования результата к логическому типу.

```python
assert ("" or "fallback") == "fallback"
assert ("ready" and [1, 2]) == [1, 2]
assert (0 and 1 / 0) == 0
assert (True or 1 / 0) is True
assert not []
```

Короткое замыкание позволяет не выполнять опасную или ненужную правую часть. Но `value and value.attribute` вернёт само ложное `value`, а не обязательно `None`. Для необязательного значения точнее `value.attribute if value is not None else None`. Не используй `a and b or c` вместо условного выражения: если `b` ложно, результатом неожиданно станет `c`.

### Побитовые операции

`&`, `|`, `^`, `~`, `<<`, `>>` работают с битами целых. Для `int` модель отрицательных значений соответствует дополнительному коду с неограниченным числом знаковых битов, поэтому `~x == -x - 1`.

```python
READ = 0b001
WRITE = 0b010
EXECUTE = 0b100

permissions = READ | WRITE
assert permissions & READ
assert not permissions & EXECUTE
permissions &= ~WRITE
assert permissions == READ
assert 1 << 5 == 32
assert 32 >> 2 == 8
assert ~5 == -6
```

Для фиксированной ширины явно ограничивай маской: `value & 0xFF` оставляет младшие восемь битов. Сдвиг на отрицательное число запрещён. `&` и `|` также перегружаются для множеств и других типов, но не обеспечивают логического короткого замыкания. Для именованных флагов смотри `enum.IntFlag`.

### Операции присваивания

Составное присваивание `+=`, `*=`, `|=` сначала пытается выполнить операцию на месте, затем при необходимости использует обычную бинарную операцию и перепривязку. Для неизменяемого числа меняется привязка; для списка `+=` обычно меняет существующий объект.

```python
numbers = [1]
alias = numbers
numbers += [2]
assert alias == [1, 2]
assert alias is numbers

count = 1
old_count = count
count += 1
assert old_count == 1
assert count == 2
```

`target += value` не всегда эквивалентно буквальной подстановке `target = target + value`: цель вычисляется один раз, и протокол операции на месте может изменить объект. Даже неуспешное составное присваивание способно оставить побочный эффект:

```python
container = ([1],)
try:
    container[0] += [2]
except TypeError:
    pass
assert container == ([1, 2],)
```

Список успел измениться, после чего попытка записать результат обратно в элемент кортежа завершилась ошибкой. Исключение не означает автоматического отката предыдущих действий.

### Операции принадлежности

`x in container` использует протокол контейнера; `not in` — отрицание результата. Для словаря проверяются ключи, для строки — подстрока, для большинства последовательностей — наличие равного элемента. Для одноразового итератора поиск потребляет элементы до совпадения или до исчерпания.

```python
assert "a" in {"a": 1}
assert 1 not in {"a": 1}
assert "ab" in "abc"

iterator = iter([1, 2, 3, 4])
assert 3 in iterator
assert list(iterator) == [4]
```

Встроенные контейнеры часто учитывают идентичность прежде равенства. Отсюда тонкость `NaN`:

```python
nan = float("nan")
assert nan != nan
assert nan in [nan]
assert float("nan") not in [nan]
```

Проверка принадлежности бесконечному источнику может не завершиться. Не используй её как бесплатный запрос к источнику данных, который должен затем обрабатываться с начала.

### Операции идентичности

`is` отвечает на вопрос, один ли это объект; `==` — равны ли значения по правилам типа. `is` не перегружается. Проверки `is None` и `is MISSING` корректны, сравнение чисел и текста через `is` — ошибка модели.

```python
left = [1, 2]
right = [1, 2]
alias = left
assert left == right
assert left is not right
assert alias is left

value = None
assert value is None
```

Кэширование целых, интернирование строк и объединение констант могут случайно делать равные значения одним объектом. Они зависят от реализации и способа создания кода. Не строй на этом прикладную логику. `id()` уникален среди одновременно живущих объектов, но после освобождения объекта идентификатор может быть использован повторно.

### Перегрузка операторов

Тип может реализовать `__add__`, `__radd__`, `__iadd__`, методы сравнения и другие специальные методы. Если операция не поддерживается для полученного второго типа, бинарный метод должен обычно возвращать `NotImplemented`, чтобы Python мог применить дальнейшие правила выбора операции.

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Vector:
    x: int
    y: int

    def __add__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return Vector(self.x + other.x, self.y + other.y)


assert Vector(1, 2) + Vector(3, 4) == Vector(4, 6)
assert Vector(1, 2).__add__(10) is NotImplemented
try:
    Vector(1, 2) + 10
except TypeError:
    print("Операнды несовместимы")
```

`NotImplemented` — значение протокола, `NotImplementedError` — исключение; они не взаимозаменяемы. Не используй `NotImplemented` как булево значение. Для сравнения и хеширования соблюдай согласованность: равные объекты имеют одинаковый хеш; изменение полей, влияющих на хеш ключа, нарушает работу хеш-таблицы. Подробности выбора отражённых методов и модели данных — в фундаменте и ООП.

### Приоритет операторов и ассоциативность

В таблице выше расположены более сильные группы. В сомнительном месте скобки полезнее проверки читателем всей таблицы.

| Группа | Операции |
| --- | --- |
| Первичные выражения | Вызов, индексирование, срез, доступ к атрибуту |
| Ожидание | `await` |
| Степень | `**` |
| Унарные | `+x`, `-x`, `~x` |
| Мультипликативные | `*`, `@`, `/`, `//`, `%` |
| Аддитивные | `+`, `-` |
| Сдвиги | `<<`, `>>` |
| Побитовое И | `&` |
| Побитовое исключающее ИЛИ | `^` |
| Побитовое ИЛИ | `\|` |
| Сравнения, принадлежность, идентичность | `<`, `<=`, `>`, `>=`, `==`, `!=`, `in`, `not in`, `is`, `is not` |
| Логическое НЕ | `not` |
| Логическое И | `and` |
| Логическое ИЛИ | `or` |
| Условное выражение | `x if condition else y` |
| Лямбда | `lambda` |
| Выражение присваивания | `:=` |

```python
assert 2 + 3 * 4 == 14
assert (2 + 3) * 4 == 20
assert 2**3**2 == 512  # 2 ** (3 ** 2)
assert -(2**2) == -4
assert (-2) ** 2 == 4
assert 2**-2 == 0.25
assert 10 - 3 - 2 == 5  # (10 - 3) - 2
```

Большинство бинарных операторов одной группы связываются слева, степень — справа; условные выражения также группируются справа. У степени особое отношение к унарному оператору справа: `2**-2` допустимо и означает `2**(-2)`. Приоритет сравнений ниже побитовых операций, а цепочки сравнений имеют собственную семантику. Для флагов и условий пиши скобки, если иначе возникает риск двусмысленного чтения.

### Производительность операций

Стоимость оператора зависит от типов и размера данных: сложение двух целых на десять бит и на миллион бит — разная работа; `list_a + list_b` копирует ссылки в новый список; `str_a == str_b` в общем случае может просматривать содержимое.

```python
chunks = [[1, 2], [3], [4, 5]]
flat = [item for chunk in chunks for item in chunk]
assert flat == [1, 2, 3, 4, 5]
```

Не складывай много списков через `sum(chunks, [])`: повторное копирование растущего результата способно дать квадратичную работу. Для потокового обхода подходит `itertools.chain.from_iterable()`, для строки — `join()`. Короткое замыкание может исключить дорогую операцию, но перестановка условий допустима только при сохранении поведения и побочных эффектов.

### Частые ошибки

| Запись | Проблема | Предпочтительная форма |
| --- | --- | --- |
| `value is 1000` | Проверка идентичности числа | `value == 1000` |
| `if value == 'a' or 'b':` | Непустая строка `'b'` делает условие истинным | `if value in {'a', 'b'}:` |
| `a and b or c` | Ложное `b` заменяется на `c` | `b if a else c` |
| `optional or default` | Теряется допустимый ноль или пустота | Явная проверка `is None` |
| `a & b` вместо `a and b` | Нет короткого замыкания, другие типы результата | Логический оператор по смыслу |
| `items += value` как «создание копии» | Возможна мутация общего объекта | Явная новая коллекция |

Сложное выражение с несколькими изменениями состояния разбей на шаги. Это улучшает не только стиль: становится видно, какая часть успела выполниться при исключении и какие инварианты должны сохраняться.

### Частые вопросы и ключевые выводы

**Почему `and` вернул список?** Он выбирает операнд по истинности, а не обязан возвращать `bool`.

**Что быстрее: `is` или `==`?** Они отвечают на разные вопросы. Выбор операции определяется корректностью; сравнение скорости не исправляет неверный смысл.

**Всегда ли `+=` меняет объект?** Нет. Это зависит от типа и протокола операции; для чисел происходит перепривязка, для списка обычно мутация.

**Самопроверка:** вычисли `-3 // 2`, `-3 % 2`, `2**3**2`, `[] or 0 or 'x'`. Затем объясни, почему неуспешное присваивание не означает отсутствия побочных эффектов.

**Документация:** [выражения и приоритет](https://docs.python.org/3.14/reference/expressions.html), [модель данных и специальные методы](https://docs.python.org/3.14/reference/datamodel.html).

## Управление потоком

### Что такое управление потоком?

Управление потоком определяет, какие действия выполняются, в каком порядке и сколько раз. Последовательное исполнение изменяется условиями, циклами, возвратом из функции и распространением исключений. Для корректности полезно знать не только обычный путь, но и все способы выйти из блока.

При чтении функции задай три вопроса: какие данные допустимы на входе, какие действия способны завершиться ошибкой и что гарантировано на каждом выходе. В этой теме `return` используется в небольших функциях; полный контракт функций разбирается в следующей главе.

### Блоки кода и отступы

После заголовка составной инструкции с двоеточием следует тело — одна или несколько инструкций с большим отступом. Возврат к прежнему уровню завершает блок. Пустые строки и комментарии сами по себе не образуют тело.

```python
age = 20
if age >= 18:
    status = "adult"
    print(status)
else:
    status = "minor"

assert status == "adult"
```

Если переменная присваивается только в одной ветви, после условия она может остаться неопределённой. Убедись, что значение создаётся на каждом используемом пути, либо заверши остальные пути через `return` или исключение.

### pass — заглушка для пустых блоков

`pass` — инструкция, которая ничего не делает. Она позволяет написать синтаксически непустое тело класса, функции, условия или обработчика.

```python
class ConfigurationError(Exception):
    pass


for value in range(3):
    if value == 1:
        pass
    print(value)  # Будут выведены 0, 1 и 2.
```

`pass` не пропускает остаток текущей итерации: это делает `continue`. Для незавершённой обязательной реализации часто лучше `raise NotImplementedError`, чтобы вызов не выглядел успешным. `...` является выражением со значением `Ellipsis`; в stubs оно используется как условное пустое тело, но это не отдельная инструкция `pass`.

### Сравнение с другими языками (блоки {})

В Python блоки задаются отступами, а фигурные скобки создают словарь или множество. Скобки вокруг условия `if` и `while` не обязательны. Логические операции записываются словами `and`, `or`, `not`; формы `&&` и `||` отсутствуют.

```python
value = 3
if value > 0 and value < 10:
    label = "small positive"
assert label == "small positive"

mapping = {"value": value}
unique = {value}
assert mapping["value"] in unique
```

`if`, `for` и `while` не вводят блоковую область переменных, привычную по некоторым другим языкам. Инкремента `++` нет: `++x` разбирается как два унарных плюса и не увеличивает `x`; используй `x += 1`.

### Условные операторы

Условие вычисляется и проверяется на истинность. Результат не обязан изначально иметь тип `bool`, но должен поддерживать однозначную проверку истинности. В цепочке `if/elif/else` выполняется не более одной ветви.

Различай выбор одной альтернативы и несколько независимых проверок: три отдельных `if` способны выполнить три действия; `if/elif/elif` выберет только первое подходящее. Это особенно важно, когда условия пересекаются.

### Условные операторы: if, elif, else

```python
def classify_temperature(value: float) -> str:
    if value < 0:
        return "freezing"
    elif value < 25:
        return "mild"
    else:
        return "hot"


assert classify_temperature(-5) == "freezing"
assert classify_temperature(10) == "mild"
assert classify_temperature(30) == "hot"
```

Порядок проверок определяет результат: слишком широкое первое условие может сделать позднее недостижимым. При внешнем `float` отдельно реши судьбу `NaN`: в этой демонстрационной функции он попадёт в последнюю ветвь, потому что оба сравнения ложны. В рабочем контракте измерения часто правильнее сначала проверить `math.isfinite()`.

### Условные операторы: вложенные условия

Вложенность удобна, когда второе действие имеет смысл только после первого. При нескольких проверках входа ранний возврат или исключение часто уменьшают вложенность.

```python
def may_edit(user: dict | None) -> bool:
    if user is None:
        return False
    if not user.get("active", False):
        return False
    return "editor" in user.get("roles", ())


assert not may_edit(None)
assert may_edit({"active": True, "roles": ["editor"]})
```

Здесь предполагается уже проверенная структура словаря. Если `roles` пришёл из произвольного JSON, `None`, строка или число потребуют отдельной валидации. Уменьшение отступов не заменяет явного контракта.

### Условные операторы: Truthiness (приведение к bool)

Ложными считаются `None`, `False`, нулевые числа и пустые стандартные контейнеры. Для пользовательского объекта применяется `__bool__`, а при его отсутствии — `__len__`; если нет обоих, объект обычно истинен.

```python
assert not any([None, False, 0, 0.0, "", [], {}, set()])
assert bool("False")
assert bool(float("nan"))
assert bool(iter([]))  # Наличие итератора не означает наличие элементов.


class Unavailable:
    def __bool__(self):
        raise RuntimeError("Истинность не определена")


try:
    bool(Unavailable())
except RuntimeError:
    print("Проверка истинности тоже может завершиться ошибкой")
```

У некоторых библиотечных объектов, например многозначных массивов, истинность намеренно неоднозначна. Выбирай `any`, `all`, проверку размера или иной критерий явно. Для итератора нельзя узнать пустоту через `bool(iterator)`; извлечение первого элемента уже меняет его состояние.

### Условные операторы: тернарный оператор

Условное выражение имеет форму `value_if_true if condition else value_if_false`. Вычисляется только выбранная ветвь, поэтому им можно безопасно исключить ненужную операцию.

```python
denominator = 0
ratio = 10 / denominator if denominator != 0 else None
assert ratio is None

timeout = 0
assert (30 if timeout is None else timeout) == 0
```

Используй его для короткого выбора значения. Длинные вложенные выражения превращают ветвление в головоломку; вынеси их в обычный `if` или функцию. Включение с фильтром `[x for x in values if condition]` и включение с условным результатом `[x if condition else y for ...]` имеют разные роли.

### Сравнение цепочек условий

```python
age = 20
assert 18 <= age < 65

role = "editor"
assert role in {"admin", "editor"}
role = "reader"
bad_condition = role == "admin" or "editor"
assert bad_condition == "editor"
assert bool(bad_condition)
assert role not in {"admin", "editor"}
```

Последняя запись намеренно демонстрирует неудачную форму: `role == "admin" or "editor"` возвращает непустую строку и потому истинно даже для чужой роли. В рабочем коде оставь проверку принадлежности, а не эту диагностику.

Для правил с разными действиями подходит `if/elif`; для точного соответствия ключа действию — словарь диспетчеризации; для структуры вложенных данных — `match`. Не заменяй поиск по диапазонам словарём, если совпадение не сводится к равенству ключа.

### Циклы

`for` получает элементы итератора до исчерпания; `while` повторяет тело, пока условие истинно. У обоих есть `break`, `continue` и необязательный `else`. Цикл сам по себе не создаёт копию данных и не защищает их от изменений.

Для потокового алгоритма сформулируй инвариант: что верно перед каждой итерацией. Например, «накопленная сумма равна сумме всех уже обработанных допустимых записей». Такая формулировка помогает проверить `continue`, ошибки и ранний выход.

### while

```python
remaining = 3
steps = []
while remaining > 0:
    steps.append(remaining)
    remaining -= 1
assert steps == [3, 2, 1]

iterator = iter(["a", "b", ""])
received = []
while (item := next(iterator)) != "":
    received.append(item)
assert received == ["a", "b"]
```

Во втором примере договорённость источника гарантирует завершающую пустую строку. Если она не придёт, `next()` возбудит `StopIteration`. Для внешнего потока обрабатывай конец по его настоящему протоколу, задавай предел ожидания там, где нужен, и следи, чтобы `continue` не пропускал изменение, необходимое для завершения `while`.

### for с range()

```python
assert [index for index in range(3)] == [0, 1, 2]
assert [index for index in range(5, 0, -2)] == [5, 3, 1]

attempts = 0
for _ in range(3):
    attempts += 1
assert attempts == 3
```

Если нужны сами значения коллекции, перебирай её напрямую: `for user in users`. Для позиции и значения используй `enumerate()`. Изменение переменной цикла внутри тела не меняет следующий элемент, который выдаст итератор `range`.

### enumerate()

`enumerate(iterable, start=0)` лениво выдаёт пары «счётчик, элемент». `start` меняет начальное число счётчика, а не позицию чтения входа.

```python
rows = ["alpha", "beta"]
assert list(enumerate(rows, start=1)) == [(1, "alpha"), (2, "beta")]
assert list(enumerate(iter(rows), start=10)) == [(10, "alpha"), (11, "beta")]
```

Для номеров строк файла обычно нужен `start=1`. Для реальных индексов списка обычно оставляют ноль. Если ты отфильтровал строки до `enumerate`, номера соответствуют уже отфильтрованному источнику; для сохранения исходных номеров сначала нумеруй, затем фильтруй.

### zip()

`zip()` лениво объединяет источники по позиции и по умолчанию останавливается на самом коротком. Источники читаются слева направо. При поиске конца часть элементов других источников уже может быть потреблена.

```python
assert list(zip([1, 2], ["a", "b"])) == [(1, "a"), (2, "b")]
assert list(zip([1, 2, 3], ["a"])) == [(1, "a")]
assert list(zip()) == []
assert list(zip([1, 2])) == [(1,), (2,)]
```

`dict(zip(keys, values))` может одновременно скрыть разную длину и заменить повторяющиеся ключи последним значением. Если это построение словаря является границей данных, проверь обе договорённости явно. Для заполнения недостающих элементов есть `itertools.zip_longest()`.

### Проверка одинаковой длины последовательностей: zip(..., strict=True)

С Python 3.10 `strict=True` превращает различие длин в `ValueError`. Проверка выполняется при чтении, а не при создании объекта `zip`, и не отменяет уже обработанные пары.

```python
pairs = zip([1, 2], ["a"], strict=True)
assert next(pairs) == (1, "a")
try:
    next(pairs)
except ValueError:
    print("Источники имеют разную длину")
```

Поэтому `strict=True` защищает от молчаливой потери хвоста, но не делает обработку атомарной. Если внешние изменения нельзя выполнять до полной проверки, сначала проверь/материализуй ограниченный вход или используй транзакционную границу. `len()` заранее доступен не у каждого источника и сам по себе не защищает от последующих изменений.

### reversed()

`reversed()` получает обратный итератор объекта с соответствующим протоколом либо подходящей поддержкой последовательности. Он не сортирует и обычно не создаёт копию всех элементов.

```python
values = [1, 2, 3]
assert list(reversed(values)) == [3, 2, 1]
assert values == [1, 2, 3]
assert list(reversed(range(4))) == [3, 2, 1, 0]
assert list(reversed({"a": 1, "b": 2})) == ["b", "a"]
```

Произвольный генератор не обязан поддерживать обратный обход. Для него потребуется буферизация, если она допустима. Не меняй структуру исходной последовательности во время обратного обхода без специально продуманного алгоритма.

### обход словарей и множеств

```python
scores = {"Alice": 10, "Bob": 20}
assert list(scores) == ["Alice", "Bob"]
assert list(scores.values()) == [10, 20]
assert list(scores.items()) == [("Alice", 10), ("Bob", 20)]

for name in scores:
    scores[name] += 1
assert scores == {"Alice": 11, "Bob": 21}

for name in list(scores):
    if scores[name] < 20:
        del scores[name]
assert scores == {"Bob": 21}
```

Словарь сохраняет порядок вставки, множество не обещает нужного прикладного порядка. Для воспроизводимого отчёта обойди `sorted(tags)` при сравнимых строковых тегах. Создание `list(scores)` делает снимок ключей, но значения исходного словаря остаются живыми и могут изменяться.

### обход строк

```python
text = "Aé"
assert list(text) == ["A", "é"]
assert [(index, ord(char)) for index, char in enumerate(text)] == [(0, 65), (1, 233)]
assert list("é".encode("utf-8")) == [195, 169]
```

Обход строки выдаёт строки по одной кодовой точке, а обход байтов — целые байты. Если задача относится к словам, строкам документа или графемам, сначала выбери соответствующее разбиение. Символьный цикл редко заменяет parser CSV, JSON или HTML.

### обход файлов

Текстовый файл итерируется по строкам, обычно с сохранением завершающего перевода строки. `with` закрывает файл при обычном выходе и исключении. Не вызывай `readlines()` только для того, чтобы сразу обойти результат: это загружает все строки.

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as directory:
    path = Path(directory) / "events.txt"
    path.write_text("first\n\nthird\n", encoding="utf-8")
    collected = []
    with path.open(encoding="utf-8") as source:
        for line_number, line in enumerate(source, start=1):
            content = line.rstrip("\r\n")
            if not content:
                continue
            collected.append((line_number, content))
    assert collected == [(1, "first"), (3, "third")]
```

`strip()` убирает также значимые пробелы по краям, поэтому для удаления конца строки он не всегда подходит. Построчная обработка ограничивает буфер текущей строкой, но одна строка тоже может быть огромной, а накопленный результат — занять всю память. Для форматов с ограничениями нужны пределы размера записи и итоговых структур.

### вложенные циклы

```python
pairs = []
for x in [1, 2]:
    for y in ["a", "b"]:
        pairs.append((x, y))
assert pairs == [(1, "a"), (1, "b"), (2, "a"), (2, "b")]
```

Если внешний цикл имеет `n` итераций, а внутренний каждый раз проходит `m` элементов, работа обычно пропорциональна `n*m`. Источник внутреннего цикла должен быть доступен заново: один и тот же итератор после первого прохода будет исчерпан. Не создавай декартово произведение, если задача решается одним поиском по словарю или множеству.

### Управление циклами

`break` завершает ближайший цикл, `continue` переходит к его следующей итерации, `return` выходит из функции. Исключение распространяется до подходящего обработчика. `finally` выполняется при этих переходах по обычным правилам раскрутки стека и может повлиять на итог, если сам делает переход или возбуждает новую ошибку.

Перед добавлением раннего выхода проверь, какие действия остаются ниже: обновление счётчика, освобождение ресурса, запись статистики. Обязательную очистку размещай в контекстном менеджере или `finally`, а не только в последней строке тела.

### break

```python
found = None
for value in [1, 3, 8, 10]:
    if value % 2 == 0:
        found = value
        break
assert found == 8
```

Цикл заканчивается сразу, оставшиеся элементы не обрабатываются. Для итератора эти элементы могут оставаться доступными из текущего состояния. Сам `break` не означает закрытие произвольного источника; жизненный цикл файла должен обеспечиваться `with`.

### continue

```python
total = 0
for value in [-1, 2, -3, 4]:
    if value < 0:
        continue
    total += value
assert total == 6
```

`continue` не считается прерыванием для `else` цикла. В `while` особенно следи за прогрессом: если обновление находится после `continue`, условие может навсегда остаться истинным.

### else в циклах

`else` выполняется при нормальном исчерпании `for` или ложном условии `while`, если цикл не был завершён через `break`. Он срабатывает и для нуля итераций. Исключение или `return`, вышедшие из цикла, не приводят к выполнению его `else`.

```python
def find_even(values):
    for value in values:
        if value % 2 == 0:
            break
    else:
        return None
    return value


assert find_even([1, 3, 8]) == 8
assert find_even([1, 3]) is None
assert find_even([]) is None
```

Это удобно для поиска «ничего не найдено», однако условие должно быть ясно читателю. Для простого поиска часто достаточно `next((...), default)`. Не воспринимай `else` как «тело цикла успешно выполнилось хотя бы раз».

### прерывание внешнего цикла

Для выхода из нескольких вложенных циклов часто проще выделить поиск в функцию и вернуть результат. Флаг подходит, если функция неуместна; исключение ради обычного локального поиска обычно добавляет лишнюю сложность.

```python
def find_position(matrix, target):
    for row_index, row in enumerate(matrix):
        for column_index, value in enumerate(row):
            if value == target:
                return row_index, column_index
    return None


assert find_position([[1, 2], [3, 4]], 3) == (1, 0)
assert find_position([[1, 2]], 9) is None
```

Вариант с `for/else` внутреннего цикла тоже возможен, но несколько уровней `else` сложно читать. Выбирай форму, в которой область раннего выхода очевидна и результат не зависит от неинициализированных переменных.

### Сопоставление с образцом (Python 3.10+)

`match` проверяет структуру значения по образцам. Это не просто `switch` по равенству: образец может одновременно проверить тип структуры, извлечь части и связать имена. Ветки проверяются по порядку; после первой подходящей с истинным guard выполняется её тело, без автоматического перехода в следующую ветку.

Предмет сопоставления вычисляется один раз. Отсутствие подходящей ветки само по себе не вызывает исключения. Если неизвестная форма является ошибкой API, добавь `case _:` с явным отказом.

### match/case

```python
def describe_command(command):
    match command:
        case "start":
            return "starting"
        case "stop":
            return "stopping"
        case _:
            return "unknown"


assert describe_command("start") == "starting"
assert describe_command("restart") == "unknown"
```

`_` в образце — wildcard, он не связывает имя. Безусловный захватывающий образец без guard должен находиться последним, иначе поздние ветки недостижимы и компиляция отклонит конструкцию. В отличие от C-подобного `switch`, `break` между `case` не нужен.

### Связывание имён при сопоставлении с образцом

Обычное имя в образце захватывает значение, а не сравнивает его с прежним значением переменной. Для именованной константы обычно нужен точечный доступ, например `State.READY`.

```python
from enum import Enum


class State(Enum):
    READY = "ready"
    STOPPED = "stopped"


def is_ready(value):
    match value:
        case State.READY:
            return True
        case _:
            return False


assert is_ready(State.READY)
assert not is_ready(State.STOPPED)

expected = 10
match 99:
    case expected:
        captured = expected
assert expected == captured == 99
```

Связанные имена доступны после успешной ветки: `case` не создаёт отдельную область. При неуспешном сложном сопоставлении нельзя полагаться на сохранение или отсутствие частичных привязок: язык оставляет такие детали открытыми. Guard выполняется после успешного сопоставления, поэтому имена уже связаны, даже если guard затем вернул ложь.

```python
match [5]:
    case [captured] if captured < 0:
        raise AssertionError("Ветка не должна выполниться")
assert captured == 5
```

Используй захваченные имена внутри соответствующей ветки и не строй логику на случайном остаточном состоянии после всех `case`. Повторно связать одно имя в одном образце нельзя: `[x, x]` не означает «два равных значения»; используй `[x, y] if x == y`.

### сопоставление с литералами

Числовые и строковые литералы обычно сопоставляются по равенству. `None`, `True` и `False` — специальные singleton-образцы, использующие идентичность. Из-за числового равенства `case 1` способен принять `True`.

```python
def literal_category(value):
    match value:
        case True:
            return "true singleton"
        case 1:
            return "one"
        case None:
            return "missing"
        case _:
            return "other"


assert literal_category(True) == "true singleton"
assert literal_category(1) == "one"
assert literal_category(1.0) == "one"
```

Если важно именно целое число без `bool`, добавь проверку `type(value) is int`. Порядок образцов с пересекающимися условиями влияет на результат, как и порядок `if/elif`.

### сопоставление с последовательностями

Образец `[head, *tail]` разбирает подходящую последовательность. Квадратная и круглая формы образцов последовательности не требуют соответственно `list` или `tuple`: один образец может принять оба типа. `str`, `bytes` и `bytearray` специально не разбираются как последовательности в таком образце; обычный итератор тоже не подходит автоматически.

```python
def unpack_command(value):
    match value:
        case ["move", x, y]:
            return x, y
        case ["echo", *words]:
            return words
        case _:
            return None


assert unpack_command(("move", 10, 20)) == (10, 20)
assert unpack_command(["echo", "hello", "world"]) == ["hello", "world"]
assert unpack_command("move") is None
assert unpack_command(iter(["move", 10, 20])) is None
```

Звёздная часть собирается в список. Один уровень образца допускает одну такую часть. Не путай синтаксис структурного сопоставления с распаковкой произвольного iterable при обычном присваивании: протоколы здесь различаются.

### сопоставление с классами

Образец `ClassName(field=pattern)` проверяет принадлежность к классу через механизм `isinstance` и сопоставляет атрибуты. Он не создаёт новый объект и не вызывает конструктор класса.

```python
from dataclasses import dataclass


@dataclass
class Point:
    x: int
    y: int


def position(point):
    match point:
        case Point(x=0, y=y):
            return "vertical", y
        case Point(x=x, y=0):
            return "horizontal", x
        case _:
            return "other", None


assert position(Point(0, 5)) == ("vertical", 5)
assert position(Point(3, 0)) == ("horizontal", 3)
```

Чтение атрибута может выполнить property или другой пользовательский код. Аннотация `x: int` в dataclass не проверяет значение при создании; образец `Point(x=x)` тоже не добавляет эту проверку. Если структура является границей доверия, используй вложенные типовые образцы и guards по контракту.

### Позиционное сопоставление объектов через `__match_args__`

`__match_args__` — кортеж имён атрибутов, определяющий смысл позиционных частей образца класса. Dataclass обычно создаёт его для подходящих полей автоматически; его можно определить явно.

```python
class Point:
    __match_args__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y


point = Point(10, 20)
match point:
    case Point(x, y):
        result = x + y
assert result == 30
```

`case Point(x, y)` означает примерно сопоставление атрибутов `x` и `y`, а не вызов `Point`. Изменение `__match_args__` меняет публичную семантику позиционных образцов. Для долгоживущего API именованные части часто устойчивее к перестановке полей. Встроенные типы вроде `int(value)` имеют специальные разрешённые формы, которые не следует выводить из обычной структуры `__match_args__`.

### сопоставление со словарями

Mapping-образец требует перечисленные ключи, но обычно допускает дополнительные. Ключи записываются литералами или допустимыми value patterns; значения могут захватываться и проверяться вложенными образцами.

```python
def parse_payload(payload):
    match payload:
        case {"kind": "user", "id": int(user_id), **rest}:
            return user_id, rest
        case _:
            return None


assert parse_payload({"kind": "user", "id": 7, "active": True}) == (7, {"active": True})
assert parse_payload({"kind": "user"}) is None
```

`int(user_id)` — образец типа, не преобразование строки в число. Он также принимает `bool` как подкласс `int`; строгий контракт требует guard. `**rest` создаёт словарь оставшихся пар, а `**_` в mapping-образце недопустим.

Сопоставление отсутствующего ключа не предназначено для запуска `defaultdict`-фабрики через обычное индексирование. Pattern matching не заменяет JSON Schema или полноценную валидацию: нужно отдельно проверить диапазоны, длины, допустимые дополнительные поля и смысл значений.

### Guards (условия)

Guard `if expression` выполняется после успешного сопоставления и может использовать связанные имена. Если он ложен, проверяется следующая ветка. Если guard возбудил исключение, оно распространяется — это не обычное несовпадение образца.

```python
def parse_quantity(value):
    match value:
        case {"quantity": int(quantity)} if type(quantity) is int and quantity > 0:
            return quantity
        case _:
            raise ValueError("Ожидается положительное целое количество")


assert parse_quantity({"quantity": 3}) == 3
for bad in [{"quantity": True}, {"quantity": -1}, {"quantity": "3"}]:
    try:
        parse_quantity(bad)
    except ValueError:
        pass
    else:
        raise AssertionError("Невалидное количество принято")
```

Проверки в guard должны оставаться понятными. Если условие выполняет сетевой запрос, меняет состояние или может существенно задержаться, обычная последовательность инструкций часто лучше выражает процесс.

### OR паттерны

Образец `p1 | p2` принимает любую альтернативу. Все альтернативы должны связывать один и тот же набор имён. `as` позволяет сохранить совпавшее значение целиком.

```python
def normalize_action(action):
    match action:
        case ("start" | "run") as command:
            return "start", command
        case ["move", x, y] | ("go", x, y):
            return "move", (x, y)
        case _:
            return "unknown", None


assert normalize_action("run") == ("start", "run")
assert normalize_action(("go", 1, 2)) == ("move", (1, 2))
```

Это оператор альтернативы в грамматике образцов, а не побитовое ИЛИ над значениями. Guard после OR относится к итоговому сопоставлению, не является независимым фильтром каждой альтернативы.

### вложенные паттерны

```python
def read_city(payload):
    match payload:
        case {"user": {"address": {"city": str(city)}}} if city.strip():
            return city.strip()
        case _:
            raise ValueError("Нужен непустой город")


assert read_city({"user": {"address": {"city": " Москва "}}}) == "Москва"
```

Вложенный образец помогает выразить ожидаемую форму, но длинная структура может затруднить диагностику: один `case _` уже не объясняет, какое поле отсутствует. Для пользовательских форм и сложных контрактов лучше валидатор, возвращающий ошибки с путём до поля. Используй `match`, когда он делает форму данных видимой, а не скрывает необходимые сообщения об ошибках.

### Сравнение match/case с if/elif

| Ситуация | Обычно проще |
| --- | --- |
| Диапазоны, независимые булевы признаки | `if/elif` |
| Разбор нескольких форм сообщения | `match/case` |
| Точное соответствие ключа обработчику | Словарь обработчиков |
| Проверка схемы с подробными ошибками | Функция валидации или подходящий валидатор |
| Сложные действия между проверками | Обычная последовательность инструкций |

`match` не гарантирует автоматическое ускорение и не обязан компилироваться в таблицу переходов. Выбор определяется выразительностью и контрактом. Статическая проверка полноты вариантов может помогать при определённых типах и настройках анализатора, но интерпретатор не обеспечивает исчерпывающее сопоставление всех возможных значений.

### Обработка исключений

Исключение переносит управление из места неуспешной операции к ближайшему подходящему обработчику по стеку. Полезный обработчик делает одно из трёх: восстанавливает допустимое состояние, переводит ошибку на уровень абстракции своего API или добавляет контекст и передаёт её дальше.

Не перехватывай ошибку только ради сообщения «что-то пошло не так», если затем программа продолжает работу с нарушенными предпосылками. Отсутствие traceback не является успешной обработкой.

### Что такое исключения?

Исключение — объект класса, наследующегося от `BaseException`. С ним связаны тип, значение и traceback. Синтаксическая ошибка при компиляции и ошибка во время выполнения — разные этапы; обычный `try` вокруг уже некорректного исходного кода не спасёт модуль от ошибки разбора.

```python
try:
    compile("if True print('x')", "<example>", "exec")
except SyntaxError as error:
    assert error.lineno == 1

try:
    int("invalid")
except ValueError as error:
    assert isinstance(error, Exception)
```

Здесь `SyntaxError` можно поймать, потому что некорректный текст поступает в `compile()` во время выполнения уже корректной программы. Не используй этот приём для исполнения произвольного пользовательского кода: это учебная диагностика заранее известного текста.

### Типы исключений

`Exception` охватывает обычные ошибки приложений. `KeyboardInterrupt`, `SystemExit` и `GeneratorExit` наследуются непосредственно от `BaseException`, чтобы широкое `except Exception` обычно не мешало прерыванию и завершению.

```python
assert issubclass(ValueError, Exception)
assert issubclass(KeyboardInterrupt, BaseException)
assert not issubclass(KeyboardInterrupt, Exception)
assert not issubclass(SystemExit, Exception)
```

Для собственных прикладных ошибок наследуйся обычно от `Exception` или подходящего конкретного подкласса. Не создавай без необходимости множественное наследование от нескольких встроенных исключений: их внутренняя структура и смысл могут быть несовместимы.

### try/except

```python
def parse_port(text: str) -> int:
    try:
        port = int(text)
    except ValueError as error:
        raise ValueError("Порт должен быть целым числом") from error

    if not 1 <= port <= 65_535:
        raise ValueError("Порт вне допустимого диапазона")
    return port


assert parse_port("8080") == 8080
try:
    parse_port("abc")
except ValueError as error:
    assert isinstance(error.__cause__, ValueError)
```

Держи тело `try` узким, чтобы было ясно, какая операция породила перехваченную ошибку. Обработчики проверяются сверху вниз: специфичные должны стоять перед общими. Для нескольких типов используй `except (ValueError, TypeError):` — эта форма переносима между версиями. Не ставь пустой `except:` для обычной ошибки разбора: он перехватывает также завершение и прерывание.

### else в исключениях

Блок `else` выполняется, если тело `try` завершилось нормально, без исключения и выхода через `return`, `break` или `continue`. Он помогает выполнить последующие действия вне области перехвата ошибок исходной операции.

```python
events = []
try:
    number = int("42")
except ValueError:
    events.append("invalid")
else:
    events.append(f"parsed:{number}")
finally:
    events.append("finished")

assert events == ["parsed:42", "finished"]
```

Исключение из `else` не попадёт в соседний `except` этого же `try`. Это полезно: ошибка сохранения результата не будет ошибочно обработана как ошибка преобразования строки в число.

### finally

`finally` выполняет очистку при нормальном выходе и обычном распространении исключения. Он также выполняется перед фактическим `return`, `break` или `continue`, которые покидают охватываемую область. Это гарантия управления потоком интерпретатора, а не обещание пережить аварийное завершение процесса, отключение питания или `os._exit()`.

```python
events = []


def operation():
    try:
        events.append("work")
        return 10
    finally:
        events.append("cleanup")


assert operation() == 10
assert events == ["work", "cleanup"]
```

Выход из `finally` через `return` способен подавить ожидающее исключение или заменить результат возврата. Новое исключение в очистке может стать основным, сохранив прежнее в цепочке. Поэтому не возвращай значения из `finally`; ресурсы по возможности обслуживай через `with`.

```python
# Python 3.14+: диагностика выхода из finally.
import warnings

source = """def hides_error():
    try:
        raise ValueError('lost')
    finally:
        return 42
"""
with warnings.catch_warnings(record=True) as captured:
    warnings.simplefilter("always", SyntaxWarning)
    namespace = {}
    exec(compile(source, "<finally-demo>", "exec"), namespace)

assert namespace["hides_error"]() == 42
assert any(issubclass(item.category, SyntaxWarning) for item in captured)
```

В Python 3.14 компилятор диагностирует некоторые переходы, покидающие `finally`, через `SyntaxWarning`. Не воспринимай предупреждение как замену проверке корректности очистки.

### raise — возбуждение исключений

`raise ErrorType(message)` создаёт отказ, голый `raise` внутри обработчика повторно возбуждает текущее исключение. `raise NewError(...) from error` задаёт явную причину, а `from None` подавляет отображение неявного контекста при стандартном выводе traceback.

```python
class ConfigurationError(Exception):
    pass


def read_required(mapping, key):
    try:
        return mapping[key]
    except KeyError as error:
        raise ConfigurationError(f"Отсутствует параметр {key!r}") from error


try:
    read_required({}, "host")
except ConfigurationError as error:
    assert isinstance(error.__cause__, KeyError)
    assert isinstance(error.__context__, KeyError)
```

`from None` не удаляет контекстный объект полностью и не является средством удаления секретов из памяти. Выбирай сообщения без чувствительных данных. Для повторного возбуждения предпочитай голый `raise`: `raise error` меняет место повторного возбуждения в traceback и обычно добавляет лишнюю рамку.

### Распространенные встроенные исключения

| Исключение | Типичная причина | Что не следует делать |
| --- | --- | --- |
| `TypeError` | Неподходящий тип или форма вызова | Подменять ошибку случайным значением |
| `ValueError` | Тип подходит, значение недопустимо | Игнорировать плохую запись без учёта потери |
| `KeyError` | Нет ключа отображения | Путать отсутствие с `None` |
| `IndexError` | Индекс вне последовательности | Предполагать безопасное индексирование как у среза |
| `AttributeError` | Нет атрибута | Считать доказательством только отсутствия данных: property тоже может ошибиться |
| `NameError` | Не найдено имя | Маскировать ошибку написания через широкий `except` |
| `UnboundLocalError` | Локальное имя ещё не связано | Исправлять случайным `global` без изменения дизайна |
| `ZeroDivisionError` | Деление на ноль | Продолжать с непроверенным результатом |
| `OSError` и подклассы | Ошибка файловой/системной операции | Проверять только `exists()` перед открытием |
| `UnicodeError` и подклассы | Ошибка кодирования/декодирования | Молча терять символы через `ignore` |
| `StopIteration` | Итератор исчерпан | Возбуждать его вручную внутри генератора вместо `return` |
| `RuntimeError` | Нарушение состояния исполнения/контракта | Использовать как единственный тип всех прикладных отказов |

Не рассчитывай на точный английский текст встроенной ошибки как стабильный машинный API: он может меняться по версиям. Проверяй тип и необходимые структурированные атрибуты, а для своей ошибки предоставляй собственный устойчивый код или поля, если потребителю это нужно.

### Продвинутая модель исключений

Неявная цепочка хранится в `__context__`, явная причина — в `__cause__`, стек — в `__traceback__`. Удержание исключения или traceback может удерживать локальные переменные кадров и большие объекты. Не складывай traceback в неограниченный глобальный список.

С Python 3.11 `add_note()` добавляет диагностическую заметку, не меняя тип исключения:

```python
try:
    try:
        raise ValueError("Некорректная цена")
    except ValueError as error:
        error.add_note("Файл events.jsonl, строка 12")
        raise
except ValueError as error:
    assert error.__notes__ == ["Файл events.jsonl, строка 12"]
```

`ExceptionGroup` объединяет несколько ошибок, а `except*` обрабатывает соответствующие подгруппы. Это полезно для параллельных операций и пакетной обработки, где одновременно произошло несколько независимых отказов.

```python
handled = []
try:
    raise ExceptionGroup("batch", [ValueError("bad value"), TypeError("bad type")])
except* ValueError as group:
    handled.append(("value", len(group.exceptions)))
except* TypeError as group:
    handled.append(("type", len(group.exceptions)))

assert handled == [("value", 1), ("type", 1)]
```

Необработанная часть группы распространяется дальше. Обычный `except ValueError` не извлекает вложенные ошибки из группы. Нельзя смешивать `except` и `except*` в одном `try`; для сочетания нужны разные вложенные уровни. `return`, `break` и `continue` непосредственно в теле `except*` запрещены, чтобы одна подгруппа не прервала обработку остальных.

Не перехватывай групповую ошибку целиком и не объявляй весь пакет успешным, если разобрана только одна категория. Для частичного успеха нужна явная модель результата и учёт оставшихся отказов.

### Утверждения и предупреждения

`assert condition, message` проверяет предположение разработчика и при ложном условии возбуждает `AssertionError`. При запуске с `-O` проверки могут удаляться вместе с вычислением условия. Поэтому `assert` не подходит для валидации внешнего ввода, авторизации и обязательных побочных эффектов.

```python
import subprocess
import sys

program = "assert False, 'invariant'; print('continued')"
normal = subprocess.run([sys.executable, "-c", program], capture_output=True, text=True)
optimized = subprocess.run(
    [sys.executable, "-O", "-c", program], capture_output=True, text=True
)
assert normal.returncode != 0
assert optimized.returncode == 0
assert optimized.stdout.strip() == "continued"
```

Предупреждение сообщает о подозрительном или устаревающем поведении без обязательного немедленного отказа. Фильтр может скрыть его, показать один раз или превратить в исключение.

```python
import warnings

with warnings.catch_warnings(record=True) as captured:
    warnings.simplefilter("always", DeprecationWarning)
    warnings.warn("Используйте new_api", DeprecationWarning, stacklevel=1)
assert len(captured) == 1

with warnings.catch_warnings():
    warnings.simplefilter("error", DeprecationWarning)
    try:
        warnings.warn("old API", DeprecationWarning)
    except DeprecationWarning:
        pass
```

`DeprecationWarning` в обычном запуске библиотеки может быть скрыт по умолчанию. В проверках включай нужную политику, например `python -W error ...`, но учитывай предупреждения зависимостей. Для библиотечного wrapper часто нужен `stacklevel=2`, чтобы сообщение указывало на вызывающий код.

### Частые ошибки

| Ошибка | Почему опасно |
| --- | --- |
| `except Exception: pass` | Ошибка теряется, состояние может быть некорректным |
| Проверка `path.exists()` как гарантия успешного открытия | Между проверкой и использованием состояние может измениться |
| Большой `try` вокруг всей функции | Неясно, какая операция дала перехваченную ошибку |
| `return` в `finally` | Может скрыть исключение или заменить результат |
| `assert` для проверки входных данных | Проверка исчезает с `-O` |
| `case expected:` для сравнения с переменной | Происходит захват имени |
| Обычный `zip` для обязательного полного соответствия | Молча отбрасывается хвост |
| Удаление элементов списка при прямом обходе | Можно пропустить часть элементов |
| Логирование и повторное логирование на каждом уровне | Один отказ превращается в много дублирующих сообщений |

### Лучшие практики

Проверяй внешний ввод на границе системы и превращай его в понятные внутренние значения. Внутри основного алгоритма работай с уже известным контрактом. Перехватывай только те ошибки, для которых есть действие; при переводе ошибки сохраняй причину через `from`.

Для ресурсов применяй контекстные менеджеры. Для CLI задай устойчивые коды завершения. Для пакетной обработки явно считай принятые, пропущенные и отклонённые записи; ограничивай объём диагностических сообщений. Для повторной попытки сначала проверь, является ли операция безопасной для повторения: сетевой тайм-аут не доказывает, что внешняя запись не произошла.

Ранний возврат, `continue` и отдельные функции часто уменьшают глубину вложенности. Однако компактность не должна скрывать порядок побочных эффектов. Проверяй пустой вход, ноль итераций, несовпадение длин, неизвестный вариант сообщения и отказ в середине обработки.

### Частые вопросы и выводы

**Когда выполняется `else` цикла?** После нормального завершения без `break`, в том числе для пустого входа.

**Проверяет ли `case int(x)` точный `int`?** Нет, используются правила проверки класса; `bool` тоже подходит. Для строгого количества нужен дополнительный guard.

**Почему `finally` скрыл ошибку?** Если он сделал собственный `return` или возбудил новую ошибку, ожидающий выход был заменён. Очистка должна сохранять ожидаемую семантику.

**Почему `except Exception` не поймал Ctrl+C?** `KeyboardInterrupt` находится вне ветви `Exception`, чтобы прерывание обычно проходило наружу.

**Практика:** реализуй чтение списка конфигураций: невалидная запись учитывается отдельно, пустая пропускается, системная ошибка чтения завершает операцию. Сформулируй, какие исключения можно обрабатывать на уровне одной записи, а какие требуют остановки всего процесса.

**Документация:** [составные инструкции](https://docs.python.org/3.14/reference/compound_stmts.html), [control flow tutorial](https://docs.python.org/3.14/tutorial/controlflow.html), [ошибки и исключения](https://docs.python.org/3.14/tutorial/errors.html), [встроенные исключения](https://docs.python.org/3.14/library/exceptions.html), [warnings](https://docs.python.org/3.14/library/warnings.html), [PEP 634](https://peps.python.org/pep-0634/), [PEP 765](https://peps.python.org/pep-0765/).

## Включения и генераторные выражения — Comprehensions

### Списковые включения: list comprehensions

Включение создаёт коллекцию из выражения и правил обхода. `[expression for item in source]` возвращает готовый список, вычисляя результат для каждого элемента сразу. Это удобная запись простого преобразования, а не отдельный режим ленивого исполнения.

```python
values = [1, 2, 3, 4]
squares = [value**2 for value in values]
assert squares == [1, 4, 9, 16]

expanded = []
for value in values:
    expanded.append(value**2)
assert squares == expanded
```

Если результат не используется, включение обычно неуместно: `[send(item) for item in items]` создаёт список ради побочных эффектов. Используй обычный цикл, где можно ясно показать ошибки, повторные попытки и учёт результата.

### Словарные включения: dict comprehensions

`{key_expression: value_expression for ...}` создаёт словарь. Повторяющийся равный ключ сохраняет последнее значение. Сами ключи остаются в порядке первого появления соответствующей записи, если не было удаления и повторной вставки.

```python
rows = [("a", 1), ("b", 2), ("a", 3)]
mapping = {key: value for key, value in rows}
assert mapping == {"a": 3, "b": 2}
assert list(mapping) == ["a", "b"]

lengths = {word: len(word) for word in ["python", "sql"]}
assert lengths == {"python": 6, "sql": 3}
```

В современном Python выражение ключа вычисляется перед выражением значения. Это важно, если в них есть вызовы с побочными эффектами; но ещё лучше избегать такой зависимости в построении данных.

```python
events = []


def mark(label, value):
    events.append(label)
    return value


result = {mark("key", "a"): mark("value", 1) for _ in range(1)}
assert events == ["key", "value"]
assert result == {"a": 1}
```

Если дубли недопустимы, одно включение не сообщит об ошибке: нужен явный цикл с проверкой ключа или отдельная валидация. Инверсия словаря `{value: key for key, value in data.items()}` теряет данные при повторяющихся значениях.

### Множественные включения: set comprehensions

Множественное включение `{expression for ...}` создаёт `set`, удаляя дубли по равенству и хешированию. Оно не сохраняет порядок результатов как прикладной контракт, а выражение должно давать хешируемые значения.

```python
names = [" Alice ", "alice", "BOB"]
normalized = {name.strip().casefold() for name in names}
assert normalized == {"alice", "bob"}

assert {value % 3 for value in range(10)} == {0, 1, 2}
assert type({value for value in []}) is set
```

Пустой `{}` вне включения — словарь. Фигурные скобки не обозначают генераторное выражение: оно записывается в круглых скобках и возвращает генератор, а не «ленивое множество».

### Фильтрация и преобразование элементов

Условие после `for` фильтрует вход, а условное выражение перед `for` выбирает результат для каждого элемента. Их позиции меняют смысл.

```python
values = [-2, -1, 0, 1, 2]
positive_squares = [value**2 for value in values if value > 0]
labels = ["positive" if value > 0 else "other" for value in values]
assert positive_squares == [1, 4]
assert labels == ["other", "other", "other", "positive", "positive"]
```

Несколько фильтров применяются последовательно, поэтому `[x for x in source if valid(x) if active(x)]` вызовет `active()` только после истинного `valid()`. Если преобразование дорого и нужно одновременно для фильтра и результата, можно применить `:=`, но не повторяй вызов случайно в двух местах.

### Несколько циклов и порядок их выполнения

Части `for` читаются слева направо, как вложенные обычные циклы. Правый цикл целиком проходит внутри одной итерации левого.

```python
pairs = [(x, y) for x in [1, 2] for y in ["a", "b"]]
assert pairs == [(1, "a"), (1, "b"), (2, "a"), (2, "b")]

triangular = [(x, y) for x in range(3) for y in range(x)]
assert triangular == [(1, 0), (2, 0), (2, 1)]
```

Фильтр располагается на том уровне, где доступны его имена. Включение с двумя источниками всё ещё может иметь квадратичную сложность; короткая запись не меняет алгоритм. Внутренний одноразовый итератор будет исчерпан после первого внешнего прохода.

### Вложенные включения

Вложенное включение создаёт вложенную структуру; несколько `for` в одном включении чаще создают плоский результат. Эти формы не взаимозаменяемы.

```python
matrix = [[1, 2], [3, 4]]
scaled = [[value * 10 for value in row] for row in matrix]
flat = [value for row in matrix for value in row]
assert scaled == [[10, 20], [30, 40]]
assert flat == [1, 2, 3, 4]

transposed = [list(column) for column in zip(*matrix, strict=True)]
assert transposed == [[1, 3], [2, 4]]
```

Транспонирование через `zip(*matrix)` без `strict=True` молча обрежет неровные строки. Распаковка `*matrix` создаёт аргументы вызова и не является универсальным решением для огромного потока строк. Если во включении сложно определить форму результата, используй обычный цикл и промежуточные имена.

### Области видимости переменных во включениях

Переменная итерации включения не выходит наружу. Это семантическая гарантия независимо от того, как конкретная версия CPython оптимизирует выполнение включений.

```python
x = "outer"
values = [x * 2 for x in range(3)]
assert values == [0, 2, 4]
assert x == "outer"

functions = [lambda: index for index in range(3)]
assert [function() for function in functions] == [2, 2, 2]

fixed = [lambda index=index: index for index in range(3)]
assert [function() for function in fixed] == [0, 1, 2]
```

Отдельная область не отменяет позднего связывания замыканий: лямбды первого списка читают одну привязку при вызове. Фиксация значения аргументом по умолчанию показана для сравнения; полное объяснение замыканий и времени вычисления defaults — в главе «Функции».

### Оператор := во включениях и его ограничения

Оператор присваивания позволяет сохранить промежуточное вычисление. Внутри включения его целевое имя обычно связывается в охватывающей области, а не остаётся локальной переменной итерации.

```python
source = [" a ", " ", " b "]
cleaned = [value for raw in source if (value := raw.strip())]
assert cleaned == ["a", "b"]
assert value == "b"
```

Это удобство может стать скрытым побочным эффектом. На пустом входе присваивание не произойдёт; при ленивом генераторном выражении оно произойдёт во время чтения, а не при создании. Не полагайся на существование последнего значения после включения, если оно не часть явного контракта.

Нельзя переприсваивать переменную итерации через `:=`, помещать выражение присваивания в итерируемую часть включения и использовать некоторые комбинации областей класса.

```python
invalid_sources = [
    "[(x := x + 1) for x in range(3)]",
    "[x for x in (items := range(3))]",
    "class C:\n    values = [(saved := x) for x in range(3)]",
]
for source in invalid_sources:
    try:
        compile(source, "<walrus>", "exec")
    except SyntaxError:
        pass
    else:
        raise AssertionError("Недопустимая форма оказалась разрешена")
```

### Генераторные выражения: базовый синтаксис

`(expression for item in source)` создаёт генератор, который вычисляет очередное значение при запросе. Он одноразовый: повторный обход продолжает текущее состояние или ничего не возвращает после исчерпания.

```python
squares = (value**2 for value in range(4))
assert next(squares) == 0
assert list(squares) == [1, 4, 9]
assert list(squares) == []
assert sum(value**2 for value in range(4)) == 14
```

Внешнее итерируемое выражение вычисляется, и его итератор получается при создании генераторного выражения. Тело и последующие части выполняются позже. Поэтому «все ошибки генератора всегда откладываются» — неверно.

```python
events = []


def source():
    events.append("source")
    return [1, 2]


generator = (events.append(f"item:{value}") or value * 2 for value in source())
assert events == ["source"]
assert next(generator) == 2
assert events == ["source", "item:1"]
```

В демонстрации побочный эффект намеренно встроен в выражение, чтобы показать момент исполнения. В обычном коде сложные действия лучше перенести в генераторную функцию. Генератор экономит память результата, но удерживает источник и другие необходимые ссылки. Если он читает файл, потребление должно происходить в пределах времени, когда файл открыт.

### Выбор между включением, генераторным выражением и обычным циклом

| Форма | Когда выбирать | Ограничение |
| --- | --- | --- |
| Списковое включение | Нужен готовый список и простое преобразование | Память под весь результат |
| Словарное/множественное включение | Нужна готовая индексирующая или уникальная структура | Дубли обрабатываются по правилам коллекции |
| Генераторное выражение | Однократная последовательная обработка | Одноразовость, отложенные ошибки |
| Обычный цикл | Несколько действий, ветвления, ошибки, учёт состояния | Больше строк, зато виден процесс |
| Генераторная функция | Сложная ленивая логика с именованным интерфейсом | Нужно продумать ресурсы и завершение |

`sum(generator)` обычно не нуждается в промежуточном списке. `sorted(generator)` всё равно собирает значения. Генератор не обязан быть быстрее включения на маленьком входе: дополнительный протокол имеет свою стоимость. Выбирай по доступу к данным и памяти, затем измеряй критичный участок.

### Подробное устройство генераторов — ссылка на раздел «Функции»

Генераторное выражение — лишь один способ получить генератор. Генераторная функция с `yield` сохраняет состояние между запросами, может делегировать через `yield from` и поддерживает протоколы завершения и передачи значений. Вызов такой функции создаёт объект, а выполнение тела начинается при потреблении.

```python
def squares(limit):
    for value in range(limit):
        yield value**2


assert list(squares(4)) == [0, 1, 4, 9]
```

Полный разбор `yield`, `yield from`, `send`, `throw`, `close`, возврата значения и асинхронных генераторов находится в [разделе «Функции»](03.%20functions.md). Здесь достаточно отличать готовую коллекцию от одноразового вычисляемого источника и понимать момент возникновения ошибок.

**Документация:** [включения и generator expressions](https://docs.python.org/3.14/reference/expressions.html#displays-for-lists-sets-and-dictionaries), [PEP 572](https://peps.python.org/pep-0572/), [генераторные выражения](https://docs.python.org/3.14/reference/expressions.html#generator-expressions).

## Итераторы и итерируемые объекты

### Введение в итераторы

Итерируемый объект (`iterable`) позволяет получить итератор через `iter()`. Итератор (`iterator`) хранит текущую позицию, возвращает очередное значение через `next()` и сообщает о конце через `StopIteration`. Итератор сам является итерируемым, но обратное неверно.

```python
values = [10, 20]
first = iter(values)
second = iter(values)
assert first is not second
assert iter(first) is first
assert next(first) == 10
assert next(first) == 20
assert next(second) == 10
assert list(first) == []
```

Список можно начать обходить заново, получив новый итератор. Сам итератор не «перезапускается» вызовом `iter(iterator)`. Файл, генератор, `map`, `filter` и `zip` обычно являются одноразовыми источниками. Не передавай один такой объект двум потребителям, если каждый ожидает полный независимый проход.

### Протокол итератора

`__iter__()` итератора возвращает его самого; `__next__()` выдаёт значение или возбуждает `StopIteration`. После исчерпания корректный итератор должен продолжать сообщать об исчерпании. `None` — обычное допустимое значение элемента и не обозначает конец.

```python
iterator = iter([None, 1])
assert next(iterator) is None
assert next(iterator) == 1
for _ in range(2):
    try:
        next(iterator)
    except StopIteration:
        pass
    else:
        raise AssertionError("Исчерпанный итератор выдал значение")
```

Для совместимости `iter()` также может использовать старый последовательностный протокол `__getitem__` с индексами от нуля до `IndexError`. Для новых типов реализуй явный `__iter__`: это делает намерение яснее. У асинхронной итерации отдельные методы `__aiter__`, `__anext__` и сигнал `StopAsyncIteration`; смешивать протоколы нельзя.

### Встроенные функции для работы с итераторами

`iter(obj)` получает итератор, `next(iterator, default)` возвращает значение по умолчанию при исчерпании. Default не подавляет произвольную ошибку `__next__()`: обрабатывается именно `StopIteration`.

```python
iterator = iter([])
MISSING = object()
assert next(iterator, MISSING) is MISSING

chunks = iter([b"ab", b"cd", b""])
assert list(iter(lambda: next(chunks), b"")) == [b"ab", b"cd"]
```

Форма `iter(callable, sentinel)` вызывает функцию без аргументов до результата, равного маркеру; сам маркер не выдаётся. Она удобна для чтения блоков `iter(lambda: file.read(chunk_size), b'')`. Здесь применяется сравнение с маркером, поэтому выбирай значение, которое однозначно обозначает конец.

`list`, `tuple`, `set`, `dict` и `sorted` потребляют источники; `sum`, `min`, `max`, `any`, `all` агрегируют их, причём некоторые завершаются раньше конца. Для пустых `min`/`max` можно задать `default`, а `any([])` ложно и `all([])` истинно.

### Как работает цикл for под капотом

Упрощённо `for` получает итератор один раз, затем запрашивает элементы, пока `next()` не сообщит о завершении. Ошибки тела не являются сигналом окончания самого протокола.

```python
source = [1, 2, 3]
iterator = iter(source)
collected = []
while True:
    try:
        item = next(iterator)
    except StopIteration:
        break
    collected.append(item)
assert collected == [1, 2, 3]
```

Тело намеренно расположено вне `try`: иначе `StopIteration`, ошибочно пришедший из обработки элемента, можно было бы принять за штатный конец источника. Это концептуальное объяснение, а не обещание одинакового байт-кода всех версий. Обычный `for` короче и меньше подвержен таким ошибкам.

### Создание собственных итераторов

Разделяй одноразовый объект состояния и многократно итерируемую коллекцию. В первом случае `__iter__` возвращает `self`, во втором — новый независимый итератор при каждом вызове.

```python
class Countdown:
    def __init__(self, start: int):
        if type(start) is not int or start < 0:
            raise ValueError("start должен быть неотрицательным целым")
        self._remaining = start

    def __iter__(self):
        return self

    def __next__(self) -> int:
        if self._remaining == 0:
            raise StopIteration
        self._remaining -= 1
        return self._remaining


counter = Countdown(3)
assert list(counter) == [2, 1, 0]
assert list(counter) == []
```

```python
class CountdownSource:
    def __init__(self, start: int):
        if type(start) is not int or start < 0:
            raise ValueError("start должен быть неотрицательным целым")
        self._start = start

    def __iter__(self):
        return iter(range(self._start - 1, -1, -1))


source = CountdownSource(3)
assert list(source) == [2, 1, 0]
assert list(source) == [2, 1, 0]
```

Если итератор управляет ресурсом, его протокол обхода сам по себе не определяет закрытие при раннем выходе. Для ресурса нужен отдельный контракт, часто контекстный менеджер. Генераторная функция нередко реализует такой обход проще; вручную писать `__next__` стоит, когда отдельный класс состояния действительно нужен.

### Итерируемые объекты в стандартной библиотеке

| Объект | Повторный независимый обход | Особенности |
| --- | --- | --- |
| `list`, `tuple`, `str`, `range` | Да, новым итератором | Неизменность исходных данных зависит от типа |
| `dict`, `dict.items()` | Да, новым итератором | Представление динамическое |
| `set`, `frozenset` | Да | Нет прикладного порядка обхода |
| Открытый текстовый файл | Обычно продолжается текущая позиция | Нужны открытый ресурс и корректная кодировка |
| Генератор | Нет | Состояние расходуется |
| `map`, `filter`, `zip`, `enumerate` | Нет | Ленивое потребление входов |
| `pathlib.Path.iterdir()` | Нет для уже созданного итератора | Результат зависит от состояния каталога |

«Можно вызвать `iter()`» не означает «можно пройти дважды». Даже новый вызов функции-источника может вернуть уже другие внешние данные. Если алгоритму необходим стабильный повторный проход, явно выбери снимок, кэш или источник с соответствующей гарантией.

### Полезные функции для работы с итераторами

```python
assert list(map(str.upper, ["a", "b"])) == ["A", "B"]
assert list(filter(lambda value: value > 0, [-1, 0, 2])) == [2]
assert list(filter(None, [0, None, "", 3, "a"])) == [3, "a"]
assert any(value > 10 for value in [1, 20, 30])
assert all(value >= 0 for value in [])
assert min([], default=None) is None

iterator = iter([0, 1, 2])
assert any(iterator)
assert list(iterator) == [2]
```

`any()` остановился на `1`, поэтому `2` не был прочитан. `filter(None, source)` удаляет все ложные значения, а не только `None`. Если ноль допустим, нужен явный предикат.

`map()` с несколькими источниками по умолчанию заканчивается на коротком; в Python 3.14 добавлен `strict=True`.

```python
# Python 3.14+: map(..., strict=True).
mapped = map(lambda left, right: left + right, [1, 2], [10], strict=True)
assert next(mapped) == 11
try:
    next(mapped)
except ValueError:
    pass
else:
    raise AssertionError("Разные длины не обнаружены")
```

Для нескольких входов на более ранних версиях часто удобнее генератор над `zip(..., strict=True)`. И здесь контроль длины выполняется по мере потребления.

### Модуль itertools

`itertools` предоставляет строительные блоки для потоковых алгоритмов. Их полезно знать вместе с моделью потребления, буферизации и возможной бесконечностью.

| Функция | Назначение | Важная оговорка |
| --- | --- | --- |
| `chain`, `chain.from_iterable` | Последовательный обход нескольких источников | Источники расходуются |
| `islice` | Выбрать участок по позициям | Пропущенные элементы тоже потребляются; отрицательных индексов нет |
| `pairwise` | Соседние пары | Для менее двух элементов результат пуст |
| `batched`, 3.12+ | Группы до `n` элементов | Последняя обычно может быть неполной |
| `accumulate` | Накопленные результаты | Имеет начальное значение и свою функцию операции |
| `groupby` | Группы соседних равных ключей | Не объединяет разнесённые группы автоматически |
| `tee` | Несколько логических ветвей одного источника | Отставание ветви вызывает буферизацию |
| `product`, `permutations`, `combinations` | Комбинаторные последовательности | Выход может быть огромным; входы могут материализоваться |
| `count`, `cycle`, `repeat` | Регулярные, в том числе бесконечные источники | Нужен внешний предел; `cycle` сохраняет прочитанные элементы |
| `takewhile`, `dropwhile` | Разделение по предикату начала | Первый нарушивший элемент у `takewhile` уже потреблён |
| `zip_longest` | Обход до самого длинного входа | Fill value нужно отличать от допустимых данных |

```python
from itertools import accumulate, batched, chain, islice, pairwise

assert list(chain.from_iterable([[1, 2], [], [3]])) == [1, 2, 3]
assert list(islice(range(10), 2, 8, 2)) == [2, 4, 6]
assert list(pairwise([10, 15, 13])) == [(10, 15), (15, 13)]
assert list(accumulate([1, 2, 3], initial=0)) == [0, 1, 3, 6]
assert list(batched(range(5), 2)) == [(0, 1), (2, 3), (4,)]
```

```python
# Python 3.13+: strict у itertools.batched.
from itertools import batched

batches = batched(range(5), 2, strict=True)
assert next(batches) == (0, 1)
assert next(batches) == (2, 3)
try:
    next(batches)
except ValueError:
    pass
else:
    raise AssertionError("Неполная группа должна вызвать ошибку")
```

`groupby()` объединяет именно соседние элементы. Для общей группировки сначала сортируют по тому же ключу, если допустимы сортировка и материализация; либо накапливают группы в словаре.

```python
from itertools import groupby

values = ["a", "a", "b", "a"]
groups = [(key, list(group)) for key, group in groupby(values)]
assert groups == [("a", ["a", "a"]), ("b", ["b"]), ("a", ["a"])]

outer = groupby(values)
key, old_group = next(outer)
assert key == "a"
next(outer)
assert list(old_group) == []  # Внутренние группы разделяют источник.
```

Сохраняй `list(group)` до перехода внешнего итератора, если группа нужна позже. Не складывай сами group-итераторы в список с ожиданием независимых данных.

```python
from itertools import count, islice, product, takewhile, tee, zip_longest

assert list(islice(count(10, 2), 3)) == [10, 12, 14]
assert list(product([1, 2], ["a", "b"])) == [(1, "a"), (1, "b"), (2, "a"), (2, "b")]
assert list(zip_longest([1, 2], ["a"], fillvalue=None)) == [(1, "a"), (2, None)]

source = iter([1, 2, 0, 3])
assert list(takewhile(lambda value: value > 0, source)) == [1, 2]
assert list(source) == [3]

left, right = tee(iter([[1], [2]]))
item = next(left)
item.append(99)
assert next(right) == [1, 99]  # Tee не создаёт глубокие копии элементов.
```

`tee()` не делает внешний источник повторяемым и не гарантирует ограниченный буфер при сильно отстающей ветви. После разделения потребляй возвращённые ветви, а не исходный итератор отдельно. Для двух полных проходов по небольшому входу готовый список может оказаться проще и предсказуемее.

### Частые вопросы и выводы

**Чем отличается iterable от iterator?** Первый позволяет получить обход, второй хранит конкретный ход обхода. Один iterable может создавать несколько независимых iterator.

**Можно ли проверить пустоту без потребления?** Универсального способа для произвольного одноразового источника нет. Извлечение первого элемента уже меняет состояние; при необходимости верни его в дальнейший поток через `chain` или используй явный буфер.

**Почему второй `sum()` вернул ноль?** Первый вызов мог исчерпать генератор. Для повторного прохода нужен новый источник или сохранённая коллекция.

**Экономит ли генератор всю память?** Он не хранит готовый результат, но удерживает своё состояние, ссылки и возможные буферы. Потребитель может всё равно материализовать данные.

**Почему нельзя `raise StopIteration` внутри генераторной функции?** Непреднамеренный выход такого исключения преобразуется в `RuntimeError` по правилам PEP 479. Для завершения генератора используй `return`; явный `StopIteration` нужен в ручном `__next__`.

**Документация:** [iterator types](https://docs.python.org/3.14/library/stdtypes.html#iterator-types), [встроенные функции](https://docs.python.org/3.14/library/functions.html), [itertools](https://docs.python.org/3.14/library/itertools.html), [PEP 479](https://peps.python.org/pep-0479/).

**Сквозная практика: обработчик событий продаж в JSONL**

Задача объединяет типы, строки, `match`, исключения, итерацию, сортировку и формат результата. Программа читает файл по одной JSON-записи на строку, считает продажи по SKU, отдельно учитывает отменённые и невалидные записи. Суммы хранятся в целых минимальных денежных единицах, без накопления двоичной погрешности.

Контракт входа:

- Пустые строки пропускаются и не входят в счётчики.
- Продажа содержит `kind='sale'`, строковый `sku`, точное целое `quantity` от 1 до 10 000 и строковую `unit_price`.
- SKU нормализуется в NFC, внешние пробелы удаляются; после этого длина от 1 до 80 кодовых точек.
- Цена неотрицательна, не больше миллиарда, точно выражается с шагом 0.01. Разрешена ASCII-запись `Decimal`, включая экспоненциальную форму; исходная строка ограничена 32 символами после удаления внешних пробелов.
- Запись `kind='cancelled'` учитывается как отменённая. Дополнительные поля здесь допускаются; сверка отмены с конкретной продажей не входит в контракт.
- Повторяющиеся ключи JSON и нестандартные константы `NaN`/`Infinity` отклоняются.
- Ошибка записи не останавливает обработку; ошибка чтения файла завершает операцию. Сохраняется ограниченное количество сообщений, но учитываются все отклонённые строки.

Это отчёт по событиям, не полноценная бухгалтерская система: валюта и уникальность событий в учебном формате не заданы. Для реального повторно читаемого потока потребовались бы идентификаторы событий и правила дедупликации. Построчное чтение не ограничивает число уникальных SKU и размер одной строки; такие пределы нужно добавлять под контракт сервиса.

Сохрани код в `syntax_events.py`:

```python
# syntax_events.py
from __future__ import annotations

import argparse
import json
import sys
import unicodedata
from collections.abc import Iterable
from dataclasses import dataclass
from decimal import Decimal, InvalidOperation, localcontext
from pathlib import Path
from typing import NoReturn


@dataclass(frozen=True)
class Report:
    accepted: int
    cancelled: int
    rejected: int
    totals_minor: dict[str, int]
    errors: tuple[str, ...]


def price_to_minor(raw: str) -> int:
    text = raw.strip()
    if not text or len(text) > 32 or not text.isascii():
        raise ValueError("некорректный формат цены")

    try:
        amount = Decimal(text)
    except InvalidOperation as error:
        raise ValueError("некорректный формат цены") from error

    if not amount.is_finite() or not Decimal(0) <= amount <= Decimal("1000000000"):
        raise ValueError("цена вне допустимого диапазона")

    with localcontext() as context:
        context.prec = 40
        rounded = amount.quantize(Decimal("0.01"))
        if rounded != amount:
            raise ValueError("цена должна точно выражаться с шагом 0.01")
        return int(rounded * 100)


def reject_json_constant(value: str) -> NoReturn:
    raise ValueError(f"недопустимая JSON-константа: {value}")


def unique_object(pairs: list[tuple[str, object]]) -> dict[str, object]:
    result: dict[str, object] = {}
    for key, value in pairs:
        if key in result:
            raise ValueError("повторяющийся ключ JSON")
        result[key] = value
    return result


def parse_event_line(line: str) -> tuple[str, int] | None:
    try:
        payload: object = json.loads(
            line,
            parse_constant=reject_json_constant,
            object_pairs_hook=unique_object,
        )
    except json.JSONDecodeError as error:
        raise ValueError("некорректный JSON") from error

    match payload:
        case {"kind": "cancelled"}:
            return None
        case {
            "kind": "sale",
            "sku": str(raw_sku),
            "quantity": int(quantity),
            "unit_price": str(raw_price),
        } if type(quantity) is int:
            sku = unicodedata.normalize("NFC", raw_sku).strip()
            if not 1 <= len(sku) <= 80:
                raise ValueError("некорректный SKU")
            if not 1 <= quantity <= 10_000:
                raise ValueError("количество вне допустимого диапазона")
            return sku, quantity * price_to_minor(raw_price)
        case _:
            raise ValueError("недопустимая структура события")


def build_report(lines: Iterable[str], *, max_errors: int = 20) -> Report:
    if type(max_errors) is not int:
        raise TypeError("max_errors должен быть целым числом")
    if max_errors < 0:
        raise ValueError("max_errors не может быть отрицательным")

    accepted = cancelled = rejected = 0
    totals: dict[str, int] = {}
    errors: list[str] = []

    for line_number, line in enumerate(lines, start=1):
        if not line.strip():
            continue
        try:
            event = parse_event_line(line)
        except ValueError as error:
            rejected += 1
            if len(errors) < max_errors:
                errors.append(f"Запись {line_number}: {error}")
            continue

        if event is None:
            cancelled += 1
            continue

        sku, amount_minor = event
        totals[sku] = totals.get(sku, 0) + amount_minor
        accepted += 1

    return Report(accepted, cancelled, rejected, totals, tuple(errors))


def render_report(report: Report) -> str:
    payload = {
        "accepted": report.accepted,
        "cancelled": report.cancelled,
        "rejected": report.rejected,
        "totals_minor": dict(sorted(report.totals_minor.items())),
        "errors": report.errors,
    }
    return json.dumps(payload, ensure_ascii=False, indent=2)


def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(description="Отчёт по событиям продаж JSONL")
    parser.add_argument("--input", required=True, type=Path)
    arguments = parser.parse_args(argv)

    try:
        with arguments.input.open(encoding="utf-8") as source:
            report = build_report(source)
    except (OSError, UnicodeError) as error:
        print(f"Ошибка чтения: {error}", file=sys.stderr)
        return 2

    print(render_report(report))
    return 1 if report.rejected else 0


if __name__ == "__main__":
    raise SystemExit(main())
```

`Report` использует `frozen=True`, чтобы запретить обычную перепривязку его полей. Вложенный `dict` при этом остаётся изменяемым: это осознанно простой объект результата, не пример глубокой неизменяемости. Функция не возвращает ссылки на внешние изменяемые коллекции, переданные вызывающим кодом.

Создай `events.jsonl` со следующим содержимым. Последняя строка намеренно не является JSON:

```jsonl

{"kind": "sale", "sku": "B", "quantity": 1, "unit_price": "3.00"}
{"kind": "cancelled", "reason": "user request"}
{"kind": "sale", "sku": "A", "quantity": 1, "unit_price": "2.50"}

not-json
```

  },
