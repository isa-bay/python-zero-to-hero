# Типы данных в Python

## Основы типов данных
В Python всё является объектом. Типы данных (классы) определяют поведение объектов.
*   **Динамическая типизация:** Переменная — это просто ссылка (имя) на объект в памяти. Тип привязан к объекту, а не к переменной.
*   **Сильная типизация:** Python не выполняет неявное преобразование типов, если это не ведет к потере данных или неоднозначности (например, нельзя сложить строку и число без явного приведения).
*   **Изменяемость (Mutability):** Ключевая характеристика. Одни объекты можно изменить после создания (`list`, `dict`, `set`), другие — нет (`int`, `str`, `tuple`).

## Числовые типы (Numeric Types)
Python предоставляет три основных числовых типа, а также поддержку дробей и десятичных чисел через модули.

*   **`int` (целое число):** Неограниченная точность (доступной памяти). В CPython реализован как массив цифр в основании `2^30` или `2^15`. Операции с большими числами (BigInt) медленнее, чем с числами, помещающимися в машинное слово.
*   **`float` (число с плавающей точкой):** Реализует стандарт IEEE 754 (обычно 64-битное, double-precision).
    *   *Проблемы:* Не может точно представить десятичные дроби вида `0.1`. Для финансовых расчетов используйте `decimal.Decimal`.
    *   *Спецзначения:* `math.inf` (бесконечность), `math.nan` (Not a Number). `NaN` не равен самому себе (проверка через `math.isnan()`).
*   **`complex` (комплексное число):** Запись вида `3 + 4j`. Имеет атрибуты `.real` и `.imag`.

## Логический тип (bool)
Подтип `int` (в Python 2 и 3). `True` == 1, `False` == 0.
*   **Важно:** В операциях с целыми числами булевы значения ведут себя как 1 и 0. `True + True` вернет 2.
*   **Булева контекст:** Любой объект в Python может быть интерпретирован как булев. По умолчанию `False` — это `None`, `False`, `0` (любой числовой ноль), пустые коллекции (`[]`, `{}`, `()`, `""`, `set()`).

## Текстовый тип (str)
Неизменяемая (`immutable`) последовательность символов Unicode.
*   **Реализация:** В CPython 3 строки хранятся в одной из форм: **compact ascii** (1 байт на символ), **compact** (1, 2 или 4 байта) или **legacy**. Это оптимизация памяти.
*   **Интернирование (Interning):** Короткие строки, похожие на идентификаторы, автоматически интернируются (кэшируются). Поэтому сравнение по `is` для них может сработать, но полагаться на это нельзя. Всегда используйте `==` для сравнения значений.
*   **Конкатенация:** Избегайте `+` в циклах из-за создания новых строк. Используйте `''.join(list_of_parts)`.

## NoneType (None)
Единственный объект с типом `NoneType`. Обозначает отсутствие значения.
*   **Синглтон:** В интерпретаторе существует только один объект `None`. Проверку нужно делать через `is None` (сравнение по идентичности), а не через `==` (сравнение по значению), так как `__eq__` может быть переопределен в пользовательских классах, но `is` всегда надежен.

## Коллекции
### Последовательности (Sequence Types)
Общий протокол: поддержка индексов, срезов, `len()`, итерирование.

*   **Списки (list)**
    *   *Изменяемый, динамический массив.*
    *   *Реализация:* Массив указателей на объекты `PyObject*`. При добавлении элементов (`append`) память выделяется с запасом (oversized allocation) для амортизированной O(1) сложности. Вставка (`insert`) в начало или середину требует сдвига всех последующих элементов (O(n)).
*   **Кортежи (tuple)**
    *   *Неизменяемый, статический массив.*
    *   *Особенности:* Если кортеж содержит изменяемые объекты (например, список), сам кортеж остается неизменным, но его содержимое (список) можно мутировать.
    *   *Производительность:* Создание кортежа обычно быстрее списка, так как не требует оверхеда на резервирование памяти. Занимает меньше памяти (знает точный размер).
*   **Диапазоны (range)**
    *   *Ленивая последовательность.* Не хранит все числа, а вычисляет их по требованию (реализует протокол последовательности). Используется для итерации.

### Отображения (Mapping Types)
*   **Словари (dict)**
    *   *Реализация:* Хеш-таблица с открытой адресацией (псевдослучайное пробирование).
    *   *Ключи:* Должны быть **хешируемыми** (`hashable`). Объект хешируем, если у него определен метод `__hash__()` (и он не меняется) и метод `__eq__()`. Все неизменяемые встроенные типы хешируемы. Пользовательские классы по умолчанию хешируемы (по `id()`), но если переопределить `__eq__`, `__hash__` сбрасывается в `None`.
    *   *Современные фичи (Python 3.6+):* Сохраняют порядок вставки элементов. Это стало возможным благодаря компактному представлению (indices + entries), что также уменьшило потребление памяти на 20-25%.

### Множества (Set Types)
*   **Множества (set)**
    *   *Изменяемая, неупорядоченная коллекция уникальных хешируемых элементов.*
    *   *Реализация:* Аналогична `dict`, но вместо "значений" хранятся фиктивные константы (или просто ключи). Операции `in`, `add`, `remove` в среднем O(1).
*   **Неизменяемые множества (frozenset)**
    *   Версия `set`, которую можно использовать как ключ в словаре или элемент другого множества.

## Бинарные типы
Используются для работы с байтами и двоичными данными (файлы, сетевые пакеты).
*   **`bytes`:** Неизменяемая последовательность байт (0-255).
*   **`bytearray`:** Изменяемая версия `bytes`.
*   **`memoryview`:** Позволяет обращаться к внутренним данным объекта (поддерживающего буферный протокол, например `bytes`, `bytearray`) без копирования. Крайне полезно для производительности при работе с большими объемами данных.

## Преобразование типов
*   **Явное (приведение):** `int()`, `str()`, `list()`, `dict()` и т.д. Конструкторы типов.
*   **Приведение к bool:** Правила "правдивости" (см. раздел `bool`).
*   **Важно:** Нельзя преобразовать словарь в список без потери структуры (`list(mydict)` вернет список ключей, а не пар).

## Проверка типов
*   **`type(obj)`:** Возвращает точный класс объекта. Использовать `type(obj) is SomeClass` для проверки на идентичность класса (не подходит для наследования).
*   **`isinstance(obj, class_or_tuple)`:** Предпочтительный способ. Учитывает наследование и абстрактные базовые классы (ABC). Например, `isinstance([], collections.abc.Sequence)` вернет `True`.
*   **`issubclass(cls, base)`:** Проверка, является ли класс подклассом другого.
*   **Утиная типизация:** Не проверяй тип, проверяй наличие метода (EAFP — Easier to Ask for Forgiveness than Permission). `hasattr(obj, '__len__')` или просто попробуй вызвать метод в блоке `try`.

## Сравнение типов
*   **`==` и `!=`:** Сравнивают *значения*. Для пользовательских классов можно переопределить через `__eq__`.
*   **`is` и `is not`:** Сравнивают *идентичность* объектов (адрес в памяти). Используйте для сравнения с синглтонами (`None`, `True`, `False`).
*   **Упорядочивание (`<`, `>`, `<=`, `>=`):**
    *   В Python 2 можно было сравнивать разные типы (числа с кортежами) по "произвольному" правилу (по имени типа).
    *   **В Python 3 сравнение разных типов (если они не реализуют общий интерфейс) вызывает `TypeError`**. Это повышает безопасность кода.

## Производительность типов (Deep Dive)
*   **Поиск в коллекции (`in`):** `set`/`dict` O(1) vs `list`/`tuple` O(n).
*   **Конкатенация:** `list.extend()` быстрее циклов с `append`. `''.join()` быстрее конкатенации строк в цикле.
*   **Создание объектов:** Использование литералов (`[]`, `{}`, `""`) значительно быстрее вызова конструктора типов (`list()`, `dict()`, `str()`), так как конструктору нужно пройти глобальный поиск имени.
*   **Слоты (Slots):** В пользовательских классах использование `__slots__` уменьшает потребление памяти (отключает `__dict__` и `__weakref__`), что критично при создании миллионов объектов.

## Частые ошибки
1.  **Использование изменяемых объектов как аргументов по умолчанию.**
    ```python
    def bad_append(item, target_list=[]):  # Список создается один раз!
        target_list.append(item)
        return target_list
    ```
    *Решение:* `def good_append(item, target_list=None): if target_list is None: target_list = []`

2.  **Путаница `==` и `is`.**
    ```python
    a = 256
    b = 256
    a is b  # Может быть True (из-за кэширования малых int)
    c = 257
    d = 257
    c is d  # Скорее всего False (разные объекты)
    ```

3.  **Изменение словаря/списка во время итерации.**
    ```python
    d = {'a': 1, 'b': 2}
    for k in d:  # RuntimeError: dictionary changed size during iteration
        if k == 'a':
            del d[k]
    ```
    *Решение:* Итерироваться по копии ключей `list(d.keys())`.

4.  **Предположение, что `float` точен.**
    ```python
    0.1 + 0.2 == 0.3  # False!
    ```

5.  **Использование пустого множества.** `{}` — это пустой *словарь*, а не множество. Пустое множество — `set()`.

## Частые вопросы и ключевые выводы
*   **Когда использовать tuple вместо list?**
    *   Когда данные гетерогенны (разные по смыслу) и имеют фиксированную структуру (например, координаты `(x, y)`).
    *   Когда нужна гарантия неизменности (ключ для dict).
    *   Когда важна производительность и меньший расход памяти.

*   **Как работает хеш-таблица в dict?**
    *   Вычисляется хеш ключа (`hash(key)`). Берется младшая часть бит для определения индекса в таблице. Если ячейка занята (коллизия), применяется пробирование (поиск следующей свободной). При загрузке таблицы более 2/3 происходит ресайз (увеличение размера).

*   **Ключевые выводы:**
    1.  Понимание изменяемости — основа предотвращения багов с неожиданным изменением данных.
    2.  Выбор правильной структуры данных (set для уникальности и поиска, deque для очереди, list для стека) часто важнее микрооптимизаций алгоритма.
    3.  Аннотации типов (typing) не влияют на производительность, но критически важны для поддержки кода на уровне Senior.
    4.  Всегда учитывайте, что присваивание не копирует объект, а создает новую ссылку. Для копирования используйте `copy.copy` (поверхностное) или `copy.deepcopy` (глубокое).
